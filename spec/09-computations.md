# 09 — Computations (§11)

Computations write values into computed fields. They share the whole expression language with rules, so everything in §1–§10 applies. Computation adds four mechanisms of its own:

1. **Every computation also generates a validation rule** over its complete alternative table (§6); under overlapping guards that rule is not "compare with the first selected result".
2. **Each computed instance evaluates to one of five outcomes** (§2), decided by the selected operation and the states of the operands it reaches. The change actions **VALUE / CLEARED / ERRORED** are a projection of those outcomes against the source document (§3.3).
3. **Two kinds of "no value"**: a clean clear cascades as **EMPTY**; an invalidity **POISONS**, and the poison is **read-driven and order-dependent** (§3).
4. **A computed value lands as a string in the target's declared shape** (the *stored form*), which is what downstream reads (§4).

## 1. The ground rules

Each bullet is a rule every computation obeys. The subsections own the scheduling graph (§1.1), the order in which static classes are reported (§1.2), the scale gate (§1.3) and the wrong-kind classes of constant and field sources (§1.4).

- **Every computation also generates a validation rule.** A filled computed field is checked against every holding alternative's guarded mismatch clause (§6). With mutually exclusive preconditions this agrees with the first selected computation result; overlapping preconditions can make validation fire on a later alternative even when the stored value equals the first result. Assigning a time-dependent value such as `Now` is legal but unstable: the generated rule can observe a later instant and report a mismatch immediately ([§6](05-dates-and-time.md)).
- **The computed field may appear neither in a precondition nor in an operation**; both directions draw the same rejection. The test is containment, not equality, so a read of a group containing the target is a read of the target. The exemptions are closed: singular `GroupFilled` over a containing group, legal for fixed and repeatable targets; the positive fixed-root `AtLeastOneGroupFilled(Root)` form; and `CurrentRepetition`, which reads a structural coordinate. The reported class follows the reading mode and the alternative walk of [§5.2](#52-the-target-self-read-gate).
- **Execution is scoped to the computed field, not the declaration group.** An all-nonrepeatable target has exactly one implicit runtime instance even when its group has no document content, so a computation declared in another fixed subtree still computes that target. The declaration group contributes no repetition of its own: a constant computation declared in a repeatable group whose fixed target sits elsewhere produces exactly one value, both when the declaring group has no instantiated row and when it has three; it is neither silenced nor repeated. Number, String, Boolean and Confirm constants declared in another group all execute to their constant at the target's own address. A repeatable cross-group target follows the same scope law: a bare constant declared at the root computes once per instantiated target row and is indistinguishable from the same constant declared at the target's own group, on all four constant families. Measured scope: these rows observe computed values; generated validation and public result/application behaviour are outside them. [§5.1](#51-operand-reach-scope-the-level-walk-and-placement) owns which declaring groups are admitted.
- **The index field is not a target.** A computation may not write into the field a repeatable group declares as its index: that target draws `MVK_ERROR_INDEX_AS_CALCULATED_FIELD`, whether the computation is declared in the indexed group or at an ancestor of it. The refusal follows the resolved target, not the field or the operation. An ordinary sibling in the same group is computed into freely, and so is a field the group names as a **sort** field, although the group declares both kinds of member alike; a rule may still report on the index field. Like the cycle law it reads declarations alone. Measured with a Number index field under a constant and an aggregate operation.
- **Two predicates are refused in a computation's conditions and ordinary in a rule.** `CustomCondition` or `RepetitionNotUnique` in an alternative's precondition, and `CustomCondition` in the common precondition, draw `MVK_ERROR_INVALID_LANGUAGE_FEATURE`; `RepetitionNotUnique` in the common precondition draws the same class. `RepetitionNotUnique` in the operation draws `MVK_UNEXPECTED_TOKEN`, an operation not being a condition. Inside a filter body neither reaches that class: the filter's own `MVK_DISALLOWED_CONSTRUCT_IN_FILTER_CONDITION` answers in the precondition, the operation and a rule alike ([§9](07-repetition-and-iteration.md)).
- **`RangeAsString(field, start, end)`** accepts one value-validating String-like field without a category or wildcard and requires `1 ≤ start ≤ end`. Its authored bounds are 1-based and inclusive over the field's evaluated String in UTF-16 code units. An empty source or an end beyond the evaluated length yields the empty String, never a partial prefix, while formal unavailability follows the ordinary poison path (§3.2). The result still passes through the normal String root-store and target checks (§2, §4).
- **`RangeAsNumber(field, start, end)`** uses the same checked field and UTF-16 range, then accepts only a nonempty ASCII digit run. Every clean mismatch, empty source or overshoot yields the real numeric value `0`; formal unavailability poisons. The result enters ordinary numeric arithmetic, generated validation and Number target checking rather than a range-specific write path ([§5](04-numbers-and-decimals.md)).
- **`FieldValueAsNumber(...)`** uses the checked selected-domain conversion of [§5 §4.5](04-numbers-and-decimals.md#45-number-valued-sources): an empty source yields the real value `0`, an exact projected token yields its Number, and formal unavailability poisons. The result enters ordinary numeric arithmetic, generated validation and Number target checking.
- **Operation-form numeric wrappers.** `RoundDown`, `RoundUp`, `RoundAccounting` and `Abs` may be the root or an ordinary operand inside larger arithmetic, and each consumes one already-checked number-like child: another wrapper, an independently admitted operand-list `Min`/`Max`, direct or grouped numeric `BaseYear`, a direct `FieldValueAsNumber(...)`, `RangeAsNumber(...)`, a numeric field-list aggregate, a temporal numeric component, a Base-Year-derived component, or a Date-only month/year-difference source. Only an immediate or grouped numeric literal is rejected at each wrapper boundary. Nested wrappers evaluate from the innermost outward; the child keeps its own division, power, target-reference and domain-failure checks. Enclosing division traversal crosses each reached value-function subtree, while each function node structurally separates an outer direct-left power. Rounding uses its authored scale; absolute value preserves the child's scale and runs after the complete child, aggregate fold or extremum selection. Computation maps every clean missing or all-empty result to numeric zero and preserves arithmetic domain failure and formal unavailability through every wrapper ([§5](04-numbers-and-decimals.md), [§6](05-dates-and-time.md)). How each wrapper moves the fill directions is owned by [§12 §4](10-validation-and-polarity.md#4-the-directional-fill-machinery-behind-the-typing).

### 1.1 Group-derived scheduling dependencies

**Calculation cycles are a static refusal, not a runtime hazard.** A12 sorts the calculated fields topologically before it generates anything and reports `MVK_ERROR_CALC_CYCLE`, spelling the cycle out. The graph reads declarations alone — each computed target and its required producers, with the group rule below — so it is decidable without a document.

- A read inside an **alternative's precondition** is an edge exactly as an operation's read is, although one is a condition spelled `FieldFilled(X)` and the other an operand spelled `[X]`.
- The graph is over **resolved fields**, so a circle closing through an aggregate over a repeatable group in one direction and an absolute read out of it in the other is refused like two sibling reads.
- A **one-node** circle is a different class: a computation reading its own target draws `MVK_ERROR_REFERENCE_TO_CALCULATED_FIELD` (§5.2), never the cycle class.
- A back edge through a field no computation writes is admitted; ordinary input fields remain operands but are not computed-target nodes.
- **A declaration a variant filter takes out is no node**: with `variantFilter` `ONLY` another variant on either computation of a two-computation circle, the model is admitted.
- Every other class measured beside the cycle withholds it: another computation's text defect or member class, a rule's text defect, a structural path class, a missing error text.
- `CurrentRepetition(group)` reads only the selected structural row coordinate: it contributes no contained-field dependency and must not be expanded into dependencies on every computed field below the group. Actual field reads remain ordinary edges, so a `First := Base` computation under `CurrentRepetition(group) > 0` may precede `Second := First` without the structural guard manufacturing a cycle.

**Operand membership, forbidden target reads and required producer order are three distinct relations.** For an expanded A12 model, a referenced group contributes every contained field to the operand inventory, including the consumer's own target and fields below deeper repeatable levels. That inventory feeds [the formal-input selection](#33-what-compute-reports); it is neither the runtime presence scan nor the scheduling graph. `CurrentRepetition` contributes a structural coordinate, not contained-field reads. The target-reference gate is [§5.2](#52-the-target-self-read-gate)'s containment test with its named exemptions.

**A group read retains its producer dependencies unless the conditional rule applies.** For plain, unindexed group guards, an ordinary field read, or a group read other than the positive containing-group forms named below, retains its ordinary producer dependency. This includes `GroupNotFilled`, a positive group outside the consumer's ancestry, and reads in a later alternative that can never execute. The admitted singular `GroupFilled(G)` and positive fixed-root `AtLeastOneGroupFilled(Root)` forms use the conditional rule when the group contains the consumer: among computed fields in `G`, omit the consumer itself and the producers whose syntactic profile protects `G`; retain every other producer. An ordinary read of that same producer still requires it.

**The syntactic profile of a nonrepeatable producer** is queried for a group `G`. A positive singular `GroupFilled(H)` leaf, or the admitted positive fixed-root `AtLeastOneGroupFilled` form, contributes protection exactly when `H` contains the producer and is `G` or a descendant of `G`. Other leaves contribute none. `And` needs protection from at least one operand; `Or` needs it from every operand. First distribute each computation's common precondition into its alternatives, then gather the **present** conditions across every computation of that target. At least one present condition must exist and all present conditions must protect `G`. An absent condition is omitted, not treated as an unprotected branch.

**A repeatable producer** first receives implicit row guards. A computation whose profile does not already require its innermost repeatable group, or a narrower containing group, receives `GroupFilled` of that repeatable group as an additional common precondition. Queries at the repeatable group or an ancestor therefore remain protected. Below that group, an absent authored condition now contributes a present condition that does not protect the narrower group; it must not be omitted. Witness: put X and Y in fixed `Box` beneath unindexed repeatable `Rows`, with `X: GroupFilled(Box) => 1` and separate `Y: GroupFilled(Box) => [X]` and unconditional `Y := 2`. Both authored orders are refused with `MVK_ERROR_CALC_CYCLE`, because Y's implicit row guard prevents protection of Box and retains the reverse dependency. Changing X's group query to Rows, adding a common `GroupFilled(Box)` to Y's constant computation, or making Rows nonrepeatable admits both orders.

**The profile is not a guarantee about when the target computes.** With fixed `Gate`, `X` and `Y` in `Form`, let `X` be `GroupFilled(Form) => 1` and give `Y` two separate computations, `GroupFilled(Form) => [X]` and unconditional `2`. Both authored orders are admitted. With only stored target seeds, `X` clears and `Y` computes `2` in either order. With `Gate` filled, `X` computes `1` and `Y` selects `1` in guarded-first order or `2` in unconditional-first order. The absent guard does not remove `Y`'s profile, and runtime selection still preserves every alternative's authored position (§5.3).

This scheduling rule does not change computation's [read policy](#31-a-precondition-clear-cascades-as-empty), validation presence, or the generated validation rule. Measured scope: protected pairs against unconditional producers, `And` against bypassing `Or`, group exemptions against ordinary field cycles, common conditions, ancestor depth, both split-target orders, unselectable ordinary reads and one unindexed repeatable level, all static except the runtime rows named; the recursive mechanism rests on a source reading, and runtime correspondence covers Number targets only, not arbitrary nested or keyed groups or other target kinds.

> **Non-normative implementation note — content is a smaller input than membership.** For an already-resolved group and a valid enclosing-row binding, keep two content constituents: descendant fields whose repetition scope equals the group's own scope, including fields reached through fixed subgroups; and physical row witnesses for the group itself when repeatable and for its repeatable descendants, restricted to the bound address prefix. Fields below another repeatable level stay in the complete operand inventory, but their values need not be fetched to establish group presence: their instantiated row already supplies content. Thus a fixed root containing repeatable descendants retains its local and fixed-descendant fields as cell inputs, and its repeated descendants as row witnesses. Apply the pending/completed overlay of [§3.1](#31-a-precondition-clear-cascades-as-empty) to the cell inputs. This representation describes sufficient content constituents, not the Kernel's physical scan order or extra scheduling edges. A missing required row binding prevents constructing this input; it is not an empty-group answer.

### 1.2 Static admission order

**A computation's own classes are asked in stages, and a failed stage ends the check.** A class of a later stage is withheld behind any class of an earlier one. The classes of the alternatives stage stand together, also across alternatives; stage 1 reports as the bounded cases below say, the first class in joined order for the generated text and, on a Number computation, the first failing alternative alone.

| stage | classes |
|---|---|
| 1. text and names | a text the parser refuses; a name resolving to nothing (`MVK_INVALID_ENTITY`) |
| 2. target | `MVK_ERROR_INDEX_AS_CALCULATED_FIELD` |
| 3. normal form | `MVK_ERROR_INVALID_LANGUAGE_FEATURE` |
| 4. alternatives | `MVK_ERROR_EMPTY_PRECONDITION`, `MVK_ERROR_INVALID_ENUM_CALCULATION`, `MVK_ERROR_REFERENCE_TO_CALCULATED_FIELD` |
| 5. rounding mode | `MVK_ERROR_WRONG_ROUNDING_MODE` |

So `MVK_ERROR_EMPTY_PRECONDITION` for one unconditional alternative beside a preconditioned one stands beside `MVK_ERROR_INVALID_ENUM_CALCULATION` or `MVK_ERROR_REFERENCE_TO_CALCULATED_FIELD` in the other alternative. A text defect in a computation's own precondition or operation withholds that computation's rounding, target and mixed-alternatives classes, while an arity or bad-name defect in another computation stands beside them.

Bounded cases:

- **On a Number computation the name stage is not computation-wide.** A name resolving to nothing is asked together with its alternative's division-count, nested-power, kind and scale gates, one alternative at a time in authored order, and the first alternative failing one of them reports that class alone. So a scale-2 copy into a scale-0 target in the first alternative beside `[Nope]` in the second draws `MVK_INVALID_COMPARE_DEC_PLACES`, the reverse order `MVK_INVALID_ENTITY`, and a precondition naming nothing answers in its own alternative's place, ahead of an unconditional alternative in either order. Within one alternative a name, a precondition's included, answers ahead of a scale mismatch or a second division. Measured on Number computations only; other target kinds are unmeasured.
- **Parse classes of the generated text** are reported first in its joined order, one class only (§6).
- **The target self-read classes** of stage 4 are judged by the alternative walk of [§5.2](#52-the-target-self-read-gate), and the parse-time classes measured beside them answer ahead of both.
- **The scale class precedes the target-read class**, and the authoring gate precedes both (§1.3).
- **Containment precedes** arity, the scale comparison and target self-reference ([§5.1](#51-operand-reach-scope-the-level-walk-and-placement)).
- **The cycle class** is withheld by every other class measured beside it (§1.1).
- **The error-text classes are withheld by no stage measured.** Each of the six classes of stages 2–5 stands beside `MVK_ERROR_MESSAGE_MISSING` and `RULE_HAS_NO_ERRORTEXT`, and the rounding class beside `INVALID_CHARACTERS` for a TAB in its message, while a text the parser refuses withholds `RULE_HAS_NO_ERRORTEXT` and leaves `MVK_ERROR_MESSAGE_MISSING` ([§13 A.2](11-messages-and-custom.md#a2-which-error-text-classes-a-refused-declaration-withholds)).
- Where `MVK_ERROR_SEMANTIC_INDEX_OR_CATEGORY_FOR_ERRORFIELD` stands against the stages before the alternatives is measured only for the parse-time classes of §5.2.

Not stated: the order between containment and an unresolved name, and where the wrong-kind classes of §1.4 sit among the stages.

### 1.3 The scale gate

**The computed field's declared scale is admitted by each alternative's generated comparison** (§6). An alternative without a tolerance band compares through the same predicate as `==`/`!=` ([§5 §1.2](04-numbers-and-decimals.md#12-the-equality-scale-gate-and-its-waiver)): equal derived and declared scales always pass; a **smaller** derived scale also passes when the whole operation retains multiplicative-constant capability, because the capable side is padded up to the declared scale; a **larger** derived scale is rejected; and an unknown derived scale is rejected unless the computation suppresses `MVK_INVALID_COMPARE_DEC_PLACES`. An alternative declaring a `toleranceRangeOp` compares through the tolerance operator, which meets no scale agreement gate ([§5 §4.6](04-numbers-and-decimals.md#46-tolerance-comparisons)). Wrap the calculation in a rounding construct to force a declared scale. A field never carries the capability, and [§5 §1.1](04-numbers-and-decimals.md#11-static-scale-and-the-multiplicative-constant-capability) owns how the capability propagates, so an operation containing a direct field reference outside a capable subexpression reduces to plain equality; that is why the equality reading holds for most authored computations without being the rule.

**The scale class precedes the target-reference gate.** Over an operation that reads its own target, a derived-scale mismatch reports only `MVK_INVALID_COMPARE_DEC_PLACES`, while suppressing that code exposes the target-reference refusal underneath, so such a computation is a two-repair rejection reported one repair at a time. The authoring gate stands ahead of both: a second unbraced division draws `MVK_TOO_MANY_DIV_FOR_CALC`, with or without a self-read and under a rounding wrapper, and so do a power over a power `MVK_TOO_MANY_POW_FOR_CALC`, a wrapped literal `MVK_NO_CONST`, a fractional exponent `MVK_INVALID_NUMBER_FOR_EXP`, and a text operand's kind class. The order holds across a computation's alternatives: a self-read in one alternative beside a scale mismatch or a second unbraced division in another draws that class in either order, and beside an unresolved name in a later one that name's class, so a checker cannot settle the target-read class one alternative at a time. An operation reading the target twice reports the target-read class once per occurrence.

Measured shapes: `+`, `-` and `*` reading the target on either side against a literal or a Number field of matching or different derived scale, over targets of two scales; a bare copy, `Abs`, an operand-list `Max`, a power, a rounded division and a braced product, each drawing the target-read class when its scale matches; a top-level division, a division under `Abs`, `Max` or a later product, a product under `Abs`, a braced product and a three-factor product, each drawing the scale class when its scale does not; the same order with the self-read in a precondition rather than the operation; the order ahead of the projected target-read class as well as the plain one; and an aggregate, a `FirstFilledValue` and a group count over the target's group, which read the target in the same order. Unmeasured: suppression over a division, aggregate or group-count self-read, and another computation family.

Sources: [join operators and guards checkpoint](../docs/sources/computation-scheduling-probes.md#src-join-operators-and-guards), a12-dmkits [`kf181`](../../a12-rulekit/docs/KERNEL-FINDINGS.md#kf181) (no local record).

### 1.4 Wrong-kind constants and field sources

**A constant operation's admission is decided by the pair of constant family and target kind.** The constant's family is a property of the literal's *content*, not of a distinct spelling: there is one string-literal syntax, so `"x"` and `"05.03.2024"` are the same authored form drawing different classes at the same String target. A wrong-kind constant's class follows an ordered ladder:

| rung | condition | class |
|---|---|---|
| 1 | a **Boolean** target, whatever the constant | `MVK_INVALID_COMPARE_TO_YESNO` |
| 1 | a **Confirm** target, whatever the constant | `MVK_INVALID_COMPARE_TO_YES` |
| 2 | a **temporal** constant (any of the three temporal families) at any remaining target, String, Enumeration, Number and DATE_RANGE included | `MVK_INVALID_COMPARE_TO_DATE` |
| 3 | a temporal target | `MVK_INVALID_COMPARE_TO_DATE` |
| 3 | a DATE_RANGE target | `MVK_INVALID_COMPARE_TO_DATE_RANGE` |
| 3 | a String or Enumeration target | `MVK_INVALID_COMPARE_TO_ENUM_OR_STRING` |
| 3 | a **Number** target, string-like constant | `MVK_INVALID_COMPARE_TO_ENUM_OR_STRING` |
| 3 | a **Number** target, Boolean constant | `MVK_INCONSISTENT_TYPES_COMPARED` |

A **CUSTOM** target is the String row exactly, with no rung of its own. Rung 2 and the Number row are the only places the pair matters rather than one side.

Admitted constants:

- A **Boolean** target admits both `True` and `False`. A **Confirm** target admits `True` but refuses `False` with `MVK_INVALID_COMPARE_TO_YES`, so a computation may set a confirmation but cannot clear one with the false constant. A Boolean or Confirm constant is written with the catalog keyword `True` / `False` and stores lowercase `true`.
- An **Enumeration** target constrains the constant's *value* statically: a literal naming a declared value is admitted, and one that does not is refused `MVK_INVALID_STRING_CONSTANT_FOR_ENUM_COMPARISON`. That static membership check is distinct from String's runtime policy, Number's split policy, and the temporal constant gate of [§4.1](#41-temporal-constants).
- TIME, DATE_FRAGMENT and DATETIME targets admit a bare constant under §4.1. A DATE_RANGE target has no known witness of an admitted bare constant.

**A field source draws the class its kind pair draws in a comparison, not the constant ladder.** The generated validation compares the target with the operation (§6), so a field copied into a field of another kind is refused by that comparison, with no computation-specific class. The comparison's arms answer in the order of the rule comparison walk ([§6](05-dates-and-time.md#cross-kind-comparison-classes)), each claiming its kind on either side, on every pair of the nine kinds measured:

| first arm that claims the pair | class |
|---|---|
| a Confirm partner, a Confirm copied into a Boolean included | `MVK_INVALID_COMPARE_TO_YES` |
| a Boolean partner | `MVK_INVALID_COMPARE_TO_YESNO` |
| a temporal field against a non-temporal one, a DateRange included | `MVK_INVALID_COMPARE_TO_DATE` |
| a DateRange partner | `MVK_INVALID_COMPARE_TO_DATE_RANGE` |
| a Number against a String or an Enumeration | `MVK_INVALID_COMPARE_TO_ENUM_OR_STRING` |

That order is why a Boolean field into a String draws `MVK_INVALID_COMPARE_TO_YESNO` where a Boolean constant draws the text class, and one into a Confirm `MVK_INVALID_COMPARE_TO_YES` where `True` is admitted. Further arms:

- **Two temporal fields** meet the date arm's format question rather than a kind test, so Date, Time and DateTime fields of different formats draw the date class against each other, while a TIME field declaring a complete-date format copies into a Date target.
- **A String against an Enumeration, and two Enumerations,** meet the display arm: a labelled side against a String or an unlabelled Enumeration draws `MVK_INVALID_COMPARE_ENUM_TO_STRING` in either direction, and conflicting labels `MVK_INVALID_COMPARE_ENUM_TO_ENUM`, while an unlabelled Enumeration copies into a String admitted.
- **At an Enumeration target the comparison answers first**, and only a copy it admits reaches the calculation's own `MVK_ERROR_INVALID_ENUM_CALCULATION` ([§4](#4-the-stored-form--a-computed-value-lands-as-a-string-in-the-targets-shape)). A String into an unlabelled target, a wider unlabelled Enumeration, a keyed String source and a stored or category read wider than the target's domain draw that class; a wider Enumeration whose labels also differ draws the display class alone. A keyed String source is measured into an unlabelled target only.
- **A Number field of the other scale** is refused `MVK_INVALID_COMPARE_DEC_PLACES` in either direction, by §1.3.
- **A field of the target's own kind and scale** is admitted on each of the eleven declarations measured, which separates the comparison from a computation-specific gate.
- **The class is raised where the comparison closes**: an arithmetic source `[Total] + 1` into a String draws the text class, and so does `[Total] [Note]`, rather than the unexpected-token class its stray read would draw.
- **A tolerance band replaces the comparison's operator**, so a String copied under one draws `MVK_INVALID_TYPE_FOR_TOLERANCE_OP` while a Number copy is admitted.
- How the target is spelled — relative below the declaring group, absolute outside it — leaves the class unchanged.

## 2. Separate operations, and the three outcomes

**Validation and computation are separate operations.** `validateFull` never computes first; the consumer composes the form-engine flow **compute → apply → validate**, where *apply* follows the placement-sensitive per-cell contract of [`01-data-model.md §4.3`](01-data-model.md#43-the-compute--apply--validate-flow).

**Each computed instance evaluates to one of five outcomes.** The outcome is what a dependent reads inside the same call. The three outcomes of this section's title are the change actions VALUE / CLEARED / ERRORED, which are derived from the evaluation outcome afterwards, relative to the computation source (§3.3).

| outcome | produced by | a dependent reads it as | change projection |
|---|---|---|---|
| **value** | a selected operation whose result passes the target check (§4) | its stored form | VALUE when it differs from the source by typed equality; otherwise no action |
| **clean no value** | no alternative selected; a selected operation that produces no value (§2 table, a final empty String, an all-empty temporal or non-Number selection) | EMPTY (§3.1) | CLEARED when the source target was filled, so a stale value is wiped rather than left standing; otherwise no action |
| **poison** | a reached read of a cell in the third state, of an invalid computed target (§3.2), or of a joined instance skipped at an invalid index column (§5.4) | poison | as clean no value; no message of its own |
| **domain failure** | a domain-invalid numeric result at a Number target, such as division by zero or runtime-invalid integral power, or a reached unresolvable DateTime literal (§3.2) | poison | as clean no value, plus a target-pointed `berechnungsWertFehler` |
| **rejected attempt** | an attempted value that fails the target check, such as digit overflow, a below-floor date or a Custom validator finding (§4) | poison, except the reserved Custom report, which leaves the attempt readable (§4) | ERRORED unconditionally; application clears it |

**An operand's state decides the outcome per kind**, following the per-kind split of [§2](03-empty-and-required.md) with compute's own twists:

| an operand that is… | NUMBER, and a Date-to-Number extractor or difference | DATE in a Date-valued operation (copy, shift, construction) | STRING in a concatenation |
|---|---|---|---|
| **empty** | reads `0` → value | the operation is not evaluated → clean no value | contributes `""` inside the expression; the final result still passes the root-store gate |
| **required and empty** | still `0`; the mandatory error is validation's concern | as empty | still `""` |
| **filled but formally invalid** | poison | poison | poison |

A Date-to-Number operation reads an empty Date as the fillable `0` of [§2 A.2](03-empty-and-required.md#a2-where-an-operator-overrides-its-kinds-default) and [§6 §3](05-dates-and-time.md#3-constructing-dates-and-checking-validity), so it belongs to the Number column; that read is measured in validation rules, and in a computation it is unmeasured. ⚠ The guard consequence cuts both ways: before a Date-valued operation an `AllFieldsFilled` precondition is redundant, because a false precondition clears exactly as the unevaluated operation does, while over a NUMBER operand the same guard changes behaviour — guarded, the target clears; unguarded, it computes `0`.

- **A non-repeatable computed field is calculated even when all its inputs are empty.** A Number calculation stores the real value `0`; a String expression runs, but a final empty text stores nothing; a literal-bearing result such as `" "` does store. Add an `AllFieldsFilled(...)` precondition to suppress the calculation.
- **A Number comparison in a computation precondition substitutes zero for a clean empty field.** The measured `==`, `!=`, `<`, `<=`, `>` and `>=` guards select exactly as on explicit zero, so `[N] + 1 > 0` and `0 < [N] + 1` select when `N` is empty. A reached division-by-zero comparison does not hold, leaving a clean empty target, but still reads its other operand: a formally invalid right operand poisons that target and its dependent computation. A false left condition under `And`, or a true one under `Or`, skips that invalid suffix. This is a computation-precondition rule; it does not change validation's omission polarity or establish another field kind's empty rule.
- **A String computation decides emptiness twice.** Replacing an empty operand by `""` is only the per-operand expression rule. The root store makes a second decision on the final result: a final empty String stores no value, whether it came from a bare copy, a literal or an all-empty concatenation. It is a clean no value, never a stored `""` value. This empty-result gate runs **before** the target format check, so an empty final result aimed at a `minLength` target clears rather than becoming a rejected attempt. A no-value Date result likewise means that no operation produced a value, while Number has no empty result arm because empty-as-zero produces the real number `0`.
- **A bare string copy** (`X = [S]`, one operand, no `+`) of an empty operand computes nothing — clean no value, never a stored `""`. The `FieldValueAsString` coercion of a not-given read follows the same split: a standalone copy is a clean no value, because the store treats an empty string value as "no calculation was done", while a concatenation gets `""`. The coercion's operand must be a NUMBER/AMOUNT field; a string copies bare. For a filled Number the coercion returns the regime-selected formal-read text of [§5](04-numbers-and-decimals.md#stored-decimal-identity-and-runtime-read-text-depend-on-the-storage-regime): a decimal-valued placement is re-rendered by the strip-and-minimum-scale projection, while a String-valued placement is read verbatim. It is not a separate raw-storage channel.
- **A final empty outcome does not undo selection.** Once an alternative has selected its operation, later alternatives are not tried, including alternatives contributed by another computation targeting the same field (§5.3). Dependents read the target as EMPTY. The change action is decided afterwards from the prior target state. Poison, domain failure and a rejected attempt are decided before the empty gate and are not swallowed by it.

## 3. Two kinds of "no value" — the empty cascade vs the poison ⚠⚠

A target with no value is not one thing; *why* it has none decides what a downstream computation sees.

### 3.1 A precondition-clear cascades as EMPTY

**A clean no value reads as plainly empty in a dependent.** A field whose own computation was cleanly unselected — because its `commonPrecondition` was false or no alternative matched — or whose selected operation produced no value reads as empty: `FieldFilled(dep)` is false and a number operand reads empty-as-`0`.

**The mechanism is a strip of every calculated field's input.** A calculation run removes every calculated field's stored value from the working data, so an un-computed calculated field reads empty regardless of what the document stored. The strip reaches every content read, not only a field read. Inside one compute call a calculated field's stored value fills no group, is not counted by `NumberOfFilledFields`, has no category, and is never formal-checked as an operand: a malformed stored value raises nothing once the field is computed, because the read sees the computed value. A target's own stored value does not answer its own precondition, while a stored non-computed field beside it does.

**What those reads see instead is the value a computation produced earlier in the same call.** It fills the group holding it and, through non-repeatable groups, that group's parent too, in each row it was computed into, a keyed row included, and it counts. A poisoned result fills nothing, and a group read over it does not poison.

Measured scope: every measured row runs a full `compute`, so the strip's reach over calculated fields a call does not run rests on a source reading; the fill is measured to depth two through non-repeatable groups only.

Sources: [inbound 2026-09-23c cascade reads](../docs/sources/inbound-handbacks.md#inbound-2026-09-23c-computation-cascade-reads), [inbound 2026-09-23d grandparent fill and malformed key](../docs/sources/inbound-handbacks.md#inbound-2026-09-23d-grandparent-fill-and-malformed-key).

### 3.2 An invalidity-clear POISONS

**Reading an unavailable cell throws inside the computing instance.** An unavailable cell is a cell in [§3](02-logic-and-formal-errors.md)'s third state ([B.2](02-logic-and-formal-errors.md#b2-the-three-cell-states--the-third-one-is-not-empty), produced by any producer of [B.3](02-logic-and-formal-errors.md#b3-what-puts-a-cell-in-the-third-state) except the validation-scoped required finding), a computed target that failed by domain failure or a rejected attempt (except the reserved Custom report, whose attempt stays readable, §4.3), or a computed target already marked invalid by the abort this section describes. The reading instance **aborts**, skips its remaining alternatives, produces no value, and **is itself marked invalid**, so its dependents' reads poison in turn. A field-cell read poisons whether it reads the value or the presence — `FieldFilled` and the field-fill scans included — while a group presence read never poisons ([§3 B.6](02-logic-and-formal-errors.md#b6-validation-excludes-computation-poisons)); [the operator reference](14-operator-reference.md#unavailable-read-in-computation) assigns each operator its class. When the unavailable cell is a formally invalid stored operand, the aborted instance and its poisoned dependents emit no message of their own and are no erroneous instances: the operand's formal finding in the formal-operand channel is the only report, and the targets are cleared.

**A category read is a read of that cell.** `[Plan -> Tier]` over a `Plan` holding a token outside its value list poisons exactly like the value read: the instance aborts and its target is reported CLEARED, whether a comparison, `FirstFilledValue`, or a value-list quantifier reaches the read. An index cell the document makes unavailable, a key two rows carry or a row carrying none, poisons the category read as it does the value read.

**Once a computed target is marked invalid, the cascade is cause-blind.** The computation cache retains only invalid-target membership; a later value or presence read throws for that target without carrying the producer's attempted value, target-error subclass, originating formal cause or message, and the dependent is marked invalid without a cascade message. Those producer details may remain in the producer's own outcome, but they do not pass through the dependency read.

**A domain-invalid numeric result is poison, projected per consumer.** Division by zero and runtime-invalid integral power are not clean empty: while the result remains in the numeric family, the shared invalid numeric result survives legal `Abs`, `Min`, `Max` and `RoundAccounting` wrappers, marks a Number target invalid, emits `berechnungsWertFehler`, and makes a dependent read poison. It produces no attempted stored value; the change projection has no action for a fresh target and CLEARED for a stale filled one. A Date-valued consumer projects the same missing numeric amount differently: `AddDays(StartDate, RoundAccounting(div, 2))` produces no Date value, clears a stale Date target, and attaches no `berechnungsWertFehler` to that Date target. These are consuming-operation rules, not contradictory global classifications. Fresh no-value output and stale CLEARED remain delta projections and do not imply a clean-empty Number target.

**The poison is read-driven, therefore order-dependent.** A reached unavailable cell poisons; one beyond a connective or scan stop is never read and never poisons.

- **Connectives.** Compute's `And`/`Or` collapse each clean condition result to whether it is known true and evaluate left to right. `And` skips its right side when the clean left is false or unknown; `Or` skips its right side when the clean left is true. A poison already encountered on the left aborts either connective.
- **Field-fill quantifiers.** A bare-group field-fill quantifier consumes the canonical field-major, repetition-major stream of [the fill-quantifier clause](02-logic-and-formal-errors.md#a4-fill-quantifiers-group-scopes-and-the-two-iteration-ranges) and stops at its deciding cell ([§1 A.4.6](02-logic-and-formal-errors.md#a46-computation-ordered-field-fill-scans)).
- **`FirstFilledValue`** is the stop-at-first value combiner: it consumes target cells only until the first filled cell, so an invalid target cell after it is invisible, while an invalid target cell before the first filled one poisons the computation. A reached filtered star keeps [§9 §3](07-repetition-and-iteration.md#3-the-filter-having-the--correlation-and-aggregation)'s separate one-kept-successor lookahead: filter poison while finding that successor can precede the current target, but a terminal current target hides filters after the prefetched successor and every later authored operand.
- **Numeric arithmetic** evaluates its **one-pass lowered tree**, not necessarily the authored tree, from left to right. At a binary node the left subtree is evaluated first and the right subtree before the arithmetic method is applied. A domain-invalid numeric result is a value-level invalid result rather than a thrown read, so it does not hide a later poisoned read; a poison already thrown by the left subtree aborts before the right subtree. A lowering rewrite can therefore change which of two poisoned field reads is encountered first.
- **Reached temporal literal failures end evaluation.** Temporal operand-list extrema evaluate reached operands in order: a malformed field before an unresolvable DateTime literal aborts without a target-local `berechnungsWertFehler`; reversing those operands reaches the literal failure first and emits that code. Both invalidate the target and poison its dependents; an ordinary literal in the same position is no failure. Number arithmetic over temporal extractions follows the same order: when an extraction that reaches the unresolvable literal is the left operand of `+`, the target reports `berechnungsWertFehler` although the right operand reads a malformed field, and the reversed sum aborts silently on that field. A reached literal therefore ends the arithmetic, unlike a division domain failure, which a later reached poison replaces, so `RoundAccounting([A]/0, 0)` left of the malformed operand clears silently. A precondition comparison that reaches the literal likewise reports at its target, whose readers are then poisoned, and reaches its operands in the same order.

**A filtered aggregate whose candidates all drop answers its all-empty result.** A count or `Sum` over zero survivors answers `0` ([§9 §3](07-repetition-and-iteration.md#3-the-filter-having-the--correlation-and-aggregation)), and every other aggregate answers its all-empty identity ([§2 A.3](03-empty-and-required.md#a3-what-an-all-empty-selection-folds-to-the-aggregate-identities)). Where that identity is no value — measured on `FirstFilledValue` into a String target — the target row receives a clean no value and a dependent reads it as EMPTY. What the reporting channel shows for that row follows the target cell's prior state, not the ground of the no-value: a target row whose cell held a value is reported present and cleared, and a target row whose cell was already absent is absent from the reported outcomes altogether. An empty candidate set and an unmet precondition behave identically once the seed is held fixed, so the split is a property of the cell rather than of the reason. Downstream the split is invisible: a dependent is present on every row and reads either shape as EMPTY, neither poisons it, and a `Length` dependent of the absent row computes `0`, exactly as over a precondition-cleared producer. The reported result therefore has two absence shapes while the cascade has one; a result-rendering consumer must carry the distinction and an evaluating consumer must not. Reordering the keys so the empty-candidate row moves to the front moves the absence with it.

**Both cascade read rules reach inside a downstream computation's `Having` filter and its preconditions' quantifiers**: a cleanly cleared upstream target reads EMPTY there, and a poisoned one poisons the reading computation.

**The two clear kinds separate only in what dependents do.** On a four-deep dependency diamond — one producer, two independent dependents, one join — a producer cleared by an **unmet precondition** is read as EMPTY by its dependent, which answers `0`, and the join answers over it normally; a producer cleared because its own source was **malformed** poisons its dependent, which clears, and the join clears with it. Poison therefore crosses a join rather than being substituted away: a join reading one poisoned and one clean operand clears, while the same join over an *absent* source substitutes empty-zero and computes. A consumer cannot read the kind off the target's own reported state: both kinds surface as cleared and not errored, with no formal-operand entry for the precondition case.

- **A clear is visible to a dependent inside the same call.** With a stale value stored in the cleared producer's target, the join answers over an empty read rather than over that stored value — `7` where reading the stale `99` would give `106`. Clearing takes effect before the dependent's read, not at application time.
- **A bare constant operation honours a precondition** exactly as a computed one does, writing when met and clearing when not, and its clear is read as empty by the same rule.
- **Computations run in dependency order through a join**: the producer before its dependents and the branches before the join; evaluating the join before its branches, or the branches before the producer, predicts a different joined value.
- **One failing branch does not abort the plan**: the independent branch computes its value in every failing row.

> **Non-normative implementation note.** Thread compute reads through an error effect, e.g. `Except Poison Value`, with **short-circuiting `And`/`Or`** that do *not* evaluate the right operand once the left decides (so an unread invalid cell never surfaces its `Poison`). This makes order-dependence a *consequence* of the evaluation order, exactly as in the engine — do **not** eagerly evaluate all operands and then combine, or you will poison on cells the engine never reads. Model the empty-cascade separately: **before** computing, replace every computed field's stored input with `empty` in the working document, so a not-yet-computed dependency reads empty (§3.1) rather than its stale stored value. These two mechanisms — pre-strip-inputs (empty cascade) and throw-on-read (poison) — are distinct and must both be present.

**A runtime failure reached in validation** — a reached unresolvable DateTime label in a rule comparison — fails the authored rule rather than computing anything; [§12 §3.1](10-validation-and-polarity.md#31-truth-testing-and-message-classification) owns its message, address and row-loop rule.

### 3.3 What compute *reports*

**The result channels are owned by [§4.3 of the data model](01-data-model.md#43-the-compute--apply--validate-flow)**: all successful non-clearing instances, their source-relative changed subset, erroneous instances, cleared source-filled instances and eager formal operand errors, with `noErrorOccurred` true exactly when both error channels are empty. This section states how compute fills them.

**The formal operand inventory is eager and target-based.** Before ordinary computation processing, the V2 operation formally validates every non-computed field in the source-defined operand set. In an expanded A12 model that set is the union across every checked computation of: directly referenced fields; every field contained by an ordinary referenced group; every field contained by a conditionally referenced ancestor group; each index field needed by a semantic-index or parallel-iteration group; and the fields contributed by implicit guards. The collection traverses operations, alternative and common preconditions, filters and semantic-index key expressions; computed fields are then excluded from formal input checking. This is a checked-plan inventory, not a runtime read trace or dependency schedule.

- **Implicit guards are part of it.** Before collecting operands, each authored computation below a repeatable group receives an implicit positive guard on its innermost repeatable ancestor, unless its explicit conditional-group profile already protects that group or a narrower group containing the target (§1.1). Expanding that implicit guard includes every uncomputed descendant, fixed and repeatable descendants included. An explicit narrower containing-group guard can therefore exclude outer siblings that the default row guard would include. An inner repeatable target adds no outer-parent subtree, and a root-only target adds no implicit subtree. Declaring the computation elsewhere does not change this target-based preprocessing. The inventory stays narrower than full validation's document-wide findings.
- **Structural findings follow the retained nodes.** The call's data is filtered to that operand inventory before its formal check: it retains the operand cells and every ancestor group instance — repeatable rows and nonrepeatable groups alike — of every operand **and computed** field, so the structural over-repetition findings it reports are exactly the full-validation findings on those retained nodes. An unread sibling field and an unread nonrepeatable subtree in an over-capacity row draw nothing, a computed target's own cell draws nothing, and the target's ancestry draws its findings even when no operand reaches it.
- **Index defaults and preliminary rules.** The full-call index-default staging used by full validation runs after computation's formal ingestion and before its selected index preliminary rules, so an eligible absent or present-empty Enumeration index can receive its declaration-owned S-value during computation. Mandatory and uniqueness preliminary rules run only for index fields retained by the operand inventory; an unused bad index does not enter this prepass. Selected invalid filled values are reported, an ordinary required-empty omission is not, and a selected empty or non-unique index is reported unless full-call default staging supplies its value. Computation processing continues after these errors are collected; a computation reading the reported empty or duplicated index cell clears as a read of poison does (§3.2), while an ordinary required-empty operand reads empty.
- **Eager is not poison.** The resulting `formalErrorsInOperands` inventory is independent of runtime reachability; it must not become a global abort or an eager poison injected into every computation. Whether an invalid producer poisons a dependent remains determined by scheduling and by whether that dependent actually reads it.
- The legacy unique-entity/H-model path has a different all-noncomputed input profile and early-abort behaviour and is outside this expanded-A12-model contract.

**The two error channels partition one message stream by exact pointer.** A message is associated with an erroneous computed instance only when a nonempty computed value exists at that pointer; otherwise it remains in the residual `formalErrorsInOperands` channel, whatever the message points at. A value-less Number target failure can therefore be both source-relative CLEARED and represented by a target-pointed residual message, with no erroneous computed instance, and still makes `noErrorOccurred` false. Cascade poison and clean no value emit no such message.

**Result assembly can fail after computation has finished.** The V2 result requires one diagnostic per full error pointer before separating computed-instance errors from residual operand errors. Two findings at the same complete pointer cause a whole-call duplicate-key failure, whatever their codes or payloads; findings at distinct physical row pointers do not collide. A reserved Custom report together with a selected index-uniqueness finding can trigger this failure. Independent computations, including their target callbacks, still run before assembly fails. No computation result or applied snapshot is returned, and the original document remains unchanged. An ordinary rejected operand, or a duplicate index with only one finding per row, permits assembly; an unused custom index contributes no selected preliminary finding.

**A cleared instance carries no informative value, so clearedness is a channel-membership fact, never a value reading.** Its value accessor reports present and empty for every clear, not the stale input it erased, measured on both codegen strategies. A consumer that reads that accessor instead of the channel aliases a clear with a computed empty string, and one that treats the accessor's optional as a has-value flag reads a clear as a value. Whether a computed empty value occurs for a given target family is not stated here, so the separation is a guarantee about the report's shape rather than a claim that both states occur for every family.

**The change projection is exact.** **VALUE only on a typed change** (the computed value differs, by typed equality, from what was stored in the computation source), **CLEARED only when the source cell was filled**, and **ERRORED unconditionally**. A report-all evaluator must project to this change boundary before differential comparison, but that projection must not erase successful unchanged instances from the full result. The public computed-instance collections are extensional by pointer and payload; no schedule-order promise follows from their iteration order. Application of these actions, to the source or to another compatible destination, is owned by [§4.3 of the data model](01-data-model.md#43-the-compute--apply--validate-flow).

**Typed equality compares V2 objects.**

- For a **Number** target it is equality of the source and computed V2 objects, not of parsed amounts or internal strings. Computed Number output is a `BigDecimal`; an original `BigDecimal` is equal only when value and scale agree, while an original V2 `String`, or a negative-scale `BigDecimal`, is unequal to every computed Number form even when its plain text and numeric amount agree. Thus computed `7.00` is unchanged only against a source decimal with coefficient `700` and scale `2`; source text `"7.00"` is still a change.
- For every other kind the ingress route decides the source identity; Time change classification is not operation- or placement-specific. Typed V2 ingress converts non-String kinds to their typed objects: nonrepeatable and repeatable `Time(...)`, `TimeFromDateTime` and Time `FirstFilledValue` therefore use ordinary stored-clock equality, and reapplying a computation over its own output produces no VALUE action for an identical clock. V1 String ingress instead leaves a typed cell holding unconverted text, so every measured non-String kind is changed even when its seed text denotes the computed value — Number, Date, DateTime, Time, DateRange, Boolean and Confirm — while String is unchanged on both routes. A source-identical discriminator must therefore use typed ingress or reapplication rather than a V1 text seed.

## 4. The stored form — a computed value lands as a string in the target's shape

**A computed value is stored in the target field's own declared format**, and that stored form is what downstream reads: a dependent computation reads the stored string back, not the expression's value. The one exception is the unconfigured interpretation-bearing DateRange route of §4.2.

- **A dependent temporal read sees the stored representation** under the target's runtime policy; it does not inherit components discarded by rendering. With Base Year 2024, adding one day to a `dd.MM.` value `31.12.` stores `01.01.`, and a dependent Year extraction reads 2024, not the expression's 2025. A wrapping FROM range copied to an admitted TO target is re-anchored as TO on dependent read: without Base Year, the observed start/end years are 1999/2000.
- **Static component compatibility still applies to a field source.** Without a Base Year a full-Date field cannot be copied into a yearless Date target, `MVK_INVALID_COMPARE_TO_DATE`; a declared Base Year admits the copy, as the comparison rule of [§6 §1](05-dates-and-time.md#1-constant-format-and-the-stringdate-literal-ambiguity-) admits a comparison whose missing year the Base Year supplies. Both are measured on a full ISO Date copied into a `MM-dd` target; the Base Year's admission into the other yearless formats is unmeasured. The other direction is the same gate: a yearless field copied into a year-bearing Date target is refused `MVK_INVALID_COMPARE_TO_DATE` without a Base Year and admitted with one, whatever the two component sets. Unlike a constant's store (§4.1), the copy takes its year from the declared Base Year and is rendered in the target's format: with Base Year 2023, `06-11` stores `2023-06-11`, `11.06.2023`, `2023-06` or `2023`, and a month-only `06` stores `2023-06-01`, its day completing to the first. An absent or malformed source clears the target, a malformed one including a day the Base Year makes unreal, such as `02-29` under 2023. Measured on plain DATE fields over every pair of the sources `MM-dd`, `dd.MM.`, `MMdd`, `ddMM` and `MM` and the targets `yyyy-MM-dd`, `dd.MM.yyyy`, `yyyy-MM` and `yyyy`, under Base Years 2023 and 2024; DATE_FRAGMENT declarations, partial precision, repeatable carriers and a DateTime target are unmeasured. A range `FirstFilledValue` list of unlike declared formats is refused (§4.2).
- **A computed result is checked with the basic format check only** — type format plus declared constraints, without the charset and leading/trailing-blank baseline that stored *input* values get — so a computed string starting or ending with a blank stores as a plain value.
- **A rejected attempt retains its attempted stored form** and projects to ERRORED unconditionally (§2).

Sources: [stored-read controls](../docs/sources/inbound-handbacks.md#src-inbound-2026-10-09a), [inbound 2026-10-27](../docs/sources/inbound-handbacks.md#src-inbound-2026-10-27), [yearless direct copy](../docs/sources/temporal-constant-and-base-year-probes.md#src-yearless-direct-copy-base-year).

### 4.1 Temporal constants

**A temporal constant passes the target carrier's gate on three grounds, then renders into the declared format.** All three grounds refuse with `MVK_INVALID_COMPARE_TO_DATE`, so a consumer must re-derive which one fired from the (literal, target) pair rather than read it off the diagnostic.

1. **Family.** The literal's temporal family — date, clock or date-time — must match the family of the target's declared *format string*; the declared kind (DATE, TIME, DATE_FRAGMENT, DATETIME) plays no part, at admission or at storage. A TIME field declared `HH:mm:ss` admits the clock literal `"12:30:00"` and refuses the date one; a TIME field declared `yyyy-MM-dd` does the opposite; a DATE field declared `HH:mm:ss` admits the clock and refuses the date. A DATE-kind field declared `HH:mm:ss` stores `12:30:00`, and a TIME-kind field declared `yyyy-MM-dd` stores `2024-03-05`, both unerrored. The date-time carrier follows its format too: a DATE-declared field carrying `yyyy-MM-dd'T'HH:mm:ss` stores `2024-03-05T12:30:00`, and a DATE_TIME-declared field carrying `yyyy-MM-dd` stores `2024-03-05`. A clock literal into `MM` is refused.
2. **Year agreement, unless a Base Year is declared.** Without a Base Year, the constant and the target must agree about carrying a year, in either direction; with one, year agreement is vacuous. A complete constant is admitted into every year-bearing format — `dd.MM.yyyy`, `yyyy-MM-dd`, `yyyy`, `yyyy-MM`, `yyyyMM` — with no Base Year, and refused into the yearless `MM` and `MM-dd` without one, identically on DATE and DATE_FRAGMENT declarations; a Base Year lifts that refusal for all four yearless targets, and clearing it restores the refusal on otherwise identical model bytes. A **yearless** constant such as `"05.03."` is the mirror image: admitted into `MM` and `MM-dd` with no Base Year, refused into every year-bearing format without one. The gate does not compare component sets: `yyyy` differs from a complete constant in two components of three and needs no Base Year, while `MM-dd` differs in one and does, and the yearless literals `"05.03."` and `"13.07."` are both admitted into `MM`. Read as *a yearless format needs a Base Year*, the rule gets both yearless-constant rows wrong.
3. **Calendar reality.** The constant must classify as a real calendar date: `"29.02."` and `"31.04."` are refused against an admitted `"30.04."`. This ground belongs to the literal and consults no Base Year ([§6 §1](05-dates-and-time.md#1-constant-format-and-the-stringdate-literal-ambiguity-)).

**The literal must lex as a temporal constant.** A double-quoted German date literal such as `"05.03.2024"` is a Date constant; a spelling that lexes as a String or Number constant is refused `MVK_INVALID_COMPARE_TO_DATE` instead. The ISO spelling `"2024-03-05"` is such a spelling: refused into targets declared `dd.MM.yyyy`, `yyyy-MM-dd` and `yyyy`, measured on those three. The date-time spelling is the admitted German Date literal and the clock literal joined by `T`: on a target declared `yyyy-MM-dd'T'HH:mm:ss` the literal `"05.03.2024T12:30:00"` stores `2024-03-05T12:30:00` on every instantiated row.

**The store renders one temporal value into the declared format.** The constant is one temporal value and the declared format is a rendering of it, exactly as a Number constant's stored text is a rendering of its amount. `"05.03.2024"` stores `05.03.2024`, `2024-03-05` and `2024` into targets declared `dd.MM.yyyy`, `yyyy-MM-dd` and `yyyy`, on every instantiated row, with nothing cleared, nothing errored and no message. A component-omitting target keeps only the components its format names, keeping the format's own separator, and discards the rest silently — no error, no clear, no warning: in a model declaring a Base Year the same constant stores `03`, `03-05`, `2024-03`, `2024` and `2024-03-05` into `MM`, `MM-dd`, `yyyy-MM`, `yyyy` and a complete date, unerrored and uncleared; `yyyyMM` stores `202403`, and a `yyyy-MM` DATE_FRAGMENT stores `2024-03`. `"05.03."` into `MM` stores `03`, dropping the day. **A declared Base Year contributes nothing to a constant's stored text**: for a constant it belongs to the admission gate only, so a consumer must not complete a constant's yearless store from the Base Year, and must not infer from an admitted constant that the target retains the year the constant supplied.

**The runtime pre-1900 policy still applies.** Two otherwise identical ISO targets receiving `"31.12.1899"` separate it: `rejectBefore1900: true` retains the attempted `1899-12-31` as a rejected attempt (ERRORED), while the unguarded target accepts the same text, and neither clears.

**A DateTime constant has two zone-sensitive verdicts.** With the model zone fixed to `Europe/Berlin`, the same model carrying the spring-forward-gap literal `"31.03.2024T02:30:00"` passes static checking under a UTC JVM default and is refused `MVK_INVALID_COMPARE_TO_DATE` under a Berlin JVM default. When the UTC-admitted model runs against its declared Berlin zone, that gap supplies no value and one addressed `berechnungsWertFehler` finding per in-capacity target row; the change projection reports no action for an empty target and a clear for a seeded target, neither with an errored attempted value. These verdicts establish a static host-zone dependency and a runtime model-zone dependency, not the Kernel's internal conversion step.

**This gate is the target carrier's.** A temporal *operation* operand is governed by three different gates — operand granularity (`MVK_WRONG_DATE_FORMAT_FOR_OP`, refusing a `MM` field in `DifferenceInDays` while admitting a `MM-dd` one), year agreement under its own code (`MVK_DATE_WITH_AND_WITHOUT_YEAR`), and calendar validity reported at the literal (`MVK_INVALID_DATE_STRING`) — owned by [§6 §9](05-dates-and-time.md#9-datetime-rides-the-date-format-definition--but-the-operand-gates-are-per-operator-) and assigned per operator in [column D](14-operator-reference.md#temporal-operand-gate). One temporal-constant gate for both carriers is wrong in both directions. On the time side, an hour-only `HH` format is refused at field declaration, and no admitted time-bearing format in the measured vocabulary of [§6](05-dates-and-time.md) names a proper subset of a clock literal's components.

### 4.2 Temporal targets

- **TIME** produced by `Time(...)` or `TimeFromDateTime(...)` stores exact zero-padded `HH:mm:ss`. This target profile admits the clock format and requires complete hour, minute and second components, so every admitted real clock passes the basic target check. The runtime temporarily carries the clock as 1970-01-01 in the model zone, but neither that date nor an instant is part of Time identity or stored output; rules evaluated after application observe the stored wall clock rather than a UTC decoding of that carrier. Missing, fully present impossible and non-relevant constructions store no value; formal unavailability remains poison rather than becoming a clock. The stored form of a `Time(...)` or `TimeFromDateTime(...)` result in a target whose declared format is not `HH:mm:ss` — a TIME field declared with a date format, or a DATE field declared `HH:mm:ss` — is not stated.
- **DATE** stores in the field's `format`, not ISO ([§6](05-dates-and-time.md)). Computation admits only a `FULL` Date target: `DAY_OPTIONAL`, `MONTH_OPTIONAL` and `YEAR_OPTIONAL` targets are rejected with `MVK_INVALID_DATE_TYPE` because the generated validation comparison reads the computed target, and suppressing that error is itself rejected with `MVK_INVALID_SUPPRESSED_WARNING`. For an admitted `FULL` target the runtime renders the concrete Date first and then runs the basic target check, so an enabled pre-1900 check reports the exact attempted Date as a rejected attempt rather than erasing it. `FirstFilledValue` selects a Date before the target renders it: the source list keeps its exact-format gate, but the target need not share that spelling or component precision, and target compatibility follows the temporal comparison rule, including year presence and Base Year. Dotted full-Date sources are admitted into ISO targets, and full-Date or year-month sources into year-only targets, storing `2024-05-06` or `2024` from the same selected value. An empty first source falls through; a reached malformed source poisons instead of using the later valid source, without affecting another physical row. DateTime-to-Date remains refused.
- **DATETIME** selected by the direct `FirstFilledValue` profile stores the exact selected instant rendered in the model zone. The measured profile stores whole seconds as `yyyy-MM-dd'T'HH:mm:ss`; source text and a cached source wall label do not determine the result.

**For the direct single-level starred temporal `FirstFilledValue` profile, selection happens in the typed value domain before target rendering.** A full Date contributes its exact instant; its underlying scalar value also carries decoded date parts and calendar basis, but this computation keeps neither after selection. A Time keeps only its decoded time of day, not the runtime transport date or instant. A DateTime keeps its exact instant rather than source text or a cached wall label.

**DATE_RANGE.** A DateRange keeps an exact ordered endpoint pair for the two full-Date policies, `yyyy`, `yyyy-MM`, and Base-Year-completed `MM` or `MM-dd`. Without Base Year, interpretation-free `MM` with slash or an empty separator, `MM-dd` with slash, and `dd.MM` with dash keep only their component pairs and never acquire a synthetic year or instant. The admitted declaration pairs are eight: `yyyy-MM-dd` with `/`, `dd.MM.yyyy` with `-`, slash-separated `yyyy`, `yyyy-MM`, `MM` and `MM-dd`, `MM` with an empty separator, and `dd.MM` with `-`.

- **Admission compares date-component sets, not lexical profiles.** Assignment and direct-star target admission admit every interpretation-free crossing within one component set in both directions: the two full-Date policies cross (a dotted full-Date range stored into an ISO target renders `yyyy-MM-dd` endpoints), `MM` crosses between slash and the empty separator, and `MM-dd` crosses with `dd.MM`. A different component set is refused `MVK_INVALID_COMPARE_TO_DATE_RANGE`. The target's own spelling renders list, construction and selection results alike.
- **A direct-field list needs one lexical profile.** The checked direct-field DateRange `FirstFilledValue` scans a finite list of at least two nonrepeatable sources under one common lexical profile, the declared `(format, separator)` pair; `interpretationOfYear` is not part of that profile, so otherwise matching `FROM` and `TO` sources may appear in one list. A lexical mismatch draws `MVK_VARYING_TYPES_NOT_ALLOWED`. The list's two gates are ordered: the common-profile requirement decides first, so a three-source list whose odd member matches the target still reports the varying-types class rather than a component refusal.
- **The list scan is ordered and lazy.** Sources are scanned in authored order: empty sources continue, while the first present value or reached formally invalid source ends selection and hides every later source; exhaustion returns no value. The eager formal-input inventory (§3.3) still reports every malformed selected source.
- **Construction.** Exact or Base-Year-completed cells render their resolved endpoints through the target profile. Without Base Year, `MM`/slash and `MM-dd`/slash constructions, and selected cells under all four yearless runtime profiles, render their kept ordered components without manufacturing a year. An inverted construction keeps the attempted target text as a rejected attempt (ERRORED) under its own spelling, empty construction input yields no value, and formal input poisons before empty. Failure to resolve an exact cell's endpoint is an unsupported boundary, not a copied or guessed target value.
- **The unconfigured interpretation-bearing route depends on declaration order.** In the measured two-block control, placing interpreted `dd.MM` declarations first makes an interpreted `MM` source `11/02` valid and stores `01.11-01.02`, while a standard `MM` source `03/10` stores `01.03-31.10`; placing the same `MM` declarations first rejects the wrap and stores `03/10` for the ordered source. Neither a dotted-carrier rule nor a declaration-local rule holds. No rule is stated for this route beyond that discriminator, and an implementation's choice there is not specified.

Measured scope: direct-construction runtime covers every admitted constructor target — full-Date input to the dotted/dash and ISO targets, no-Base-Year `MM` and `MM-dd` under both spellings of each, `yyyy` and `yyyy-MM` including equal-endpoint rows, and the Base-Year-completed `MM` and `MM-dd` targets, which render back to their declared components even where the completion reaches a leap-aware month end — each with an inverted attempt. Direct-star static admission covers all eight declaration pairs and every crossing within a component set; runtime covers all eight pairs, both full-Date crossing directions, the yearless `MM` and `MM-dd` crossings, and configured and no-Base-Year fragment results. The direct-field list is measured on full-Date dotted/dash lists of two and three sources, three-source lists for all four slash-separated fragment profiles, an empty-separator `MM` list into a slash-separated `MM` target, a two-source dotted `dd.MM` list mixing `FROM` and `TO`, ISO/slash list execution, an empty-separator `MM` target rendering the halved form, a fragment list's formal suffix reported by the eager inventory while an earlier value is kept, and a four-source list selecting its fourth source; longer lists, the remaining five declaration pairs as list carriers and a seeded target on those profiles are unmeasured. Whether the engine decodes and re-renders or copies text is not stated; the typed account is semantic.

### 4.3 Number, String, Enumeration and Custom targets

**NUMBER.** A computed Number first receives a **scale-19 `HALF_UP` pre-round**, then follows one of two scale branches.

- On the ordinary **fit** branch, where the stripped natural scale does not exceed the target's `maxFractionalDigits`, it renders at `max(naturalScale, minFractionalDigits)` (`10` into a two-decimal field stores `10.00`) with **no length cap**. An over-15-digit fit result is therefore kept **in full** and is a rejected attempt under the ordinary target check, never re-rounded to pass it. The fit-path first-error order is: more than 15 total digits; forbidden negative sign; effective integer-digit cap (explicit `maxIntegerDigits`, otherwise the amount trait's `15 − maxFractionalDigits`); forbidden zero; rendered minimum length; rendered maximum length; value below the inclusive minimum; value above the inclusive maximum. Length counts the sign and decimal separator. The canonical rendering produces no invalid character, plus sign, signed zero or leading zero, and fit rendering already guarantees the declared fractional interval, so no other check applies.
- On the **no-fit** branch the value renders with at most 16 significant digits when its integer part permits that bound and is a rejected attempt unconditionally; only total-digit overflow and a forbidden negative sign precede the inevitable decimal-place mismatch, and the fitting-only suffix is not reached. The no-fit branch is reached when the computation suppresses `MVK_INVALID_COMPARE_DEC_PLACES`; whether a tolerance-banded alternative reaches it is unmeasured (§6). It is a warning-suppressed compatibility surface, not permission for an ordinary implementation to round every result to the target's maximum scale.
- On both branches and at every magnitude, the stored text is plain dot-decimal notation, never exponent notation. The change equality of §3.3 is scale-sensitive: a computed `7.00` over a stored `7` counts as a change.

**STRING.** For an ordinary String target the final-empty root decision happens before the basic check (§2), so no value clears rather than violating a positive minimum. A nonempty attempted value is checked in declaration order: forbidden CR/LF first; then, when line breaks are permitted, CRLF→LF normalization in a temporary checking view; then the declared pattern, positive minimum length and positive maximum length. Length is the normalized UTF-16 code-unit count, an explicit zero bound is inactive, and both authored bounds stay active when combined. A declaration without a maximum still carries one of 99,999 units, and a bounded pattern does not raise it, so a computed 100,000-unit text is a rejected attempt while a Custom target stores the same text once its validator accepts it. The normalization does not rewrite the computed attempt: an accepted value and a rejected attempt both keep the exact attempted internal String, while the first failing clause supplies the error cause.

**ENUMERATION.** For an ordinary closed Enumeration target, authoring refuses an out-of-domain computed token before runtime.

- A constant must belong to the target's stored-token domain (§1.4).
- A direct Enumeration source must have its complete stored-token domain contained in the target domain and must satisfy the ordinary direct-Enumeration display-remapping compatibility gate. A category source is checked by its complete projected category-token domain and bypasses that display gate. `FirstFilledValue` is admitted only when every selected Enumeration or category source satisfies the same compatibility.
- A source reached by up-steps from a fixed group inside a repeatable one is judged as a local one: `[../Banded -> Band]` is admitted where `Band`'s tokens lie in the target domain.
- `MVK_ERROR_INVALID_ENUM_CALCULATION` refuses a direct unkeyed String source, a direct Enumeration source whose domain leaves the target's, and a category source whose tokens leave the target's domain, on fixed targets and, measured with unlabelled Enumerations, on repeatable ones. It also refuses a keyed String source such as `[Claims/Memo For "X"]`, and a wider category or a wider field reached by up-steps. Arbitrary String fields and expressions are not Enumeration-producing operations merely because both families store text.
- On a repeatable labelled target, a `FirstFilledValue` list whose member's display differs draws `MVK_ERROR_INVALID_ENUM_CALCULATION`.
- A labelled target, fixed or repeatable, meets the copy comparison's display classes (§1.4): `MVK_INVALID_COMPARE_ENUM_TO_STRING` against an unlabelled Enumeration or a String, `MVK_INVALID_COMPARE_ENUM_TO_ENUM` against a conflicting label map. A Number source is refused `MVK_INVALID_COMPARE_TO_ENUM_OR_STRING`, measured on a root computation and on one reading its declaring group's Number.
- At runtime an empty selected source is no value, a formally invalid reached source poisons the computation, and an admitted present source stores its exact selected token through the common String-shaped target result.

**CUSTOM.** A `FirstFilledValue` into a Custom target, like one into a String target, admits any string-like list — a plain or raw String, a Custom of any type or policy and an Enumeration, in either order — while a Number, Date or Boolean beside them draws `MVK_VARYING_TYPES_NOT_ALLOWED`. A computed Custom target invokes its registered validator on the attempted text, with the declaration bounds, effective locale and stored-value mode. An empty root or inherited poison bypasses the target callback. Acceptance produces a value; any callback finding produces a rejected attempt (ERRORED) with the exact attempted text and project payload, even if it equals the old target. An ordinary rejection makes the target unavailable to later computations. The exact reserved `testIDNummer` report instead leaves the attempted value readable in the same call, while application still clears that target. Neither the old target's stored value nor source acceptance can replace target checking; the same rule applies after `FirstFilledValue` selection. [Custom ingestion and continuation](06-strings-and-enumerations.md#a3-custom-field-type-validation) distinguish this target check from the source's single normalization pass.

> **Non-normative implementation note.** Keep a Number target's exact decimal representation as `{unscaled, scale}` through target checking and typed change comparison: kernel V2 uses scale-sensitive decimal equality, so `7` and `7.00` differ even though their rational amounts agree. Render the normalized stored representation only at the document boundary in plain dot-decimal form, and parse that stored representation on downstream reads; any locale-specific decimal separator belongs to a separate display/materialization layer and does not alter stored text. Keep the computed-result formal check a *reduced* variant (no charset/blank baseline) distinct from the input formal check of [§3](02-logic-and-formal-errors.md).

## 5. Where a computation runs — scope and the parallel join

### 5.1 Operand reach: scope, the level walk and placement

**A computation iterates over its computed field's repetition scope** — where it *writes*, not where its node is declared — and an all-non-repeatable target computes exactly one instance even on an empty document, a non-repeatable group being implicitly present (§1). That instance's precondition is decided like any other, because **a computation precondition has no row gate**: `[Quantity] < 5` selects on `{}`, on an empty `Order`, and on an `Order` holding only the computed target's own stored value, which the strip of §3.1 removes. A guard over a group below a repeatable row selects whether that group is empty, absent or holds only another field. Validation's [row gate](03-empty-and-required.md#a4-the-row-gate--where-the-substitutions-stop) is validation's alone; [§9](07-repetition-and-iteration.md) owns rule iteration.

**An operand is read at its own path inside the current target row.** On the ordinary bound-scope route an operand is admitted exactly when the computed target's repetition scope binds every repeatable level the operand crosses: a nonrepeatable operand feeding a repeatable target is ordinary, as is an operand one level up feeding a target two levels down. Which target instances an operand reaches follows from its path: a form-level operand reaches every target instance; an operand one level up from a two-level target reaches only the instances under its own enclosing row, and two enclosing rows with different values give their own leaves different results. Emptiness and formal invalidity travel the same way: an invalid operand poisons exactly the target instances beneath it and leaves its siblings' instances computing normally.

**A starred operand binds the enclosing row only for levels strictly above its first star.** A same-group star spans **all** rows, which is also how one poisoned sibling cell aborts every row's dependent.

**Every repeatable level an operand leaves unbound is asked one walk, outermost first.** Every repeatable level a read leaves unstarred is read per row, and containment is asked of it first. The walk answers per level:

| the level | class |
|---|---|
| any level, when the target lies outside the declaring group | `MVK_ERROR_FIELD_NOT_IN_RULEGROUP`, on either side of the first star, whatever binds the level and whatever its index declaration; the fully starred operand is admitted into a fixed target |
| a level the target lies in | bound by the target's repetition scope, like any operand's |
| a level below the first star, or below the target's own group, the target inside that level included | `MVK_NO_WILDCARD`, whatever its index declaration; the `*` wildcard under an aggregate is the flattening route for that shape |
| a level beside the target's group that declares no index field | `MVK_NO_WILDCARD` |
| a level beside the target's group that declares an index field, the target's own path declaring none | `MVK_ERROR_FIELD_NO_INDEX` |
| a level beside the target's group, both chains keyed | the parallel-iteration route of §5.4 and its index gates ([§9 §2](07-repetition-and-iteration.md#2-parallel-iteration--joining-two-repeatable-groups-by-key)): matching index-field names admit it, different names draw `MVK_ERROR_FIELD_INVALID_INDEX` |

With the target inside the declaring group, the outermost unstarred level the target does not bind names the class. A declaring group beside the target's own that binds nothing refuses exactly as one that binds the level does. A starred aggregate over a sibling repeatable group remains admitted. A `For` key on a level below the first star is judged by the index gate instead. A plain read and a fixed group operand follow the same table, into a String target as into a Number one and whatever leaf reads the field, a repeatable group named without its star included, whose own level counts. The token and Boolean value counts, `SumOfProducts` and the Number, DateRange and Enumeration `FirstFilledValue` place the class by the target too.

- **Not per-row reads.** A `Having` filter's own leaf and a semantic index's value half are not per-row reads: from a fixed declaring group the target lies outside, `Sum(../Shipments*/ShipWeight Having [../Shipments/ShipKey] == "X")` and, with `Shipments` keyed, `[../Shipments/ShipWeight For "A"] + 1` are admitted, as they are from the target's own group and on the rule arm.
- **Precedence.** Containment answers ahead of arity, the scale comparison and target self-reference, whichever operand reads the target, and an operand list is judged whole: a star's unbound level answers ahead of a duplicate elsewhere in the list, in either order.

**Placement is a containment gate that fires only under derived iteration.** `MVK_ERROR_FIELD_NOT_IN_RULEGROUP` fires exactly when the computed field does not lie at or below the declaring group, and only when iteration is derived from one of two independent sources: the computed field's own repeatable scope, which reaches the gate through the generated rule anchored at that field (§6), or a per-row read, whatever binds its level.

- **Target source.** A pure constant with no operand is refused into a repeatable target declared in an unrelated group, while the same constant is admitted at the target's own group and at any ancestor of it, the root included — containment, not parenthood.
- **Operand source.** A repeatable declaring group derives no iteration by itself: a constant into a fixed target is admitted from one, and only adding a per-row operand refuses it. An aggregate over a star is not a per-row operand while it leaves no repeatable level unstarred; one that leaves a level unstarred, above its first star or below it, reads that level per row and is refused like any per-row read.
- **A fixed target has no placement restriction until an operand derives iteration.** A sibling-star `FirstFilledValue` into a fixed target is admitted from the target's own group, from an ancestor, from an unrelated sibling group and from the starred source's own repeatable group, matching a bare constant at all four placements; only an unstarred per-row read refuses, by containment wherever the target lies outside the declaring group, with a diagnostic naming iteration. From a declaring group that contains the target, the same unstarred read is refused by the walk table above; from a declaring group the target lies outside, repeatable or not, it reaches the placement gate, uniformly across both index declarations. Neither reading alone is right: placement alone can refuse when the target repeats, and the operand alone can refuse when the target lies outside the declaring group.
- **The operand side of a shape that cannot iterate is free.** In a direct nonrepeatable `FirstFilledValue` list a source need not lie in the declaring group, and two sources of one list need not share a group; both spellings are admitted at every declaring-group placement, with a two-format list in the same cross-group shape refused `MVK_VARYING_TYPES_NOT_ALLOWED`.
- **Containment is path containment, nothing root-relative.** With two root groups declared, a bare constant and a star aggregate reading the other root's repeatable group both compute a fixed target across the root boundary, while the same constant into a *repeatable* target from the other root is refused exactly as a same-root non-containing sibling is.
- **Only a computation separates the two sources.** A rule's error field must be referenced by its own condition, so a repeatable error field is a per-row operand too and the two sources collapse into one; the gate is shared, but the constant-into-a-repeating-target shape exists only on the computation side.
- **Containment governs the operand-bearing routes too.** A sibling-star `FirstFilledValue` into a repeatable target is admitted from the target's own parent and from every ancestor, and refused only from a sibling the target does not lie below; a constant control at the same four placements gives the identical pattern. Moving such a declaration to an ancestor while leaving the operand spelled relative to the old base refuses on an operand-resolution failure with a different class: `MVK_INVALID_ENTITY` while the stale walk stays inside the tree, and `MVK_TOO_MANY_PARENT_GROUPS` once the new declaring group is a root, where the `..` walks off the top and arity refuses first. Re-spelled for the new base, or written absolute, the ancestor declaration is admitted.

### 5.2 The target self-read gate

**The computed target is statically forbidden anywhere in the computation's common precondition, alternative preconditions or operations**, nested condition and filter syntax included. This is authoring rejection, not a runtime dependency cycle or an empty read. References to other computed fields remain ordinary scheduling dependencies (§1.1).

**The predicate is containment.** A reference to any ancestor of the computed field is a read of it, so a computation writing `Legs/Distance` draws `MVK_ERROR_REFERENCE_TO_CALCULATED_FIELD` from `GroupNotFilled(/Routing/Legs)`, from `NumberOfFilledGroups(/Routing/Legs*) > 0`, and from `GroupNotFilled(/Routing)` over the root — which an ordinary rule admits, so no entity-list root class competes there. The exemptions are closed and are carve-outs rather than a rule about group predicates, which the refused `GroupNotFilled` over the same group shows: singular `GroupFilled` over such a group, the admitted positive fixed-root `AtLeastOneGroupFilled(Root)` form, and a `CurrentRepetition` operand. Group-list expansion does not extend the exemption: for a target inside non-root `G`, `AtLeastOneGroupFilled(G)`, `AtLeastOneGroupFilled(G,H)` and `AllGroupsFilled(G,H)` draw `MVK_ERROR_REFERENCE_TO_CALCULATED_FIELD`, and so do starred `AtLeastOne`/`No` operands containing the target. A checker keyed on equality admits the group rows; one keyed on containment alone refuses the two the Kernel admits. The law reaches a target with no declared scale unchanged, in the operation and in the precondition alike.

**The class follows the reading mode.** A plain direct target-field occurrence reports `MVK_ERROR_REFERENCE_TO_CALCULATED_FIELD`. An occurrence read through a **projection** — an Enumeration category `[target -> Category]` or a semantic index `[target For key]` — reports `MVK_ERROR_SEMANTIC_INDEX_OR_CATEGORY_FOR_ERRORFIELD`, whose repair is to drop the projection rather than the reference. Naming the computed field as a semantic index's **key** reports the projected class too, measured for one key position. Projecting any other field is an ordinary computation source.

**Which reads are judged follows the alternative walk.** Alternatives are walked in authored order:

- **From two alternatives on, an unconditional alternative's own reads of the target go unjudged**, whether or not another alternative is preconditioned. `[T]; [B]`, `[T]; [T]` and an unconditional `[T]` beside a preconditioned `[B]` each draw `MVK_ERROR_EMPTY_PRECONDITION` alone, while a sole unconditional alternative reading its target draws the target-read class. The empty class is reported once however many alternatives are unconditional, at the first one's place.
- **Every judged read draws the target-read class once**, alternative by alternative in authored order, once per written occurrence. Within one alternative a self-reading precondition and operation draw the same class, so their relative order is not observable.
- **A common precondition guards no alternative; its target-read findings appear at the first alternative the walk judges, once per written read.** A common `FieldFilled(T)` over `[B]; FieldFilled(G) => [C]` draws the empty class and then the target-read class; over `FieldFilled(G) => [B]; [C]` the reverse; over two or three preconditioned alternatives the target-read class once; over two unconditional alternatives the empty class alone. This specifies the reported findings, not how often the common check executes.
- **The projected class answers alone and once per computation**, from an alternative's operation, guarded or not, and from the common precondition, and it withholds both the empty class and the plain class. It pre-empts the plain class wherever both readings occur: in one operation, in either operand order of a two-entry `FirstFilledValue`, and across slots, so the classes cannot be decided slot by slot. `[T For "a"]` beside an unconditional `[B]` draws it alone in either order, as `[T -> Category]` does beside an unconditional projection or a guarded plain read.
- The walk holds alike on a repeatable target and on a fixed one nested below its root, and the common-precondition placement and multiplicity hold on fixed root, fixed nested and indexed repeatable Number targets.

**Parse-time classes answer ahead of both self-read classes.** Beside a plain self-read in the operation, a text in a rounding slot of the same operation draws `MVK_NO_NUMBER`, an argument too many in the precondition `MVK_PARAMSIZE_INVALID1`, and an unresolved name `MVK_INVALID_ENTITY`, each alone. The projected class yields to a precondition's `MVK_NO_NUMBER` or `MVK_INVALID_ENTITY` the same way, and so does `MVK_ERROR_INVALID_ENUM_CALCULATION` (a text computed into an Enumeration) to a precondition's arity gate or unresolved name.

**Repeatable-target cells.** On a repeatable target a category self-read draws the projected class, compatible or not, directly and in a two-entry `FirstFilledValue` in either position; a semantic-index self-read draws the projected class; and a plain self-read in a two-entry `FirstFilledValue` of stored reads draws the plain class even where the other entry's domain leaves the target's.

Unmeasured cells: a projection in an alternative's own precondition; incompatible categories on a fixed target; the incompatible plain-read pair on a fixed target; category or mixed lists longer than two; stars; a projection living only inside a `Having` filter; and scheduling interactions. A checker's class choice in these cells is not specified.

### 5.3 Selection across alternatives and declarations

**Alternatives evaluate top to bottom, and the first selected alternative ends the scan.** Only a known-true precondition selects, and an absent precondition selects directly; a clean false or unknown precondition falls through; a poisoned read or a reached runtime failure aborts the computation and skips the remaining alternatives. The first selected alternative supplies the operation and ends the scan even if that operation later produces no value, while no selected alternative yields a clean no value. Exhausting the table without a selection and selecting an operation that stores nothing both store nothing, but only the former lets every later row be considered.

**The empty-precondition gate is per declaration.** Within one computation a missing precondition is legal only on the sole alternative; a multi-alternative table must guard every row (§1.2). Mutual exclusivity is authoring discipline rather than a consistency gate: overlapping preconditions resolve at compute time to the first declared.

**Several computations for one field form one first-selected table.** Code generation distributes each computation's common precondition into its alternatives and concatenates all those alternatives, in the order the model supplies, into one table for the field. The combined table may therefore hold unguarded rows from separate declarations (§1.1's `Y` holds one). A non-holding guard falls through across computation boundaries; a later computation's alternatives win only when every earlier alternative falls through without selection. Over targets that are not joined, the combined table is measured for Number, String, Date and Enumeration targets at fixed and repeatable rows.

**Into a key-joined target the combined table runs over the join, and a separate declaration that reads no partner field never stores a value there; its position decides what it does.** A declaration reading a partner field anywhere, a guard included, is joined.

- **A leading declaration reading no partner field** clears the target at every row whatever any precondition says and whatever follows: a constant, a starred `Sum`, a target-row read, a root read and a precondition false at the row all clear, and a malformed read inside it poisons no dependent.
- **Behind a joined lead,** the scan passes over every later declaration reading no partner field without reading it: its guards are not evaluated, a guard holding at the row selects nothing, a malformed read in it poisons nothing, and a later joined declaration still computes. A joined declaration guarded by `[Headcount] == 1`, then one reading no partner field guarded by `[Headcount] >= 2`, then a joined one guarded by `[Headcount] >= 1` write the last one's value at a row of headcount 2.
- **Joined declarations** concatenate as usual, also when they join different partner groups by the same key, and alternatives inside one declaration that reads a partner field select and evaluate normally whichever of them read the partner.

Measured scope: passing over is measured on Number, String and Date targets, and on Enumeration targets only the leading case; joined concatenation is measured on Number, String, Date and Enumeration targets.

Sources: [joined declaration order](../docs/sources/group-count-topology.md#src-k22-joined-declaration-order), [inbound 2026-10-25](../docs/sources/inbound-handbacks.md#src-inbound-2026-10-25), [joined group target leaves](../docs/sources/key-join-and-parallel-probes.md#src-k22-joined-group-target-leaves), [cross-declaration checkpoint](../docs/sources/model-structure-and-declaration-probes.md#src-k22-cross-declaration).

### 5.4 Parallel joins

**Operands reaching into sibling indexed groups run [§9](07-repetition-and-iteration.md#2-parallel-iteration--joining-two-repeatable-groups-by-key)'s parallel iteration.** Rows join by the shared **index-field value**, never by physical position; a partner joins the target path's keyed level by shared index name, an unkeyed ancestor level included. An unmatched side reads empty, and the calculation never creates a repetition: a key present only on the partner computes nothing. The route needs the iterated group's index field to carry the **same name** as the index field on the computed field's path, and the operand to be a bracketed **non-starred** reference; a starred reference is a wildcard rather than an iteration and takes the ordinary route.

**An invalid index column skips target instances by a truncated prefix.** On this route an unavailable index column — a key empty, malformed or carried by two rows — yields no iteration values, so the loop body never executes and no read-time throw occurs; the affected target instances are skipped after the loop instead. The skip key takes the target instance's coordinates truncated to the shared prefix — the repeatable levels down to and including the common ancestor of the computed field and the malformed index group's parent — and every target instance whose truncated coordinates match is skipped. Which group carries the bad key therefore decides the blast radius:

| the unavailable column is in | effect |
|---|---|
| an **off-path** iterated index group | the truncation falls *above* the sibling level, so sibling parent rows are skipped too, and a clean sibling's target is cleared although its own key still matches a clean row |
| the computed field's **own on-path** index group | the truncation falls *below* the sibling level, so siblings stay distinguished and a clean sibling's target keeps its value |
| any joined group, when the target scope and that group's parent share no repeatable level | every instance of each computation joining that group is skipped; a joined computation that does not read that group keeps its values |

The over-reach is deliberate engine behaviour, not incidental. A skipped instance stores no value, and a dependent that reads it clears as a read of poison does (§2) instead of reading it as empty. Measured on a keyed group sharing no repeatable level with the target, under a duplicated and under a malformed key: an arithmetic dependent of the skipped target and a starred `Sum` over the skipped targets are both cleared, where an empty read would compute `0`. An arithmetic dependent of an instance skipped at its own row's duplicated key is cleared the same way. A String or Enumeration row copy and a Date shift of a skipped String, Enumeration or Date target clear too, measured on targets nested below an unjoined repeatable group, but an empty read would clear them as well, so those rows do not separate poison from emptiness. Unmeasured: a presence read of a skipped instance, and the dependents of an instance skipped over capacity, which is a clean clear.

**A target row beyond its group's capacity clears alone**, while the rows within capacity compute.

**A joined computation's precondition reads the same joined row as its operation.**

- Presence, field-fill lists, text, Date and category comparisons, value-list membership and `Length` read partner fields by key, an unmatched partner reading empty.
- `GroupFilled` of the partner group holds for a partner row carrying only its key and fails without a partner. `GroupFilled` of the target's own group is admitted, while `GroupNotFilled` of it draws `MVK_ERROR_REFERENCE_TO_CALCULATED_FIELD` (§5.2). `GroupFilled` of a group enclosing the joined groups holds at every row the join computes, a key-only target row without a partner included: that row excludes a reading which narrows the group to the joined row without its keys, and the whole-content reading cannot differ for `GroupFilled` from one narrowing it to the joined row with them, since both contain the target row and its valid key.
- `Today` compares either side's Date with the evaluation's date.
- A key read off the partner row, `GroupFilled(/Staffing/Ledger For /Staffing/Demand/Label)`, selects by the partner's value per joined row; on a target row without a partner it names no row and the guard fails.

**An atom with no joined form keeps its ordinary meaning at the target's row**, each in the position it is measured in, contributing the value it has at the target's row, the same on every joined row: a star spans every row of its group, and a keyed read selects the same row for every joined row.

- **In a joined precondition:** a starred aggregate or field-fill list, a filtered starred `Sum`, a literal-keyed read of a third group or of the partner group, and `PatternMatched` are admitted, with the captured values agreeing with that ordinary meaning.
- **In a joined operation, beside a partner read:** a literal-keyed read of a third group, a filtered starred `Sum` over the whole group, `DayFromDate(Today)`, `NumberOfFilledFields` over target-row fields, and a starred aggregate. The unmatched partner read beside them reads empty, so the operation computes from the remaining atoms. `[/Staffing/Demand/Base] + Sum(/Staffing/Demand*/Base)` adds the sum over every Demand row to the partner's value, and a target row without a partner computes the sum alone.

**A guard alone can join.** A computation whose only partner read is a precondition keyed by a partner field, `GroupFilled(/Staffing/Ledger For /Staffing/Demand/Label)` over an operation reading only the target row, still joins: it writes where the partner's key selects a row and clears where it selects none or no partner exists.

**Every target kind joins the same way.** `[/Staffing/Demand/Label]` into a String field of the target group, `[/Staffing/Demand/Stamp]` into a Date field and `[/Staffing/Demand/Kind]` into an Enumeration field copy the partner row's value or stored token, with or without a precondition over the target row; a partner without the copied field and a target row without a partner both clear the target. These targets clear as a Number target does at an invalid index and beyond capacity.

**Number keys join by numeric value** across differing maximum fractional digits, a key `1` pairing with `1.00`, and an unmatched key computes with the partner read empty.

**A semantic-index read is column-strict in compute.** Any invalid cell in the index column ([§10 §4.1](08-paths-and-references.md#41-what-a-semantic-index-read-yields)) — malformed, duplicated or empty — clears every computation reading that parent-scoped column, even one whose key matches a clean row, which is broader than validation's per-lookup rule ([§10 §4.2](08-paths-and-references.md#42-per-lookup-validation-vs-per-column-compute)). Over a clean column the compute read equals the validation read: a no-match or matched-but-empty cell reads empty-as-`0`. A matched formally invalid cell poisons per *read cell*: a sibling computation reading a clean cell of the same row keeps its value.

Sources: [parallel instance leaves](../docs/sources/key-join-and-parallel-probes.md#src-parallel-instance-leaves), [cross-declaration checkpoint](../docs/sources/model-structure-and-declaration-probes.md#src-k22-cross-declaration), [joined carrier admission](../docs/sources/key-join-and-parallel-probes.md#src-joined-carrier-admission), [joined carrier limits](../docs/sources/key-join-and-parallel-probes.md#src-joined-carrier-limits), [K22 joined computations](../docs/sources/key-join-and-parallel-probes.md#src-k22-joined-computations), [inbound 2026-10-27](../docs/sources/inbound-handbacks.md#src-inbound-2026-10-27), [runtime open-cells probe](../docs/sources/model-structure-and-declaration-probes.md#src-runtime-open-cells).

### 5.5 Sibling-star selection and repeatable `Time` construction

**A sibling-star `FirstFilledValue` selects per enclosing parent.** A target in one sibling repeatable group may read starred fields in other sibling groups under the same enclosing repeatable parent. Each physical target row binds every operand to its own enclosing parent, exhausts the complete first operand's extent before entering the next, and keeps authored source order, never zipping sibling rows or scanning globally. The scan is the stop-at-first scan of §3.2: an empty extent falls through to the next operand; the first filled cell is selected and hides malformed cells later in that extent and in every later operand; a reached malformed cell before it poisons the target. Exhaustion of every extent answers the target kind's all-empty result ([§2 A.3](03-empty-and-required.md#a3-what-an-all-empty-selection-folds-to-the-aggregate-identities)). The selected value then meets the target's ordinary policy (§4), and the generated rule reports at the exact repeated target instance (§6). Removing the only star from such an operand is refused `MVK_NO_WILDCARD`.

`FirstFilledValue(../Choices*/Window)` into `Tasks/SelectedWindow` runs once per physical task row and scans only that task's enclosing parent's choices, so two tasks under one parent receive the same first choice while tasks under another parent receive that parent's value. A stale second task whose stored target differs from the selected value reports the computation's message at `Projects[1]/Tasks[2]/SelectedWindow`. A parent with a task but no choices clears the stale target, and the cleared-versus-stored mismatch stays unreported (§6).

| target kind | target policy and measured scope |
|---|---|
| Number | A nonempty list of same-scale, unfiltered, single-axis sibling-star operands, such as `FirstFilledValue(../Primary*/Candidate, ../Secondary*/Fallback)` into `Targets/Result`. An empty first extent's missingness still makes a later generated-rule mismatch OMISSION. Clean exhaustion computes the real Number `0`, and a selected value above the target maximum is a rejected attempt. Measured on one and two operands, two parents, multiple target rows, zero, clearing and one target rejection. Root or global stars, group and filtered operands, different-scale lists or suppression, materialized topology, later validation and pointer rendering are unmeasured. |
| Time | The `HH:mm:ss` profile only, `FirstFilledValue(../Choices*/SourceTime)` into `Tasks/SelectedTime`. It selects parsed clock identity rather than source text or transport instant. An empty extent or reached malformed prefix clears only source-filled targets; a source-identical accepted clock is absent from the changed subset, while a stale target receives the exact selected clock. Materialized application is unmeasured. |
| FULL Date | Matching ISO declarations, `FirstFilledValue(../Choices*/PromiseDate)`. A target whose `rejectBefore1900` policy is enabled is admitted from a source whose policy is disabled; a selected pre-1900 Date is a rejected attempt at the exact repeated target, keeping its exact rendered attempt, with no formal operand finding. A malformed source clears instead, `1900-01-01` and later values are accepted, and one parent's rejected target stays independent of a sibling parent's accepted value. |
| DateTime | Complete ISO DateTime, `FirstFilledValue(../Choices*/Stamp)` into `Tasks/SelectedStamp`. Malformed source text before a later valid source poisons and clears the target. The same-format, single-zone measurement does not separate exact-instant selection plus target rendering from source-text copying. |

A missing component yields no value and clears only the affected stale target. A missing component does not stop evaluation: a later malformed component is still reached and stays in the formal operand channel. Incomplete and unreal constructions both store no value. |---|---|
| constants | `Time("5", "2", "9")` stores exact `05:02:09` as a VALUE action for a stale row and for absent and present-empty targets, while source-identical rows under two different parents are absent; the generated comparison message fires only at the stale filled target |

| String fields | a String declaration with maximum length 2 and a digit-only pattern; `Time(/TimeProbe/RootHourText, ../ParentMinuteText, RowSecondText)` converts leading-zero text such as `"05"`, `"02"` and `"09"` to the clock parts. ## 6. The implicit validation rule, precisely

The "also acts as a validation rule" ground rule has one exact generated shape, shown with every optional member present, `⏎` marking a line break and spacing insignificant:

```
one alternative:  FieldFilled(F) And (commonPrecondition⏎) And (precond₁⏎) And [F] mismatch₁ operation₁
two or more:      FieldFilled(F) And (commonPrecondition⏎) And (⏎
                    ((precond₁⏎) And [F] mismatch₁ operation₁⏎) Or⏎
                    ((precond₂⏎) And [F] mismatch₂ operation₂⏎) Or … ⏎)
```

Each `mismatchᵢ` is an infix comparison operator: `!=` unless that alternative declares a `toleranceRangeOp`, in which case it is the named fixed `DiffersWithToleranceRange1 / 2 / 5 / 10` operator. The `[F]` the shape writes is the computed field's path as the declaring group reads it, spelled by [§10 §1](08-paths-and-references.md#1-absolute-relative-and-short-name-references); that a keyword-named segment is single-quoted there is inferred from that clause and unmeasured. The list's opening `(⏎` and its `Or⏎` separators rest on a source reading of the alternatives joiner, unmeasured against a spelling without those line breaks.

**Every member is parsed inside that one text, so each is followed by a `)` it did not write, except a lone alternative's operation, which ends the text.** A member that stops short therefore draws `MVK_UNEXPECTED_TOKEN` wherever an added `)` follows it: a blank, `null` or whitespace operation beside a sibling, an operation ending on `+` or with `{` or `[` open beside a sibling, a precondition ending on `And`, `Or` or a comma or with `[` open, and a common precondition ending on `And` or with `[` open. Only where it ends the text does it keep its own class: a lone blank operation or one ending on `+` draws `MVK_INCOMPLETE_INPUT`, and a lone operation with `{` open `MVK_EXPECTED_TOKEN_NOT_FOUND`. A lone alternative's precondition with `(` open draws `MVK_EXPECTED_TOKEN_NOT_FOUND` too, because the added `)` closes its call and leaves its own group open. The codeless `problem.document.basic.computationOperationEmpty` line accompanies an empty or `null` operation and not a whitespace one.

**The members are one text for class precedence too: among the classes raised while the joined text is parsed, on every pair measured, A12 names only the one first in the joined order.** A precondition's class stands ahead of its own operation's, an unresolved name in that operation included, and the common precondition's ahead of an alternative precondition's. The first alternative's operation's class stands ahead of the second alternative's precondition's, so the preconditions are not all judged first. The alternatives stage and the error-text classes of §1.2 are not parse classes, and there several stand together. The `[F]` the shape writes is read like any bracket: a `DAY_OPTIONAL` Date target draws `MVK_INVALID_DATE_TYPE` and a raw String target `MVK_INVALID_RAW_TYPE`, each with no comparison class beside it, on the rows measured with a source of the target's own kind. A partially known Date or raw String *source* into a Number draws the same read class, where a full Date or an ordinary String source draws a comparison class (§1.4).

**When it fires.**

- It fires **only when the field is filled** and at least one alternative whose precondition holds **disagrees** with the stored value, with the **computation's own name** as the fired error code.
- A tolerance alternative's stored and computed values inside or exactly on the normalized band produce no mismatch.
- A **cleared-versus-stored** mismatch is deliberately not flagged: no alternative's comparison holds.
- **Overlapping alternatives make validation and computation differ.** When the alternative preconditions are mutually exclusive, the one holding comparison describes the same operation that computation selects. If they overlap, computation executes only the first holding operation, while the generated rule keeps every holding alternative's mismatch disjunct and may fire even when the stored field equals the first operation. That is why authors must make preconditions mutually exclusive even though model consistency checking does not reject overlap.

**The computation's `roundingMode` is judged against each alternative's comparison.** It is declared once, as `Exact`, `RoundUp` or `RoundDown`, an absent mode meaning `Exact`; any other spelling, a different letter case included, leaves the model unbuildable with no class. `RoundUp` or `RoundDown` beside an alternative declaring no `toleranceRangeOp`, whose mismatch is therefore the strict `!=`, draws `MVK_ERROR_WRONG_ROUNDING_MODE`; either against a band, and `Exact` against either, are admitted. The gate is owed by every alternative, so one band-less alternative among banded ones refuses a `RoundUp` computation in either position.

**An admitted banded mode rounds the written value to zero places, and the generated validation compares the operation as authored.** Beside a tolerance band, `RoundUp` rounds toward +∞ and `RoundDown` toward −∞, at zero places, as measured into a two-digit target: `RoundUp` writes 1.25 as 2 and −1.25 as −1, and `RoundDown` writes 1.75 as 1 and −1.25 as −2. `Exact` beside a band floors a finer operation to the target's declared digits, 1.255 as 1.25 and −1.255 as −1.26, where the same model without its band errors; whether that error is a static refusal or a rejected attempt is not recorded. An empty operand writes 0 under `Exact` and `RoundUp`. Under `DiffersWithToleranceRange1` the validation stays silent on 0.30 and on 2.20 beside an operation of 1.25, and fires on 0.25 beside a finer 1.259, under every mode, which comparing with the rounded or floored value would not reproduce. Measured on one model and one band.

**The generated rule anchors at the computed field.** Its error entity is the target's absolute location (the `computedFieldRelPath` resolved from the computation node, even across sibling subtrees or roots), independent of the declaring container's instance content: an empty declaring container does not silence it. A repeatable target therefore derives iteration through this anchor, which is the target source of the placement gate in [§5.1](#51-operand-reach-scope-the-level-walk-and-placement).

**The message's type and channels.** The message is typed by the directional dispatch of [§12 §4](10-validation-and-polarity.md#4-the-directional-fill-machinery-behind-the-typing) applied to the generated inequality, and its channels follow these rules:

- **The stored side is fixed.** Headroom is necessary but not sufficient for OMISSION: growth must also move the computed quantity toward the stored value. A grow-only count below capacity with every cell filled types VALUE when its computed `3` already exceeds a seed of `1`, and OMISSION on the same document at a seed of `9`. The at-capacity witnesses of [§12 §4.1](10-validation-and-polarity.md#41-the-same-rule-fires-either-type) show the fixity, since a stored side able to move would have typed them OMISSION.
- **`referenced` carries each operand's own reach**, together with the computed target. A **group** operand names the fields anywhere in its subtree, at any depth and however many there are: a shell whose only field lies two levels below it names that field, and a group owning two fields names both. A **field** operand names that field alone: a `Sum` over one flattened field in the same message set does not name its sibling. The extent follows the authored operand's reach and must not be widened from a field operand to its enclosing group. For the group-count operator both operand forms use the one group extent, leaving a fixed operand and a starred one indistinguishable in the field set; the coordinates distinguish them. An authored rule's `referenced` inventory is [data model §3.1](01-data-model.md#the-message-and-its-two-pointer-channels)'s.
- **`referenced` is an authored-shape inventory, not a reached-cell trace, and it is invariant under filling.** For a starred operand the set is byte-identical between a document with no instantiated row and one with four rows whose every cell is filled; a read-derived inventory would be empty in the first and enumerate every reached cell in the second. A group the evaluator cannot read is named all the same.
- **`fillToFix` is the ordinary rule arm's omission projection of the generated condition** ([the data model](01-data-model.md#the-message-and-its-two-pointer-channels)): empty on every VALUE message, and on an OMISSION one the pointers the condition's ordinary operands contribute. The computed target is always among them, since the mismatch comparison reads it, while a field the condition reads only through positive presence is referenced but not listed, so the set is a proper subset of `referenced` wherever such a field stands. A common precondition `FieldFilled(Gate)` withholds `Gate`, a positive field-fill quantifier `AtLeastOneFieldFilled(A, Rows*/N Having …, B)` withholds its field operands while the fields its `Having` filter reads stay listed, and a `GroupFilled` precondition withholds its group's fields except those the condition also reads ordinarily, which stay listed: on the measured parallel witness, the operation's operand and both groups' index key. A listed pointer is not a claim that the cell is empty: a target typing OMISSION on row headroom alone with every referenced cell filled lists each filled pointer its ordinary operands contribute. Measured scope: those three precondition and quantifier forms, and, on one fixed group of Number fields, an upward count against a literal, `NumberOfFilledFields(Rider1, Rider2) > 0`, whose operands are withheld as an authored rule's count pruning withholds them; a count against a field, the reversed operand order and starred operands are unmeasured.
- **No message where an operand group holds only malformed content.** Such a group leaves the computation with its count written and **no** implicit message, measured for a fixed group, direct and nested, and for a fixed group below a star. The whole target loses it, a starred row count in the same operand list included, while a separate target counting starred rows in the same document keeps its own. Beside an admitted value the same malformed cell keeps the message, so a formal error alone does not suppress it. For a fixed group below a star one such instance suffices, even beside a filled one, while one in an over-limit row suppresses nothing. Validation leaves a malformed-only fixed group undecided, which accounts for the absence; for the below-star form that validation premise is inferred, not measured. Measured on one formal cause, unparseable Number text.

> **Non-normative implementation note.** Generate this rule as a **desugaring** of the complete alternative table into an ordinary `Rule` (the same machinery as the "required" desugaring of [§4](03-empty-and-required.md)). Reuse the same condition and operation semantics, but do **not** reuse computation's first-match selector for the generated rule: it must keep one guarded mismatch disjunct per alternative. Prove agreement between selected computation and generated validation only under an explicit mutual-exclusivity assumption (or another sufficient condition such as equal results for every simultaneously holding alternative). The `FieldFilled(F) And …` gate and the "cleared-vs-stored not flagged" behaviour fall out of the generated shape above.
