# 10 — The validation model and message polarity (§12)

Three topics, one of which (polarity) is a *whole second semantic dimension* a naive reimplementation omits entirely:

1. **Severity** (ERROR/WARNING/INFO) is pure message metadata — only ERROR invalidates.
2. **Message type** (VALUE vs OMISSION) is **computed from the data** via *directional fillability* and combines with Kleene truth in a verdict algebra that retains `unknown`.
3. **Full vs partial** validation — partial gates rules by a relevant set and treats out-of-set references as UNKNOWN.

If you only implement "does the rule fire", you have implemented *half* of validation. The engine also answers "*why*, and what repair helps" — that is the polarity, and it is load-bearing for the message a user sees.

---

## 1. Formal validation vs. rule validation

Two independent layers:

- **Formal validation** — the field-type checks the engine performs automatically (type, pattern, decimal places, required-by-checkbox, charset, blanks, …). These carry the internal sentinel path `formalePruefung` and make a field **"unknown"** while they stand ([§3](02-logic-and-formal-errors.md)).
- **Rule validation** — the author-written (and generated) rules. These **never** block a field from evaluation.

Formal validity is *prior* for every built-in read: a formally-invalid cell is UNKNOWN to predicates, comparisons, and aggregates that consume it. `CustomCondition` is the explicit host-SPI exception because its hidden read footprint is unavailable to the kernel; a reached callback receives the formal-invalid set and owns the decision for its necessary fields ([§14](11-messages-and-custom.md#part-b--14-customcondition--the-escape-hatch)).

## 2. Severity is metadata

A rule's severity (**ERROR / WARNING / INFO**) is metadata on the resulting message, **not part of evaluation** — the condition fires identically whatever the severity. Only **ERROR**-severity messages make the document invalid: a "no error occurred" check considers **only ERRORs** (warnings and infos may be present and it still passes). A firing WARNING therefore surfaces a message without failing validation — useful for "are you sure?" advisories.

> **Non-normative implementation note.** Keep severity out of the evaluation core entirely — attach it to the emitted `Message`. "Document valid?" = "no emitted message has severity ERROR". Never let severity influence firing.

## 3. Every fired message is typed — VALUE vs OMISSION ⚠⚠

Beyond severity, every message carries a **message type**:

- **OMISSION** — filling one or more currently-empty fields *could* satisfy the rule ("something is missing").
- **VALUE** — no fill can; only changing an entered value helps ("what you entered is wrong").

Because empty operands participate in so many firings ([§2](03-empty-and-required.md)), the type is what tells a user *which* repair to attempt. Internally, the evaluation result must also preserve a formally-invalid/suppressed **unknown** result; it is **not-fired / fired-as-value / fired-as-omission / unknown**, with its own `And`/`Or` algebra and (again) **no negation** combinator:

- under **`And`**, **omission wins** (filling could still rescue the whole rule);
- under **`Or`**, **value wins** (the value branch alone convicts).

> **Non-normative implementation note.** Model the full evaluation result as a unified verdict so `unknown` can never be mistaken for `notFired`:
> ```lean
> inductive Polarity where | value | omission
> inductive Verdict where
>   | notFired
>   | fired (polarity : Polarity)
>   | unknown
> -- conj: notFired dominates; then unknown; among two fires omission wins.
> -- disj: a fire dominates unknown/notFired; among fires value wins.
> ```
> The explicit tables live in [`../A12Kernel/Core.lean`](../A12Kernel/Core.lean). A suppressed branch contributes `unknown`, not `notFired`; strong-Kleene dominance then explains why a fired `Or` can decide despite an unknown sibling while a fired `And` cannot.

The public validation finding projection emits a message only for `fired`; both `notFired` and `unknown` yield no finding. Their distinction remains part of the executable semantics because enclosing `And`/`Or` consumers can distinguish them, but a terminal leaf result with no such consumer is not independently message-observable.


### 3.1 Truth testing and message classification

An ordinary rule first tests whether its complete condition is known true. This Boolean pass visits leaves in authored order: `And` skips its right side after false or unknown; `Or` skips its right side after true. A runtime exception already reached aborts before any later connective can suppress it.

If the complete condition is true and its authored constructs enable omission classification, the rule evaluates every condition leaf again in authored order and combines their verdicts with the polarity algebra. This second pass is eager across both connectives. Its static enablement is independent of the current document's eventual message type: a child `GroupFilled` guard enables it, while unfiltered `FieldFilled` and a field-free `Now` comparison do not. Root-group presence follows the separate root-condition classification. Field-value operations enable the pass even when the current values are present. When classification is disabled, the first pass's skipped branches remain unreachable and a normal firing is a value message. Singular `FieldValueIncludedInValueList` / `FieldValueNotIncludedInValueList` enables classification only through field-value operations in its value list; a literal-only membership does not. The plural `No` / `NotAll` quantifiers enable it, while plural `AtLeastOne` requires a filter on either side. Their shared pure verdict does not make these authored forms interchangeable in a condition that can fail at runtime.

A runtime failure in either pass reaches the same enclosing rule handler. A true `FieldFilled(Flag)` disjunct can therefore hide a failing `Now` comparison when no classification-triggering construct occurs, while adding a child-group presence guard reaches that comparison during classification and aborts the ordinary row loop. A false complete first-pass result runs no classification, including when an earlier omission-valued leaf made an `Or` true. These distinctions are retained in the [classification matrix](../docs/sources/temporal-runtime-fold-probes.md#src-compositional-temporal-disposition); [the temporal failure clause](09-computations.md#32-an-invalidity-clear-poisons) owns the loop handler and error address.

## 4. The directional-fill machinery behind the typing

The type is **not** a per-operator constant — it is computed from **directional fillability**: every operand carries *"could this result still grow / still shrink if something were filled"*, and the enclosing comparison's direction decides whether a fillable direction could clear the firing. The load-bearing pieces:

- **An empty number's fillability is asymmetric and sign-aware:** it can always **grow**, but can **shrink only if the field is *signed*** — and the trigger is `positivesOnly`, **not** `minValue`. So `[Unsigned] >= 0` fired on the empty substitution is a **VALUE** error (no fill breaks `>= 0` from above), while the signed twin is **OMISSION**.
- **Fill propagates through arithmetic and the value functions:** `+` combines both directions, `−` flips the subtrahend's, and `×`/`÷` use both current signs plus joint-direction terms. Power is not a parity-only rule: it dispatches by fixedness, base magnitude relative to `−1`, `0`, and `1`, exponent direction and parity, with reciprocal-first negative handling and conservative fallback branches. `Round*` preserves the flags, `Abs` transforms them with the value's sign, operand-list `Min`/`Max` combine them directionally, `RangeAsNumber` is grow-only. So `[F] != [A] + [B]` with an empty `B` types **OMISSION** — the right side can still move.
- **Each NUMBER aggregate combiner has its own directions after a present value enters the fold:** an incomplete `Sum` always grows and shrinks exactly when at least one missing contributing declaration is signed; signedness is attached to each omitted source, not selected once for the whole operand list. `MaxValue` is grow-only, and `MinValue` is shrink-only. The all-empty identity is the exception: if missingness exists but no present value entered the fold, the common result is `0` marked able to grow and shrink regardless of signedness or aggregate operator. A starred aggregate's missingness input includes every empty selected leaf and every open declared tail **at every reopened repeatable level from the first star downward**, checked per actual parent as specified in [§9](07-repetition-and-iteration.md#4-where-a-star-binds--the-anchor-rules-). Only exhaustion of every finite reopened level plus no empty selected leaf removes that input; an unbounded reopened level always retains it, while capacity above the first star remains bound and irrelevant. After a present value, the aggregate applies its combiner direction to this hierarchical missingness; with no present value, it participates in the both-directional all-empty branch.
- **The counts can only grow:** a fired `count >= n` is **VALUE** (no fill lowers a count), while `count < n` stays **OMISSION**.
- **Dates ride a *symmetric* combiner:** a fired date comparison types **OMISSION iff either side is not-given**, regardless of the comparison's direction.
- **An encountered `Having` filter can escalate:** value-list polarity follows its operator-specific traversal. Fields-side `AtLeastOne`/`NotAll` use the deciding witness's filter, fields-side `No` retains every reached filter on its exhausted absence scan, values-side `AtLeastOne` retains a filter only when that operand selected a present member, and values-side `No`/`NotAll` retain reached filter/missing potential from their complete values pass. A reached filter makes every available Number `Sum`, `MinValue`, `MaxValue`, or `NumberOfDifferentValues` result both-directionally fillable, even when the ordinary unfiltered combiner would be fixed or one-directional; a fired comparison consuming that result therefore remains OMISSION. Filter encounter is likewise ordered for multi-operand `FirstFilledValue`: each operand slot marks its own filter immediately before that slot is scanned, and a terminal value or formal error prevents every later slot and its filter from being observed. Filtered **value counts** escalate shrinkability only when the filter actually counted a matching value; a kept nonmatch stays grow-only. **`FieldValuesNotUnique` escalates on a positionally reached filter**: its scan walks operands in authored order, marks a filter when a filtered operand yields a value that is *actually compared* — mere specifiedness is not enough, so a present-but-unconvertible cell does not mark it, and answers the moment it detects a duplicate. A firing is therefore omission-polar exactly when a filtered operand's compared value was collected at or before the duplicate — *even when every retained value is filled*, because the filter selects which values are compared — and value-polar otherwise. A filter authored **after** the duplicate-detecting value never retypes it, and a filtered operand that contributes only empty or unconvertible cells never marks anything, so the escalation is not a static "some operand is filtered" test; the two accounts agree on a single operand and on a uniformly filtered or uniformly unfiltered list. This is distinct from the filtered count-rule cases above: no missing potential in the selected cells escalates it, since a skipped empty or an uninstantiated declared row can only add a later duplicate, never clear the present one.
- **A concatenation ORs the not-given flag across its parts:** a fired string comparison is **OMISSION iff any operand carries the flag** — so a concat containing *any* not-given read (an empty field, a no-match indexed read, a not-given coercion) types a fired mismatch OMISSION even though the concatenated string is non-empty.

For valid numeric operands `a` and `b`, write `Gₐ`/`Sₐ` for “can grow”/“can shrink,” and similarly for `b`. The exact ordinary-arithmetic propagation is:

| Result | Can grow | Can shrink |
|---|---|---|
| `a + b` | `Gₐ ∨ Gᵦ` | `Sₐ ∨ Sᵦ` |
| `a − b` | `Gₐ ∨ Sᵦ` | `Sₐ ∨ Gᵦ` |
| `a × b` | `(Gₐ ∧ Gᵦ) ∨ (Sₐ ∧ Sᵦ) ∨ (b > 0 ∧ Gₐ) ∨ (b < 0 ∧ Sₐ) ∨ (a > 0 ∧ Gᵦ) ∨ (a < 0 ∧ Sᵦ)` | `(Gₐ ∧ Sᵦ) ∨ (Sₐ ∧ Gᵦ) ∨ (b > 0 ∧ Sₐ) ∨ (b < 0 ∧ Gₐ) ∨ (a > 0 ∧ Sᵦ) ∨ (a < 0 ∧ Gᵦ)` |

Division rejects a current numeric-zero divisor before fillability is consulted. Otherwise it applies the multiplication table to `a × (1 / b)`, where `G(1 / b) = Sᵦ ∨ (b < 0 ∧ Gᵦ)` and `S(1 / b) = Gᵦ ∨ (b > 0 ∧ Sᵦ)`. The joint terms are load-bearing: two grow-only operands currently at zero produce a grow-only product even though neither current sign alone contributes.

Power first transforms a negative exponent by taking the precision-50 reciprocal of the base and swapping the exponent's directions; invalid `0`-negative, fractional, and out-of-range cases stop before polarity. For a valid nonnegative exponent, the kernel's conservative branch table is:

| Fixedness/value region | Result directions |
|---|---|
| fixed exponent `0`, or both operands fixed | fixed |
| fixed positive odd exponent | base directions |
| fixed positive even exponent | grow; shrink iff the base can move toward zero from its current sign |
| fixed base `> 1` | exponent directions |
| fixed base `= 1` | fixed |
| fixed base in `(0, 1)` | swapped exponent directions |
| fixed base `= 0`, exponent cannot shrink, exponent `> 0` | fixed |
| fixed base `= 0`, exponent cannot shrink, exponent `= 0` | shrink-only |
| fixed base `= 0`, exponent can shrink | grow-only |
| fixed base in `(−1, 0)`, exponent cannot shrink | shrink-only for even, grow-only for odd |
| fixed base in `(−1, 0)`, exponent can shrink | grow and shrink |
| fixed base `= −1` | shrink-only for even, grow-only for odd |
| fixed base `< −1`, exponent cannot grow | shrink-only for even, grow-only for odd |
| fixed base `< −1`, exponent can grow | grow and shrink |
| both operands variable, with `base > 1` and neither able to shrink | grow-only |
| every other both-variable case | grow and shrink |

This power table is the kernel's hand-written conservative metadata algorithm, not a theorem that the flags equal exact mathematical reachability. In particular, do not simplify it from intuition about parity. Invalidity and the separate “result is empty” provenance marker remain independent of these two direction bits.

The consuming comparison dispatches those directions per operator:

| Fired comparison | A legal fill could falsify it when… |
|---|---|
| `left > right` / `left >= right` | left can shrink **or** right can grow |
| `left < right` / `left <= right` | left can grow **or** right can shrink |
| `left == right` | either operand can move in either available direction |
| `left != right` | the currently smaller side can grow **or** the currently larger side can shrink |
| `DiffersWithToleranceRangeN(left, right)` | after independent scale-19 normalization, the currently smaller side can grow **or** the currently larger side can shrink toward the closed band |

The `!=` and tolerance arms are directional rather than “any operand is fillable.” For example, an empty unsigned number reads `0`; `0 != -1` fires **VALUE** because equality would require the unsigned empty side to shrink below zero, which it cannot do. The signed twin fires **OMISSION** because a signed empty can shrink. The same distinction applies outside a tolerance band: unsigned empty `0` versus `−2` at range 1 fires VALUE, while the same operand versus `+2` fires OMISSION because growing toward `+2` can close the gap. a12-dmkits' [`DirectionalPolarityDiffTest`](../../a12-rulekit/adapter/src/test/kotlin/io/github/mbackschat/a12/dm/adapter/laws/DirectionalPolarityDiffTest.kt) locks the sign-aware directional basis and `>=`/`<=` controls; its retained [`empty-polarity` corpus family](../../a12-rulekit/corpus/cases/empty-polarity/) locks these exact `!=` witnesses and their literal-direction controls.

> **Non-normative implementation note.** Attach two booleans to every evaluated *numeric* operand — `canGrow`, `canShrink` — seeded at the leaves (empty unsigned number: `canGrow=true, canShrink=false`; empty signed: both true; a filled value: neither, unless it feeds an aggregate with a fillable tail) and propagated by the operator table above. Supply aggregate missingness from the recursive reopened-tree completeness predicate of §9, not from one flattened row count or a preselected global bit. Apply the explicit comparison-direction dispatch, including the dedicated normalized-side `!=` arm, and type OMISSION exactly when a legal move can falsify the currently true error condition. Dates use a simpler `notGiven` bit with a *symmetric* rule; strings/concats OR a `notGiven` bit; counts are grow-only. This is a second interpreter pass structurally parallel to truth — budget for it from the start; retrofitting polarity onto a truth-only evaluator is painful.

### 4.1 The same rule fires either type

Because the type is computed from data, **one rule legitimately fires OMISSION on one document and VALUE on another**:

- `NotExactlyOneFieldFilled(A, B)` fired at **0 filled** is OMISSION (filling one reaches exactly one) but at **2 filled** is VALUE (no fill gets back to one).
- `FirstFilledValue` types OMISSION when the complete scan exhausts with missing declared capacity, an instantiated empty cell *precedes* the first filled one, a reached star contributes no concrete cell before a later selected value, or an encountered operand slot carries `Having` (empties *after* the first value are irrelevant). The combiner retains omitted-tail state separately for its all-exhausted identity, but the runtime's field-list wrapper presents a reached no-row star as a not-given prefix before moving to the next authored operand; this applies at flat and nested reopened levels. The operator is prefix-sensitive generally: operands after the first filled one are never read, so a formal error or filter there is invisible; a formal error before it suppresses the rule.
- A **clean no-match from a reached semantic-index operand** contributes a not-given prefix to `FirstFilledValue`: if a later operand supplies the first filled value and the comparison fires, it types **OMISSION**. A filled prefix that terminates before the indexed operand acquires no omission from that unreached no-match ([checkpoint](../docs/sources/inbound-group-operand-batches.md#src-selected-typed-comparisons)).
- `CurrentRepetition` is a structural row index no fill can change — a fired comparison against it is **always VALUE**.
- A **starred operand** in a computation's operand set normally types that computation's implicit self-validation message **OMISSION**, and the reason is the grow-only rule above rather than anything about the star: the operand's extent can gain a row. **Declared capacity is the boundary.** With the starred group holding five of five declared rows and every cell filled, `NumberOfFilledGroups(Rows*)`, a mixed `NumberOfFilledGroups(Fixed, Rows*)`, and `Sum(Rows*/Value)` all type VALUE; at four of five, all three type OMISSION while a wildcard-free `NumberOfFilledGroups(Fixed, Other)` in the same run stays VALUE. One row of remaining capacity is the whole difference ([checkpoint](../docs/sources/group-and-iteration-probes.md#src-starred-operand-message-polarity)).
- **Headroom is read per operator against its own quantity, not once per operand.** At capacity with every row *empty*, one document splits them: the two counts type VALUE, because a count grows only by rows and no row can be added, while `Sum(Rows*/Value)` over the same starred group types OMISSION, because a row's empty cell can still be filled. So an implementation tracks growth per evaluated quantity, and "a starred operand can never reach all-filled" is false — exhausting capacity reaches it. A count over a fixed group below a star grows by content in any instance: with both declared batches instantiated and every `Seal` empty, `NumberOfFilledGroups(Batches*/Seal)` types OMISSION where `NumberOfFilledGroups(Batches*)` over the same rows types VALUE ([checkpoint](../docs/sources/group-list-and-capacity-probes.md#src-ancestor-starred-group-count-computation)).
- **A group count's declared extent multiplies the capacities of every reopened repetition level.** Bound ancestors contribute no factor, and repeatable descendants below the counted group do not enlarge it. Thus `NumberOfFilledGroups(Rows*/Items*)` over two capacity-two levels has extent four: two instantiated Items rows leave growth available even when they exhaust one parent's Items capacity. The same extent determines count polarity in full/partial validation and implicit computation validation; a fixed group below those stars uses the same product but counts content rather than structural terminal rows ([checkpoint](../docs/sources/group-count-topology.md#src-nested-group-count)).
- **The message's `referenced` channel carries each operand's own reach**, together with the computed target. A **group** operand names the fields anywhere in its subtree, at any depth and however many there are — a shell whose only field lies two levels below it names that field, and a group owning two fields names both. A **field** operand names that field alone: a `Sum` over one flattened field in the same message set does not name its sibling. So the extent follows the authored operand's reach and must not be widened from a field operand to its enclosing group. For the group-count operator both operand forms use the one group extent, leaving a fixed operand and a starred one indistinguishable in the field set; what the Kernel distinguishes there is the coordinates.
- **It is an authored-shape inventory, not a reached-cell trace, and the set is invariant under filling.** For a starred operand the set is byte-identical between a document with no instantiated row and one with four rows whose every cell is filled. A read-derived inventory is empty in the first and enumerates every reached cell in the second, so this is not merely consistent with an authored-shape account — it refutes a partially-read one. A group the evaluator cannot read is named all the same. One message carries two pointer spellings: a repetition-free address bare, and one crossing a repeatable group carrying its axes, where the starred axis is **unbound** rather than a row index — it stays at the same unbound value whether zero or four rows exist. These channels remain sets, so no order is specified ([checkpoint](../docs/sources/group-and-iteration-probes.md#src-nested-descendant-group-count-runtime)).
- **On this carrier `fillToFix` is all of `referenced` or none of it**, never a proper subset. It tracks the type exactly — empty on every VALUE message, the whole referenced set on every OMISSION one — so it is one decision spelled as a list rather than a per-cell analysis, and the computed target's own pointer is included. Do not read a listed pointer as a claim that this cell is empty: in the measured witness a target types OMISSION on row headroom alone while every referenced cell is filled, and each of those filled pointers is listed. This sharpens the general non-minimality note in [§2](01-data-model.md) into an exact projection for the computation's implicit self-validation message; it is not established for authored rule messages, whose operator-specific projections stay as recorded ([checkpoint](../docs/sources/group-and-iteration-probes.md#src-starred-operand-message-polarity)).
- **The type is the ordinary directional rule applied to the computed-versus-stored inequality, with the stored side fixed.** Headroom is necessary but not sufficient: OMISSION also requires that growth move the quantity *toward* the stored value. A grow-only count below capacity with every cell filled types VALUE when its computed `3` already exceeds a seed of `1`, and OMISSION on the same document at a seed of `9` — one variable, and the coarse "can it move at all" reading predicts OMISSION on both. The stored side's fixity is the at-capacity documents' contribution, since a stored side able to move would have typed them OMISSION. Each conjunct therefore has its own separating document ([checkpoint](../docs/sources/group-and-iteration-probes.md#src-starred-operand-message-polarity)).
- **No message where an operand group holds only malformed content.** Such a group leaves the computation with its count written and **no** implicit message, measured for a fixed group, direct and nested, and for a fixed group below a star. The whole target loses it, a starred row count in the same operand list included, while a separate target counting starred rows in the same document keeps its own. Beside an admitted value the same malformed cell keeps the message, so a formal error alone does not suppress it. For a fixed group below a star one such instance suffices, even beside a filled one, while one in an over-limit row suppresses nothing. The implicit message is a generated validation rule ([§6](09-computations.md#6-the-implicit-validation-rule-precisely)), and validation leaves a malformed-only fixed group undecided, which accounts for the absence; for the below-star form this project infers that validation premise rather than observing it. Confidence limit: one formal cause, unparseable Number text ([checkpoint](../docs/sources/group-list-and-capacity-probes.md#src-ancestor-starred-group-count-computation)).

## 5. Full vs. partial validation

`validateFull` checks the whole document. `validatePart(document, relevantSet)` checks a relevant subset and guarantees only **one direction**: it never reports an error fixable only *outside* the subset. It does **not** guarantee a complete check of the relevant fields themselves — some checks may be skipped for performance (an implementation detail that may change). A document passing a partial validation can still fail a full one. A field referenced by a rule but living on another screen is excluded from the relevant set **unless it has the `Global` flag**.

Verified mechanics:

- **Filtered rules are skipped first in kernel 30.8.1.** If the elaborated rule contains any `Having` filter, partial-with-3VL validation returns from that rule before error-field relevance, iteration, correlation, or condition evaluation. Full validation still evaluates the rule normally. This is a versioned kernel profile, not a guarantee that later kernels expose the same public skip set.
- **Rule-gating by the error field, compared at the levels the rule's iteration BOUND.** A rule (including the auto-generated formal/mandatory/unique checks) runs only when its error field is in the relevant set **at the repetition levels the rule's iteration actually bound**. Which levels those are follows from the rule's ITERATION as [§9](07-repetition-and-iteration.md) already defines it: reference-driven, not decided by where the rule is declared. The relevant identifiers reaching the error path are first compressed into one selector, every coordinate on which they differ becoming a wildcard, and the bound levels must match that selector. One identifier therefore gates a per-row rule to its own row, two parts of one line admit every part of that line, and two parts of different lines admit every part of every line, so a condition that holds without the error field's own cell fires on rows the call never names ([ordinary partial dispatch checkpoint](../docs/sources/group-count-topology.md#src-k22-ordinary-partial-dispatch)). A formally invalid relevant cell still takes part in that merge while the rule reads it as unknown, and the generated mandatory check reads only its own cell, so a row reached only through the merge stays silent there: lines 1 and 3 relevant around an empty required cell in line 2 report nothing, and line 2 relevant reports it ([checkpoint](../docs/sources/group-count-topology.md#src-k22-partial-dispatch-merge), [inbound](../docs/sources/inbound-handbacks.md#src-inbound-2026-10-25)). Levels below them were never chosen by any iteration: the kernel defaults them to the first repetition for the message pointer and does not require the relevant set to name that repetition, so a rule that reports into a repeatable group it does not iterate runs when **any** of that group's rows is relevant. The error path itself must still be relevant somewhere under the bound levels; a relevant sibling field is not enough. Parallel rules compress the same way and add the joined-slot conditions described below; their unmatched error side still carries the `-5` sentinel ([§9](07-repetition-and-iteration.md#2-parallel-iteration--joining-two-repeatable-groups-by-key)). Of the rules that run, a **non-relevant referenced instance is three-valued UNKNOWN**, and Kleene logic decides: `true Or Unknown` still fires (no value could prevent it), while `true And Unknown` is suppressed.
- **A field whose value leads to a formal error is not relevant, in either kind of validation.** The kernel's own account defines the relevant list as the rule-referenced fields that are on the validated screen (or `Global`) **and** do not carry a formal error, with the error clause present for full validation too. The screen-membership half is measured: three documents through `validateFull` and through `validatePart` with the whole group relevant agree cell for cell, the malformed one included.

  **An erroneous member contributes neither TRUE nor FALSE to a quantifier over its list, so a quantifier is decided exactly when the members whose state is *known* already settle it.** A known TRUE settles the existential, a known FALSE settles the negation, and only a verdict that would need the erroneous member's own state stays undecided. Over a three-member list with one erroneous member and two filled, `AtLeastOneFieldFilled` **fires** while `AllFieldsFilled`, `NotAllFieldsFilled`, `NumberOfFilledFields == 3`, and `== 2` all stay silent; over the same list with the other two **empty**, `NotAllFieldsFilled` fires instead and the existential goes silent. That second document is what makes the rule symmetric rather than making the existential an exception. Measured on two converters, a malformed Number and an out-of-calendar Date, against a three-valid and a one-empty control, with a liveness rule reading a field outside every quantified list firing on every document, so a silence is scoped to the lists containing the error rather than to a document the Kernel gave up on ([checkpoint](../docs/sources/inbound-group-operand-batches.md#src-erroneous-member-quantifier-undecidable)).

  **What this refutes is the operand being dropped from a quantifier's operand list**, and an earlier reading of this clause said so. Dropping predicts the universal firing over the two clean members; counting the member filled predicts `== 3`; counting it empty predicts the negative quantifier and `== 2`. None of the three occurs, so the erroneous member is in the list and settles nothing — the ordinary three-valued reading, not a list-membership one.

  Whether the Kernel's internal relevant list also excludes the field is a separate question this observation cannot reach; only the operand-list reading of it is refuted.
- **The filled-group count and the group-presence predicates diverge under partial coverage, and the divergence is measured rather than derived from the family.** The predicates are ordinary three-valued quantifiers over the asymmetric per-group presence below: one covered admitted cell proves a group FILLED however its uncovered siblings read, while proving a group UNFILLED needs that group fully relevant, so a member nobody covers is UNDECIDED rather than empty. `GroupFilled` and `AtLeastOneGroupFilled` are therefore decided by one covered filled member, and `NotAllGroupsFilled` by one **settled unfilled** member — it stays silent when the only uncovered fields are the ones that would settle it, and fires as soon as some member is fully covered and empty even though another operand field is still outside the set. `NumberOfFilledGroups` over the same coverage is the one operator that genuinely needs **total** coverage: every field of every operand group must be in the relevant set, or the count is undecided. That requirement is operand-local: a field the condition does not reference may stay outside the set with no effect, while one uncovered field of any operand group silences the count. An empty relevant set produces no message at all, not even a rule whose error field is otherwise gated in ([checkpoint](../docs/sources/group-list-and-capacity-probes.md#src-partial-coverage-group-operands)).
- **Full group relevance combines descendant coverage across declared repetitions.** A relevant ancestor group covers its subtree. Otherwise every descendant must be covered: all concrete positions of a finite repeatable child can jointly supply that coverage, whether selected as groups or through their complete descendant fields. The same requirement applies at each deeper repeated level, even when the document holds fewer rows. Duplicate coordinates, over-limit replacements, missing fields and incomplete nested combinations do not complete coverage. This full-relevance product is shared by negative group predicates and the group count’s first-instance gate; their separate presence and extent policies still apply ([checkpoint](../docs/sources/group-count-topology.md#src-group-relevance-union)).
- **Partial validation gates the formal-error channel by the same coverage.** A malformed cell reports its own formal finding under `validatePart` only when that cell is in the relevant set, while `validateFull` reports it either way. A consumer must therefore not read a partial run's formal findings as the document's formal state.
- **Global fields are auto-added** to the relevant set (by the runtime layer at the `validatePart` boundary, wildcarded at all repetitions) — so a rule whose error field is global runs even when the caller's set omits it.
- **Masking applies to references, and a structural repetition coordinate is not one.** `CurrentRepetition(G)` answers from the row the rule is iterating rather than from a cell, so no relevant set can drive it to UNKNOWN. Under a coverage naming only its error field, a rule reading that coordinate answers exactly as it does under full validation — not fired on the first row, fired on the second — while a rule identical in every other respect that reads a *field* in the same operand position goes UNKNOWN on both rows. The twin is what separates this from a partial validation that ignores coverage. Unmaskable is not unconditional: the error-field gate above is checked per row and runs first, so a coverage naming neither the error field nor anything conferring relevance on it reports nothing at all, even though the coordinate itself needed no coverage ([checkpoint](../docs/sources/group-and-iteration-probes.md#src-repetition-operand-partial-relevance)). Measured at one repetition level; multi-level coverage of the coordinate is untested.
- **The relevant-set wildcard is explicit `IIdentifier.ALL_INDICES` (`0`).** It means every repetition at that level and is the wildcarded state used by global-field augmentation and the starred-aggregate rules below. An omitted index or `1` is the concrete first repetition, never all rows; conflating those spellings silently narrows partial validation to row 1.
- **A starred aggregate's relevance is per operator, and the operator list is measured rather than inferred from the family.** For an operand field, partial relevance first normalizes the caller's set: a relevant group contributes a pattern for every descendant field by retaining the group's coordinates and wildcarding the deeper coordinates; within one field, a broader wildcard pattern removes every narrower pattern it encompasses; patterns certainly outside the current iteration subtree are then ignored. The all-rows aggregates (`Sum`, `MaxValue`, `MinValue`, `NumberOfDifferentValues`) evaluate only when that retained set is nonempty and **every retained pattern wildcards every repeatable level the operand reopens**, from the first starred level downward per the star-binding anchor of [§9](07-repetition-and-iteration.md#4-where-a-star-binds--the-anchor-rules-), asked separately for each row of the rule's iteration scope. One wildcard does not override concrete siblings that survive normalization; a broader wildcard that encompasses them removes them before the gate. Enumerating every concrete row still leaves these aggregates UNKNOWN. A starred **group** operand is asked field by field: it evaluates only when every field the group contains passes its starred field's gate at that field's own path, so field identifiers alone establish the extent and an identifier on a descendant group covers the fields below it, while the group path itself is never the target ([inbound](../docs/sources/inbound-handbacks.md#inbound-2026-09-24b-kf464-partial-group-extent)). That is measured on `Sum`, `MaxValue` and numeric `NumberOfValueInFields`; `MinValue`, `NumberOfDifferentValues` and `SumOfProducts` over a group operand, a multi-star group operand and a starred group containing a nested repeatable group are not. `SumOfProducts` reaches neither that combiner nor its survey and carries a weaker completeness gate: it evaluates when each operand's declared starred extent is covered as a complete cross-product, taken over the union of the relevant entities addressing that row, and is UNKNOWN under an enumeration covering only present rows when declared slots remain. Independently keyed parents and missing selections follow the [product extent account](07-repetition-and-iteration.md#4-where-a-star-binds--the-anchor-rules-). `FirstFilledValue` is order-aware (UNKNOWN only when a non-relevant cell precedes the first filled one) and likewise evaluates under concrete rows. Do not extend one operator's gate to another by syntactic resemblance.
- **Unfiltered field-fill quantifiers ask relevance at declared slots, including missing ones.** A covered missing slot is empty; an uncovered slot is neither a filled nor an empty witness. Consequently `AtLeastOneFieldFilled` and `MoreThanOneFieldFilled` can fire from covered values despite uncovered siblings, `NotAllFieldsFilled` can fire from a covered missing slot, and `AllFieldsFilled` and `NoFieldFilled` need every slot that could defeat their conclusion decided. `NotExactlyOneFieldFilled` and `FieldsNotCollectivelyFilled` retain the combinations defined in [spec/02 §A.4](02-logic-and-formal-errors.md). This applies to starred fields and field-by-field expansion of starred or keyed groups. When the key selects no parent, the target slots are empty only under identifiers wildcarding that parent; the lower declared slots may be covered by a union of concrete identifiers. Enumerating physical parents does not bind an absent selection. Keep this per-slot account separate from the wildcard-only aggregate and complete-product gates above. `FirstFilledValue` likewise checks the relevance of each reached missing slot before a later value can decide the prefix ([reviewed KF527 handback](../docs/sources/inbound-handbacks.md#inbound-2026-10-09-extensions)).
- **Ordinary partial value-list extent is coverage of declared slots, independently of concrete value availability.** For finite starred field and group operands, the union of relevant identifiers may cover every declared slot using concrete coordinates; one wildcard covering the whole extent also suffices. Covering only instantiated rows is insufficient when declared slots remain uncovered, including an absent trailing row. Relevant concrete cells remain available witnesses even under incomplete extent. The resulting extent uncertainty follows the quantifier's side-specific rule: `AtLeastOne` ignores it on either side, `No` is suppressed on either side, and `NotAll` ignores it on the fields side but is suppressed on the values side. Formal unavailability retains the separate quantifier policy. [Capacity-two/three controls](../docs/sources/group-list-and-capacity-probes.md#src-partial-list-declared-extent) distinguish this rule from wildcard-only coverage and from physical-row-only coverage. The runtime's additional all-USB relevance gate concerns its separate USB iteration dimension; it must not be generalized into a wildcard requirement at every ordinary repeated group.
- **Selected value lists retain the selected parent while testing lower declared slots.** A matched key binds that parent's concrete coordinate; complete concrete coverage of the lower declared capacity suffices for the list quantifiers. Coverage under another parent does not. With no selected parent, coverage must wildcard the indexed level, while lower declared slots may still be covered concretely. Relevant keys, index cells and available target witnesses remain separate requirements. This is measured for Number and String lower field/starred-group operands under one String index; count and aggregate gates remain distinct ([checkpoint](../docs/sources/group-list-and-capacity-probes.md#src-selected-list-declared-extent)).
- **The three direct starred count loops select their extent independently.** `NumberOfFilledFields(F*)` has the all-rows reduced-universal outcome pattern and numeric `NumberOfValueInFields(v In F*)` the existential value-list one. `NumberOfFilledGroups` is decided on the counted group's own instances rather than on its fields, in four steps, and is UNKNOWN when any step fails for any operand, a list mixing a starred and a fixed operand included, each way round ([inbound](../docs/sources/inbound-handbacks.md#inbound-2026-09-24b-kf464-partial-group-count), [mixed list](../docs/sources/inbound-handbacks.md#inbound-2026-09-24d-mixed-group-count)):
  1. **The group's own identifiers settle the extent.** They are the relevant identifiers at or above the counted group together with every relevant descendant identifier cut back to the group's depth, restricted to the current iteration subtree and reduced by wildcard dominance as a field's are. The set must be nonempty and every member must wildcard every repeatable level the operand reopens. A field named concretely in every declared row therefore decides the group count where `NumberOfFilledFields` over the same group, which asks that field itself, stays UNKNOWN; a concrete identifier left at a reopened level makes the count UNKNOWN even when every instance is wholly covered.
  2. **The first declared instance must be fully relevant and not erroneous.** Covering only the second row leaves the count UNKNOWN although both rows are filled, and a covered malformed value makes the first instance erroneous where the same value in a later instance does not. A fixed group is its own first instance. A descendant rejected for exceeding declared repetition capacity reports a structural finding but never enters the invalid-field cache, so it does not make an ancestor group erroneous; an in-capacity malformed descendant does ([checkpoint](../docs/sources/group-count-topology.md#src-bound-nested-count)).
  3. **Every declared instance the document lacks must be fully relevant.** The walk visits every declared coordinate up to capacity, not only the held rows, so naming a field in the two held rows of four leaves the count UNKNOWN.
  4. **Every held instance must have decided presence.** Relevant admitted content counts, including content beside an independent error in a later instance. Fully relevant clean absence contributes zero. A later malformed-only instance or partly covered instance without visible admitted content makes the whole count UNKNOWN, rather than contributing zero. A repeatable instance's instantiated row is content, so an empty row counts. The first-instance gate above remains stricter.

  Two reopened levels, nested repeatable descendants and one bound ancestor above them are [calibrated](../docs/sources/group-count-topology.md#src-bound-nested-count). Excluding a malformed field from first-instance coverage leaves the same silence as healthy input under that incomplete coverage; it does not isolate error filtering from relevance. Whether a held instance can go unreached once the extent passes remains unmeasured ([`SPEC-2026-09-24-04`](https://github.com/mbackschat/a12-kernel-lean/blob/e2bc04e5cefbcce7b380a1c8f0687b5c2cd4a730/docs/A12-DMKITS-SPEC-SYNC-LEDGER.md#spec-2026-09-24-04)). The exact positive-document outcomes over a two-row `Items*` (50) of a `Tag` and a `Qty`, whose `Tag` no selection names, are:

| relevance selection | `NumberOfFilledFields` | `NumberOfFilledGroups` | numeric `NumberOfValueInFields` |
|---|---:|---:|---:|
| field wildcard alone | fires | silent | fires |
| field wildcard plus both concrete group rows | silent | silent | fires |
| field wildcard plus a concrete identifier for that field | fires | silent | fires |
| concrete field identifier plus wildcard group | fires | fires | fires |
| all-semantic field wildcard plus concrete group rows | fires | silent | fires |
| field wildcard plus physical-root concrete group rows | silent | silent | fires |
| both concrete group rows only | silent | silent | silent |
| row 1 only | silent | silent | silent |
| row 2 only | silent | silent | silent |

  Under wildcard relevance, two nonmatching filled quantities fire only the filled-field and filled-group rules, two instantiated empty rows fire only the filled-group rule, and no rows fire none. These controls keep count content separate from extent relevance. The String/Enumeration and admitted Boolean/Confirm `NumberOfValueInFields` overloads share the same Kernel loop by source inspection. Boolean constants are resolved to the admitted declaration’s label before entering the token overload; their static kind and label gates remain separate. String and Boolean value counts answer a column wildcard beside concrete group rows as the Number count does, and concrete group rows covering the whole declared capacity make a String or Boolean column relevant without its wildcard, as they do for the value-list quantifiers ([checkpoint](../docs/sources/group-count-topology.md#src-k22-runtime-r11), `CV2`, `CB7`); the Number count is not separately measured under that coverage ([source route](../docs/sources/group-and-iteration-probes.md#src-boolean-value-count-partial-loop)). The root coordinate is compared literally, `0` encompassing every row and `1` naming the one root: an all-semantic field wildcard fires the filled-field, value-count and `Sum` rules beside physical-root group rows `[1,1]` and `[1,2]` as it does beside `[0,1]` and `[0,2]`, a concrete field beside the physical-root group wildcard `[1,0]` fires all five rules as it does beside `[0,0]`, and a field wildcard rooted at `1` stays silent on the filled-field, filled-group and `Sum` rules beside group rows of either root form ([checkpoint](../docs/sources/group-count-topology.md#src-k22-runtime-r7), `rA`).
- **Group presence has asymmetric relevance.** Any relevant descendant gives its ancestors partial relevance, and an admitted filled descendant in that slice can prove `GroupFilled`. `GroupNotFilled` requires full relevance of the group plus no admitted content and no error; one relevant empty descendant cannot prove absence. Explicit relevance of the group or an ancestor, or complete descendant-field coverage across deeper repeatable axes, supplies full relevance. For this absence-coverage judgment, fixed descendant groups require coordinate one or wildcard, while the terminal field's coordinate is ignored and its identity retained. Thus coordinate two on a fixed descendant group prevents full coverage, but coordinate two on the terminal field does not. Concrete-cell relevance and aggregate/list extent retain their separate coordinate gates ([fixed-suffix checkpoint](../docs/sources/group-count-topology.md#src-group-fixed-suffix-coverage)).
- **Starred group predicates retain missing positions under partial validation.** `AtLeastOneGroupFilled` and `NoGroupFilled` combine fixed groups and starred group positions through the same three-way presence classification. Reopened declared coordinates remain observable even when no row exists: an uncovered missing position is unavailable, not empty. A relevant descendant makes an instantiated repeatable terminal visible as structural content, even when that descendant is empty. One filled position decides the positive predicate despite unavailable peers; the negative predicate needs every position empty and available. The [mixed-list matrix](../docs/sources/group-count-topology.md#src-mixed-group-predicates) measures single-level fixed, repeated and independent starred operands, both orders, coverage and capacity controls.
- **A semantic index binds the selected parent without consuming lower group stars.** `AtLeastOneGroupFilled` and `NoGroupFilled` apply the same declared-position presence judgment below that parent: terminal rows supply structural content, while fixed below-star groups need admitted descendant content. A missing selected parent proves no negative predicate from index coverage alone. The indexed level must be wildcarded and the lower declared positions covered; complete concrete lower-slot coverage suffices for finite capacities, but concrete parent coordinates cannot replace that wildcard. Unknown selection stays unavailable ([checkpoint](../docs/sources/group-count-topology.md#src-keyed-star-predicates)).
- **A relevant instance is always evaluated**: partial validation **overrides the content gate** of [§2](03-empty-and-required.md), firing empty-as-`0` even on an empty or **phantom** relevant row. The rows a partial call walks are the declared-capacity domain full validation walks, with the content gate overridden: `[Qty] < 100` declared in a three-row `Items` fires at all three declared rows of an empty document, where full validation fires none ([checkpoint](../docs/sources/group-count-topology.md#src-k22-partial-channel)). Uniqueness checks need the duplicate **partner** relevant too because duplicate relations are built from relevant fields only, and so does every **ordinary rule reading that cell**, since a `uniqueIndex`-compromised cell is UNKNOWN for any rule referencing it. Omit the partner from the relevant set and the cell is clean, so the rule runs. For `RepetitionNotUnique`, every component cell of every composite key must be relevant before its row can participate; if any component is nonrelevant, that row is excluded, while an independently decisive relevant branch in the surrounding `And`/`Or` tree can still fire ([§9](07-repetition-and-iteration.md#6-repetitionnotunique-precisely-)).
- **A shift amount takes the gate the same count or aggregate takes as a comparison operand.** `AddDays(Low, Sum(Rows*/N))` evaluates in a partial call only where `Rows/N` or its group is wildcard-relevant; one concrete row, or concrete group rows beside the field wildcard, leaves the shifted date unavailable, as the same `Sum` is as a comparison operand, and `MaxValue`, `MinValue`, `NumberOfDifferentValues` and `NumberOfFilledFields` amounts take the same all-rows gate ([checkpoint](../docs/sources/group-count-topology.md#src-k22-runtime-r7), `rC`; [checkpoint](../docs/sources/group-count-topology.md#src-k22-runtime-r9)). A Number, String or Boolean value count takes the value-count extent above, so concrete group rows beside the column wildcard still evaluate it, and `NumberOfFilledGroups(Rows*)` takes its four-step instance walk, so one column's wildcard or a malformed first instance leaves it unavailable while every member column's wildcard or the group wildcard evaluates it. On every measured relevance set each amount answers as its comparison twin ([checkpoint](../docs/sources/group-count-topology.md#src-k22-runtime-r11)). A filtered amount skips its rule in every partial call, as every filtered rule does. A keyed difference operand such as `DifferenceInDays(Rows/D For Key, Low)` needs the index column and the selected row's cell relevant ([checkpoint](../docs/sources/group-count-topology.md#src-k22-runtime-r7), `rC`).
- **Parallel iteration is keyed by RELEVANT index cells.** The outer join of [§9](07-repetition-and-iteration.md#2-parallel-iteration--joining-two-repeatable-groups-by-key) takes its keys from each group's index field, and under partial validation that cache is built from the relevant cells only, the same restriction uniqueness relies on. A relevant set naming a joined group's payload field but **not** its index field therefore produces no keys, no iterations, and no messages, however relevant everything else is; a relevant *group* supplies its own index cell and so keeps its iteration. Leaving one group's index cell out while the other side still supplies the key does not remove the iteration: that group becomes the unmatched "not specified" side and the message reports at the `-5` sentinel.
- **Parallel dispatch compresses error-field relevance before reading leaves.** Ancestor selections project onto the error field; differing coordinates across its selected identifiers become wildcards in the dispatch envelope. When the parallel rule also has ordinary outer iteration, a concrete coordinate at the parallel key slot cannot satisfy that slot's iteration bound and suppresses the rule. Two distinct concrete row selectors therefore may permit dispatch where either alone suppresses it. Without ordinary outer iteration, concrete joined-row selectors still permit dispatch. **A level the error field reopens below its joined group bounds dispatch as an ordinary outer level does:** with the error field `Lines/Parts/Count` below the joined `Lines`, a concrete line selector suppresses the rule, with or without concrete parts and also for two parts of one line, while parts of two different lines compress to a wildcard line and dispatch ([nested-join partial checkpoint](../docs/sources/model-structure-and-declaration-probes.md#src-k22-nested-join-partial)). The compressed coordinate at each level below the joined group still narrows the rows the rule visits: part 2 of line 1 and part 2 of line 3 run part 2 of every line and no first part, even for a condition that would fire there without the error field's cell, and leaf relevance then limits the firing parts to the relevant ones ([checkpoint](../docs/sources/group-count-topology.md#src-k22-partial-dispatch-merge), [inbound](../docs/sources/inbound-handbacks.md#src-inbound-2026-10-25)). The original, uncompressed relevant set governs every condition read; neither the rule's declaring group nor its projected message row replaces it. [Captured scope/root/union controls](../docs/sources/model-structure-and-declaration-probes.md#src-partial-parallel) settle these distinctions.
- **Unmatched parallel availability requires wildcard coverage.** A missing side is definite empty only when its index column is formally available and both its index field and the referenced field cover the unknown joined repetition. Selecting every currently instantiated index row separately does not cover an unknown repetition. Otherwise the read is UNKNOWN, even though a far-side positive branch may still emit at the unknown error coordinate. For a missing group, an ancestor selection or complete wildcard descendant-field coverage can establish full group relevance; an explicit group selector is not required.
- **One-sided parallel frames retain the declared iteration domain.** The ordinary frame uses the same small declared-product versus occupied-prefix traversal as full ordinary validation, with the parallel key slot contributing no numeric bound. Far-side keys can drive evaluations in uninstantiated frame slots. Full and partial calls share that domain; partial dispatch and leaf relevance then apply independently. The [3/6-frame controls](../docs/sources/model-structure-and-declaration-probes.md#src-partial-parallel) distinguish it from iterating physical frame rows only.

- **A keyed read is judged at the coordinate its key resolves to.** A key that matches a row reads that row, so the read is decided exactly when the target is covered at that row, a concrete row identifier included, and the key column alone decides nothing; `GroupFilled` of the keyed group is the exception, decided from the key column because the row is filled through its key. A key that matches no row is decided only when the keyed group is covered by a wildcard, the group itself or every field of it, and stays UNKNOWN under the key column, under every existing row listed concretely, and under both: covering the rows that exist does not decide a no-match. A key read from a field needs the key fields covered beside the group. The order-aware `FirstFilledValue` account above holds over separately named operands, over a group operand's fields, and over a category read alike: an empty uncovered first operand leaves it UNKNOWN although a later filled one is covered, while a covered filled first operand decides it whatever follows, measured on separately named operands and over a keyed group operand's fields, where the key column must be covered beside that first filled cell. Measured with every rule firing under full validation, keyed by a text literal, on a group whose index field is a Number and on one whose index field is a String, which decide alike ([inbound](../docs/sources/inbound-handbacks.md#inbound-2026-09-24b-keyed-partial-read), [inbound](../docs/sources/inbound-handbacks.md#inbound-2026-09-25-keyed-group-walk)).
- **An evaluation-empty index field with a declared default has phase-specific staging.** The default is the S-value stored token of an ordinary closed Enumeration index. One instance is eligible only when the index field is not explicitly mandatory, its repeatable group has exactly one physically instantiated row under the current parent, and that row's index is clean-empty—either physically absent or physically present-empty—rather than carrying an admitted explicit value. Full validation injects the stored S-value into its transient evaluation cache before index mandatory/uniqueness and authored-rule evaluation; it does not mutate the immutable document. Partial validation does not inject it: the same eligible empty index cell is made unavailable for that call without emitting `mandatoryField` or `uniqueIndex`, so dependent conditions see UNKNOWN and cannot create an error that full validation would not report. Multiple sibling rows, an explicitly mandatory index, an admitted explicit value, or a non-Enumeration index receives no default; a formally invalid explicit value remains unavailable and never exposes the S-value to authored evaluation. This silent suppression is distinct from a generated finding and does not instantiate a phantom row.

> **Non-normative implementation note.** Model kernel 30.8.1 partial validation as an ordered three-stage contract: (1) skip an elaborated rule containing any `Having` filter; (2) otherwise emit/evaluate the rule only if its error field belongs to the relevant set after global augmentation, compared at the levels the rule's iteration bound and with deeper levels treated as wildcards; (3) during that evaluation, read an out-of-set or call-locally unavailable reference as `notCheckRelevant`-style **UNKNOWN** and let Kleene logic decide. Two stage-(2) mistakes are easy and silent: testing one concretely resolved error pointer disables every rule reporting into a repeatable group it does not iterate, while taking bound levels from the rule's declared group instead of its actual iteration over-fires rules whose references iterate deeper than their declaration. Derive the bound levels from the same iteration decision §9 specifies. Derive group relevance separately as `NONE`/`PARTIAL`/`FULL`; do not infer definite absence from one relevant empty child. Normalize relevance for each operand field before asking the starred-extent question: expand relevant groups to descendant-field patterns, remove every pattern encompassed by a broader wildcard pattern, and then filter patterns certainly outside the current iteration subtree. The **four combiner aggregates** are known only when the remaining set is nonempty and **every** remaining pattern wildcards every level the operand reopens for the iteration row being evaluated. The **starred value-list extent** is known as soon as **one** covering pattern does; do not share one predicate between the two, because a single shared predicate is a measured defect in both directions. The local direct-count account reuses those predicates by operator and operand path: filled fields use the reduced-universal field path, filled groups use the reduced-universal group path to reproduce the fifth observed pattern, and value count uses the existential field path. This is an executable account of the outcomes, not a claim that the Kernel implements those predicates internally. An implementation that answers once per star path rather than per iteration row, or derives reopened levels from the path's deepest repeatable level rather than its first star, is wrong on measured cases for both. Keep `SumOfProducts`' union-based complete-cross-product gate and `FirstFilledValue`'s ordered prefix gate separate. A phantom relevant row is still evaluated and may fire through empty-as-zero, while the partial index-default path produces unavailability rather than a physical/defaulted cell or generated message. Keep relevance as wildcardable cell and group patterns rather than a flat cell list.
