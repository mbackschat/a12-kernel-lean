# 02 — Logic, truth values, and the "unknown" state (§1 + §3)

This is the core of the evaluation model, and the place a reimplementation most often goes wrong. Two ideas interlock:

- **§1** — the logic is two-valued (`And`/`Or` and the predicates are satisfied or not), there is *no* generic negation, and connectives need explicit parentheses.
- **§3** — but the *data* has a **third state** (present-but-formally-invalid = "unknown"), and when an operand reads it, the operand becomes UNKNOWN and ordinary Kleene `And`/`Or` decides how far that reaches.

The punchline: **only the data is three-valued; the logic stays two-valued and simply propagates the unknown.** Get the third state into your value domain from day one — a two-state `Option`-style value cannot express this language.

---

## Part A — §1 Truth values and logical evaluation

### A.1 Connectives are two-valued; parentheses are mandatory

`And` and `Or` are ordinary two-valued connectives. There is **no implicit precedence** between them — mixing them without brackets is a *parse* error (`MVK_BRACKET_MISSING`), not a default grouping:

```
( FieldFilled(A) And [A] <= 0 ) Or FieldNotFilled(B)      -- ok
FieldFilled(A) And [A] <= 0 Or FieldNotFilled(B)          -- rejected at parse time
```

The two bracketings mean different things, so the language refuses to choose. A reimplementation's parser should reject the un-bracketed mix rather than pick a precedence.

### A.2 There is no `Not`

The language has **no generic negation operator**. Every negative check is a *dedicated predicate* with its own evaluation logic. This is deliberate: it avoids ever having to define negation over the "unknown" state.

The consequence that bites: **positive/negative predicate pairs are not always logical complements.** You cannot assume `NotP ≡ ¬P`.

- `AllFieldsFilled(L)` vs `NotAllFieldsFilled(L)` — `NotAllFieldsFilled` holds when **at least one** field is unspecified, *including when none are filled*.
- `FieldsNotCollectivelyFilled(L)` holds when at least one **but not all** are filled — it *excludes* the all-empty case (so it is not the negation of "all filled").
- `NotExactlyOneFieldFilled(A,B,C)` holds for **0 filled and for 2+ filled**.

```
NotExactlyOneFieldFilled(A, B, C)   -- satisfied at 0 filled AND at 2+ filled
```

> **Non-normative implementation note.** Do **not** model predicates as `p` and `Not p`. Model each predicate as its own constructor in the AST with its own evaluation clause. There is no `K.not` combinator (§B below), and you will never need one — which is a feature, because Kleene negation would otherwise force awkward choices on the unknown value. Treat the non-complementary pairs as *distinct predicates that happen to read related*.

### A.3 Boolean is a three-state field *type* (distinct from three-valued logic)

Careful — two different "threes". The **logic** carries an unknown value (§B). Separately, the **Boolean field type** has three *states*: not-filled, `True`, `False`.

```
[Flag] == True       -- holds iff Flag is filled AND its value is True
[Flag] == False      -- holds iff Flag is filled AND its value is False
FieldFilled(Flag)    -- holds iff Flag has any value (True or False)
```

So `[Flag] == True` is **not** `FieldFilled(Flag)`, and an unset boolean satisfies *neither* `== True` nor `== False`. To say "not confirmed" for a Confirm field, write `[Confirm] != True`.

**Confirm vs Boolean** differ on the empty case: an unspecified **Confirm** reads `False` in a comparison; an unspecified **Boolean** leaves the comparison *not evaluated* (see [§2](03-empty-and-required.md)). At the storage tier, validation always compares the exact lowercase tokens `true` and `false` case-**sensitively**. A Boolean accepts only `true` or `false`; every other token is the formal error `feldJaNeinFalsch`. A Confirm accepts only exact `true` or unspecified; every other nonempty token, including `false`, is `feldJaFalsch`, consistent with "a checkbox whose only value is True". A model may declare an alternative `notInDCustomTrueValue` for either type and an alternative Boolean `notInDCustomFalseValue`, but validation must ignore them: those declarations are `@NotInD`, no A12-supported configuration channel carries them into the formal check, and honouring them would diverge from the Kernel. Do not import casing from a neighboring layer: a host may case-fold while ingesting a document, and comparison of an already-stored value may case-fold, but neither makes the storage formal check case-insensitive. Condition syntax is different again and uses capitalized `True`/`False` ([§12](12-concrete-syntax.md)).

### A.4 Fill quantifiers: group scopes and the two iteration ranges

The fill quantifiers (`AllFieldsFilled`, `NoFieldFilled`, `AtLeastOneFieldFilled`, `MoreThanOneFieldFilled`, `NotExactlyOneFieldFilled`, `NotAllFieldsFilled`, `FieldsNotCollectivelyFilled`) and the group quantifiers (`AllGroupsFilled`, `NoGroupFilled`, …) have subtle counting rules:

- **A group operand means "every field inside it, recursively."** A field-fill quantifier over a group expands to the quantifier over every descendant field, through nested subgroups; a repeatable group in the operand carries its `*` onto each descendant; a mixed group+field operand list is legal. Value aggregates (`Sum`, `MinValue`, `MaxValue`, `NumberOfDifferentValues`) over a starred group expand the same way.
- **A bare-group field-fill quantifier expands to a field-major, repetition-major stream.** Descendant fields occur in the recursive model declaration order of [§1](01-data-model.md#1-model--a-typed-tree), and one field is completed before the next. Its instantiated repetitions occur in repetition order; when the operator uses the declared range, that field's declared-but-uninstantiated repetitions follow immediately as empty cells before the next descendant field. An instantiated-range operator adds no declared omissions. Computation consumes this order through its operator-specific deciding scan. Validation's externally visible result is determined by the final classification counts described below; its physical read order and unread suffix are not established. A reached formally invalid cell contributes neither FILLED nor EMPTY in validation and poisons computation; a formally valid value remains FILLED even when it has no concrete scalar projection, so a valid `DAY_OPTIONAL` value with an omitted day remains FILLED.
- **Two iteration ranges over a starred scope.** `AllFieldsFilled` / `NotAllFieldsFilled` walk the **full declared range** — up to `repeatability`, an un-instantiated repetition reading *empty* — so `AllFieldsFilled(G*)` holds only when every *declared* row is filled. `AtLeastOneFieldFilled`, `NoFieldFilled`, `MoreThanOneFieldFilled`, `NotExactlyOneFieldFilled` clamp to the **instantiated** rows. `FieldsNotCollectivelyFilled` mixes them (≥1 filled over instantiated rows AND ≥1 empty over the declared range). On a non-repeatable scope the two ranges coincide.
- **Group-list quantifiers admit both field and group operands.** A field operand contributes its checked presence state; an ordinary group operand contributes the product state described below. Direct non-wildcard duplicates and strict group/descendant overlap are rejected. Direct duplicate checking skips wildcarded operands, so a repeated starred group remains a repeated authored occurrence. `AllGroupsFilled`, `NotAllGroupsFilled`, and `GroupsNotCollectivelyFilled` require at least two operands and reject root groups and wildcards. **Diagnostic identity is per carrier and follows gate order.** A single ordinary operand under those three draws `MVK_PARAMSIZE_INVALID2`; a sole root instead draws `MVK_ROOT_GROUP_REFERENCED`. `NoGroupFilled` and `AtLeastOneGroupFilled` admit a sole root but draw `MVK_ROOT_GROUP_WITH_OTHER_PARAMETERS` when that root is accompanied by a disjoint operand. `NumberOfFilledGroups` uses the same latter root class for a root beside a disjoint operand. In every carrier, a root beside its own descendant still draws the earlier overlap class `MVK_DUPLICATE_PARAM2`. Exact equality and strict ancestry remain separate: the same path twice draws `MVK_DUPLICATE_PARAM1`, and an ancestor/descendant pair draws `MVK_DUPLICATE_PARAM2`. Wildcards split in three: a starred operand where the quantifier forbids one draws `MVK_NO_WILDCARDS_G_ALLOWED`, scalar `GroupFilled(G*)` draws `MVK_NO_WILDCARDS_ALLOWED`, and an unstarred repeatable group whose level is not already bound by the error-field row draws `MVK_NO_WILDCARD`. An unknown group path draws `MVK_INVALID_ENTITY` in both the quantifier and count carriers. **The error field's locus selects whether an unstarred repeatable operand is fixed.** From outside the repeated group, both a sole operand and a pair draw `MVK_NO_WILDCARD`. With the error field inside that group, `AllGroupsFilled(repeatable, fixed)` and the singleton-admitting positive quantifiers are admitted; a sole `NumberOfFilledGroups(repeatable)` reaches its own multiplicity class `MVK_PARAMSIZE_INVALIDGN`, while the two-operand count reaches the separate iteration gate `MVK_NEG_CONDITION_IN_ITERATION`. The same inside behavior holds when the rule group itself is the repeated group. An unguarded sole `NoGroupFilled` at that level also draws `MVK_NEG_CONDITION_IN_ITERATION`, while its `GroupFilled`-guarded form is admitted. A fixed singleton has the same semantics as the corresponding scalar field/group presence predicate.

The error-locus matrix above is measured for one repeatable level. It does not establish nested repeatable binding.
- **The count-zero / count-≥1 group members admit a starred group beside plain operands.** In `NoGroupFilled(..., G*, ...)` and `AtLeastOneGroupFilled(..., G*, ...)`, each *instantiated* row of `G*` contributes one definitely-filled operand to the same tally as the plain fields and groups; zero rows contribute nothing, and a **created-but-empty row still counts as filled group content** ([§9](07-repetition-and-iteration.md)). Three rows answer `3` whether one cell is filled, every cell is `null`, or every row is written empty, so no cell is read ([checkpoint](../docs/SOURCES.md#src-starred-group-quantifier-capacity)). **Whether an over-limit row also contributes here is unreached, and an implementation may answer either way without diverging on any document yet built.** These two quantifiers turn on whether the group has *any* instantiated row, and every document either estate can construct that has an over-limit row also has an in-capacity one — a positional row array cannot express a hole, and the kernel's own instance factory materializes the prefix, so instantiating row three of a `max 2` group leaves `NumberOfFilledGroups` reading `2` ([checkpoint](../docs/SOURCES.md#src-starred-group-quantifier-capacity)). Do not read that silence as agreement with the numeric count: `NumberOfFilledGroups(G*)` is *measured* to stop at the declared capacity, on documents that separate it, while these two are not measured on that dimension at all. `AllGroupsFilled`, `NotAllGroupsFilled`, and `GroupsNotCollectivelyFilled` reject every starred group operand.
- **A non-repeatable terminal below starred ancestors is not a repeatable-row count.** For a path such as `Sections*/Items*/Details`, the stars select the concrete `Sections`/`Items` environments, then `Details` contributes its ordinary validation group product independently in each environment. Instantiating an ancestor row does not by itself fill `Details`; admitted scalar content or an instantiated repeatable descendant does, while malformed-only content is unavailable. This composition does not create a `NumberOfFilledGroups` star form for a non-repeatable terminal.
- **Non-starred group operands use the validation group state from [§9](07-repetition-and-iteration.md#5-groupfilled-and-the-other-repetition-rules), not a Boolean descendant scan.** A group is definitely filled when admitted content is observed in a relevant slice; it is definitely empty only when the complete group is relevant, contentless, and error-free. An erroneous or insufficiently relevant group belongs to neither bucket unless admitted content already establishes positive presence.
- **Validation and computation consume reached invalid cells differently.** In a validation fill tally, a present-but-invalid cell (§B) is *neither* filled nor empty. In computation, reaching that slot poisons the computation instance; an invalid slot after the full predicate's final decision is unread and therefore inert. Any invalid element reached by a value aggregate makes the aggregate non-evaluable.

For unfiltered validation, let `t` be the number of known filled instantiated cells, `e` the number of known empty instantiated cells, `u` the number of formally invalid or non-relevant instantiated cells, and `d` the number of declared-but-uninstantiated omissions. An invalid cell contributes to the range but to neither the filled nor empty bucket. **The range is the operand's evaluation domain, not every instantiated cell it could address:** a cell in a row beyond its group's declared repeatability enters none of `t`, `e`, or `u`, so it neither counts nor makes the tally unavailable ([§7](07-repetition-and-iteration.md)). That is a fact about the range rather than about the classification, and the two are separated by a malformed cell — one index below capacity it makes the aggregate non-evaluable, one index above it does not. The leaf exposes only `TRUE_WF` (VALUE), `TRUE_AF` (OMISSION), or the single collapsed `FALSE_OR_UNKNOWN`; the kernel-visible result does not distinguish hidden false from unknown. Empty-row eligibility is a separate whole-condition gate, and `Having` can change both the selected range and firing polarity, so neither is part of this unfiltered table:

| Validation predicate | Range | Fires when | Unfiltered polarity |
|---|---|---|---|
| `AllFieldsFilled` | declared | `e = 0 ∧ u = 0 ∧ d = 0` | VALUE |
| `NoFieldFilled` | instantiated | `t = 0 ∧ u = 0` | OMISSION |
| `AtLeastOneFieldFilled` | instantiated | `t ≥ 1` | VALUE |
| `MoreThanOneFieldFilled` | instantiated | `t ≥ 2` | VALUE |
| `NotAllFieldsFilled` | declared | `e + d ≥ 1` | OMISSION |
| `NotExactlyOneFieldFilled` | instantiated | `(t = 0 ∧ u = 0) ∨ t ≥ 2` | OMISSION in the zero-filled region; VALUE in the at-least-two region |
| `FieldsNotCollectivelyFilled` | instantiated fill plus declared empty | `t ≥ 1 ∧ e + d ≥ 1` | OMISSION |

For a resolved entity list, let `pₜ` be definitely filled contributions, `pₑ` be definitely empty contributions, and `pᵤ` be contributions in neither bucket. A checked field is definitely filled when it has a value, definitely empty when cleanly empty, and unavailable when formally invalid or not relevant. An ordinary resolved group uses the product-state classification above. A terminal repeatable star contributes one filled item per instantiated terminal row; a non-repeatable terminal below stars contributes one ordinary group-product classification per selected ancestor environment. The five legal group-list quantifiers consume that common tally without treating unavailable as empty:

| Validation predicate | Fires when | Unfiltered polarity |
|---|---|---|
| `AllGroupsFilled` | `pₑ = 0 ∧ pᵤ = 0` | VALUE |
| `NoGroupFilled` | `pₜ = 0 ∧ pᵤ = 0` | OMISSION |
| `AtLeastOneGroupFilled` | `pₜ ≥ 1` | VALUE |
| `NotAllGroupsFilled` | `pₑ ≥ 1` | OMISSION |
| `GroupsNotCollectivelyFilled` | `pₜ ≥ 1 ∧ pₑ ≥ 1` | OMISSION |

The plain numeric `NumberOfFilledGroups(g1, g2, …)` reads each operand through the same definitely-filled/definitely-empty/unavailable decision as the partial tally above **on every dimension but coverage**, sums the definitely-filled ones, and is unavailable when any operand's presence is undecided. On coverage it is strictly stricter: under partial validation the count needs every field of every operand group in the relevant set, where the tally's predicates decide from the content they can see ([§12](10-validation-and-polarity.md)). Do not collapse the two projections into one. **A formal error blocks only the negative answer.** A group holding admitted content counts as filled however its other descendants failed, and only a group with no admitted content is left undecided by one: over a filled sibling group, an operand carrying a filled cell beside a malformed one counts exactly as the clean control does, while the same operand holding only the malformed cell makes the whole count unavailable rather than dropping to zero. Neither operand position nor an error elsewhere in the document matters — the pair repeats on the second operand, and a malformed cell in an unreferenced group leaves the count intact ([checkpoint](../docs/SOURCES.md#src-group-count-unavailability)). This is the same rule `GroupFilled` obeys, so the count and the scalar predicate cannot disagree about an erroneous group. **The rule is about undecided presence rather than about one error channel**: a group whose repeatable descendant exceeds its declared capacity carries a structural over-limit diagnostic rather than a cell finding, and it still counts when its content is admitted, measured on its own model against an at-capacity control. Each authored fixed group is one declared entity, not one entity per descendant: one admitted descendant makes a half-filled group count as given, and a measured two-group comparison has fixed movement once both group entities are given. **A group's content is read over its whole subtree rather than over its direct children.** A group owning no direct field at all, whose only field lies two levels down, counts as filled when that field is filled and drops out of the count when it is emptied; the computation and validation arms agree there, measured separately ([checkpoint](../docs/SOURCES.md#src-nested-descendant-group-count-runtime)). Content has **two constituents and either is sufficient**: an admitted descendant cell anywhere in the subtree, or an **instantiated row** in a repeatable descendant. The row constituent alone is enough — one row carrying no filled cell at all still makes the group count as filled, and removing that row drops the count ([checkpoint](../docs/SOURCES.md#src-repeatable-descendant-group-count)) — and the cell constituent alone is enough in a subtree with no repeatable group in it. **Repetition depth does not bound the row constituent**, exactly as nesting depth does not bound the cell one: a shell whose only content is a repeatable group containing a second repeatable group counts on one instantiated leaf row with an empty cell, and drops when the rows are removed ([checkpoint](../docs/SOURCES.md#src-deep-repeatable-descendant-group-count)). The mechanism is subtree containment rather than an axis count, measured at two repetition levels. **The outer row alone is content**: a shell whose repeatable descendant holds one row with no inner row beneath it counts, on both spellings of that document — an outer row carrying no inner group key, and one carrying an explicitly empty inner list — against a no-row control that does not count ([checkpoint](../docs/SOURCES.md#src-group-count-row-domains)). A reading that required a row at the *deepest* repeatable level is refuted there. The disjunction itself is measured, on one operand owning both a nonrepeatable descendant and a repeatable one: the cell alone with no row instantiated counts, the instantiated empty row alone with no cell filled counts, and neither counts as one ([checkpoint](../docs/SOURCES.md#src-repeatable-descendant-group-count)). That third document is what separates the rule from counting unconditionally. This is the same fill notion the scalar group predicates use, and the unstarred multi-group count is measured to obey it rather than to have a rule of its own. Keep that form separate from `NumberOfFilledGroups(G*)`, whose declared entity extent is the group's repeatability and whose values are the in-capacity instantiated rows. **That extent is the starred group's own row maximum and is not multiplied by a repeatable descendant.** A starred member whose group owns a further repeatable group counts identically to one that does not, and three rows in a `max 3` group beside one fixed member reach the extent `1 + 3` rather than a product — the opposite of `NumberOfFilledFields`, whose slot capacity does multiply through repeatable descendants. A malformed cell inside a starred row leaves that row counted and contributes no unavailability of its own ([checkpoint](../docs/SOURCES.md#src-group-count-unavailability)). A repeatable row counts structurally even if every descendant is empty; two rows in a capacity-two group therefore exhaust the extent and make the count fixed, while one row or no rows leaves a grow-only count. Over-limit rows remain only in the complete structural topology and never increase this numeric result.

**The static gate table for `NumberOfFilledGroups` is one table and it is the same in rules and in computations**, measured on both arms rather than carried from one to the other ([checkpoint](../docs/SOURCES.md#src-group-count-static-gates-both-arms)). Arity is a minimum of two, not a pair: a lone fixed operand is rejected `MVK_PARAMSIZE_INVALIDGN`, while fixed lists of four and five and mixed lists of three and four are admitted. Two members naming the same group are rejected `MVK_DUPLICATE_PARAM1`. **Strict containment between any two members is rejected `MVK_DUPLICATE_PARAM2`** — an ancestor beside its descendant, the model root beside any contained group, and equally a fixed group beside a star strictly inside it or a star beside a star strictly inside it, in either authored order. The one exception is **equal paths where both sides are starred**, which are admitted and counted once per position; that exception is what makes the rule containment rather than distinctness, and it is the only sense in which a wildcarded operand escapes duplicate checking. **A root operand beside a disjoint one is rejected `MVK_ROOT_GROUP_WITH_OTHER_PARAMETERS`**, in either order and whichever side is starred, against a live control admitting a nonroot group beside another root's star. **Containment is checked before rootness**: a root beside its own descendant draws the containment class, so an author is told to resolve the overlap rather than to remove the root. A repeatable group written without `*` is rejected `MVK_NO_WILDCARD`. The starred form is not restricted to a singleton: `NumberOfFilledGroups(G*)` and a mixed `NumberOfFilledGroups(G*, Fixed)` are both statically admitted in rules and computations. An ordinary nonrepeatable root cannot acquire a star and is rejected `MVK_INVALID_WILDCARD` when written that way. A fixed operand whose fields lie only in a **nested descendant** subgroup is admitted too, in either list position and at arity three ([checkpoint](../docs/SOURCES.md#src-nested-descendant-group-count-admission)), and depth does not bound that: content three levels down is admitted, as is a group whose only content is a **repeatable** descendant. A group that is *itself* repeatable follows the operator's ordinary wildcard rule with nothing nesting-specific about it, refused `MVK_NO_WILDCARD` unstarred and admitted starred. The empty group refuses `MVK_GROUP_IS_EMPTY` on this same carrier, which is what separates admitting nested content from refusing nothing ([checkpoint](../docs/SOURCES.md#src-nested-descendant-group-count-runtime)). **The starred operand's computation runtime is measured, and the two operand forms in one list contribute unlike quantities.** A seeded Number target computed from `NumberOfFilledGroups(G*)` over a repeatable `G` takes that group's **instantiated row count**: no rows counts `0`, one instantiated but wholly empty row counts `1`, and three empty rows count `3`, so the result is neither a presence bit nor a filled-row tally. This is the same extent the validation carrier uses for the starred form, which makes the two arms agree here even though the *fixed* form has them inverted on formal invalidity. In the mixed list the contributions stay independent and keep their own shapes: `NumberOfFilledGroups(Fixed, G*)` is the fixed operand's zero-or-one **plus** the starred operand's row count, so emptying the fixed group's only field drops the total by exactly one while the starred operand still contributes every row ([checkpoint](../docs/SOURCES.md#src-starred-group-count-computation)). **An over-limit row is excluded on this arm too, measured rather than inherited from the validation carrier.** A repeatable group declared `max 5` holding five, six, and seven instantiated rows counts `5` on all three, and a starred `Sum` over the same rows stops at the same in-capacity five; a four-row control separates that from a quantity pinned at capacity regardless of content. The arms therefore agree here, but on two measurements rather than on one carried across — the same operator has them inverted on formal invalidity. **The fold sums over authored operand positions, not over the distinct groups those positions name.** Two starred operands in one list add their cardinalities independently: three rows in one group beside two in another count `5`, three beside none count `3`. The same group named twice contributes twice, counting `6` where three rows are instantiated, which is the row that separates the two readings; nothing deduplicates the two **equal** starred operands, which is exactly the pair the containment gate above admits. Duplicate checking does **not** otherwise skip a wildcarded operand: a star strictly inside another member's group is refused like any other containment. Static authoring admission of those lists is measured separately and agrees: the same starred group twice, two distinct starred groups, and a fixed group beside two starred ones are all admitted, on a run whose refusing rows prove the gate was live. All three facts are measured ([checkpoint](../docs/SOURCES.md#src-starred-group-count-computation)). Not established by these rows: a row holding only formally invalid content, and a starred group owning a repeatable descendant.

**In computation that same operator inverts: an erroneous operand group counts as filled.** A seeded Number target computed directly from `NumberOfFilledGroups(Alpha, Beta)`, where `Alpha` holds only a formally invalid cell, takes the ordinary exact count `2` — the same value as when both groups are clean and filled — while two *empty* groups still yield `0`. So absence decides the count and formal invalidity does not, which is the opposite of the validation reading of the same operator over the same cell. The reason is that the operator **tests presence and never reads a value**: during `compute()` the invalid cells are converted so that nothing is treated as irrelevant, which leaves the malformed cell merely present, and a count that never reads it never reaches the throw that poison travels through. That is measured rather than argued: a value-*reading* computation over the same cell in the same compute run parts company with the count, producing no value where the count produces its exact total. The general third-state rule for computation is therefore intact and must not be weakened to accommodate this — it governs a **read** ([§11](09-computations.md)), and a presence test is not a read. The rule reaches a **nested** invalid cell exactly as it reaches a direct one: a shell group whose only field lies two levels down and holds a non-numeric value still counts as filled, taking the same exact `2`, with that cell listed in `formalErrorsInOperands` and the target neither cleared nor errored; emptying it instead drops the count to `1` ([checkpoint](../docs/SOURCES.md#src-nested-descendant-group-count-invalid)). Do not generalize the count's behavior to structural or call-local group errors, or to a repeatable operand, none of which these observations cover. Whether the reading twin *clears* its target or *aborts* is a separate question this observation does not settle.

Computation uses the following ordered scans over the canonical resolved slot stream. A declared-but-uninstantiated slot is a clean declared absence, not a value read:

| Computation predicate | Ordered decision |
|---|---|
| `AllFieldsFilled` | Scan the declared range; first empty or uninstantiated slot → not true; exhaustion → holds. |
| `NotAllFieldsFilled` | Scan the declared range; first empty or uninstantiated slot → holds; exhaustion → not true. |
| `NoFieldFilled` | Scan instantiated slots; first filled slot → not true; exhaustion → holds. |
| `AtLeastOneFieldFilled` | Scan instantiated slots; first filled slot → holds; exhaustion → not true. |
| `MoreThanOneFieldFilled` | Scan instantiated slots; second filled slot → holds; exhaustion with zero or one → not true. |
| `NotExactlyOneFieldFilled` | Run the `NoFieldFilled` decision first; if a filled slot exists, restart and run the `MoreThanOneFieldFilled` decision. Zero or at least two filled slots hold; exactly one does not. |
| `FieldsNotCollectivelyFilled` | Run the instantiated `AtLeastOneFieldFilled` decision first; if a filled slot exists, restart and run the declared-range `NotAllFieldsFilled` decision. It holds exactly when both witnesses exist. |

Every reached invalid slot in these computation scans poisons the computation instance. Each component scan stops at its own result, but a successful first stage of either composite starts the stated second scan again from the beginning. Only a suffix after the full predicate's final decision is unread.

> **Non-normative implementation note.** "Declared range vs instantiated range" is a real semantic fork, not an optimisation — encode both. A clean approach: give a repeatable group both its `repeatability` (declared) and its actual row count, and let each quantifier state which range it folds over. `AllFieldsFilled` folds over the 1-based semantic range `1 .. repeatability` (missing rows = empty); `AtLeastOneFieldFilled` folds over `1 .. rowCount` (an empty range when `rowCount = 0`).

## Part B — §3 Formal errors and the "unknown" state

### B.1 What a formal error is

A field whose value violates its **data-type configuration** produces a **formal error**. While it stands, built-in validation reads observe the field as **"unknown"** and cannot consume it as a checked operand. Formal errors:

- ordinarily use a **fixed, non-authorable** message (contrast rule errors, which are authored and can be error/warning/info); a registered custom field validator is the explicit exception, carrying its project code and optional validator-provided message ([§7](06-strings-and-enumerations.md#a3-custom-field-type-validation)),
- are attributed internally to a sentinel rule path (`formalePruefung`) — so from the *author's* rule's viewpoint the rule simply produces nothing,
- **block the field from participating in built-in predicates, comparisons, and aggregates** (author rules never create this state — only formal errors do).

[`CustomCondition`](11-messages-and-custom.md#part-b--14-customcondition--the-escape-hatch) is the deliberate host-SPI exception to that read boundary. The kernel cannot infer the callback's hidden field dependencies from the rule AST, so a reached callback receives the document plus the complete formal-invalid set and decides for itself whether one of its necessary fields prevents evaluation. The callback contract requires `false` in that case, but the runtime does not pre-suppress the invocation.

**A would-be tautology is not one.** If `F` has a formal error:

```
FieldFilled(F) Or FieldNotFilled(F)     -- does NOT hold: F is unknown, so neither branch is satisfied
```

### B.2 The three cell states — the third one is *not* "empty"

A cell has three states: **empty**, **filled**, and **not-check-relevant** (present but formally invalid). The empty-value substitutions of [§2](03-empty-and-required.md) are the *empty* column only; an invalid cell answers "unknown" and lands differently everywhere:

| What reads the cell | empty cell | **not-check-relevant** (filled-but-invalid) cell |
|---|---|---|
| a comparison reading its value | per-kind substitution ([§2](03-empty-and-required.md)) | **UNKNOWN** — the branch cannot decide |
| `FieldFilled` / `FieldNotFilled` / fill quantifiers | a definite FALSE / TRUE (counts as empty) | **UNKNOWN** — counted as *neither* filled nor empty (so `NoFieldFilled` does **not** fire over it) |
| a value aggregate or count over a selection containing it | the empty cell is dropped or substituted | the **whole aggregate is non-evaluable** — the enclosing rule is suppressed, wherever in the selection the cell sits |
| `FieldValuesNotUnique` over a selection containing it | the empty cell is skipped | **skipped too** — the deliberate exception, see below |
| a computation reading it | the per-kind compute behaviour ([§11](09-computations.md)) | the read **aborts the computing instance** — compute's *poison* ([§11](09-computations.md)) |

The distinction *empty ≠ invalid* is the reason a two-state value domain cannot model the language: `NoFieldFilled` fires over empties but not over invalids; an aggregate substitutes/drops empties but goes non-evaluable on one invalid.

**`FieldValuesNotUnique` is the one value predicate that skips instead.** An invalid operand is treated exactly like an empty one: a duplicate on either side of it still fires, and two *equal* invalid values do not duplicate because neither enters the comparison ([§9](07-repetition-and-iteration.md)). The split is real, but it is **not** predictable from which relevance gate the operator consumes: all of these operators consult the same three-valued gate, so a rule of that form predicts the same answer for `Sum` and for `FirstFilledValue`. What separates them is each operator's own accumulation rule — whether its combiner can still change once a value has been taken. An all-cells combiner must account for every selected cell, so it propagates the UNKNOWN and becomes non-evaluable. A stop-at-first combiner never reaches a later cell, which is why `FirstFilledValue` fires when the malformed cell follows the first filled row and suppresses when it *is* the first filled row. This predicate has no early return on an invalid cell at all: its own return is at the first *duplicate*. Do not infer any of the three from family resemblance, and do not infer it from the shared gate either — read the operator's own stop rule. The two accounts also coincide on every selection whose only invalid cell would not have produced a duplicate anyway, so a case built on that shape cannot tell them apart.

For the all-rows aggregates the malformed cell's authored position does not change the **verdict**, measured with that cell at head and at tail. That is a claim about the verdict alone: the cell's own formal error still names the row it sits in, so validation *output* is not position-blind. Whether the aggregate reaches its non-evaluable answer by stopping at the first such cell or by surveying the whole selection is **not observable here**, because verdict identity is what both accounts predict, and an implementation may do either. The whole-selection reading is not hypothetical: the same combiner path can answer non-relevant for an entire repetition without reading a single cell, which is why an all-rows aggregate stays UNKNOWN in partial validation even when every concrete row is enumerated ([§12](10-validation-and-polarity.md#5-full-vs-partial-validation)).

### B.3 What puts a cell in the third state

More than a type-format mismatch. The *same* checked-cell mechanism (same eventual "unknown", same suppression for authored validation rules) receives findings from several stages:

- **a malformed value** — the base case, *plus* two cross-kind baseline checks that run before any type-format check on a stored/input value: the model's [legal charset](06-strings-and-enumerations.md#a2-legal-charset-definitions-and-atomic-matching), and no leading/trailing blanks;
- **a declared-constraint violation** — range, length, pattern, digit counts, enum domain: a parseable-but-out-of-bounds value is *exactly as invalid* as an unparseable one. A value violating several checks reports the **first** in the engine's fixed precedence;
- **a registered custom field-validator rejection** — one project-coded formal observation reused by every consumer of that relevant concrete-valued cell ([§7](06-strings-and-enumerations.md#a3-custom-field-type-validation));
- **the "required" checkbox on an empty field** ([§4](03-empty-and-required.md)) — after its generated mandatory rule has fired and its hit/message has been retained, the empty target is annotated with a validation-scoped required finding; authored validation rules then see unknown, while computation sees plain empty (an important asymmetry, [§11](09-computations.md));
- **a duplicate index value** — a later model/instance check marks *every* participating cell, field-locally;
- **an over-repetition row** — the address-formal check detects a coordinate beyond the group's declared `repeatability` before scalar conversion, supplies the structural finding in place of any would-be scalar finding, and suppresses the ordinary checks of that row **and of everything the document writes beneath it** while retaining its physical row content. In the measured `/Order[1]/Lines[3]/Qty` instance, the complete formal channel contains exactly `zuGrosseZeile@/Order[1]/Lines` and `zuGrosseKontextnummer@/Order[1]/Lines[3]/Qty`, with no Number, Boolean/Confirm, String-length, or other scalar-format finding for that row. **The multiplicity is one row-level code plus one context-number code per node the document writes beneath the row, and every one of them is attributed to the outermost violation.** Measured at kernel 30.8.1, the outermost over-limit row in a subtree draws exactly one `zuGrosseZeile` on its own address, plus one `zuGrosseKontextnummer` for every instantiated descendant row and every present cell the document writes under it, at any depth. The set is read off the written document, not off the model: the same row written as an empty row object draws the row code alone although descendants are declared beneath it, and a cell holding a value stamps exactly as an empty one, with its ordinary format check suppressed. **An over-limit row nested inside that subtree is absorbed**: it contributes its nodes to the count but draws no `zuGrosseZeile` of its own, and no message names its group, so its violation is invisible until the outer one is fixed and the formal channel is not monotone in the document. The absorption is **transitive** — three nested violated levels still draw one row code, and all fourteen findings name the outermost group — and the suppression reaches the same distance: a malformed cell two levels below an over-limit row reports nothing, while the identical value in an in-capacity sibling row reports normally. Over-limit rows in disjoint subtrees stay independent and each names its own group. Every context-number message therefore carries the **outermost** violated group's declaration path and its offending index whatever the stamped node's depth; `referenced` holds exactly the stamped address and `fillToFix` is empty ([multiplicity](../docs/SOURCES.md#src-over-limit-finding-multiplicity), [attribution](../docs/SOURCES.md#src-nested-over-limit-attribution), [absorption depth](../docs/SOURCES.md#src-over-limit-absorption-depth)). The two routes spell addresses differently and the reason is now known: the **kernel** channel elides a repetition-one coordinate at every level and indexes the violated row, so the same finding reads `A[3]/B/C/Value` with `B` and `C` at row 1; the overload matrix above reached this document through a peer renderer that instead indexes every segment but the last, which is correct for a field and drops a repeatable group node's own row. Take the address *set* as measured, and read the kernel spelling from the runtime channel rather than from the matrix.

String checking has an ingestion boundary that precedes every evaluation-side read. A checked-and-valid String replaces each **CRLF pair** with LF before it enters the evaluation cache; a lone CR is unchanged, and the stored document text is never rewritten. The format measure, rule reads including `Length`, and computation reads consume this normalized cache value. Rule-message field-value interpolation is a separate display path: it consumes the caller's `getValueForDisplay` result, and the public DocumentV2 route obtains that result from the immutable input document rather than the evaluation cache; the renderer performs no CRLF normalization. Inside the String format check, the clause order is: raw-type gate → full-check gate → line-break permission on the **raw** text → normalization → pattern XOR enumeration-domain check on normalized text → min/max length on normalized text. The line-break gate also covers Enumeration fields, so a break-carrying value outside the enum domain reports the newline error before any domain or pattern error. Maintained a12-dmkits dual-kernel-route differentials confirm that an ordinary CRLF-bearing String can be normalized for rule evaluation while its message display preserves the original CRLF bytes; this repository retains no matching portable observation.

A String field declared with `noValueValidation` is **not** a producer of the third state. Its stored content remains ordinary content for presence predicates, while model validation closes every operation that would expose its value; the sole admitted `Length` declaration is eliminated into metadata rather than evaluated as a runtime rule ([§7](06-strings-and-enumerations.md)).

These boundaries are source- and dual-strategy-differential-locked in a12-dmkits' [`CrlfLengthNormalizationDiffTest`](../../a12-rulekit/adapter/src/test/kotlin/io/github/mbackschat/a12/dm/adapter/laws/CrlfLengthNormalizationDiffTest.kt) (IF124) and [`NvvRawTypeDiffTest`](../../a12-rulekit/adapter/src/test/kotlin/io/github/mbackschat/a12/dm/adapter/laws/NvvRawTypeDiffTest.kt) (IF125).

> **Non-normative implementation note.** Keep one checked-cell representation, but do not collapse every producer into the base `formalCheck : FieldPolicy → RawCell → CheckedCell`. The base function handles ordinary local findings such as malformed data and declared constraints, including String normalization at the ingestion boundary after the raw-text line-break gate. Over-repetition is the address-formal exception: decide it first and construct the same checked-cell shape with `.overRepetition` without running the scalar checker. Generated preliminary findings then annotate admitted base cells. Requiredness specifically runs in this order: evaluate the generated `mandatoryField` rule against the base cells, retain its hit/message, then, on a hit, annotate the empty target with `.required` before authored validation rules run. Annotating first would make the mandatory rule's own `FieldNotFilled` read UNKNOWN and suppress the message that creates the annotation — a circular self-suppression. `observeCell` maps applicable findings to validation `unknown` and ordinary computation `poison`, but ignores `.required` during computation so the cell remains empty. Raw-type values never reach `observeCell` through a legal value-reading rule; reject those windows during elaboration. Do not scatter invalidity handling across operators, and do not perform per-kind empty substitution inside the read.

### B.4 Suppression is branch-scoped, and reaches presence checks

For built-in predicates and operators, a formal error does **not** remove the whole rule; it makes the reading operand UNKNOWN and Kleene `And`/`Or` decides the rest:

```
healthyValueTrue Or  [broken] > 0     -- still FIRES  (the VALUE-fired branch decides the verdict)
healthyTrue      And [broken] > 0     -- SUPPRESSED   (unknown absorbs the And)
```

A single-branch rule is just the case where branch-scoped and rule-scoped suppression look identical. The unknown reaches **even built-in operators that read no value**: `FieldFilled(malformed)` decides nothing (it is UNKNOWN, not FALSE). And the suppression is **silent** from the author's viewpoint — the engine emits its own formal-error code on the sentinel path while the author's rule yields nothing; in a report the discriminator is the sentinel path vs the rule's own path. The VALUE qualifier matters for the unified `Verdict`: `Or` uses value-wins polarity, so an OMISSION-fired branch may still be upgraded by a VALUE-fired sibling. The truth table establishes the result despite an unknown sibling, but it does not by itself establish whether validation physically skipped that read; treat validation read traces as unobserved until a focused engine probe exposes them. A reached `CustomCondition` is different: it receives the formal-invalid set, returns its own Boolean leaf result, and only then participates in the ordinary surrounding `And`/`Or`.

### B.5 The strong-Kleene tables (the exact algebra)

The propagation follows strong three-valued Kleene logic (the third value is written `U`):

| `And` | T | F | U |   | `Or` | T | F | U |
|---|---|---|---|---|---|---|---|---|
| **T** | T | F | U |   | **T** | T | T | T |
| **F** | F | F | F |   | **F** | T | F | U |
| **U** | U | F | U |   | **U** | T | U | U |

Note the absorbing cases that make suppression branch-scoped: `F And U = F`, `T Or U = T`. There is **no** negation row — the language provides none, so you never need to define `¬U`.

> **Non-normative implementation note.**
> ```lean
> inductive K where | tru | fls | unknown
> def K.and : K → K → K
>   | .fls, _ => .fls | _, .fls => .fls
>   | .tru, .tru => .tru | _, _ => .unknown
> def K.or : K → K → K
>   | .tru, _ => .tru | _, .tru => .tru
>   | .fls, .fls => .fls | _, _ => .unknown
> ```
> A predicate that reads a cell produces `K` (not `Bool`): reading a `notCheckRelevant` cell yields `.unknown`; reading `empty`/`filled` yields a definite `.tru`/`.fls` per the operator's rules. Define the strong-Kleene information order by `U ⊑ T`, `U ⊑ F`, and reflexivity, with `T` and `F` incomparable. `And` and `Or` are monotone in each argument under this order: refining unknown input may resolve the result to either truth value, while a result that is already definite is stable under further input refinement. This exact statement is the useful regression theorem; a blanket "not-fired can only move toward fired" claim is false because unknown may refine to false as well as true.

### B.6 Validation *excludes*; computation *poisons*

The two operations treat the third state with opposite temperament — a difference that matters wherever computed fields chain:

- **Validation excludes.** An invalid cell drops out: tallies count it in neither bucket, aggregates over it go non-evaluable, referencing branches go UNKNOWN. Nothing propagates beyond the rules that reference it.
- **Computation poisons.** During `compute`, invalid cells are set up so that any *read* of one throws; the reading computation instance aborts, produces no value, is itself marked invalid, and that mark cascades to its dependents' reads in turn — **order-dependently**, because only cells an evaluation actually reads can poison it.

The compute side is the subject of [§11](09-computations.md); the key is that the *same* third state you handle by exclusion in validation, you must handle by an (order-sensitive) abort in computation.

## Checklist for a faithful reimplementation of §1 + §3

- [ ] Value domain has **three** states (`empty` / `filled` / `notCheckRelevant`), resolved once at the read.
- [ ] `And`/`Or` are strong-Kleene over `K = {T,F,U}`; **no** negation combinator.
- [ ] Parser **rejects** un-bracketed `And`/`Or` mixes.
- [ ] Negative predicates are individual constructors, **not** `Not p`; the non-complementary pairs behave as specified.
- [ ] Boolean has three field-states; `== True` ≠ `FieldFilled`; Confirm-empty = `False` while Boolean-empty = not-evaluated.
- [ ] Fill quantifiers distinguish the **declared** vs **instantiated** iteration ranges and use the canonical field-major/repetition-major bare-group stream. Validation counts an invalid cell in neither bucket; computation poisons on a reached invalid slot and leaves every suffix after the full predicate's final decision unread.
- [ ] Group-list quantifiers admit checked field and group operands and use one definitely-filled/definitely-empty/unavailable tally; the two wildcard-admitting members may mix or repeat starred groups. A terminal repeatable star contributes one filled count per instantiated row, while a non-repeatable terminal below stars contributes its descendant-derived group product per selected environment. Plain multi-group `NumberOfFilledGroups` remains group-only, reads each fixed operand's content over its whole subtree at any depth — content being an admitted descendant cell **or** an instantiated repeatable-descendant row, either sufficient — and is unavailable only where an operand's presence is undecided — an error on a group with admitted content leaves it counted — while the starred single-repeatable-group numeric form counts only in-capacity rows and leaves over-limit rows in the structural topology.
- [ ] Legal-charset and registered custom-validator rejections enter the same formal-observation boundary; the latter preserves its project code and optional message.
- [ ] Suppression is **branch-scoped** and reaches presence predicates (`FieldFilled(invalid)` = UNKNOWN).
- [ ] Strong-Kleene information order is explicit; `And`/`Or` are monotone under it, and definite results are stable under refinement.
