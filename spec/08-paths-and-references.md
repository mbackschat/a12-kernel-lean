# 08 — Paths and references (§10)

How a condition names a field. Mostly mechanical, with two things that matter for a faithful reimplementation: the **two-tier bare-name resolution order** (declaring group, then flag-gated model-wide uniqueness) and the fact that **rows are addressed by semantic key, never by position**.

Path resolution reads a cell *relative to the current repetition context* ([`01-data-model.md §2.1`](01-data-model.md#21-repetition-contexts-the-iteration-environment)); this file is about how a path string selects that cell.

---

## 1. Absolute, relative, and short-name references

- **Keyword-named fields must be quoted.** A field or group named like a keyword (`And`, `Date`, `Today`, …) is single-quoted in a path: `FieldFilled(Order/'Date')`.
- **`RuleGroup`** references the rule's own containing group as an entity: `GroupFilled(RuleGroup)` validates and **counts as referencing the error field** ([§9](07-repetition-and-iteration.md)). When that group declares an index field, `RuleGroup For "key"` uses the ordinary semantic-index suffix: `GroupFilled(RuleGroup For "SKU-1")` is admitted for an indexed `/Order/Items` rule group, while the same suffix on unindexed `/Order` reports `MVK_NO_INDEX_FIELD`. `RuleGroup*` remains rejected.
- Paths are **absolute** (`/Order/Quantity`) or **relative** (`../Other`). Relative paths within a rule's group are shorter and survive the group being moved.
- **The one combination that *requires* absolute:** the `*` may not be attached to a relative `..` step (`MVK_INVALID_WILDCARD_REL`). A named segment reached after walking upward may still be starred, so `../Items*/Count` is legal; `..*/Budget`, which tries to reopen the ancestor step itself, must instead use an absolute path such as `/Project/Milestones*/Budget`.
- **An up-step stands only in a relative path's leading run.** Elsewhere it is refused `MVK_UNEXPECTED_TOKEN`, and what decides whether anything is resolved first is what precedes the step, not the segment beside it. With no named segment before the step starred, nothing before it is resolved, so `Claims/Nope/..` draws the token class. When a named segment before the step is starred, or the path opens with an up-run, the whole prefix is walked first, each segment with its own gates, so `Claims*/Nope/..` and `../Nope/..` draw `MVK_INVALID_ENTITY`, `/Nope/Claims*/..` the root class and `Claims/Amount*/..` the star-on-a-field class; only a prefix that clears its gates reaches the token refusal. A misplaced named turning point, `Claims/..Policy/Holder`, is an up-step on the same terms. The same two triggers walk a path that stops at a separator, checking each step once its production completes, and a `$` mark is measured there as a third ([§12](12-concrete-syntax.md#3-the-condition-and-operation-grammar-sketch), [inbound](../docs/SOURCES.md#inbound-2026-09-26p-walked-path), [inbound](../docs/SOURCES.md#inbound-2026-09-27-completed-steps)). Up-steps chain only through `/`: `.. / .. / Code` is admitted, while `.. ..`, `.. .. / Code` and `..../Code` draw `MVK_UNEXPECTED_TOKEN`, a second `..` after a closed one being a stray token [inbound](../docs/SOURCES.md#inbound-2026-09-26o-production-close). A path of up-steps alone names an ancestor group and draws what a group in that slot draws: from a nested rule `..` is the root, which a field-fill operand refuses as a root and a group operand takes. A starred leading step that stays inside the model answers `MVK_INVALID_WILDCARD_REL` at its own segment, ahead of a later climb out of the model or a later `.*` suffix. Across a condition the first defect in text order answers, a misplaced up-step taking its turn like any other reference; [§12](12-concrete-syntax.md#3-the-condition-and-operation-grammar-sketch) owns when each class is raised. A message parameter never walks the prefix: every misplaced up-step there draws `MVK_UNEXPECTED_TOKEN`, so `$../Nope/..$` does where the same text in a condition draws the entity class ([inbound](../docs/SOURCES.md#inbound-2026-09-24c-path-walk)).
- A field may be referenced by a **bare short name** (`[Quantity]`). Direct lookup under the declaring group is always attempted; the model-wide fallback requires `fieldRefByShortNameAllowed`, whose kernel default is off.
- **A group may be declared empty, and then it may not be named.** A group carrying no field anywhere in its subtree is legal in a model, and `model check` reports the model valid, but every operand naming one is refused: `MVK_GROUP_IS_EMPTY`, or `MVK_ROOT_GROUP_IS_EMPTY` when the group is a root, as a fixed root's presence and a starred repeatable root's count draw it. That holds once the operand's star is right, because the read answers first: an empty repeatable group or root written without its star at a reference that does not iterate it draws the walk's `MVK_NO_WILDCARD`, and a star on an empty fixed group draws `MVK_INVALID_WILDCARD` ([inbound](../docs/SOURCES.md#inbound-2026-09-26k-empty-star)). The gate is over the whole subtree rather than the direct children, so a group populated only through a descendant subgroup is admitted. It applies to both repetition shapes, including a starred count over an empty repeatable group. In an entity list it answers ahead of every list gate ([§9 entity lists](07-repetition-and-iteration.md#entity-list-operand-reads)). The [empty-group checkpoint](../docs/SOURCES.md#src-empty-declared-group) owns the matrix and its limits.

## 2. Bare-name resolution order ⚠

A bare segment resolves in exactly two tiers — **declaring-group-first, then (flag-gated) model-wide unique field lookup:**

1. Look **directly under the declaring group**: a rule's, or a computation's rather than the group of the field it writes ([checkpoint](../docs/sources/static-admission-and-class-probes.md#src-field-value-read-predictions)).
2. Only on a miss, **and** for a relative reference with `fieldRefByShortNameAllowed` on, run a **model-wide unique field short-name lookup over fields only**:
   - more than one match ⇒ `MVK_FIELDNAME_NOT_UNIQUE` (**never a silent pick**);
   - zero matches ⇒ falls through to `MVK_INVALID_ENTITY`.
   The serialized condition **retains** the short name (resolution is not rewritten into a path).

The fallback answers the **first segment of a relative path** that opens with no up-step, starred or not, whatever follows it, and **never a later segment**; no row measures a path behind an up-step. An ambiguous first segment draws `MVK_FIELDNAME_NOT_UNIQUE` where a positional reading of the whole path would name a miss: `Remark/Nope`, `Remark*/Nope` and `Remark/Claims*` from a group declaring no `Remark`. A unique one binds its field, so the segment below it misses with `MVK_INVALID_ENTITY` and a star on it is a star on a field, `MVK_INVALID_WILDCARD`. A first segment naming a group of the declaring group takes no fallback, so `Insured/Holder` misses although `Holder` is a unique short name. **A bare name naming a group of the declaring group takes none either**: the first tier finds the group, so from `/Grid` with a fixed group `Ledger`, `[Ledger] > 0` and `FieldFilled(Ledger)` draw `MVK_NO_GROUPS_ALLOWED` whether one field elsewhere is named `Ledger` or two ([checkpoint](../docs/sources/static-admission-and-class-probes.md#src-field-value-read-remaining-sites)). A message parameter's first segment reaches the same fallback in that surface's own vocabulary ([inbound](../docs/SOURCES.md#inbound-2026-09-24c-path-walk)).

There is **no implicit ancestor walk**. A field in an ancestor group is reachable only through explicit `../` navigation or, when its short name is model-wide unique, through the flag-gated fallback. The earlier observation that `[Tier]` from `/Subscription/Addons` bound an ancestor field was the fallback firing in a draft with the flag enabled; with the flag off, the same reference is rejected as `MVK_INVALID_ENTITY`.

The **named-ancestor** form remains separate: in a `..Name/rest` path the up-count comes **only** from the `..` tokens; the trailing `Name` merely *names* (and validates) the ancestor landed on — a matching `..Name/rest` resolves exactly like `../rest`.

The two-tier mechanism and both flag arms are locked in a12-dmkits' [`ShortNameRefDiffTest`](../../a12-rulekit/adapter/src/test/kotlin/io/github/mbackschat/a12/dm/adapter/laws/ShortNameRefDiffTest.kt) and [`PathLawsTest`](../../a12-rulekit/src/test/java/io/github/mbackschat/a12/dm/rulekit/validate/laws/PathLawsTest.java) (IF119).

> **Non-normative implementation note.** Resolution is a scoped name lookup with two tiers: (1) declaring group, (2) flag-gated model-wide unique field short name. Implement as `resolve : Path → DeclaringGroup → Model → Except ResolveError FieldRef`, returning a *distinct error* for the not-unique case (never a silent first-match). Do not add an implicit ancestor tier; parent lookup requires explicit `..`. The `..Name` name is a *validation label*, not an extra hop; compute the target purely from the `..` count.

## 3. The asterisk and `$`

- The **asterisk `*` flattens** a repeatable group into the list of its rows. **If an outer repeatable group uses `*`, every repeatable group below it in the path must also use `*`** (you cannot flatten an outer level while pinning an inner one).
- **A star may land only on a repeatable group.** On a fixed group, the root, or a field it is refused with `MVK_INVALID_WILDCARD`. That refusal answers ahead of the slot's own wildcard gate and ahead of a later segment that names nothing, so a starred fixed group followed by an unknown leaf draws it. It also answers **alone**: where the same reference leaves a repeatable level unstarred, and the twin with the star moved onto that level draws the position's own class — containment, `MVK_NO_WILDCARD`, `MVK_NO_WILDCARDS_ALLOWED` in a date slot or a scalar value-list subject, `MVK_DIFFERENT_GROUPS` in a `SumOfProducts` pair — the misplaced star draws `MVK_INVALID_WILDCARD` and nothing else, and so does a star on the field beside a star on every level. Both a star on the field and a star on a fixed group are measured at every position listed. A fixed group's star answers alone also against an unreferenced error field, and whether the twin without that star is admitted, as in the date slot and the scalar value-list subject, or draws a class of its own. **Alone holds per defect, not per condition:** of a misplaced star and an unstarred repeatable level in one condition, whichever the text reads first answers, within one call's operand list and across two calls alike ([inbound](../docs/SOURCES.md#inbound-2026-09-24e-misplaced-star), [inbound](../docs/SOURCES.md#inbound-2026-09-25-fixed-group-star)). The [starred-path checkpoint](../docs/sources/path-resolution-class-probes.md#src-starred-path-segment-order) owns the matrix.
- **The field-value read `[…]` asks four gates of the entity it names as its bracket closes, wherever it stands** ([inbound](../docs/SOURCES.md#inbound-2026-09-25f-field-value-read), [checkpoint](../docs/SOURCES.md#src-field-value-read-grid)). The reader's own classes answer first — `MVK_NO_WILDCARD` for an unstarred repeatable level, `MVK_INVALID_WILDCARD` for a misplaced star, `MVK_INVALID_ENTITY` for a name that resolves to nothing — and so does containment. Then a group draws `MVK_NO_GROUPS_ALLOWED`, a starred group, the root, and in a filter's body the level the filter iterates and a repeatable group it does not iterate included ([inbound](../docs/SOURCES.md#inbound-2026-09-25g-field-value-read)), a starred path `MVK_NO_WILDCARDS_ALLOWED`, a String with `noValueValidation` `MVK_INVALID_RAW_TYPE`, and a partially known Date `MVK_INVALID_DATE_TYPE`. The star gate asks the spelling, not the binding, so a star on the level the rule iterates is refused too.
- **Because each bracket is checked as it closes, a read's class answers ahead of the construct around it.** Of two reads in one comparison the left one's class is named, and a failing read answers ahead of the comparison's kind classes, ahead of an arithmetic operator's `MVK_NO_NUMBER_FOR_CALC`, ahead of a filter chain's `MVK_NO_ITERATION_FOR_WILDCARD`, and ahead of a scalar value list's own gates ([§8](06-strings-and-enumerations.md#b4-scalar-membership-is-a-singleton-specialization-not-boolean-negation-), [checkpoint](../docs/sources/static-admission-and-class-probes.md#src-field-value-read-carriers)). The star and group gates are measured on a comparison side, an arithmetic operand, a scalar value list's members, a filter's body and a computation's operation, and the raw and partial-Date gates on those carriers but a filter's body. On a computation's operation the group and raw gates are measured writing a String, an Enumeration, a Time and a Number target, the partial-Date gate writing a Number and a Date, and the star gate one Number target, while an unstarred repeatable group there draws the reader's `MVK_NO_WILDCARD` on a Number and a String target. Into a nonrepeatable Enumeration target a starred source draws `MVK_NO_WILDCARDS_ALLOWED` ahead of the target's source gate, read stored or through a declared category, while a category the Enumeration does not declare draws `MVK_CATEGORY_UNKOWN` ahead of the star ([inbound](../docs/SOURCES.md#inbound-2026-09-25i-enum-source)). A pattern comparison's field is a read too, so its group, raw and partial-Date classes answer ahead of the comparison's own `MVK_INVALID_TYPE_FOR_PATTERN_COMPARISON`, and so are a DateRange comparison's sides, measured with a group on either side and a raw String on the right ([checkpoint](../docs/sources/static-admission-and-class-probes.md#src-field-value-read-remaining-sites)). A category read `[G -> C]` whose `G` names a group draws `MVK_NO_GROUPS_ALLOWED` too, as a comparison side, a scalar value list's member or subject and a computation's operation, and as an entity-list operand, measured in `NumberOfFilledGroups`, `AtLeastOneGroupFilled`, `AllGroupsFilled`, `GroupFilled`, `GroupNotFilled`, `AllFieldsFilled` and `RepetitionNotUnique`, ahead of a repeat in `AtLeastOneGroupFilled` ([inbound](../docs/SOURCES.md#inbound-2026-09-26b-entity-list-category)). An operator argument typed as an entity is not a field-value read and meets its operator's own gates, so `[Total] == Sum(Lines*/Qty)` is admitted. **A field an operator names as a parameter asks the reader's classes and the group gate, but not the read's value gates** ([checkpoint](../docs/sources/static-admission-and-class-probes.md#src-field-value-read-predictions)). Inside `Length`, `RangeAsNumber`, `FieldValueAsNumber`, `FieldValueAsString` and a DateRange endpoint's date component a fixed group draws `MVK_NO_GROUPS_ALLOWED`, and inside `Length`, `FieldValueAsNumber` and `FieldValueAsString` an unstarred repeatable group draws `MVK_NO_WILDCARD`, as it does before the substring operators' gates, and past them each operator asks its own gates ([`kf395`](../../a12-rulekit/docs/KERNEL-FINDINGS.md#kf395), [`kf405`](../../a12-rulekit/docs/KERNEL-FINDINGS.md#kf405)). Over a raw String `Length` draws `MVK_INVALID_LENGTH_OF_RAW_TYPE`, `RangeAsNumber` `MVK_INVALID_RAW_TYPE`, `FieldValueAsNumber` `MVK_NO_CONVERT_IN_NUMBER` and `FieldValueAsString` `MVK_NO_NUMBER`, and over a partially known Date `Length` draws `MVK_NO_STRING`, `RangeAsNumber` `MVK_INVALID_TYPE` and `FieldValueAsNumber` `MVK_NO_CONVERT_IN_NUMBER`. **A category read `[F -> C]` of a field declaring no Enumeration draws `MVK_NO_ENUMERATION`**, ahead of the read's raw and partial-Date gates and of `MVK_CATEGORY_UNKOWN`, over a raw String, a String, a partially known Date and a full Date alike. It does so as a comparison side, a scalar value list's member or subject, a value-list quantifier's field, starred or not, a computation's copied source into a nonrepeatable or a repeatable target, and an entity list's member inside `Sum`, `NumberOfFilledFields`, `DateRangesOverlap`, `AtLeastOneDateRangeOverlaps` and `FieldValuesNotUnique`. An unstarred repeatable level meets the walk first, whether the category reads a group or a field. **An entity list whose carrier refuses a category draws `MVK_CATEGORY_NOT_ALLOWED` for an Enumeration's category** ([inbound](../docs/SOURCES.md#inbound-2026-09-26b-entity-list-category)): the nine field-fill predicates, `DateRangesOverlap`, `FieldValuesNotUnique`, `NumberOfFilledFields`, `NumberOfFilledGroups`, `NumberOfDifferentValues`, the five group-list quantifiers, `GroupFilled`, `GroupNotFilled` and `RepetitionNotUnique`. The three counts ask it ahead of the list's repeat, and the other carriers measured behind it, so beside a repeated operand `AllFieldsFilled`, `FieldValuesNotUnique`, `AtLeastOneGroupFilled` and `RepetitionNotUnique` draw `MVK_DUPLICATE_PARAM1`. The category is part of the operand's identity for that repeat, so `AllFieldsFilled(Tier -> Level, Tier)` draws the category class. On `GroupFilled` and `GroupNotFilled` the category class answers ahead of the field class a category-free field draws, and on `RepetitionNotUnique` ahead of the class a root rule draws.
- **A repeatable or parallel computation target, and a rule declared in a repeatable group, read as a nonrepeatable target and a root rule do** ([checkpoint](../docs/sources/static-admission-and-class-probes.md#src-field-value-read-predictions)). Into a repeatable Number, Enumeration or String target a fixed group draws `MVK_NO_GROUPS_ALLOWED` and a raw String `MVK_INVALID_RAW_TYPE`, and into a Number or an Enumeration target a partially known Date draws `MVK_INVALID_DATE_TYPE`. The walk starts from the target's scope, so the target's own group passes it and draws `MVK_NO_GROUPS_ALLOWED`. A parallel iteration's operand reads the same way, a fixed group inside the keyed operand group and that group itself drawing `MVK_NO_GROUPS_ALLOWED`. A rule declared in a repeatable group draws the group and raw classes on an arithmetic operand and the group class on `Length`'s parameter.
- The **`$`** operator switches resolution to the complete captured outer repetition environment. Statically a marked read is judged as the same read outside any filter, against the rule's error field, except that a marked read carrying a semantic index still draws `MVK_SEMANTIC_INDEX_NOT_ALLOWED` where no other class answers first, and the filter's walk does not see it ([§9](07-repetition-and-iteration.md#3-the-filter-having-the--correlation-and-aggregation), [inbound](../docs/SOURCES.md#inbound-2026-09-26d-marked-read)). The marked reference's resolved group/path selects the corresponding level's coordinate, so parent and nested-descendant `$` references may resolve through different row coordinates; correspondingly, `CurrentRepetition` over those paths may yield different indices. `$` may be used **only inside a filter condition**, and not every reference in the filter may be `$`-marked ([§9](07-repetition-and-iteration.md)).

(How a star *binds* the enclosing indices — the anchor rules — is [§9 part 4](07-repetition-and-iteration.md#4-where-a-star-binds--the-anchor-rules-); this section is only about the *path syntax* constraints.)

## 4. Rows are addressed by semantic key, never by position ⚠

The language has **no positional row addressing** — no `[Field At n]`, no neighbour offset.

- **`CurrentRepetition(G)`** yields a numeric index for comparison, arithmetic, or `$` correlation, as detailed in [§9](07-repetition-and-iteration.md); it does not select a row. For a repeatable group it yields the bound row coordinate; for a non-repeatable group it yields the constant `1`. Its semantic domain is therefore a resolved group level, not only a repeatable level. `CurrentRepetition(G) == n` **cannot stand alone**; it must be combined with a condition ensuring the repetition is filled. **Its operand is refused by a first-hit cascade** ([inbound](../docs/SOURCES.md#inbound-2026-09-27a-current-repetition)), measured from a root rule reporting on a root field, on a missing, a fixed and a repeatable group, each plain and starred, as the group and as a field in it, in an ordinary comparison and in a `Sum(Repeating*/Amount Having …)` body: a name that resolves to nothing draws `MVK_INVALID_ENTITY`, a star on a fixed group `MVK_INVALID_WILDCARD`, an unstarred repeatable level outside a filter `MVK_NO_WILDCARD`, a field `MVK_NO_FIELDS_ALLOWED` even starred, and a starred repeatable group `MVK_NO_WILDCARDS_ALLOWED`. The unstarred groups are admitted, except that inside the filter a fixed group draws `MVK_NO_ITERATION_FOR_WILDCARD` while the filtered repeatable group itself is admitted.
- The **only row-selection form** is the **semantic index** `[Field For key]` (equivalently `Group For "value"`), which addresses a row by an **index-field value**.

**A key addresses the level of the group declaring the index, and only that level** ([inbound](../docs/SOURCES.md#inbound-2026-09-25i-key-addressing)). A sound key addresses its read, so each operand gate measured, probed on an operand it refuses, answers with its own class, as for a read of a level the rule iterates, where the same read unkeyed from the root draws `MVK_NO_WILDCARD`. Several index fields on the keyed path draw `MVK_MULTIPLE_INDEX_FIELDS`, but several repetition layers are not refused as such: an unindexed repetition above the index group still needs the rule's own iteration, a star there drawing `MVK_SEMANTIC_INDEX_BELOW_WILDCARD`. So from the root `Riders/Legs/Amount For "X"` over an unindexed `Riders` draws `MVK_NO_WILDCARD`, and from a rule declared inside `Riders` it reaches `Sum`'s arity class. An index declared on the root or on a fixed group addresses no repetition.

**A defective key answers before the operand's gate.** No index group on the path draws `MVK_NO_INDEX_FIELD`, a field key of another kind `MVK_INDEX_TYPE_INCONSISTENT`, a constant the index field refuses `MVK_INDEX_VALUE_INVALID`, over an Enumeration index ahead of the operand's own filter too, and a key that itself crosses an unbound repetition `MVK_SEMANTIC_INDEX_INVALID_ITER`, outside a filter body, where the filter's own classes answer. That last class belongs to the key: the keyed value crossing an unbound repetition draws `MVK_NO_WILDCARD`, so the class says whether the refused read stood inside the key, not whether it carried one. Of two reads, the one first in the text answers.

The semantic index is **unsupported** with a star at or above its index group, and with certain predicates; a star below the index group is admitted. One further combination has its own class: a **field-valued key read from inside the indexed group itself** is refused `MVK_SEMANTIC_INDEX_CONTAINED_IN_INDEX`, so a rule iterating that group cannot key the lookup by its current row's own field. The same lookup keyed by a field outside the group, or by a literal, is admitted from that iterating locus.

Admission after selection is operator-specific. An indexed field is admitted by `NumberOfFilledFields`; an indexed group is admitted by `AllFieldsFilled` and `NoFieldFilled`, while the corresponding unindexed repeatable group reports `MVK_NO_WILDCARD`. `NumberOfFilledGroups` and `RepetitionNotUnique` instead refuse semantic-index operands with `MVK_SEMANTIC_INDEX_NOT_ALLOWED`, and a star draws the class of where it stands against the index group, the nearest group on the entity's chain declaring an index field: at that group's own level `MVK_SEMANTIC_INDEX_AND_WILDCARD`, on a level above it `MVK_SEMANTIC_INDEX_BELOW_WILDCARD`, inside the key `MVK_SEMANTIC_INDEX_WITH_WILDCARD`, and below it none ([`kf351`](../../a12-rulekit/docs/KERNEL-FINDINGS.md#kf351), [inbound](../docs/SOURCES.md#inbound-2026-09-25i-key-addressing)). `RuleGroup For "key"` uses this same selector for the containing group rather than introducing another addressing mechanism. In an entity list a keyed group and a keyed field of it repeat only under one key: `Sum(Claims For "X", Claims/Amount For "X")` draws `MVK_DUPLICATE_PARAM2`, and with the field keyed `"Y"` nothing repeats and `Sum` draws its number class ([inbound](../docs/SOURCES.md#inbound-2026-09-25i-keyed-duplicate)). A **keyed field list whose star stands below the index group** keeps its list role: with the key on `Packages` and the star on its repeatable `Parcels`, `NumberOfFilledFields`, `NumberOfDifferentValues`, `NoFieldFilled`, `AllFieldsFilled`, `AtLeastOneFieldFilled`, `FieldValuesNotUnique`, `AtLeastOneFieldValueIncludedInValueList` against a literal or a field, `Sum`, `MinValue` and `MaxValue` over one or two such lists, and `SumOfProducts` are admitted under a string key, and `NumberOfFilledFields` and `NumberOfDifferentValues` under a field-valued key too, while the same list with a `Having` draws `MVK_SEMANTIC_INDEX_NOT_ALLOWED`, and a `$`-marked list or a `$`-marked key from a root rule `MVK_INVALID_OUTER_ITERATION`. `NumberOfFilledGroups` asks the index before the field kind: a keyed lower-star field draws `MVK_SEMANTIC_INDEX_NOT_ALLOWED` beside a sound group operand in either order and a keyed scalar field draws it before one, where the unkeyed field draws `MVK_NO_FIELDS_ALLOWED` ([inbound](../docs/SOURCES.md#inbound-2026-09-27a-keyed-lower-lists)). No admission verdict transfers to an operator absent from this measured matrix; [§9](07-repetition-and-iteration.md) owns the group/entity-list carrier clauses.

**A `Having` written after a field-valued key is the key's own filter** ([inbound](../docs/SOURCES.md#inbound-2026-09-25c-key-filter)). The key is an entity specification, which takes a filter, while a string key is a literal and takes none. So in `Sum(Claims*/Amount For Reference Having [Claims/ClaimRef] == "X") > 0` the filtered entity is the unstarred key `Reference`, and the filter's `MVK_WILDCARDS_REQUIRED` answers where the same operand unfiltered draws the index's `MVK_SEMANTIC_INDEX_AND_WILDCARD`. The same class answers with the operand unstarred and on a starred group operand carrying the index. A group key draws `MVK_NO_GROUPS_ALLOWED`, and a starred key `MVK_SEMANTIC_INDEX_WITH_WILDCARD`, as it does unfiltered. After a string key the `Having` is the operand's: starred, the index's `MVK_SEMANTIC_INDEX_AND_WILDCARD` answers, with a bad name in the body too, and unstarred the filter's `MVK_WILDCARDS_REQUIRED` answers where the same operand unfiltered reaches the aggregate's `MVK_PARAMSIZE_INVALIDN`, while an unstarred group operand draws `MVK_NO_GROUPS_ALLOWED`. Where the key's filter raises its classes around its body is [§9](07-repetition-and-iteration.md)'s.

Index-key identity belongs to the declared index field. For a **Number** index field, both each admitted stored key and the requested literal or field-valued key are normalized numerically before lookup, so decimal spellings such as `5` and `5.00` select the same row. This lookup normalization does not widen literal authoring: a `For` literal is first format-checked against the index field's declaration during code generation and is rejected with `MVK_INDEX_VALUE_INVALID` when it does not fit. Thus a field with `minFractionalDigits = 2` rejects `For "250"` even though an admitted `For "250.00"` and stored numeric `250` would normalize to the same lookup key. **The check is a shape, one rule per kind** ([inbound](../docs/SOURCES.md#inbound-2026-09-26-index-key-shape)). A Number key is an optional minus, ASCII digits and a fraction after `.` or `,` whose digit count lies within the declared fraction bounds, no fraction counting as none and a field declaring no fraction admitting none; the integer digits and a leading zero are not asked, so `05` and `12345` pass where `+5` does not. A temporal key matches its format one digit per component letter, so `2020-13-45` passes `yyyy-MM-dd`, and a date-range key is two such dates around its separator. A Boolean key is exactly `true` or `false`, a Boolean declaring the custom values `J` and `N` refusing both, and a Confirm key is only `true`. A String key meets its declared length bounds and its declared pattern over the whole key, either failing refusing it, and the pattern is matched over code points, so `😀` is one character to `[^0-9]{2}` and fails it where the key `😀a` passes, both beside the repertoire refusal ([inbound](../docs/SOURCES.md#inbound-2026-09-26m-index-key-pattern)); the empty key is refused on a String index. A key's line terminators reach both checks normalized, a CRLF to LF and a lone CR kept, measured on string keys written in the condition, which does not separate the key's own normalization from the condition text's, and unmeasured for a field-valued key: against the pattern `a\n` the keys `a` + LF and `a` + CRLF pass and `a` + CR fails, against `a\r` only `a` + CR passes, `a\r\n` passes none, a maximum length 2 admits all three and a minimum length 3 none. The pattern is Java's, matched against the whole key, and the peer's grid confirms that dialect on its case-insensitive flags, escaped code points, class union, intersection and complement, and property classes; captured backreferences are unmeasured ([inbound](../docs/SOURCES.md#inbound-2026-09-27a-index-key-dialect)). An Enumeration key is one of its stored tokens exactly, case-sensitively and never a label ([inbound](../docs/SOURCES.md#inbound-2026-09-25i-literal-key)). **A key written without quotes is no literal**: a digit sequence is read as an entity name and draws `MVK_INVALID_ENTITY` over a String, an Enumeration and a Number index alike, a leading zero included, while a decimal does not parse and draws `MVK_UNEXPECTED_TOKEN`. For every non-Number index field, lookup uses exact internally stored text instead; a String key that visibly resembles a Number is not numerically normalized. Empty and formally invalid index keys do not become selectable entries, and duplicate participants are unavailable rather than resolved by row order — measured as **UNKNOWN** rather than empty, separated by a presence operand that fires on a no-match and stays silent on a duplicate, with the index reporting `uniqueIndex` on each participating index cell. A formally invalid *matched* cell reads UNKNOWN the same way, reporting only its own class. **A star below a keyed parent expands inside the selected row** ([inbound](../docs/SOURCES.md#inbound-2026-09-27a-keyed-parent-stars)): with `P1` holding two `Items` weighing 2 and 5 and `P2` holding only its key, `Sum`, `NumberOfFilledFields`, `MaxValue` and `MinValue` of `Packages/Items*/Weight For "P1"` read 7, 2, 5 and 2, `NoGroupFilled(Packages/Items* For …)` is false for `P1` and true for `P2` and for an absent key, a duplicated `P1` leaves `NoFieldFilled` silent, and `FirstFilledValue` falls through `P2`'s empty list to its next operand, on both runtime strategies. **A field-valued key meets the index field's kind as a parallel iteration's two index fields meet each other** ([§9](07-repetition-and-iteration.md)), on the pairs measured, and draws `MVK_INDEX_TYPE_INCONSISTENT` where they split: a date-range key beside a Date index field and the reverse, while a Date index admits a Date and a DateTime key and a date-range index a date-range key ([inbound](../docs/SOURCES.md#inbound-2026-09-25b-index-type-table)), and a Number key beside a String index field splits too ([§9](07-repetition-and-iteration.md)).

### 4.1 What a semantic-index read yields

- A **matched, filled cell** reads its value.
- **No matching row** *and* a **matched-but-empty** cell **both read as the kind's empty value** ([§2](03-empty-and-required.md)) — a number reads the fillable `0` (so `[X For "k"] == 0` fires and types OMISSION), a string/date reads NOT-GIVEN. Crucially, a no-match is **empty, never "unknown"**.
- As a **presence** operand, an absent row is judged like an empty cell (**FALSE**) — `FieldNotFilled(X For "k")` **fires** when no row carries the key.
- A **malformed matched cell**, or a **formally-invalid key field**, reads **UNKNOWN**.
- **A keyed group operand reads the selected row's cells, a repeatable level below the key included** ([inbound](../docs/SOURCES.md#inbound-2026-09-25g-keyed-group)). `NumberOfFilledFields(Packages For "P1")` counts every filled row of a repeatable `Items` below the key, where collapsing that level to its first row counts fewer, and `AllFieldsFilled` reads that level's declared rows. A key no row carries reads every cell empty, and a key two rows carry is undecided while a deciding sibling operand still fires. A malformed cell in the selected row keeps `NumberOfFilledFields` and `NoFieldFilled` silent in validation, and in computation `NoFieldFilled` over it poisons its alternative while `AtLeastOneFieldFilled` stops at the filled key. Under partial validation a key no row carries decides nothing while the key column is outside the coverage. Statically, `Sum(Packages/Items For "P1")` over a repeatable group below the key draws `MVK_NO_WILDCARD`, and starred it meets `Sum`'s number gate. Confidence limit: one model, both Kernel strategies agreeing.
- **A malformed field-valued key is not a key that matches no row.** It makes every keyed consumer unusable ([inbound](../docs/SOURCES.md#inbound-2026-09-23d-grandparent-fill-and-malformed-key)). In validation it reads unknown under group presence and its negation, a multi-operand group quantifier, field presence of either polarity, a value comparison, and `FirstFilledValue` over the keyed group alike, so none of them fires, while a key matching no row fires the negative-presence consumers and a zero comparison over `FirstFilledValue`. In computation the same read poisons the precondition or operation holding it, so the table aborts rather than falling through to a later alternative. Confidence limit: measured for a Number index field keyed by a Number field holding malformed text.

### 4.2 Per-lookup (validation) vs per-column (compute)

- **Validation-side** indexed reads are judged **per lookup**: a malformed key cell *elsewhere* in the column does **not** suppress a clean match; but an *unresolvable no-match* over a column that contains **any** not-check-relevant cell **suppresses** the referencing rule.
- **Compute-side** is **stricter — per column**: any invalid cell in the index column clears every reading computation ([§11](09-computations.md)).

> **Non-normative implementation note.** Make indexed lookup phase-aware and return a `CellObservation`, with **no match returning `empty`** rather than `unknown` or `poison`. This is the load-bearing difference from “missing ⇒ invalid,” and it is why `[X For "k"] == 0` and `FieldNotFilled(X For "k")` fire on absence. Keep the validation-per-lookup versus computation-per-column strictness as an explicit lookup policy: validation checks the selected cell plus the documented no-match invalid-column guard, while computation can poison from the index column. Keep `CurrentRepetition` as a value-producing operand shaped around a resolved group level: return `1` for a non-repeatable level, otherwise read the named repeatable level's coordinate from the selected `Env`; `$` chooses the captured outer environment before that lookup. It is not a positional row selector; omit any positional-select constructor from the AST, and fail closed on a missing or ambiguous repeatable binding.
