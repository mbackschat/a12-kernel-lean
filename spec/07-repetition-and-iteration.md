# 07 — Repetition, iteration, and cross-array evaluation (§9)

A flat rule fires zero or once. Repeatable data creates **per-row rule messages only through an iteration-bearing condition reference**: a star consumed operand-locally by an aggregate reopens that operand's row stream without itself producing one rule evaluation per reopened row. Several constructs turn a rule into a small **query language over arrays** — joins, correlated subqueries, aggregates, uniqueness.

The model to hold: **iteration produces a set of repetition contexts** (the `Env` of [`01-data-model.md §2.1`](01-data-model.md#21-repetition-contexts-the-iteration-environment)), the rule is evaluated once per context, and each construct says how that environment is built and extended:

1. which references make a rule iterate, over which domain, where its message lands, and which conditions are admitted inside the iteration (§1);
2. how two repeatable groups that are not nested are joined by key (§2);
3. how a `Having` filter selects a starred operand's rows, how `$` correlates them with the iterating row, and how aggregates consume the selected stream (§3);
4. which levels a star binds and which it reopens, and what a row beyond its declared capacity contributes (§4);
5. group presence and the repetition predicates built on it (§5);
6. the per-row uniqueness relation `RepetitionNotUnique` (§6).

---

## 1. When a rule iterates, and where its error lands

### 1.1 Iteration scope

**A rule iterates when its condition contains an iteration-bearing repeatable reference, and its iteration scope is derived from the condition's references — never from the rule node's placement or from the error entity by itself.**

- An ordinary unstarred reference contributes its repeatable path.
- A starred operand contributes only the already-bound repeatable prefix strictly above its first `*`; the starred level and every level below it are reopened by that operand rather than added to the surrounding rule iteration (§4).
- Candidate-local references inside `Having` belong to the operand-local traversal rather than to the surrounding rule scope (§3).
- A semantic-index operand replaces only its selected level: its payload binds its ordinary ancestor levels, the selected level is not ordinary iteration, and a field-valued key retains its own authored scope (§1.4).
- Compatible nested references select the deepest ordinary nonparallel path. Incompatible sibling or cross-branch paths require the separate parallel-iteration construction of §2; they are not merged positionally.
- **The error entity alone is not an anchor.** A rule whose error field sits deeper-repeatable than its condition references keeps the references' scope; the error field does not deepen iteration on its own.

Example: a rule with error field `Round` inside a repeatable `Poker` group, condition `FieldFilled(Poker/Round) And [Poker/Win_Loss] >= 0`, evaluates once per round of the rule iteration domain (§1.3), fires only at an existing round whose `Round` is filled, and reports on the offending round.

Two bounded cases fix where a message lands when the scope does not cover the whole error path:

| Case | Evaluation | Message address |
|---|---|---|
| **No iteration-bearing reference** (no repeatable non-starred reference) | At most once, anchored at its error entity, regardless of its declaring container's instance content; the declaring group matters only for resolving relative references. When the error field lies in a repeatable root group the rule does not iterate, the rule runs once at that root's first row with no content gate; otherwise the run is subject to the whole-condition content gate of [§2 A.4](03-empty-and-required.md#a4-the-row-gate--where-the-substitutions-stop) over the error field's root instance. | Every repeatable error-path level the empty scope does not bind is pinned to concrete repetition `1`, unless the selected-reference reanchoring of [§10 §4.3](08-paths-and-references.md#43-selected-references-in-validation-messages) replaces that level. The address may name a physically present first row or a first row with no stored content; this is not the partial-validation phantom row of [§1 §2.2](01-data-model.md#22-over-repetition-and-phantom-rows). |
| **Error-only levels** (the derived scope is a proper prefix of the error field's repeatable scope) | Once per iteration context; deeper error-path levels neither multiply the domain nor require a stored row at the emitted address. | The iterated prefix is preserved and every remaining error-path level uses coordinate `1`, unless [§10 §4.3](08-paths-and-references.md#43-selected-references-in-validation-messages) reanchoring replaces it. A parent-group condition reporting on a child field therefore emits at the first child under each firing parent, even when that child is absent, and a child-star aggregate keeps the same parent-bound address. |

Error-field membership and the per-level reference checks of §1.5 still apply in both cases. Omitting `[1]` in a rendered projection does not turn an address into a declaration pointer; the exact/message-pointer distinction is [`01-data-model.md §2.1`](01-data-model.md#21-repetition-contexts-the-iteration-environment). Rule placement remains irrelevant.

### 1.2 The document the rule iterates

**Runtime evaluation uses the V2-effective repetition structure.** A mutable V1 document may contain only a placement at repetition `n`, but validation and computation first convert it to immutable V2. That conversion creates missing ancestors and pads repetitions `1..n-1` with empty group instances, scoped independently under each concrete parent. Those padded repeatable rows are instantiated content and participate in per-row iteration exactly like explicitly created empty rows.

This is not an alternative sparse JSON encoding: every object in a canonical Document JSON array is explicit, including `{}`. At the Kernel Document JSON conversion boundary:

- **Non-object array elements** (including `null`, scalars and nested arrays) are discarded before surviving objects receive consecutive coordinates. A null prefix therefore does not create predecessor rows or preserve the original JSON index; an explicit empty object does. This normalization applies independently within each surviving parent. It is separate from field-valued `null`, which remains present-empty.
- **A member the model declares nothing for is dropped**, leaving no cell, no group and no validation finding, so a document carrying it validates exactly as the one without. Measured members: an undeclared string or object member of a fixed group; an undeclared string key inside a repeatable row; a boolean, `null`, number or array member of a fixed group; an object in a nested fixed group or inside a row; a string beside the root group. Unmeasured: an undeclared boolean, `null`, number or array member inside a row; an undeclared member of any kind other than a string at the document root; any notification the conversion raises for a dropped member.
- A declared member whose JSON shape does not fit its declaration (an object where a repeatable group is declared, an array where a fixed group is declared, an object or array where a field is declared) is not stated.

Sources: [conversion checkpoint](../docs/sources/evaluation-and-application-routes.md#src-json-row-normalization), [undeclared-member checkpoint](../docs/sources/domain-ingestion-probes.md#src-undeclared-document-members), [inbound 2026-10-23](../docs/sources/inbound-handbacks.md#src-inbound-2026-10-23) (KF1).

### 1.3 Evaluation domains

**Each consumer of repeated data walks its own domain, and no domain may be substituted for another.** Physical rows alone determine none of them. This chapter defines each domain once:

| Domain | What it walks | Defined in |
|---|---|---|
| **rule iteration domain** | the coordinates an ordinary full-validation rule is evaluated at: declared slots in a small declared space, occupied coordinate prefixes in a larger one | this section |
| **uniqueness relation domain** | occupied coordinate prefixes under depth-wide document bounds, always | this section |
| **instantiated rows** | the in-capacity instantiated rows of each level a star or group operand reopens | §4.3 |
| **declared capacity** | every declared slot `1 .. repeatability` of each reopened level; a missing slot reads empty and creates no row | §4.2 and [§1 A.4.2](02-logic-and-formal-errors.md#a42-the-two-iteration-ranges) |
| **filter traversal extent** | the coordinates a filtered star tests, each starred depth running to its highest stored repetition, then searched dense or sparse by consumer | §3.9 |
| **computation target domain** | the in-capacity instantiated rows of a repeatable target; excluded rows stay in the clearing domain | §4.3 |
| **join domain** | the union of index tokens of two joined groups within each common or frame row | §2.3 |
| **relevant set** | the coordinates a partial call admits | [§12 §5](10-validation-and-polarity.md#5-full-vs-partial-validation) |

Which consumer uses which domain:

| Consumer | Domain | Width source | Threshold | Reset rule | Over-capacity rows | Lookahead |
|---|---|---|---|---|---|---|
| ordinary full-validation rule (single root, nonparallel) | rule iteration domain | declared capacities, the root's included | declared product `> 5` → occupied prefixes | coordinate `1` at every axis reset | each axis bounded by its capacity | — |
| frame of a parallel rule and the levels below a joined side | rule iteration domain, the joined level counted once | as above | as above | as above | as above | — |
| `RepetitionNotUnique` duplicate relation | uniqueness relation domain | depth-wide document maxima in the searched levels | none: always occupied prefixes | coordinate `1` at every reset | key cells beyond capacity drop their row (§6) | — |
| unfiltered star or group operand of an aggregate, quantifier or count | instantiated rows (declared capacity for a declared-range scan) | in-capacity instantiated rows | — | — | outside the domain | a prefix consumer stops at its decision |
| filtered star | filter traversal extent | highest stored repetition per starred depth; in a computation, the whole-programme cache scope | product `> 100` → sparse, for a sparse-enabled consumer only | dense search below a changed axis until a candidate is kept | capped by capacity | one kept successor |
| repeatable computation target | computation target domain | in-capacity instantiated rows | — | — | not computed into; a stored value is cleared | — |
| partial validation | relevant set over the declared-capacity domain | [§12 §5.2](10-validation-and-polarity.md#52-which-rules-run-and-where) | — | — | — | — |

Stored group presence, starred operands, automatic field checks, parallel identity and computation each keep their own domain; full-rule coordinates do not add stored rows, materialize a group, affect a physical starred operand or create a computation target. [The operator reference](14-operator-reference.md#traversal) assigns each operator the domain its operand walks and its filter scan.

**The rule iteration domain.** For the single-root, nonparallel rule route:

- **Root dispatch.** The root dispatcher selects root instances with stored admitted content or explicit repeated descendants, bounded by the root's declared capacity. ⚠ A rule evaluated without admitted content — a presence condition that can hold on empty, a count on a comparison's small side, or a read of a second root ([§2 A.4](03-empty-and-required.md#a4-the-row-gate--where-the-substitutions-stop)) — also runs under a nonrepeatable root that holds none. On `{}` and `{"Order":{}}`, `FieldNotFilled(Gifts/Note)`, `NumberOfFilledFields(Gifts/Note, Gifts/GiftNo) < 1`, `FieldNotFilled(Gifts/Note) Or FieldFilled(Gifts/GiftNo)` and `[/Other/O] < 5 And FieldNotFilled(Gifts/Note)` reporting on `Gifts/Note` fire at both declared rows of the twice-repeating keyed `Gifts`, as a group target `Gifts/Card` does, while `[Email] == "e" And FieldNotFilled(Gifts/Note)` waits for `Email`. A second root's read dispatches alone: `[/Other/O] > 5 Or FieldFilled(Gifts/Note)` fires at both rows of a blank `Order` once `O` exceeds five. Dispatch under a repeatable root is not observed: every negative or small-side count measured over a repeatable root, a nested keyed level or an unkeyed level is refused `MVK_NEG_CONDITION_IN_ITERATION` or its own class, and the second-root rule measured over a repeatable root is admitted only beside a positive presence that needs content.
- **Declared product.** The rule's declared iteration-bound product includes the root capacity before dispatch pins a root coordinate. At product ≤ 5 the rule traverses every declared child slot. At product > 5 every axis reset still visits coordinate `1`, while each subsequent coordinate requires an occupied coordinate prefix.
- **Occupancy** is document-wide and independent of group identity, and includes fixed hierarchy levels: another group's rows at the same coordinate prefix can widen the domain. Each axis remains bounded by its declared capacity.
- A missing child context does not materialize a group, affect physical starred operands or create a computation target.
- Measured scope: capacities 2, 5 and 6; products 2×2, 2×3 and 2×6; fixed intermediate groups; root repetition; foreign-root occupancy; over-capacity inputs. Partial validation and global or cross-root dispatch are separate boundaries.

**The uniqueness relation domain.** `RepetitionNotUnique` always uses the occupied-prefix iterator over depth-wide document bounds in its searched levels, retaining coordinate `1` at each reset. It does not inherit the enclosing rule's dense small-space traversal. The 2×2 and 2×3 ancestor-key/optional-child controls both report only the two first-child duplicates; the extra dense rule coordinates acquire no duplicate merely because the ancestor key is filled. A coordinate absent from the duplicate cache does not fire the predicate.

> **Non-normative implementation note.** Compute ordinary iteration scope from checked condition references, retaining lexical origin separately from row binding. Enumerate validation contexts from the declared-product and occupied-prefix rules; preserve complete parent coordinates and the error-only suffix rule. Keep each consumer's domain a separate function rather than one shared enumeration.

### 1.4 The reference set

**The reference set of a condition is every reference outside every filter body, plus the `$`-marked references inside filter bodies.** The error-field reference gate and the iterating-reference gate of §1.5 read only this set; this section is the one owner of what it contains. A reference reaches an error field in one of three roles: **direct** (the same entity), **containing** (a non-root group at or above it) and **form** (the root group at or above it). The roles overlap — an error field that is itself a group makes one reference fill two — and the Kernel unions them rather than partitioning.

| Reference | Contributes to the reference set |
|---|---|
| a direct field reference: a value read, a presence test, a field operand of a list operator | that field |
| a non-root group operand: a group presence such as an enclosing `GroupFilled(Group)`, a group operand of an entity-list quantifier, a group operand of the numeric filled count | every field in its recursive subtree, in the depth rule of [§1 §3.1](01-data-model.md#31-rules-validation), as a containing reference to each field and group inside it |
| a semantic-index selection `P For K` | its payload `P` (a field, or a group's expansion) and a field-valued key `K`; merely consulting the declared index column does not reference the index field, while explicitly selecting the index field does |
| an authored `RepetitionNotUnique` `@From G` | the whole subtree of `G`: fields inside `G` and its descendant groups, not parent fields |
| the root group | the form role only, which leads to the root-group cascade of §1.5 |
| an unmarked read inside a `Having` body | nothing |
| the keys' own group of a `RepetitionNotUnique` without an authored `@From` | nothing, even when default scope resolution selects the same group |

So a `Having` body's unmarked read does not reference the error field: `Sum(/Shipment/Received*/Quantity Having [/Shipment/Received/Note] == "x") > 0` reporting on `Note` draws `MVK_ERROR_FIELD_NOT_REFERENCED`, while `Sum(/Shipment/Received*/Quantity Having [/Shipment/Received/Quantity] > 1 And [$Note] == "x") > 0` is admitted, and the root group named only inside a body reaches nothing. Dropping `@From` rejects the inside and descendant error fields that the authored `@From` admits, so an implementation must retain whether `@From` was authored rather than reconstructing it from the resolved scope. The semantic-index row rests on Kernel source reading and is unmeasured; the other rows above are measured; another reference form is unmeasured.

**A group error entity is referenced by its own presence and by a containing group's presence**, and not by a field inside the group or above it, nor by a group inside it: reporting on the fixed group `Notes`, `GroupFilled(Notes/Remarks)` draws `MVK_ERROR_FIELD_NOT_REFERENCED`, while inside `Lines` the presence of the `RuleGroup` shorthand references a `Lines/Parts` target. Other leaves over a group target are unmeasured.

### 1.5 Error-field admission

The error field must inhabit a scope compatible with the derived iteration, and the reference set must name it. The gates below decide this; where two of them can both apply, the order between them is stated with the gate.

**Scope compatibility.** A genuine cross-cardinality split is rejected `MVK_ERROR_FIELD_NOT_IN_RULEGROUP`.

- With the error field outside the rule group every per-row read draws that class, whatever binds its level: a rule in a repeatable group reporting on the root refuses a read of its own row, and a rule in a fixed group inside a repeatable one refuses a read of the parent row.
- At or below the rule group the error field's own scope binds the levels holding it: from the root with the error field in `Claims/Sub`, `[Claims/Amount] > 0` is admitted while a read of the unkeyed sibling `Plain` draws `MVK_NO_WILDCARD`.
- A read the rule's iteration binds, from the declaring group or from the error field's, meets its slot's own gate. Of a repeatable `Claims`, `FieldFilled` of its fixed subgroup draws `MVK_NO_GROUPS_ALLOWED`, and a Boolean membership subject, `AddDays` and `ValueAsDate` over a String, and `RangeAsString` over a Number draw their own classes, where from a root rule reporting at the root each draws `MVK_NO_WILDCARD`.
- A climbing read is judged at the level it lands on: from a fixed group inside `Claims`, `../`, `../../Claims/` and a keyed `../` read each meet the gate on every operand gate measured, and `../../Riders/` into an unbound repeatable draws `MVK_NO_WILDCARD`.

**Operand locus, before the reference gate.** A condition holding an unstarred repeatable operand read from a non-iterating locus is rejected `MVK_NO_WILDCARD` even when the error field is absent from that condition, while the same unreferenced error field draws `MVK_ERROR_FIELD_NOT_REFERENCED` once the repeatable operand is removed. A starred operand counts as that unstarred read until its stars cover every repeatable level it crosses: from the root, `Sum(Parcels*/Items/Qty) > 0` and `Sum(Parcels/Items*/Qty) > 0` draw `MVK_NO_WILDCARD`, the first with the error field referenced beside it too, and only `Sum(Parcels*/Items*/Qty) > 0` reaches the unreferenced class. The locus gate also runs before whole-list arity: a sole bare overlap operand draws `MVK_NO_WILDCARD` from a non-iterating locus but reaches `MVK_PARAMSIZE_INVALIDFN` from an iterating locus. A consumer that checks error-field reference or arity before operand loci reports a class the Kernel does not.

**The error field must be referenced** by the reference set of §1.4, or the model is rejected `MVK_ERROR_FIELD_NOT_REFERENCED`. This is an admission and error-targeting constraint, not another source of iteration levels. A condition that never names its error field draws this class alone, ahead of the negative-condition guard of §1.8.

**The reference must iterate.** When a direct field or non-root containing-group reference names the error field, every ordinary rule iteration level must also be bound by at least one reference naming that field; otherwise admission reports `MVK_ERROR_FIELD_AND_ITERATION_INVALID`. Membership alone does not establish an iterating reference.

- A starred payload can satisfy membership while reopening its row level, so `FieldFilled(Rows/Other) And Sum(Rows*/Amount) > 0`, reporting on `Rows/Amount`, is refused even though both fields inhabit the same repeated group; replacing the guard with `FieldFilled(Rows/Amount)` admits it. Selected token, Date and DateRange operands follow the same distinction.
- A marked filter read binds its own outer path; merely making an outer binding available to a candidate-only filter supplies no ordinary rule iteration.
- A semantic-index payload's selected level is not ordinary iteration, so a sibling-field guard cannot supply the payload's missing iteration level, whereas an explicit guard on the error field can (source reading, unmeasured). Emitted message references remain a separate projection ([§10 §4.3](08-paths-and-references.md#43-selected-references-in-validation-messages)).
- Under parallel iteration the reference must join the parallel iteration (§2.2).
- Root-group-only references follow the cascade below instead.

**The root-group cascade.** When no direct and no containing reference exists, so the condition reaches the error field through its root group alone, a separate iteration cascade applies; no witness is known of another route drawing its classes:

| Shape | Class |
|---|---|
| plain iteration bound at any level below the root by an unstarred and unkeyed read of that level | `MVK_ERROR_FIELDGROUP_ITERATION4_INVALID` |
| parallel iteration, unless the rule's index field sits at the root-group level | `MVK_ERROR_FIELDGROUP_ITERATION5_INVALID` |
| a condition offending both, in either authored text order | `MVK_ERROR_FIELDGROUP_ITERATION5_INVALID` |
| a starred or keyed read of the error field's own group or of a parallel one, or an unmarked body read | admitted (it binds no iteration there; a marked body read binds it) |

- **The level is bound, not written.** A condition with no wildcard anywhere still draws the plain-iteration class when the rule's own group binds the level, so an implementation testing for a star in the surface admits the rule.
- **Both classes need two further conditions.** The error field's own group must repeat — a wholly flat model is admitted — and the rule must be declared in the error field's own group, since a target outside the declaring group draws `MVK_ERROR_FIELD_NOT_IN_RULEGROUP` from a parse-time containment gate on the own-group and parallel reads alike.
- A repeatable root carrying `indexFieldName` draws `MVK_MULTIPLE_INDEX_FIELDS` during the parse, so a model differing in that one declaration reports that class instead of an iteration class.
- Adding a direct reference to an otherwise identical parallel-iterating condition admits it, which makes this the reference partition's rule rather than the iteration's.

**A group operand needs a path, absolute or relative; its bare short name is refused, and the refusal is about the operand being a group rather than about the root.** `GroupFilled(/Root)` and the relative `GroupFilled(..)` are both admitted and reach the cascade above identically — the same condition draws `MVK_ERROR_FIELDGROUP_ITERATION4_INVALID` under either spelling — so no cascade class depends on how its form reference is written. The bare `GroupFilled(Root)` draws `MVK_INVALID_ENTITY` across every whole-group operator measured, and so does the bare name of a non-root group, while bare field short names are admitted from the identical conditions: the model-wide short-name fallback resolves fields only. A relative walk that leaves the model draws `MVK_TOO_MANY_PARENT_GROUPS`, and `.` is not a spelling of the current group, drawing `MVK_UNEXPECTED_TOKEN` from the grammar.

### 1.6 The error target's declaration

**The error field's declaration is checked before the condition's grammar.** The Kernel resolves the rule's error entity and refuses a null one (`MVK_MISSING_ERROR_FIELD`) before it parses the condition at all, so a rule with no usable error field reports that class and none of the syntax classes its condition would otherwise draw.

- A declared relative path that resolves to nothing lands in the same class, beside `MVK_ERROR_FIELD_MISSING`, the pair [01 §3](01-data-model.md#3-rules-and-computations) also names for a blank path. `MVK_ERROR_FIELD_NOT_VALID` is the narrower state of an error entity that resolves but is absent from the model's entity container, and it — unlike the missing class — is suppressed under a lenient parse.
- The failed target withholds the message's error-text classes too, `RULE_HAS_NO_ERRORTEXT` included, exactly as a refused condition does ([11](11-messages-and-custom.md#part-a--13-error-message-interpolation)). A reserved rule name's `MVK_RULE_NAME_INVALID`, a blank code's `MVK_ERROR_CODE_MISSING` and a missing or blank text's `MVK_ERROR_MESSAGE_MISSING` are reported beside the pair, and so is `MVK_ERROR_MESSAGE_FOR_LANGUAGE_MISSING` when one of two declared locales has a text.
- A target naming a group is an ordinary declared entity: with `../Items` as target and a condition reading only `Value`, the rule draws `MVK_ERROR_FIELD_NOT_REFERENCED`, which withholds the error text and gives way to an unresolved name.

**The declared path climbs from the rule element and takes `..` lexically.** From a rule in `/Order`, `../Code` names `/Order/Code`, while `Code` names a child of the rule element and draws `MVK_ERROR_FIELD_MISSING` with `MVK_MISSING_ERROR_FIELD`. An up-step after a named segment is admitted, `../Meta/../Code` naming `/Order/Code`, where a condition reference refuses it as a token. Under a condition naming no group, a path landing on a group draws `MVK_ERROR_FIELD_NOT_REFERENCED` (`../Meta`, `../Meta/Ref/..`), except on the group the rule is declared in, where the model fails to build and no class is reported, by whichever spelling reaches it (`../Code/..`, `../../Order`); to a rule declared in `/Order/Meta` the root is an ordinary group (`../..`). A computation's target naming any group, its own (`..`) or another, fails the build.

### 1.7 A group as error entity

**The error entity may be a group, whose own level is not iterated.** A rule reporting on a non-root group fires at the group's own pointer, once per row of each iterated level above it. When the group itself repeats, the message names its first row, rendered bare as `Order/Lines[2]/Parts`.

- **Reads at the group's level.** An unstarred field read at that level reads the first row, and so does a fixed subgroup's presence, while the group's own presence reads every row: `GroupFilled(Lines/Parts)` fires on a line whose only filled part is its second.
- **References** follow §1.4.
- **Iteration and guard.** Only the iterated levels above the group need a binding reference, so `GroupFilled(Lines) And FieldFilled(Lines/Parts/Count)` is admitted, while the negative-condition guard still judges the group's own level: `FieldFilled(Lines/Sku) And GroupNotFilled(Lines/Parts)` draws `MVK_NEG_CONDITION_IN_ITERATION` with `Lines` guarded.
- **Message type, fill-to-fix entries and references come from the condition's leaves** ([§12 §3.1](10-validation-and-polarity.md#31-truth-testing-and-message-classification)). The group's own presence alone fires a `VALUE_ERROR` with no fill-to-fix entry and references the group's fields at the pointer's rows, and its negation an `OMISSION_ERROR` listing them; beside it a negative field read or a starred `Sum` makes the message an `OMISSION_ERROR` whose fill-to-fix entries are that read's fields; a containing group's presence references its own fields at the pointer's rows and its repeatable subgroups' fields at row `[0]`.
- **Partial validation** reports no rule on a group target ([§12 §5.2](10-validation-and-polarity.md#52-which-rules-run-and-where), item 3).
- A rule reporting on the root: its admission follows §1.6; its firing is unmeasured.

**A group target beside a parallel join** (§2):

- A group target is admitted beside a joined side: `GroupFilled(Lines/Parts) And FieldFilled(Picks/Ref)` fires once per joined line whose `Picks` row holds `Ref`, at the line's first part.

Measured where the group's key differs from the join key; a group keyed by the join's own key is unmeasured. - Its `GroupNotFilled` twin, which an unkeyed target draws `MVK_NEG_CONDITION_IN_ITERATION` for, is admitted and fires one `OMISSION_ERROR` per `Picks` row holding `Ref`, a line without slots and a pick without a line included, each at `/Order[1]/Lines[1]/Slots` with the group's own coordinate `-5`. ### 1.8 The negative-condition guard

**Static negative-condition admission is checked separately at every ordinary iteration level the rule's iteration selects.** At one level L:

- a leaf is **guarded** at L when it references L and its leaf class admits it there, and **unguarded** when it references L and its class refuses it there;
- an `And` is admitted when at least one child both references L and is itself admitted;
- an `Or` is admitted only when every child references L and is admitted.

Apply this recursively over the authored connective tree. An `Or` conjoined with a negative therefore lends a guard when every disjunct references and guards L: two same-level positives admit, including a presence/comparison pair. Mixing in an off-level positive refuses, and a positive at no repeatable level does not guard L. A condition refused at L draws `MVK_NEG_CONDITION_IN_ITERATION`; at a parallel level the same algebra draws `MVK_PARALLEL_ITERATION_INVALID` (§2.2). A condition that never names its error field draws `MVK_ERROR_FIELD_NOT_REFERENCED` alone, ahead of this gate.

**What "references L" means.** Every rule here asks whether a leaf references L outside filter bodies. A `$` read inside a `Having` lists its level for judging but references it from no leaf (source reading, unmeasured). Besides a presence predicate at L:

- an ordinary value **comparison** on a field at L references L — one conjunct apart from a refused bare negative;
- an **unstarred** reference into a *different* repeatable group also licenses, on field and group presence alike, while the **starred** quantifier over that same field does not, so the level a licensing child names is not always the negative's own.

**The level licence.** A bare negative with no admitting child at all is licensed when the group the negative names both declares an index field **and** has maximum repeatability exactly `2`. Neither conjunct alone does it — three repetitions refuse with an index declared, two refuse without one — and the conjunction holds at the root and nested alike, independently of that group's contents and of whether the rule is declared on it. **The licence belongs to the level, not to the leaf:** such a group's level is not judged at all, so it admits a list quantifier and a count below one there as well, while a negative inside such a group is still judged at an enclosing level that lacks the licence and is refused there unless guarded at that level. The index declaration alone does not license: the bare negative is refused with the index and without it under the same class, even when the error field is the index field itself.

**The gate is syntactic and is not a predicate over the condition's meaning.** `FieldsNotCollectivelyFilled` is grammatically negative and admitted, while `NumberOfFilledFields(G) < 1` carries no negation at all and is refused. Because that count cannot fall below zero, `< 1`, `<= 0` and `== 0` denote one predicate, yet `< 1`, `< 2`, `<= 1` and `!= 1` are refused where `<= 0`, `== 0`, `>= 0`, `> 0` and `>= 1` are admitted; the tautologous `>= 0` passes. So the analysis does not normalize the comparison and does not decide the condition's truth set. It tracks the **iterated** level, not the operand, so one spelling at one polarity can be admitted or refused according to where the error field sits. The positive guard lifts the refusal, e.g. `GroupFilled(K) And AtLeastOneFieldFilled(K/F)`.

**The leaf classes.** Each row is marked by its evidence: *measured* on the Kernel, or *source* (Kernel source reading, unmeasured). A leaf not in this table has no stated class.

| Leaf at L | Guarded when it references L | Unguarded when it references L | Evidence |
|---|---|---|---|
| `FieldFilled`, `GroupFilled`; an ordinary value comparison on a field at L | always, unless a comparison row below refuses the comparison | — | measured |
| `FieldNotFilled`, `GroupNotFilled` (bare) | only under the level licence | otherwise | measured |

**Which operations are zero-sensitive, positive-threshold-sensitive or both.** For a plain or filtered-star Number entity list at one ordinary scope, `FirstFilledValue`, `Sum`, `MinValue` and `MaxValue` are zero-sensitive; `NumberOfDifferentValues` is instead sensitive to a positive threshold under `<`, `<=`, `!=` or tolerance when the count is on the left and the reversed directions when it is on the right; `NumberOfValueInFields` has both sensitivities, and its String/Enumeration overload uses the same zero and positive-threshold branches over its selected target references. A row-aligned plain-star `SumOfProducts` is zero-sensitive but has no positive-count sensitivity. Top-level operation-list `Abs`, rounding, and operand-list `Min`/`Max` whose direct Number references all iterate at L retain the zero-sensitive partition. The direct field operations of §1.10 are zero-sensitive. A filtered entity-list slot contributes its selected target reference to this classifier, not the references inside its `Having`; those filter references retain their separate authoring and runtime roles.

**Semantic-index operands.** A semantic-index operand replaces only its selected level: its enclosing parent levels and any field-valued key's ordinary iteration still contribute to the per-level analysis, and group expansion and a star below the selection preserve that contribution. Entity-operation guards retain their operator-specific zero and positive-threshold rules; the additional rejection of mixed iterating and non-iterating references applies to `Sum`, the extrema, first-filled and the counts, but excludes `SumOfProducts`. These are distinct questions: a mixed product may be admitted at the key's level while an all-iterating zero comparison remains refused at the parent level. Kernel source reading and retained `Sum` disjunctions establish this distinction; other carriers are unmeasured. A field or group selection binds its parent's row and its key's row at the rule's own row, so it is admitted below an unkeyed iterated row and with a key read from the iterated row; the row it selects is fixed, so `Lines/Sku For "1"` references no `Lines` row and does not guard `Lines`. That the evaluator then reads the selection at the rule's row is unmeasured. A clean no-match rule over the keyed negative presence fires **once** with row coordinate `-5`, the Kernel's unknown reanchoring sentinel, which a consumer preserves as *no matching row* rather than rejecting the rule or reading it as wildcard `0`. Once a positive guard makes such a rule iterate, the error field must be referenced through an iterating operand; the keyed lookup itself does not satisfy that requirement and draws `MVK_ERROR_FIELD_AND_ITERATION_INVALID`.

**The slot rule for field-fill and uniqueness leaves.** Over direct fields and finite wildcard field operands, the guard distinguishes ordinary references bound at L from operands that can supply slots independently of that row:

- A direct independent field contributes one slot; a wildcard contributes the product of its declared repetition limits, without evaluating its `Having` filter.
- In the Number, String and temporal uniqueness overloads alike, each field a semantic-index selection reads or a group operand expands to contributes, like a wildcard, the product of the declared limits of its repeatable levels below the selected row or the group, a starred group's own level included. So a fixed group of two direct fields fails `FieldValuesNotUnique` beside the row field where a fixed group of one passes, a fixed group whose one field sits in a two-row repeatable child fails too, and a group inside the iterated row contributes none.
- The field-fill quantifiers weigh a selection the same way, so a constant selection is one independent slot, whether it selects a row of another group or of the iterated group itself, and so is each in `FieldValuesNotUnique`.

| Leaf | Unguarded at L when |
|---|---|
| `AtLeastOneFieldFilled`, `FieldsNotCollectivelyFilled` | at least one independent slot |
| `MoreThanOneFieldFilled`, `FieldValuesNotUnique` | at least two independent slots |
| `NoFieldFilled`, `NotAllFieldsFilled`, `NotExactlyOneFieldFilled` | any list operand ordinarily iterates at L |
| `AllFieldsFilled` | never for multiple operands or a wildcard; its sole direct-field form requires that field to iterate |

Candidate filter reads do not supply enclosing rule iteration. Captured reads can supply that iteration, but do not change the selected list operand's own iteration status. The surrounding `And`/`Or` analysis still applies. These are validation-rule gates; the corresponding computation guards do not apply them.

**Group-list leaves.** For a group-list leaf containing a starred group, a queried level is referenced only by operands whose captured prefix contains that level, and a level outside every operand's captured prefix is not referenced by that leaf. Mixing a fixed operand with an iterating starred operand makes `AtLeastOneGroupFilled` unguarded. These leaf results compose through the same `And`/`Or` rules: an independently guarded conjunct can admit a negative starred list, while a guarded sibling of an `Or` cannot.

### 1.9 Converting the comparison constant

For the direct iterating Number-field-versus-immediate-number-literal shape, and for every zero-sensitive and positive-threshold-sensitive leaf of §1.8, the guard classifies the literal by its **host-converted integer form**, not by its exact decimal sign or zero. The host conversion parses the finite decimal to nearest-even binary64, applies Java `Math.round` — half-up toward positive infinity, with long saturation — and then narrows to signed 32-bit by two's-complement wrap before testing zero or positivity. Exact rational value plus the authored fractional-digit count determines this conversion, because number literals have no exponent and the parser removes only redundant leading zeros; signed zero is the sole lost spelling and has the same converted integer. Three distinct stages produce the gap between the converted form and the exact decimal, and they must not be conflated:

- **Narrowing.** On a **scale-0** field a bare integer literal satisfies the comparison's decimal-places gate and reaches the classifier, where it is judged on its *narrowed* value: `== 4294967296` (`2^32`) is **rejected** because it narrows to zero, while `== 4294967297` is admitted because it narrows to one; a widening or saturating conversion admits both, so this pair pins 32-bit truncation. `2^63` is admitted: rounding saturates at the maximum long, which narrows to minus one. At the long boundary the two signs disagree because the range is asymmetric, not because of the parse step: neither `+(2^63 − 1)` nor `−(2^63 − 1)` is representable in binary64, both parse onto `±2^63`; `+2^63` exceeds `Long.MAX_VALUE` and saturates to `2^63 − 1`, whose low 32 bits are all set, narrowing to minus one; `−2^63` **is** `Long.MIN_VALUE`, passes unsaturated, and has its low 32 bits clear, narrowing to zero. So `== 9223372036854775807` is admitted while `== -9223372036854775807` is **rejected**; exact 64-bit integer arithmetic would narrow `−(2^63 − 1)` to one and admit it. One representable step away, `== -9223372036854773760` is admitted again, since doubles just below `2^63` are spaced 1024 apart and only the low-32-bit residue decides. `== 9223372036854775808` behaves as its neighbour `2^63 - 1` and is admitted, both parsing onto the same double.
- **Rounding.** `Math.round` does **not** lift a double strictly below one half. Its half-up direction is asymmetric about zero: `0.50` converts to one while `−0.50` converts to zero. Half-even would give zero for both and half-away-from-zero one for both. So `0.4` and `-0.5` refuse where `0.5` and `-0.6` admit.
- **Parsing.** Binary64 round-to-nearest-**even** lifts every decimal in `[½ − 2⁻⁵⁵, ½)` onto exactly one half, because that interval's values are ties between `0.5` (even significand) and `0.5 − 2⁻⁵⁴` (odd); rounding then yields one. The lift is positive-side only: a lifted `−0.5` still converts to zero.

**The parse-time lift is authorable behind the one waivable diagnostic.** Its shortest witness needs **17** fractional digits — at sixteen or fewer the interval holds no decimal strictly below one half — while a Number field's maximum fractional digits caps at **14** ([§5 §4.7](04-numbers-and-decimals.md#47-declared-digit-quantities-and-the-fractional-pair)) and a comparison literal may carry at most the field's scale. That literal gate is `MVK_INVALID_COMPARE_DEC_PLACES`, the Kernel's only suppressible code, so the cap raises the authoring cost of the witness rather than forbidding it. Against a scale-14 field with the gate suppressed, `== 0.49999999999999998` is **admitted** and `== 0.49999999999999990` is **rejected**: two literals of equal length differing only in the final digit, both strictly below one half, straddling the partition. The literal gate is *at most*, not equality: a shorter literal is admitted and reaches the partition normally. The historical `floor(x + 0.5)` implementation of `Math.round`, which did lift a double just below one half, is confined to host JDKs before 7 and must not be reproduced.

This section describes static model admission only; runtime still evaluates the original decimal comparison.

## 2. Parallel iteration — joining two repeatable groups by key

When a rule references **two repeatable groups where neither is nested in the other**, they are iterated **jointly, keyed by an index field** that each group declares under the same name, with kinds that form an admitted pair (§2.2). This is an **outer join** over the index values: every key either side carries is visited once per rendered token (§2.3), a side with a row for the key binds that row, and a side without one binds the unmatched sentinel.

```
FieldsNotCollectivelyFilled(Demand/Units, Capacity/Units)   -- iterated per shared Warehouse index value
```

### 2.1 Frames

The repeatable levels above the two joined groups decide how the join nests in ordinary iteration:

| Outer scopes of the two groups | Iteration |
|---|---|
| equal (a **common frame**, possibly empty) | Each common outer row binds both sides before their key union is constructed, so equal keys in different outer rows do not join. That the outer rows follow the rule iteration domain (§1.3) is unmeasured. |
| one a strict prefix of the other (a **one-sided frame**: a repeatable non-indexed level above exactly one joined group) | The frame level iterates ordinarily over the rule iteration domain, and the join runs inside each frame row against the other side. With frame bound 3 the frame visits its third, uninstantiated slot when far-side keys exist; with bound 6 it visits only occupied prefixes plus each reset's first coordinate. |
| frames on both sides that diverge | not stated |

Non-repeatable intermediate groups are **transparent** to the join. Any additional ordinary frame level is checked by the negative-condition guard independently, against references to that level. The rule's declaring group resolves authored paths; it need not be the joined common parent. An error field on the unframed side of a one-sided frame is unmeasured.

A semantic index's key meets its index field on measured pairs of its own ([§10](08-paths-and-references.md#4-rows-are-addressed-by-semantic-key-never-by-position-)).

**Under a legal pair each carrier meets its own gates as on a group that does not repeat.** A group operand meets the same index gates on the rule arm; the multiple-index class is not measured on a group. Then `FieldFilled` and `FieldNotFilled` over the group draw `MVK_NO_GROUPS_ALLOWED`, a sole `NumberOfFilledGroups` `MVK_PARAMSIZE_INVALIDGN`, `Sum` and `NumberOfValueInFields` `MVK_NO_NUMBER`, `FirstFilledValue` `MVK_VARYING_TYPES_NOT_ALLOWED`, and the other measured carriers are admitted. A field read on the joint level meets its scalar slot's own gate the same way: a text field in `RoundUpValue` draws `MVK_NO_NUMBER`, as a text field of a group that does not repeat does, one in `DifferenceInDays` beside such a field draws `MVK_NO_DATE`, and the typed controls are admitted, so neither slot declines a jointly iterated level as unaddressed.

**Prohibited combinations.** Parallel iteration is not allowed over rules using `RepetitionNotUnique` (`MVK_PARALLEL_ITERATION_NOT_ALLOWED`). A filtered star below either joined group draws `MVK_PARALLEL_ITERATION_FOR_FILTERED_ENTITY_NOT_ALLOWED` (§3.1), also from a rule declared inside the error side's group, unless `RepetitionNotUnique` beside the join draws `MVK_PARALLEL_ITERATION_NOT_ALLOWED` first; a filtered star in a group outside both is admitted, and an unstarred read of a joined group's child draws `MVK_NO_WILDCARD`. These gates retain precedence over the two below.

**A reference naming the error field must join the parallel iteration.** When no direct reference to the error field reads the error side's joined level unstarred, and no group containing the error field at or below the error side's joined group is referenced, the rule draws `MVK_ERROR_FIELD_AND_ITERATION_INVALID`, ahead of the guard below. `Sum(Lines*/Qty) > 0 And FieldFilled(Picks/Ref)` reporting on `Lines/Qty` refuses, a read of another field in the error field's group does not help, and `FieldFilled(Lines/Sku) And FieldsNotCollectivelyFilled(Lines*/Sku, Picks/Ref)` reporting on `Lines/Sku` is admitted. A presence of a group above the joined one, such as the unkeyed `Weeks` holding both joined sides, does not join, while one of the error side's joined group does. Beside an unkeyed group the same starred-only shapes form no parallel iteration and draw `MVK_NO_WILDCARD` instead.

**The parallel guard is the algebra of §1.8 at the parallel level**, drawing `MVK_PARALLEL_ITERATION_INVALID`: an `And` needs at least one child that references and guards the parallel level, and every `Or` child must reference and guard it, applied recursively over the authored connective tree. Thus `FieldFilled(L/V) And FieldNotFilled(M/W)` may pass while the corresponding `Or` fails; merely finding a positive leaf anywhere is insufficient. Leaf classification is the operator's static iteration rule, not its runtime truth or message polarity. A presence of the partner group marks its keyed level as a read of its field does: reporting on `Lines/Qty`, `FieldFilled(Lines/Qty) Or GroupNotFilled(Picks)` draws `MVK_PARALLEL_ITERATION_INVALID` and `Sum(Lines*/Qty) > 0 And GroupFilled(Picks)` draws `MVK_ERROR_FIELD_AND_ITERATION_INVALID`, as their twins over `Picks/Ref` do. Nested and disjunctive controls and the combination precedence are measured on Kernel 30.8.1.

### 2.3 Join construction

**The iteration value set is the lexically ordered union of rendered index tokens from the joined groups**, built within each common or frame row (§2.1). For Number keys, each declaration strips unnecessary fractional zeros and pads to its minimum fractional digits; each side then normalizes the iteration token again for its own lookup. Numeric equality therefore determines matching, while rendered-token equality determines the number of visits. With minima 0 and 2, value `5` produces tokens `5` and `5.00`: both select the same pair, so a firing rule can emit twice. Value `5.25` produces one token and one visit. Differing maximum fractional digits join the same way and are admitted from either side: an integer index keyed `1` pairs with a two-place index stored `1.00` or `1.0` but not with `1.5`, one visit each, and rows keyed `2` and `2.00` pair across the two groups whatever their row order.

**Each side's lookup map is keyed by the index field's normalized value, not its stored text**, using the same declared-kind projection as the semantic index. On a Number index field, `5` and `5.00` denote one lookup identity within and across groups; this does not collapse distinct declaration-rendered iteration tokens. On a String index field, the same tokens remain distinct for lookup as well.

**Cache membership, relevance and formal admission precede every index-identity relation.**

- An over-limit row is outside the cache and contributes no key, collision participant, selectable row or column compromise.
- An in-cache stored index cell that is non-relevant for a partial call, empty, built-in-invalid, or rejected by a registered custom type contributes no key, collision participant or selectable row, and **compromises** an unresolved column to UNKNOWN. Relevance is checked first, so excluding a custom cell does not invoke its validator.
- With Number rows `05 -> 10` then `5 -> 20`, lookup `5` selects row 2 while row 1 retains its leading-zero formal error; reversing them selects admitted row 1. With `05`, `5` and `5.00`, the invalid row stays outside the relation while the admitted peers collide, so key `5` is unavailable.
- Presence uses the resolved identity: an unavailable matching key makes both `FieldFilled` and `FieldNotFilled` UNKNOWN.

**A duplicated index value is not a selectable entry.** Every colliding row leaves the map, so row order never resolves the value. The value keys the join only if another group carries it cleanly, and references to it from the compromised group are unmatched and therefore UNKNOWN. A clean value in the same compromised group still joins normally. A duplicated or empty index value marks that group's index invalid for the parent, so references into it read three-valued **UNKNOWN** for unmatched values — which *suppresses* a negative operator like `FieldsNotCollectivelyFilled`.

**An unmatched side reads "not specified".** Its message `PartiallyKnownDocumentMultiPointer` carries the fixed sentinel repetition index **`-5`** (`IIdentifier.UNKNOWN`) at the side's joined level; that address has no exact-pointer counterpart ([§1 §2.1](01-data-model.md#21-repetition-contexts-the-iteration-environment)). Index unavailability is checked before group presence: an unmatched clean group is empty, while an unmatched compromised index makes the group operand unavailable.

**A duplicate key does not imply an absent message address.** When another disjunct fires, a duplicate error-side key is resolved through the index cache's separate pointer association, and its coordinate can remain concrete. The cache population order, rather than physical first or last row order, settles which duplicate address is selected ([§10 §4.3](08-paths-and-references.md#43-selected-references-in-validation-messages)).

**Selected targets below an indexed group.** A target below the indexed group inherits its nearest indexed ancestor: the key selects that outer row, authored target-group coordinates remain independently iterated, and lower levels default to row `1` for message attachment. Message-pointer target identity is authored syntax rather than canonical runtime-key identity:

- An ordinary message reference to the repeated error field, directly or through a containing group operand, keeps physical iteration authoritative.
- Otherwise only semantic references targeting the repeated error field or an ancestor group containing it count. One exact authored key target carries its selected repetition or clean-no-match `[-5]`, using the deepest error-containing selector independently of operand order, while two distinct key expressions retain ordinary error-row iteration even when they normalize to one Number key or currently select one row.
- Sibling payload references add no pointer target.
- On the compute path, the current cascade overlay supplies both a field-valued query key and the selected scalar or group payload below an indexed ancestor.

**Under partial validation** each side's map is built from the **relevant** index cells only, and the union is taken as above ([§12 §5.7](10-validation-and-polarity.md#57-parallel-iteration-under-partial-validation)). Three consequences are measured:

1. A relevant set that names a payload field but not the index field yields an empty key set and therefore no iteration.
2. A group whose index cell is absent from the relevant set while the other side still supplies the key binds the `-5` sentinel exactly as a group with no row does, so relevance can make the sentinel reachable; rule gating treats that unmatched side's own repetition level as unbound because no row was chosen there.
3. A non-relevant index cell also **invalidates the column for that parent**, exactly as an empty cell does, so unmatched references into that group read UNKNOWN rather than definite empty. One such cell is enough on either side. Only a negative operator separates this rule from the weaker account.

Ordinary leaves beside the pair follow the same iteration: a call covering one row of either side or one field alone fires none of the measured leaves, and a call covering one error-side row with every row of its partner group fires exactly that row's full-validation messages.

A computation that runs over a joined pair, including its truncated-prefix marking, follows [§11 §5.4](09-computations.md#54-parallel-joins).

> **Non-normative implementation note.** Model the join as: collect each group's rendered index-token map; union the tokens without collapsing numeric aliases; normalize each token for each side's lookup; and for each iteration token build an `Env` where a present side binds its row and an absent side binds the `-5` sentinel. Keep the sentinel explicit, because several downstream reads, such as a negative predicate going UNKNOWN on an unmatched side, depend on distinguishing absent from empty. A computation's joins are owned by [§11 §5.4](09-computations.md#54-parallel-joins).

### 2.4 Reading the joined row

**Every leaf reads each joined group as if it were a fixed group at its joined row, and an unmatched side reads as an empty row at its `-5` address, its key field included.** Measured members, each admitted beside a pair leaf: a text or Date comparison across or within the sides, an Enumeration category read, value-list membership and its negation, `Length`, a String comparison between the two sides, a filled-field count, and a presence test of a side's own key field. So an unmatched partner's fields read empty, as a partner row holding only its key reads its other fields, and these leaves, negated ones included, do not fire on it through their ordinary empty-operand rules, while a Number inequality and `FieldNotFilled` of a partner field fire as omissions. An unmatched error side fires at its `-5` pointer through a keyed read or a presence test of its own key even when its group has no free row. A malformed partner field leaves its leaf undecided, firing nothing.

The bounded cases below are where the fixed-group reading needs more than that rule.

**Group presence.** Group-presence operands read the resolved joined group, including its instantiated-row content, rather than substituting one payload field. Group presence of an unmatched side is not a key-only row's: `GroupFilled` of a partner holding only its key holds, and of an absent partner fails ([§11 §5](09-computations.md#5-where-a-computation-runs--scope-and-the-parallel-join)).

**Keyed reads beside the join.**

- **A keyed group read selects its row at the common outer binding.** `GroupFilled(/Kp/Rows For "k1")` beside a joined field pair, with `Rows` outside both joined groups and a literal key, is admitted, and so are keyed field and group message parameters under the same key, the group parameter guarded by that positive read as in an ordinary rule. The selected row does not depend on the joined row: each joined row reads the same group content, renders the same selected row beside its own partner value, and references that row's fields beside the joined ones.
- **Every other keyed leaf keeps its ordinary meaning at the row that binds its reads.** The Kernel admits beside a joined pair a literal-keyed field read of a third group, a literal-keyed read into the partner group, and a key field read on the error side's row, such as `For Supply/Note`; a joined computation's generated rule carries a starred or filtered aggregate and `PatternMatched` the same way, a starred aggregate included where it stands beside a joined read in the compared operation. Their messages agree with each leaf meaning what it means in an ordinary rule at the common outer row or, where it reads the error side's row, at that row: a literal key selects the same row for every joined row, an error-side key selects per row, and a key naming no row reads as empty, so a Number comparison against it fires an omission. Such an omission's fill-to-fix set names the unknown keyed row and the error side's fields, that side's index field included.
- **A key read off either side's row selects per joined row.** A key field of the partner side, such as `GroupFilled(/Staffing/Ledger For Demand/Label)` beside a pair whose error field is on `Supply`, is admitted and selects by the partner row's value. An unmatched side's non-key fields are empty, the error side's included, so a read keyed by one of them names no row. Beside `FieldFilled(Demand/Base)` with the error field `Supply/Note`, `GroupNotFilled(/Staffing/Ledger For Supply/Note)`, `FieldNotFilled(/Staffing/Ledger/Amount For Supply/Note)` and `FieldNotFilled(Supply/Note)` fire as omissions for a Demand row without a Supply row, at the error side's `-5` address, the keyed reads referencing the unknown ledger row at `-5` too.

**Reads below a joined group bind that side's joined row.** Beside a joined pair, starred children of either side, at one or more starred levels, as in `NumberOfFilledFields(Supply/Items*/Q)`, `Sum`, `FirstFilledValue`, `AtLeastOneFieldFilled` or `NoFieldFilled` over them, and a field of a fixed subgroup of either side, as in `FieldFilled(Supply/Sub/X)`, are admitted and read at that side's row of the join; such a read alone anchors the join to its side's group through the unstarred part of its path. A side without a row for the key has no children, so they read empty, also when the side's group is full and its key-only row lies beyond capacity: a count or sum over them is zero, `NoFieldFilled` and `FieldNotFilled` hold, and `FieldFilled` fails. Their references name the slot at the side's row with each starred level at `[0]`, an unmatched side's at its `-5` row with a fixed subgroup there written at `[1]`, and a read below a side's row brings that side's index field into the fill-to-fix set.

**An error field below a joined side iterates its own levels within each joined row.** A rule reporting on `Lines/Parts/Count`, with `Lines` and `Picks` joined on `LineNo`, visits each part of each joined line:

- `FieldFilled(Lines/Parts/Count) And NoFieldFilled(Lines/Parts/PartNo, Picks/Ref)` fires at the part's own pointer where its `PartNo` and the joined `Ref` are empty, also on a line without a `Picks` row, whose partner references name the unresolved row `[-5]`, and never on a line without a key; on a `Picks` row without a line the part's `Count` reads empty, so this rule's `FieldFilled` fails there. Its references hold both index fields, the part's fields at its row and the partner row's.
- Statically the pair over the nested field is judged as the direct pair: `NoFieldFilled(Lines/Parts/PartNo, Picks/Ref)` draws `MVK_PARALLEL_ITERATION_INVALID`, while `AtLeastOneFieldFilled` over the same pair draws `MVK_NEG_CONDITION_IN_ITERATION` and a positive read of the part admits the rule, as an unguarded and a guarded level do in §1.8. A condition that reads the joined pair but not the nested level, `FieldFilled(Lines/Sku) And FieldFilled(Picks/Ref)`, draws `MVK_ERROR_FIELD_NOT_REFERENCED`, and a comparison over the nested field is admitted: `[Lines/Parts/Count] > 1 And FieldFilled(Picks/Ref)` fires at each part whose `Count` exceeds one on a joined line whose `Picks` row holds `Ref`.
- A computation into the part with that pair as its precondition computes every instantiated part whose precondition holds, an empty one included, on a matched and an unmatched line, and clears each seeded part of a matched line whose precondition fails; its generated rule fires on a filled part whose stored value differs.
- **The parts a rule visits follow the rule iteration domain with the joined level counted once** (§1.3). With `Parts` declared five times every joined row visits all five; declared six times, the declared space exceeds five, so it visits its first part and each part index some content of the document occupies at that depth, whatever its group: another line's parts, a line's `Slots` rows and the `Bows` rows of the unjoined `Wraps` all widen it. A `Picks` row without a line visits the same parts, its messages naming the unresolved line, as `/Order[1]/Lines[-5]/Parts[2]/Count`: `[Lines/Parts/Count] < 5 And FieldFilled(Picks/Ref)` fires there on every visited part.
- Unmeasured: value leaves over the nested field other than that comparison, a part of an unmatched line whose precondition fails, a non-Number target below a joined side, and an error field below the partner's side. Partial dispatch over such a rule is the nested-level case of [§12 §5](10-validation-and-polarity.md#5-full-vs-partial-validation).

**A filled-field count over one field of each side is the ordinary validation count over the joined row.** Reporting on `Lines/Qty`, `NumberOfFilledFields(Lines/Qty, Picks/Ref)` meets the count rule of §1.8: against a positive constant, `<`, `<=` and `!=` draw `MVK_PARALLEL_ITERATION_INVALID`, as the mirrored `1 > N` does, while every other comparison with 0 to 3 is admitted, `< 0`, `<= 0`, `== 0` and `>= 0` included, and so is a comparison with a field beside the join. Over the nested `Lines/Parts/Count`, `< 1` draws the same class, `> 0`, mixing the nested read with the partner's, draws `MVK_NEG_CONDITION_IN_ITERATION`, and a guarded `> 1` is admitted. At runtime the count is the number of the joined row's filled operands, an unmatched partner's counting as empty, and is unavailable when an operand is formally invalid, so a malformed `Qty` beside a filled `Ref` silences even `> 0` and `>= 0`. A fired comparison is OMISSION where filling an empty operand could falsify it, as `== 0`, `<= 0` and `== 1` beside one empty operand are, and VALUE otherwise. Its references name both operands and both index fields, and `fillToFix` follows the count's omission selection of [§1 §3.1](01-data-model.md#31-rules-validation), so a count asked to be larger than an empty field fires OMISSION with no fill-to-fix entry.

**A distinct count or uniqueness test over one field of each side counts the joined row's two values.** `NumberOfDifferentValues(Supply/Note, Demand/Label)` and `FieldValuesNotUnique(Supply/Note, Demand/Label)` are admitted beside a pair. As the whole condition, `NumberOfDifferentValues(…) > 1` is admitted and `< 2` draws `MVK_PARALLEL_ITERATION_INVALID`. An empty value, an unmatched side's included, makes `< 2` fire as an omission and leaves `> 1` silent; two equal values make `< 2` and the uniqueness test fire.

**Joined message references retain index fields.** Under parallel iteration, a referenced payload field brings the joined group's index field into the reference list and, for an omission's fill-to-fix list, into that list too. A rule referencing only one group does not acquire its index field merely because the group is keyed.

## 3. The filter `Having`, the `$` correlation, and aggregation

`Having` filters a repetition list (a `*`-path) down to the rows where a condition holds, **before an aggregate or quantifier consumes it**:

```
Sum(Products*/Quantity Having [Products/ProductName] == "N33") > 100
```

The filter attaches to a starred **field** operand. Its condition is evaluated per candidate row of the operand's filter traversal extent (§3.9) against two environments: unmarked references read the candidate row, and `$`-marked references read the complete captured environment of the enclosing iteration (§3.2). Only a known-true result keeps a candidate (§3.3).

### 3.1 The filter condition and its static gates

**The filter's condition is the ordinary condition production, and the ordinary refusals apply inside it**, so a reimplementation reaches the filter through its full condition evaluator; the `$` machinery is an addition to that grammar. Which class a refused filter reports is a property of the filter, not of the operator that wraps it — identical across a temporal extremum, a distinct count and a filled-field count on every refusal tested.

- Measured admitted in a field-list filter: a String equality against a literal or another String field; `FieldFilled` and `FieldNotFilled` with no iteration-negativity refusal; a Number `!=`; `And`, `Or` and parentheses; a bare outer scalar reference with no `$`; a group-presence leaf; arithmetic on the field side; `CurrentRepetition` against a literal. A Number field takes all six ordinary operators against a Number literal written on either side.
- **The literal scale gate applies to `==` and `!=` alone**: on a scale-0 field `== 1.5`, `== 1.0` and `!= 1.5` draw `MVK_INVALID_COMPARE_DEC_PLACES` while `<`, `<=`, `>` and `>=` against `1.5` are admitted, and two Number fields of different scales split the same way. The equality scale gate admits the same literal against a declaration whose scale fits.
- Measured refused by the general rules rather than by a filter-specific gate: mixing `And` with `Or` unbracketed draws `MVK_BRACKET_MISSING` exactly as at a rule's top level ([§1 A.1](02-logic-and-formal-errors.md#a1-connectives-are-two-valued-parentheses-are-mandatory)); a String field in a numeric ordering comparison draws `MVK_INVALID_TYPE_FOR_COMPARISON` from a single-leaf filter carrying neither connective nor parentheses; a String field under `==` or `!=` against a Number literal draws `MVK_INVALID_COMPARE_TO_ENUM_OR_STRING`; two literals draw `MVK_INVALID_COMPARE_TO_CONST`.

**The comparison gate has two columns, selected by the operator rather than by the literal, and they agree on only the two temporal kinds.**

| Comparison inside a filter | Field side String, Boolean, Confirm, Enumeration or DATE_RANGE | Field side temporal |
|---|---|---|
| an ordering such as `> 0`, which first asks whether both sides can be ordered | `MVK_INVALID_TYPE_FOR_COMPARISON` (singular — not the plural constant the value-list quantifiers draw) | `MVK_INVALID_COMPARE_TO_DATE` |
| an equality, which never meets the ordering gate | under `== "x"` the kinds spread across four classes exactly as the constant-assignment ladder of [§11 §1.4](09-computations.md#14-wrong-kind-constants-and-field-sources) does at its string-like row, String being admitted and Enumeration gated on its stored-token domain; under `== 0` each kind draws its own class | its kind's own class |

**A comparison between two fields inside a body draws the class its family draws outside a filter.** Over fields of the filtered row, a String against a Number draws `MVK_INVALID_TYPE_FOR_COMPARISON` under `<`, the ordering gate reading both sides, and `MVK_INVALID_COMPARE_TO_ENUM_OR_STRING` under `==`. The other pairs measured under `==`:

| Pair | Class |
|---|---|
| a text against a Date; two Dates of different formats | `MVK_INVALID_COMPARE_TO_DATE` |
| an Enumeration against a Boolean | `MVK_INVALID_COMPARE_TO_YESNO` |
| an Enumeration against a String | `MVK_INVALID_COMPARE_ENUM_TO_STRING` |
| two Enumerations giving one stored token different labels | `MVK_INVALID_COMPARE_ENUM_TO_ENUM` |
| two Numbers whose fraction digits differ | `MVK_INVALID_COMPARE_DEC_PLACES` |
| two date ranges of different formats | `MVK_INVALID_COMPARE_TO_DATE_RANGE` |

The literal, tolerance-operator and pattern-comparison refusals measured in a body draw their own families' classes as well.

**The filter site.** A filter belongs to a starred field operand; **a `Having` filter site refuses a group path outright, and no spelling attaches a filter to a group operand.**

- The refusal is `MVK_NO_GROUPS_ALLOWED` naming the filter as the site, and it answers ahead of the repetition walk, so an unstarred repeatable group handed to a filter draws `MVK_NO_GROUPS_ALLOWED` as its starred twin does, not `MVK_NO_WILDCARD`. `NumberOfFilledGroups(G/Sub* Having (…), G2)` is rejected in either operand position and on both the validation and the computation arm, while the same filter over a field list and the same group operand unfiltered are both admitted. The refusal is reached at static arbitration, not only at code generation.
- Measured carriers, each against its own unfiltered control and with the same filter admitted on the field form: the four field-fill quantifiers, `FieldValuesNotUnique`, `FirstFilledValue`, the value aggregates, `NumberOfFilledGroups` and `NumberOfFilledFields`. On a filtered group, `MinValue` and `Sum` draw this class where the plain twin draws `MVK_NO_NUMBER`, in every shape measured — a field-bearing subgroup, that subgroup unstarred, and the repeatable group itself — as the sole operand and beside another; a filtered starred field inside that same subgroup carrying the identical filter is admitted, so the refusal attaches to the operand's group-ness and not to the filter's spelling, depth or scope.
- A `Having` written after the operand list is a **parse error**, not a second refused site.
- A filter cannot therefore move a gate on a group operand, and no filtered group-operand state exists to have a behaviour. A consumer that pushes a row filter down onto a group operand emits a model the Kernel rejects.

**The scope gate: a filter must reference a level its operand reopens** (`MVK_NO_ITERATION_FOR_WILDCARD`). It is satisfiable: one in-scope reference admits the condition.

- A filter whose condition carries no reference into the filtered list's own iterated level draws the class, whether the out-of-scope reference is a plain field predicate on a nonrepeatable other group's field, a group-presence leaf, or two such conjuncts together; one in-scope reference admits the same condition, in either conjunct order. A root-level field the filter's star cannot bind reports this class. A filter whose unmarked references are all confined to bound ancestor levels does not establish the filtered iteration and is refused too, and a bare outer reference as a filter's whole condition is refused here whether or not it is marked.
- **A group-presence leaf is admitted inside a field-list filter**, as one conjunct beside an in-scope reference and as the sole condition when the group it names is the filtered list's own, so a group reference binds the iteration exactly as a field reference does. Measured on both the validation and the computation arm.
- **The requirement is a syntactic occurrence check that accepts any reopened level.** One ordinary reference at any level the operand reopens satisfies it: a two-star operand whose filter references only the outer starred level is admitted. Connective position is irrelevant: an in-scope reference under `Or` is admitted.
- **The check counts unmarked references, not field pointers**, so a `CurrentRepetition` operand satisfies it alone: `CurrentRepetition(Rows) != CurrentRepetition($Rows)` is admitted as a filter's whole condition, and the same comparison with both sides marked is refused. What a reference contributes is the repeatable scope of its path, exactly as a field reference declared in that group would: a nonrepeatable group whose path carries no repeatable level is refused as the sole condition and admitted beside one in-scope conjunct, while a nonrepeatable group nested under the starred level is admitted as the sole condition. Neither gate reads the named group's own repeatability.
- **A `$`-marked reference does not satisfy the requirement.** A filter whose only reference is `$`-marked draws the class, measured on a field-presence leaf and on a String equality against a literal, and one in-scope conjunct beside the identical marked leaf admits the whole condition: `$` pins a reference to the captured outer repetition and moves it out of the filtered level.
- `AllGroupsFilled`, `NoGroupFilled`, `NumberOfFilledGroups` and `NumberOfFilledFields` inside a filter condition behave as the scalar group-presence leaf does: admitted beside an in-scope reference in either spelling, refused as the sole condition in either spelling.
- A comparison's own gate inside the body answers first: `Having [Reference] > 5` over a text field the filter does not iterate draws `MVK_INVALID_TYPE_FOR_COMPARISON` where its sound twin `Having [Reference] == "x"` draws the scope class.

**The iteration gate: a filter condition may not reference a repeatable level off the operand's path, and no conjunct rescues it** (`MVK_INVALID_ITERATION_IN_FILTER_CONDITION`).

- A reference to a field inside a repeatable group the filtered operand's path does not contain is refused as the sole condition and beside an in-scope conjunct alike; the identical conjunct that admits a nonrepeatable out-of-scope leaf leaves this one refused. So these are two gates, separated by satisfiability.
- **Path membership is the whole predicate, and the direction along the path is irrelevant.** A level above the star that still lies on the operand's path — bound by the host, not reopened — draws the satisfiable scope class and is admitted beside one in-scope conjunct, in both the plain and the marked spelling. A repeatable level nested under a level the operand's star reopens, but off its path, is refused as the sole condition and beside an in-scope conjunct alike. Neither gate reads depth: a reference two repeatable levels above the star is admitted exactly as an immediate ancestor is, and one whose path crosses two repeatable levels off the operand's path is refused exactly as a single off-path level is.
- The same reference outside any filter draws the ordinary `MVK_NO_WILDCARD`, so the code is filter-specific. The filtered operand's own starred group may be referenced in its own filter. A star written inside a filter condition is refused `MVK_NO_WILDCARDS_ALLOWED`, so the condition cannot supply the missing iteration itself; its operands are unstarred, so a filter referencing `Items*/Sku` is rejected while the unstarred `Items/Sku` inside the same filter is admitted. The filter therefore names the candidate row it tests, never a second flattened stream.
- Hosting the rule inside the off-path repeatable level leaves the unmarked reference refused exactly as from a non-iterating locus.
- **The marker is the remedy.** `$` moves the reference into the captured environment, which clears the iteration gate and leaves only the satisfiable scope gate: a `$`-marked reference to an off-path repeatable level the enclosing iteration binds is refused as the sole condition and admitted beside an in-scope conjunct. With no enclosing iteration to capture, the same marked reference draws the walk's class instead: `MVK_NO_WILDCARD`, or `MVK_ERROR_FIELD_NO_INDEX` for a keyed level beside an error field's group whose path declares none, as `Sum(/Policy/Plain*/PAmount Having ([$/Policy/Claims/Amount] == [/Policy/Plain/PAmount])) > 0` shows from a fixed group beside the keyed `Claims`. Only those two classes are measured on a marked reference, with the error field inside the rule group; from a fixed group the peer measures the same two, a marked read of a field that does not repeat being admitted and the keyed body unmarked drawing `MVK_INVALID_ITERATION_IN_FILTER_CONDITION`, so the marker alone selects the walk's class over the filter's.
- Which of two coincident properties this gate reads is not established. Every refused reference names a level at once off the operand's path and unbound by the operand's star, and every admitted out-of-scope one names a level at once on that path and bound by an enclosing iteration. The discriminating shape — an unstarred repeatable ancestor on the operand's path that nothing binds — makes the operand itself illegal (`MVK_NO_WILDCARD`, the unfiltered control confirming the refusal is the operand's), and no separating witness is known; the gate is stated by its observable.

**Disallowed constructs.** A nested filter, `CustomCondition` and `RepetitionNotUnique` inside a filter condition draw `MVK_DISALLOWED_CONSTRUCT_IN_FILTER_CONDITION`, whose message names the offending language feature, **on every carrier**: in a computation's precondition and operation as in a rule, although a precondition outside any filter draws `MVK_ERROR_INVALID_LANGUAGE_FEATURE` for the same two ([§11 §1](09-computations.md#1-the-ground-rules)). That list is exactly three. The construct is the nested *filter*, not the aggregate: an aggregate with no filter of its own as a body's comparison side, `Sum(Claims*/Paid Having Sum(Claims*/Units) > 0) > 0`, draws `MVK_NO_ITERATION_FOR_WILDCARD` rather than the construct class. When a filter offends the construct rule and the iterated-level rule at once, the iterated-level class is reported: a filter consisting only of a `CustomCondition` leaf draws `MVK_NO_ITERATION_FOR_WILDCARD`, and the construct class surfaces once the filter also carries a term that references the iterated level. The construct class is the last of the filter's parse-time gates, answering only where each earlier one passes.

Two further constructs carry classes of their own:

- **A semantic index** at any level of an unmarked reference in an operand's own filter draws `MVK_SEMANTIC_INDEX_NOT_ALLOWED`, decided during the parse by the filter's own per-level index walk rather than by the post-parse gate that also names that class, so it pre-empts whole-rule gates a post-parse reading would predict. A marked one escapes that walk (below).
- **A filtered operand riding a parallel-iterated level** draws `MVK_PARALLEL_ITERATION_FOR_FILTERED_ENTITY_NOT_ALLOWED`, which is the rule's gate rather than the filter's and is decided by whether any one entity id carries both a filter and the parallel marker, so an unrelated unstarred read elsewhere in the condition can arm it while the filtered operand stays unchanged. The class is drawn when the parallel-iterated level is an outer one the filtered operand rides; a filter whose unmarked body read would iterate the parallel group draws `MVK_INVALID_ITERATION_IN_FILTER_CONDITION`, because a filter body may not iterate at all and that broader gate answers first. A condition carrying `RepetitionNotUnique` beside that shape draws `MVK_PARALLEL_ITERATION_NOT_ALLOWED` instead, that gate running first; a captured `$` read inside the filter can also reach that class. Capturing the parallel group does so directly; capturing the rule's own row does so when another reference makes the surrounding rule parallel-iterate, and is admitted without that additional reference. An ordinary candidate read alone does not supply the parallel iteration for the uniqueness gate.

The index walk carries a third class: a reference riding a repeatable level the filtered entity does not sit under draws `MVK_INVALID_ITERATION_IN_FILTER_CONDITION`, thrown inside the walk, whereas the iterated-level demand is a flag read only after every reference has been walked.

**The filter's own chain is raised at two points around its body.**

- The filtered entity's kind is asked as `Having` is read, so a group operand draws `MVK_NO_GROUPS_ALLOWED` ahead of a refused comparison, a name resolving to nothing and a broken token in its body, and a group key's filter ahead of a refused comparison.
- The rest of the chain is asked once the whole specification is read, so a refused comparison in the body answers first: ahead of an unstarred operand's `MVK_NO_WILDCARD`, a nested filter's construct class, a repetition the body reads that the filter does not iterate, a starred key's `MVK_SEMANTIC_INDEX_WITH_WILDCARD` and an unstarred key's `MVK_WILDCARDS_REQUIRED`; `[Parties/Count] == [Claims/Paid]` over the non-iterated `Parties` draws the scale gate's `MVK_INVALID_COMPARE_DEC_PLACES`. On a starred key's filter, a body reading a repetition it does not iterate draws `MVK_INVALID_ITERATION_IN_FILTER_CONDITION` ahead of the key's star class.
- A star on the filtered field itself is refused as its path is read, `MVK_INVALID_WILDCARD`, with either of the two bodies measured.

**A filter written after an entity key is walked against the key.** [§10](08-paths-and-references.md) owns whose filter a `Having` after an index key is; its walk is this chapter's. The filter's scope and iteration gates are asked of the specification it follows, and after `For Parties*/Name` that specification is the key, walked while the key is parsed and before the operand's index gates. So in `Sum(Orders*/Units For Parties*/Name Having …) > 0` a body read of the keyed `Orders`, of another repetition or of a level below the keyed one draws `MVK_INVALID_ITERATION_IN_FILTER_CONDITION`, one such read being refused however much else binds; a body binding no key star draws `MVK_NO_ITERATION_FOR_WILDCARD`; and a read the key's star binds passes the walk, leaving the key's own `MVK_SEMANTIC_INDEX_WITH_WILDCARD`. An index in the key's body sits inside the key's own index and draws `MVK_SEMANTIC_INDEX_WITH_SEMANTIC_INDEX` as it is parsed, a comparison in the body answers first, and an unstarred key's own gates answer before its body is walked: `For Parties/Name` draws `MVK_SEMANTIC_INDEX_INVALID_ITER` and `For Reference` `MVK_WILDCARDS_REQUIRED`.

**The walk reads every specification in the body, and the end of a nested filter hands the rest of the body back to the rule.**

- A starred specification binds no level, so `Claims*/Paid Having Sum(Claims*/Units) > 0` draws `MVK_NO_ITERATION_FOR_WILDCARD` and is admitted beside `[Claims/Units] > 1`; an unstarred aggregate of the filtered level reads the filtered row; and a nested aggregate's operand is walked, so `Having Sum(Parties/Count, Claims/Units) > 0` draws `MVK_INVALID_ITERATION_IN_FILTER_CONDITION`.
- On a two-level path the path question is asked of the level above the below-star one: `Orders*/Units Having Sum(Orders*/Lines/Qty) > 0 And [Orders/Units] > 1` draws the iteration class, `Orders*/Lines*/Qty Having Sum(Orders*/Lines/Qty) > 0 And [Orders/Lines/Qty] > 1` draws `MVK_NO_WILDCARD`, and `Orders*/Units Having Sum(Orders*/Lines*/Qty) > 0 And [Orders/Units] > 1`, starred at every level, is admitted.
- A nested filter's body is read by the outer walk and by its own, and its own scope gate stays its own. Once it ends, the outer body's remaining specifications and the nested filter's unstarred base are checked as the rule's reads, drawing `MVK_NO_WILDCARD` for `[Claims/Units] > 1` after it and for the base `Claims/Units`, and `MVK_INVALID_OUTER_ITERATION` for a marker there.

**A `$`-marked read in a body is judged statically as the same read outside any filter**, from anywhere in the body, nested filters included: it meets the rule's containment and index chain against the rule's error field, and the filter's walk does not see it, so it neither clears nor fails a filter gate.

- From a root rule reporting on `Reference`, `[$Claims/Units]` in a `Claims*` body draws `MVK_NO_WILDCARD`, and from a rule declared in `Parties` reporting on the root, `[$Parties/Count]` draws `MVK_ERROR_FIELD_NOT_IN_RULEGROUP` where the unmarked read draws the filter's iteration class.
- A marked read alone binds no level, `MVK_NO_ITERATION_FOR_WILDCARD`, and a marked read at the rule's coordinates is admitted. Its bracket's star gate still answers, `[$Claims*/Units]` drawing `MVK_NO_WILDCARDS_ALLOWED`, while outside any filter the marker's position answers first, `MVK_INVALID_OUTER_ITERATION`.
- A marked read carrying a semantic index draws `MVK_SEMANTIC_INDEX_NOT_ALLOWED` beside a body read that binds the filter, from a root rule reporting on `Reference` too, while alone it draws `MVK_NO_ITERATION_FOR_WILDCARD` and beside an unmarked read of the path it keys that read's iteration class. That index class is raised after the parse, so a parse-time class later in the text answers first: from a root rule reporting on `Claims/Notes`, a second `Parties*` filter whose body reads `Orders/Note` draws its iteration class alone.

**Whole-rule admission after the parse.** After parse-time checks succeed, whole-rule admission checks these conditions in order: a `RepetitionNotUnique` combined with parallel iteration; a filtered reference carrying parallel iteration; parallel iteration anywhere inside a filter body; a semantic index anywhere inside a filter body; multiple `RepetitionNotUnique` occurrences; multiple legacy row-uniqueness occurrences; and an invalid raw-String `Length` shape. Final iteration checks follow. These are whole-tree checks, so successful parsing of a later sibling precedes their selection; a parse-time failure in that sibling wins instead. Computations apply this order to the complete generated condition of [§11 §6](09-computations.md#6-the-implicit-validation-rule-precisely), before output rounding compatibility. This ordering is source-derived and does not extend the measured filter-shape boundaries above.

**Group-list overlap inside a filter is not separated by `$`.** For unindexed group-list operands, a group and its strict descendant are rejected `MVK_DUPLICATE_PARAM2` even when one is captured and the other is candidate-bound. Identical paths are a different check: repeating the same path with the same origin is `MVK_DUPLICATE_PARAM1`, while one candidate and one captured reference are distinct operands. Thus `AllGroupsFilled(Info, $/Form/Info)` passes these duplicate gates, whereas `AllGroupsFilled(Info, $/Form/Info/Child)` does not; the filter must independently satisfy its iteration and scope gates. Source-derived; filter-specific runtime calibration is unmeasured.

### 3.2 Correlation: `$` and `CurrentRepetition`

**The `$` operator — usable only inside a filter condition — switches a reference from the candidate environment to the complete captured outer repetition environment of the enclosing iteration**, turning the filter into a correlated subquery (for example, holidays whose date equals the current stop's ETA).

- **The capture source is whatever instance the filter's enclosing evaluation iterates, not specifically a rule:** a computation whose target is a repeatable field is evaluated once per target row, and `$` binds that row, measured at exact per-row values on both codegen strategies.
- The reference's resolved repeatable level selects its own coordinate from that environment: a parent-level `$` reference and a nested-descendant `$` reference may denote different repetition indices in the same rule instance. Collapsing the captured environment to one scalar outer row is incorrect.
- At least one unmarked reference must reach a repeatable level reopened by the filtered operand (§3.1); every other unmarked reference must be available from the candidate environment, and every `$` reference from the captured environment.
- **`$` may only name a level the enclosing iteration binds:** a marked reference to a level the operand's own star reopens is refused `MVK_NO_WILDCARD`, because the captured environment has no coordinate there, while the same marker on a level the rule does bind is admitted.
- **Outside a filter the marker is refused `MVK_INVALID_OUTER_ITERATION`**, even where the enclosing iteration binds the level named, so the site is checked before any binding question. Measured on both arms: a validation condition at a host that binds `G`, and a computation operation whose target is repeatable, each refused while the identical marker inside a `Having` filter in the same model is admitted and the unmarked spelling at the same host is admitted. A marked nonrepeatable group draws the same refusal. [§6](05-dates-and-time.md) carries the same rule from the `DateRange` endpoint carrier. On the entity-list carriers of §3.5 a `$` marker outside a filter is an operand read drawing this class.

**Whether the marker changes a reference depends on the level, not the scope:**

| Level the reference names | Unmarked | Marked |
|---|---|---|
| a level the star **reopens** | reads the candidate's coordinate | refused `MVK_NO_WILDCARD` unless the enclosing iteration binds it too, where it reads the captured coordinate; the marker is the sole way to read it |
| an unstarred repeatable **ancestor on the operand's own path** that the enclosing iteration binds | the candidate environment inherits that coordinate from the captured prefix unchanged, so both spellings are admitted and read the same row; measured on a two-level model with a one-star operand, deeper chains unmeasured | same row |
| a repeatable level **off the operand's path** | refused `MVK_INVALID_ITERATION_IN_FILTER_CONDITION` as the sole condition and beside an in-scope conjunct, even when the enclosing rule iterates that very level | admitted beside an in-scope conjunct |

A consumer may therefore drop or add the marker on a non-reopened level of the operand's own path without changing behaviour, must never do so on a reopened level, and must not strip it off-path. A reference to a level the star does not reopen resolves to the same row for every candidate (§3.3).

**A same-group starred candidate set includes the current outer coordinate unless explicitly excluded; correlation does not imply self-exclusion.** `CurrentRepetition(G) != CurrentRepetition($G)` compares the resolved repetition coordinate at level `G`, not an opaque physical-row identity. In a multi-star `A*/B*` candidate set, comparing only `B` can therefore exclude every candidate that shares the outer row's `B` leaf index across different `A` rows.

**`CurrentRepetition(G)` is admitted exactly when an iteration binds every repeatable level on `G`'s path.**

- The host obeys this law: `CurrentRepetition(G)` is admitted in a rule whose error field lies inside `G` and refused `MVK_NO_WILDCARD` from a rule placed above `G`, each placement's plain-condition control being admitted. A computation whose computed target is repeatable binds it, and the identical calculation with the target moved to the root is refused `MVK_NO_WILDCARD`.
- **The requirement runs over the named group's whole path**: every repeatable level on that path must be bound, and the refusal names the unbound ancestor. A nonrepeatable group nested under a repeatable one is admitted from a host that binds the ancestor and refused `MVK_NO_WILDCARD` from a host above it, the diagnostic pointing at the repeatable ancestor and not at the group named; a nonrepeatable group with no repeatable ancestor is admitted from that same non-binding host with a constant index. Naming a repeatable sibling from a host that does not bind it is the same refusal, the named group supplying the unbound level itself.
- **The two spellings draw on different binding sources.** An unmarked `CurrentRepetition(G)` is satisfied by the enclosing iteration or by an operand's own star that reopens `G`, so inside a filter it is admitted even from a non-iterating host, while a marked `CurrentRepetition($G)` reads the captured environment and is satisfied only by the enclosing iteration — refused `MVK_NO_WILDCARD` in that same shape. The self-exclusion pair therefore needs its level to be at once star-reopened and host-bound, since it carries one reference of each kind: a rule iterating `Lines` whose operand stars only `Items` draws `MVK_NO_WILDCARD` for `CurrentRepetition(Items) != CurrentRepetition($Items)`. The reflexive unmarked `CurrentRepetition(Rows) == CurrentRepetition(Rows)` is admitted too, so the gate turns on the marker rather than on the comparison being non-trivial.
- The [§1 §3.1](01-data-model.md#31-rules-validation) reference expansion gives a `CurrentRepetition` operand no field pointer at all, so a gate implemented over that expansion refuses both spellings.
- **Within a condition or a computation operation the operand is an ordinary Number expression**: admitted bare, inside arithmetic, on either side of a comparison, against a field operand, and as a comparison operand inside a `Having` filter, on the validation arm and as a computation's whole operation alike. The one position that refuses it is an aggregate's operand list (§3.5).

**The group carrier of a filter reference behaves as the field carrier does**, including the split between the two gates: a nonrepeatable out-of-scope group leaf as the filter's sole condition is refused `MVK_NO_ITERATION_FOR_WILDCARD` whether or not it carries the marker, and one in-scope conjunct admits either spelling, while `GroupFilled` naming a repeatable sibling is refused `MVK_INVALID_ITERATION_IN_FILTER_CONDITION` as the sole condition and beside an in-scope conjunct alike. So `GroupFilled` reads the captured environment as a field reference does and obeys both gates, and its marker is redundant only where a field reference's is.

### 3.3 Selection: what a filter keeps

**The keep rule is exact: retain a candidate only when the filter condition is known true.** A false or three-valued unknown result drops that row before the aggregate or quantifier reads the selected consumer cell. The generated Boolean tree tests each leaf for known truth: `And` skips its right branch after a false or unknown left leaf; `Or` skips its right branch after a true left leaf. This agrees with ordinary condition truth tables for selection while preserving authored reachability of runtime failures. In a standalone comparison, an invalid row-local operand drops only that candidate; an invalid captured-outer operand makes that comparison unknown for every candidate that reads it, so each such standalone filter drops.

**A dropped row leaves the aggregate available, which is the opposite of what an unavailable target does.** A non-true conjunct removes its own candidate and the aggregate then answers over the survivors — zero of them included, which yields the consumer's all-empty identity of [§2 A.3](03-empty-and-required.md#a3-what-an-all-empty-selection-folds-to-the-aggregate-identities) (the fillable `0` for a count, a `Sum` or a Number extremum; no value for a temporal extremum or a non-Number `FirstFilledValue`) and not an unavailable operand. One malformed filter cell among several selected rows therefore costs exactly that row: a two-row selection whose first row is well-formed and whose second carries a malformed filter operand answers from the first row alone, whereas the first selected formally unavailable target makes the whole aggregate unavailable (§3.4).

⚠ **The empty-operand-as-zero rule of [§2](03-empty-and-required.md) reaches an absent filter operand and not a formally invalid one.** An absent Number operand participates as `0` and the comparison decides normally, so `[Amt] < 5` is true on an absent `Amt` and keeps the row; a malformed `Amt` instead makes the conjunct non-true in both comparison directions and keeps no row under either. A filter's three-valued drop is not reducible to a substituted value that then compares false.

**A reference to a level the star does not reopen is a constant, so the filter keeps every candidate or none of them.** A reference naming any repeatable level on the operand's path other than the one the operand stars, or a nonrepeatable field, resolves to the same row for every candidate. An unstarred repeatable **ancestor** is constant wherever the enclosing iteration binds that ancestor to the same row, so two host rows disagree only when they differ in that coordinate; a **nonrepeatable** leaf is constant across the whole document. Measured with the ancestor two levels above the star, and on `Sum` over a two-level operand: three host rows gating `1, 0, 1` yield `30, 0, 50` under the ancestor filter and `30, 70, 50` under the leaf one, and the leaf filter collapses to zeroes on a document differing only in that cell. **A domain the filter empties yields the consumer's all-empty identity, not a cleared target**: for `Sum` the gated-off row reports a value of `0`, the same empty-domain identity a never-instantiated domain and a capacity-emptied one produce. This holds on both arms and in both spellings: a validation rule over such a filter fires on exactly the host row whose selection emptied, and the `$` marker computes identically at a level the star did not reopen. A reference the star does reopen is the candidate-varying case: it drops its own row and leaves the aggregate at its ordinary value.

**An operand's star binds its own filter and not its host rule, so the rule still reports once.** A rule at a non-iterating locus whose aggregate stars a repeatable level and filters on that level's coordinate fires **one** message, attached to its own error field, even when the filter admits several rows; the discriminating observation is the error pointer of each fired message.

**A reached evaluation failure is distinct from a filter result.** With the UTC static-literal profile and a Berlin model, a spring-gap DateTime literal inside a `Sum` filter comparison produces the authored validation rule's VALUE error; computation clears its seeded target and retains `berechnungsWertFehler`. An earlier malformed field suppresses the later literal failure during computation, whereas reversing those operands retains the residual error; validation reaches the literal in either order. An empty field does not suppress it. If the candidate conjunct is false and the literal is never reached, the empty selection instead computes `0` without that residual error. These compositions keep the static-host/runtime-model zone distinction and require a failure channel outside ordinary false/UNKNOWN-as-drop. A reached missing named-type validator in a `Having` predicate is likewise a rule-level failure, not selection truth: validation aborts the enclosing rule with VALUE before reading the selected aggregate target, empty or formally unavailable predicate input bypasses the lookup, and computation keeps its own target-local failure and clearing boundary ([§7 A.3](06-strings-and-enumerations.md#a3-custom-field-type-validation)).

**Computation uses the same condition tree but not validation's unknown-as-drop projection.** A formally invalid filter operand actually reached during computation poisons the reading computation. Filter and target reads are interleaved by one **kept-successor lookahead**: after a candidate is kept, the iterator searches through later false candidates until it finds the next kept candidate or exhausts the stream before the consumer reads the current candidate's target. A poison met during that search therefore wins over a filled current target. Once one successor has been kept, a terminal current target leaves every filter after that successor unread. This is neither eager filtering of the complete selection nor target-first row evaluation, and an earlier terminal authored operand still hides every later operand and its filter.

⚠ **Reordering filter operands is safe only when it preserves reached effects.**

- The failure-free validation projection has strong-Kleene selection laws: a true disjunct dominates an unavailable one from either side, and reordering preserves selected rows. Executable validation nevertheless short-circuits left to right and may raise a runtime failure, such as a missing named-validator lookup: a false conjunct before that lookup bypasses it, and reversing the operands produces VALUE.
- The computation arm reads left to right and the first **reached** poison aborts, so authored order is observable, and both connectives short-circuit on their own dominating polarity. With a malformed `Amt` and a present `Sku`, `Having (FieldFilled(Amt) Or FieldFilled(Sku))` produces no computed outcome while `Having (FieldFilled(Sku) Or FieldFilled(Amt))` computes its value. On the same malformed `Amt` with `Sku` absent, `Having (FieldFilled(Sku) And FieldFilled(Amt))` computes its value while the reverse spelling produces no outcome; filling that `Sku` makes both conjunction spellings abort. Each document's validation count is available under every spelling.
- For these ordinary-presence witnesses, reordering preserves validation selection while changing computation; this does not extend to validation leaves that can raise. Once compute has run, a rule reading the computed field sees the changed value, so a rewrite that is order-safe for one filter is not thereby order-safe for the document. The eager `formalErrorsInOperands` inventory reports the malformed cell in every one of those cases and cannot predict the abort ([§11](09-computations.md)).

> **Non-normative implementation note.** For a dense traversal, a filtered star is `filter (fun candidateEnv => evalFilter cond candidateEnv outerEnv doc) candidates`; sparse traversal additionally uses the last kept candidate to decide which later candidates reach the filter (§3.9). In both modes `evalFilter` resolves a `$`-marked reference against the complete captured `outerEnv` and an unmarked reference against `candidateEnv`, each resolved reference naming the repeatable level whose coordinate it reads. The filter-content restrictions of §3.1 are a well-formedness check on the AST.

### 3.4 Aggregation consumes an ordered stream

**Aggregation consumes an ordered resolved stream, not a mathematical set.**

- Authored entity-list entries retain their authored order. A group entry expands its fields depth-first in model declaration order, a subgroup's fields standing at the subgroup's position and an index field at its own declared position. Repetition coordinates advance in ascending order, the lowest nested repeat level changing fastest.
- Evaluation preserves repeated wildcard streams; it never silently deduplicates them.
- `Having` selection occurs before the selected target is read (§3.3). The first selected formally unavailable or non-relevant target makes the aggregate unavailable immediately, so the suffix is not read. The kept-successor order determines which reached filter or target failure occurs first, but the public computation result erases that source identity: a draining aggregate that reaches the same failure set cannot expose filter-versus-target precedence, while a prefix consumer such as `FirstFilledValue` can expose which suffix was never reached.
- `Sum` performs no arithmetic step for an unspecified cell — the same numeric contribution as zero — but records that cell's own declaration for polarity. Its per-step arithmetic is specified in [§5](04-numbers-and-decimals.md#5-internal-precision--the-constants-that-must-match-exactly).
- `MaxValue` and `MinValue` ignore unspecified fields; a list with none specified yields the all-empty identity of [§2 A.3](03-empty-and-required.md#a3-what-an-all-empty-selection-folds-to-the-aggregate-identities) — the fillable `0` for a Number list, no value for a Date list.
- **An aggregate's operand list takes field and group paths and no expression of any kind.** `Sum(CurrentRepetition(G))` is a parse refusal, `MVK_UNEXPECTED_TOKEN` naming the operator, and an arithmetic wrapper there is refused identically ([§5](04-numbers-and-decimals.md)).

Sources: [CurrentRepetition operand carriers](../docs/sources/group-and-iteration-probes.md#src-currentrepetition-operand-carriers), [inbound 2026-09-26i expansion order](../docs/sources/inbound-handbacks.md#inbound-2026-09-26i-expansion-order).

### 3.5 Entity-list operand admission

The entity-list carriers — the value aggregates `Sum`, `MinValue`, `MaxValue`, `FirstFilledValue` and `NumberOfDifferentValues`, the counts, the field-fill quantifiers, `FieldValuesNotUnique`, the value-list quantifiers, the group-list quantifiers and `RepetitionNotUnique` — admit their operand list through gates of two kinds. **The operand reads, the root gate, arity, the star gate and both duplicate gates belong to the shared entity-list checker, which every carrier in this family routes through, so they do not vary by carrier even where a row measured only one; the kind gate is each operator's own question about the expansion's values, so one carrier's class never transfers to a sibling.**

<a id="entity-list-operand-reads"></a>**Every operand is read before any list gate, and the first operand that cannot be read answers.**

- An index that cannot be read — its group declares no index field (`MVK_NO_INDEX_FIELD`), its key is empty (`MVK_INDEX_VALUE_INVALID`), or its key field is a `NUMBER` against a `STRING` index field (`MVK_INDEX_TYPE_INCONSISTENT`) — an empty group (`MVK_GROUP_IS_EMPTY`) and an empty root (`MVK_ROOT_GROUP_IS_EMPTY`) each answer ahead of a duplicate in either position, of the root gate, of the kind gates and of the date walk. Between two unreadable operands the earlier one answers whatever its class, and an empty group inside a root answers ahead of the root's containment.
- An index that resolves reads cleanly and leaves the list gates to answer as without it, an index-selected group's kind gate over its fields included.
- Measured carriers: the value aggregates, `NumberOfFilledFields` and `NumberOfFilledGroups`; and `AtLeastOneFieldFilled`, `FieldValuesNotUnique`, `AtLeastOneGroupFilled`, `NumberOfValueInFields`, both value forms of `AtLeastOneFieldValueIncludedInValueList`, `RepetitionNotUnique` and `FieldValueIncludedInValueList`'s value list, where an index without an index field, an empty key, the empty group and the empty root each answer first and last beside a duplicate pair, the value list, whose values are reads, carrying the index operands alone. The index-type class is measured on the aggregates only. On those eight carriers a `$` marker outside a filter is read the same way, drawing `MVK_INVALID_OUTER_ITERATION`, and on the value-list quantifier so is an undeclared category, `MVK_CATEGORY_UNKOWN`. Not measured under a `Having` filter.

**Duplicates.** Duplicate checking rejects repeated direct non-wildcard field references, repeated fixed group paths and indirect group/field overlap, while wildcarded occurrences are treated differently rather than symmetrically.

- Repeating either a direct field or a fixed group reports `MVK_DUPLICATE_PARAM1`; repeating the same starred group is admitted, so `Lines*/Qty, Lines*/Qty` is admitted where `Total, Total` is a duplicate.
- **All exact non-wildcard identities share one authored encounter scan, independent of field/group class:** the duplicate whose second occurrence arrives first supplies the repair witness, and only after no exact duplicate exists does strict ancestor overlap run. Thus `(group, field, field, group)` names the field while `(group, group, field, field)` names the group.
- The indirect ancestor/descendant arm (`MVK_DUPLICATE_PARAM2`) still fires between two wildcarded references: `Sum(/Invoice/Lines*, /Invoice/Lines*/Fees*)`, a starred group beside its own starred descendant, is rejected while the same starred group twice is accepted. The indirect check requires equal semantic-index and category identities as well as strict path containment, so a stored group does not overlap its projected Enumeration child; one field read under two different keys is not a duplicate.
- Inside `Having`, the `$` marker participates in the exact direct-operand identity rather than being erased before the duplicate scan: the authored pair `($P, P)` is admitted under `Sum`, `NumberOfFilledFields` and `NumberOfDifferentValues`, while `(P, P)` in the same filter reports `MVK_DUPLICATE_PARAM1`. The reverse pair and `($P, $P)` are unmeasured.
- Measured scope: the field/star and starred-overlap boundaries under `Sum`; fixed-group equality and the two mixed-fault orders under `FirstFilledValue`. HModel wildcard checking is a separate profile whose indirect arm has no known witness.

**The root gate.** A root group is refused as an operand with `MVK_ROOT_GROUP_REFERENCED`, asked of the list the duplicate scans return.

- Every entity of a model lies under its root, so a root repeated is the exact duplicate and a root beside any entity of its own root is the nested one; the root class answers only for a root alone or beside another root's entities, and there it answers ahead of the carrier's kind gates. A root operand already satisfies arity, so those two gates never both apply.
- An index-selected root meets both root gates as a plain one does: beside a field, `/Lot For "k"` draws `MVK_ROOT_GROUP_REFERENCED` under `Sum`, `MaxValue`, `NumberOfFilledFields` and `NumberOfDifferentValues`, and `MVK_ROOT_GROUP_WITH_OTHER_PARAMETERS` beside a group under `NumberOfFilledGroups` in either order, where an index-selected field in its place draws `MVK_SEMANTIC_INDEX_NOT_ALLOWED`.
- On the value list the root gate answers ahead of the slot-kind gate, so a root holding only a Date draws the root class where the Date alone draws `MVK_ONLY_STRING_ENUM_NUMBER_ALLOWED`. The field-read spelling asks the gate of each side's own list: a root on either side of the `In` draws the root class, and so does a root across the `In` from its own field, which one list would report as the nested duplicate. A category projection of a field under the root does not make that pair a nested duplicate: the root beside it draws the root class.
- `RepetitionNotUnique` asks no root gate.
- Measured scope: the lone root on the value aggregates, `FieldValuesNotUnique`, `DateRangesOverlap`, `NumberOfValueInFields` and all three value-list quantifiers; a root beside another root's entities under `FirstFilledValue` and the three value-list quantifiers; a computation's `FirstFilledValue` into a String target draws the class on both rows, the only computation carrier measured. The non-root and `AtLeastOneDateRangeOverlaps` combinations are unmeasured.

**Arity.** The direct plain-field form of `Sum`, `MaxValue`, `MinValue`, `FirstFilledValue` and `NumberOfDifferentValues` requires at least two distinct resolved field references. The rule is a disjunction, and the class `MVK_PARAMSIZE_INVALIDN` states it as one: more than one field **or** at least one group. **Arity reads the authored slots**, so one repetition-list or group selector satisfies it alone: a sole starred field and a sole starred group are each admitted where a sole direct field is refused, and a single-field group is admitted under `FieldValuesNotUnique` and `MoreThanOneFieldFilled` while that same field authored alone is refused. A sole starred group then meets its carrier's kind gate: under `FirstFilledValue` a heterogeneous one draws `MVK_VARYING_TYPES_NOT_ALLOWED`, which shows the group passed arity. The singleton direct-field cardinality fault is structurally separate from the duplicate gates because it contains no operand pair.

**The star gate reads the authored path and checks each operand at its own level only.**

- A single starred group is a complete operand list by itself, measured for `Sum`, `MaxValue`, `MinValue` and `NumberOfDifferentValues` over one repeatable group and for `NumberOfFilledFields` over another.
- A repeatable group operand written without its `*` is rejected `MVK_NO_WILDCARD` (measured under `Sum` and `NumberOfFilledFields`), while the starred form of that same operand is admitted. A non-repeatable group operand is admitted unstarred, and a star written on one is rejected `MVK_INVALID_WILDCARD` (both measured under `NumberOfDifferentValues`, on conditions identical apart from the `*`); the same code is measured for a starred nonrepeatable root under `NumberOfFilledGroups` ([§1 A.4.9](02-logic-and-formal-errors.md#a49-static-admission-of-group-and-field-slot-operands)), so the star refusal is not root-specific.
- A group operand mixes with ordinary field operands, and nested stars both survive: `Sum(/Invoice/Lines*/Fees*)` is admitted.
- **A group operand and its written-out expansion are two different models.** `FieldsNotCollectivelyFilled(Sections*, Note)` is admitted, while `FieldsNotCollectivelyFilled(Sections*/Title, Sections*/Answers/Text, Note)` — that same expansion written out — is rejected `MVK_NO_WILDCARD` for the nested repeatable level's missing star, and starring that level admits it again. A consumer that normalizes a group operand into its expansion can emit a model the Kernel rejects.

**The kind gate reads the group's expansion, not the group**, the index field included and at any depth, and every carrier keeps its own class. An admitted group operand is expanded and the result type-checked: a DATE group against a String value list is rejected `MVK_ONLY_STRING_ENUM_NUMBER_ALLOWED` where the same carrier over a String group is admitted. A group declares no kind of its own, so a checker must own the expansion's extent, including its recursion into nested subgroups, and its declaration order: the first expanded field is the leading operand wherever a carrier judges by position.

**`Sum`'s class reads neither position nor operand form.** A group holding one String fails a numeric list behind a Number field (`Sum(Weight, Specs)` draws `MVK_NO_NUMBER`), while a group of numbers leading a Number field is admitted; `Sum(Keyed*)` over a String index field and `Sum(Nested)` over a String two levels down draw `MVK_NO_NUMBER`. A plain String field draws the class whether it leads (`Sum(Title, Weight)`), follows a group of numbers (`Sum(Grading, Title)`) or follows a Number field (`Sum(Weight, Title)`), and a starred String field draws it alone, leading and following. Measured for a String only.

**The extrema's class is positional.** The first operand selects the family and every later operand must join it. The same two operands in the other order draw different codes with the verdict unchanged — `MaxValue(Amount, DueOn)` against `MaxValue(DueOn, Amount)` — and "later" means "not first": `MaxValue(DueOn, ShipOn, Amount)` reports the date class and `MaxValue(Amount, Cap, DueOn)` the sortable class.

- The sortable leader set is `{NUMBER}` together with every temporal kind — DATE, TIME, DATE_TIME and DATE_FRAGMENT all lead successfully. ENUM, BOOLEAN, CONFIRM, DATE_RANGE, CUSTOM and STRING each draw `MVK_NOT_SORTABLE` leading the list, so none of them leads an overload of its own, and each draws that same code after a Number leader. A leading String is classified by the same rule: `MaxValue(DueOn, Note)` is `MVK_DATE_AND_NONDATE` while `MaxValue(Note, Amount)` and `MaxValue(Amount, Note)` are both `MVK_NOT_SORTABLE`.
- A later position admits the leader's own class, so DATE follows DATE and TIME follows TIME; only after a Number leader is NUMBER the sole survivor.
- All four extrema follow this, the field-list `MinValue`/`MaxValue` and the operand-list `Min`/`Max` alike, each with a family-homogeneous control admitted, so the refusal attaches to the mix rather than to operand count.
- A typedef field resolves to its base kind, so a NUMBER-based typedef leads and follows exactly as a NUMBER does while a STRING-based one draws `MVK_NOT_SORTABLE`. A starred single-field operand takes the same verdict and code as the plain field of that kind in both positions. A `Having`-filtered starred field reads its declaration the same way: a filtered STRING leading beside a NUMBER draws `MVK_NOT_SORTABLE` and a filtered DATE leading beside a NUMBER draws `MVK_DATE_AND_NONDATE`, each equal to its plain-star twin, while an all-Number pair and a same-set DATE pair are admitted. So on a starred field the filter selects rows and reaches neither the declaration nor this gate.
- A group operand's expansion supplies the leading kind: `MaxValue(DatedBatches*, Weight)` over a group of Dates draws `MVK_DATE_AND_NONDATE`; an expansion declaring ENUM then NUMBER then DATE draws `MVK_NOT_SORTABLE`, one declaring DATE then NUMBER draws `MVK_DATE_AND_NONDATE`, and an all-NUMBER expansion is admitted. A group uniformly of one unsortable kind is refused `MVK_NOT_SORTABLE` in both repetition shapes, the equivalent explicit field list drawing the same code. The extrema rows do not separate expansion order, since a later Number there draws the same `MVK_NOT_SORTABLE`.

**The component-set gate of the extrema and the distinct count reads the declaration's component set, not its format spelling or its kind.**

- Two DATE fields declared `yyyy-MM-dd` and `dd.MM.yyyy` carry identical component sets under different spellings, and `MaxValue`, `MinValue` and `NumberOfDifferentValues` all admit them — at an explicit field list, at explicit starred fields and at a group operand's expansion alike, each against a same-format control. So does `yyyy-MM` beside `yyyyMM`.
- A TIME-declared and a DATE_TIME-declared field each carrying `yyyy-MM-dd` are admitted at the extrema beside a DATE declared the same, while those same two kinds carrying their own default clock and stamp formats are refused `MVK_DATEFORMATS_NOT_COMPATIBLE`.
- A `TIME` declaration carrying no format takes the `HH:mm:ss` component set: it is admitted beside a `TIME` declared `HH:mm:ss` and refused `MVK_DATEFORMATS_NOT_COMPATIBLE` beside a `DATE`, measured for `TIME` only.
- Component sets that genuinely differ are refused `MVK_DATEFORMATS_NOT_COMPATIBLE`, which names both formats with the first operand's as the expected one. A declared **Base Year** lifts that refusal for a yearless operand exactly when the remaining components already agree: a yearless `MM` aggregates with `yyyy-MM` and `MM-dd` with a complete date, while both stay refused against a year-only operand.
- A partially known date is refused by both carriers ([§6 §3](05-dates-and-time.md#3-constructing-dates-and-checking-validity)).

**The distinct count's admission is decided by its first operand.** The first operand fixes the required family and each later one must join it, so the refusal code names the first operand's class rather than the offending one. Both orders of each pair are measured and each flips the code; `(Number, Number, String)` and `(String, String, Number)` report their leading class, and `(Number, Date, String)` — two different offenders behind an admissible lead — still reports the Number class. A first operand outside the three families is refused earlier, by the class-admission gate naming the admitted set, `MVK_ONLY_STRING_ENUM_NUMBER_CMP_DATE_ALLOWED`: a Boolean first draws it whatever follows, and Confirm and DATE_RANGE operands are measured refused with it. Behind an admitted lead a Boolean is merely a homogeneity violation and draws that lead's class — the Number code behind a Number, the String/Enumeration/Custom code behind a String — so **the class-admission code is reachable only from the leading slot**; a Confirm or DATE_RANGE behind an admitted lead is unmeasured. The Kernel's text for this refusal names the offending operand while the code names the class the list was judged against, so a consumer locating the bad operand reads the text. A Custom-declared field is admitted and classed with the String family — mixing it with a Number draws `MVK_STRING_ENUM_AND_NON_STRING_ENUM` — the opposite of the custom-type validity predicate of [§6](05-dates-and-time.md), which refuses a Custom operand outright. A group operand supplies the leading kind through its expansion: a nonrepeatable group declaring a NUMBER then a STRING draws `MVK_NUMBER_AND_NON_NUMBER` while one declaring a STRING then a NUMBER draws `MVK_STRING_ENUM_AND_NON_STRING_ENUM`; `NumberOfDifferentValues(Batches*, Label, Released)` over a group of Numbers draws `MVK_NUMBER_AND_NON_NUMBER`; `NumberOfDifferentValues(Rekeyed*, Title)` draws `MVK_NUMBER_AND_NON_NUMBER` where the String index field follows the Number; and a group whose subgroup of a String precedes its Number draws the String class. An all-Number group is admitted, also beside a Number field.

**The extrema's kind domain is strictly narrower than the distinct count's.** CUSTOM is refused at the extrema yet admitted by both `NumberOfDifferentValues` and `FieldValuesNotUnique`, while DATE_RANGE is refused by all four, with different codes at the two distinct-count members: `NumberOfDifferentValues` reports `MVK_ONLY_STRING_ENUM_NUMBER_CMP_DATE_ALLOWED` and `FieldValuesNotUnique` the `CMP_`-less `MVK_ONLY_STRING_ENUM_NUMBER_DATE_ALLOWED`. So neither gate's domain may be read off the other, and the two codes belong to separate checks.

**`FirstFilledValue`'s gates are asked in one order over the expanded fields, and a list breaking two of them reports the one asked first.**

1. Operand reads, as on the whole family — an empty root twice included — plus one more read class here: a filter or a category projection on a group operand draws `MVK_NO_GROUPS_ALLOWED`.
2. The shared duplicate classes: a repeated field reports `MVK_DUPLICATE_PARAM1` over a Confirm or a type defect in the same list, and a group beside its own member reports `MVK_DUPLICATE_PARAM2` over a type defect, and over its Confirm member in either order.
3. The root gate and arity: a sole Confirm field reports `MVK_PARAMSIZE_INVALIDN`.
4. The Confirm class: a list holding a Confirm field reports `MVK_NO_BOOLY_ALLOWED` wherever that field stands, leading a mixed list included, and even when a type mismatch comes earlier in authored order; Confirm draws it beside a String and beside a Boolean alike.
5. The type class `MVK_VARYING_TYPES_NOT_ALLOWED` across families, measured for each member of the String family beside a `NUMBER`, for a `STRING` beside a `DATE`, a `DATE_RANGE` or a `BOOLEAN`, for a `BOOLEAN` beside a `NUMBER`, for a `NUMBER` beside a `DATE_RANGE`, and for a `DATE` beside a `DATE_RANGE`.

A group operand is judged by the fields it expands to at gates 4 and 5: a group holding a Confirm field draws the Confirm class, and one mixing text and number draws the type class, alone or beside a field; the written-out expansion draws the same code. An index that resolves leaves the duplicate, Confirm and type gates to answer as they would unindexed. Two `BOOLEAN` fields are admitted as a family of their own whatever stored values either declares, the defaults beside custom ones and two different custom pairs included, and two `NUMBER` fields share a list whatever fraction digits each declares. Measured scope: the missing-index-field class ahead of a duplicate in either position but ahead of a type defect only when it leads, and the empty and wrong-type keys only when they lead; the filter's place ahead of the duplicate scan on a root leading a list whose other operand lies inside it; the category projection on a group on a root alone.

**Among temporal operands `FirstFilledValue` reads the declared format string, not the kind and not the component set.** A DATE declared `yyyy` beside a DATE_FRAGMENT declared `yyyy` is admitted across two kinds, while two complete dates spelled `dd.MM.yyyy` and `yyyy-MM-dd` carry one component set and are refused `MVK_VARYING_TYPES_NOT_ALLOWED`. Two date-bearing kinds sharing one exact format are admitted: `TIME` beside `DATE_TIME` at `HH:mm:ss` and at `yyyy-MM-dd`, a `TIME` or a `DATE_TIME` beside a `DATE` at `yyyy-MM-dd`, a `DATE_FRAGMENT` beside a `TIME` there, and a `DATE` declared `HH:mm:ss` beside a `TIME`. Differing formats are refused whatever the kinds, one kind included: two `DATE_TIME` or two `TIME` fields at two legal formats are refused where their same-format pairs are admitted. `DATE_RANGE` behaves identically with its allowlisted (format, separator) pair as the format. Measured scope: `DATE_FRAGMENT` beside `DATE_TIME` is unmeasured, and the rows placing `TIME` and `DATE_TIME` in this family are measured on validation conditions only. **The four entity-list carriers split two and two on the equal-component-set pair**, measured on one model with the carrier as the only variable: `MinValue`/`MaxValue` and `NumberOfDifferentValues` admit it, while `FirstFilledValue` and `FieldValuesNotUnique` refuse it under different codes, each against its own same-format control.

**`FirstFilledValue` scans ordered entity-specification operands.** An operand may be a direct field or wildcard field list, an Enumeration category projection, a literal- or field-keyed semantic-index field, a plain or wildcard group, a literal- or field-keyed semantic-index group, or the correlated form where its owner admits it. Group operands expand recursively to descendant fields in declaration order; category operands expand through their category projection. A semantic-indexed group remains document-selected and cannot be replaced by a static field list. Inside `Having`, a plain captured outer group is admitted but literal- and field-keyed semantic-index selections are rejected `MVK_SEMANTIC_INDEX_NOT_ALLOWED`. Its scan is §3.7's.

**`FieldValuesNotUnique`'s order.** All operand reads finish before the duplicate/overlap, root, category and multiplicity gates. Its whole-expansion kind and format scan precedes common-base-type agreement, which precedes the raw-String value-validation gate. The scan remembers the exact format of each date-like declaration even across intervening admissible non-temporal fields: Number plus two differently formatted Dates reports `MVK_ONLY_STRING_ENUM_NUMBER_DATE_ALLOWED`, whereas Number plus one Date reaches `MVK_VARYING_TYPES_NOT_ALLOWED`. This ordering is source-derived; external calibration of the combined defects is unmeasured. Its kind and category gates are stated with the operator in §5.

**Whether a group-scope operand is admitted at all is a property of the individual operator, so no verdict here transfers by analogy.**

| Admits a group operand | Refuses it `MVK_NO_GROUPS_ALLOWED` |
|---|---|
| the seven field-fill quantifiers; the three plural value-list quantifiers in both their literal and entity value forms and in either slot; `FirstFilledValue`; `NumberOfFilledFields`; `Sum`, `MinValue`, `MaxValue`, `NumberOfDifferentValues`; `NumberOfValueInFields` in both overloads; `FieldValuesNotUnique`; `AtLeastOneDateRangeOverlaps` in its `In` slot — in both repetition shapes wherever both are legal | the operand-list `Min` and `Max` in either shape; `DateRangesOverlap`; the custom-type `Valid`/`Invalid` overload; `FieldValueAsString`, `ValueAsDate` and `RangeAsString` |

### 3.6 Value identity

**Each carrier that compares operand values chooses its own value identity, and no carrier's identity may be borrowed for another's.**

| Carrier | Number | String, Enumeration, Custom | Temporal |
|---|---|---|---|
| parallel join key (§2.3) | the normalized numeric value (`5` and `5.00` one lookup identity); visits counted per rendered token | String: the exact token; other kinds: the declared-kind projection of the semantic index ([§10 §4](08-paths-and-references.md#4-rows-are-addressed-by-semantic-key-never-by-position-)) | the declared-kind projection; two keys of different kinds: unmeasured |
| `NumberOfDifferentValues` | scale-19 equality, as ordinary Number comparison and uniqueness use | the evaluated String value or the ordinary stored Enumeration token, exactly; String and stored-Enumeration fields may mix and the same token from either kind counts once; category projection is not admitted; Custom: unmeasured at runtime | the decoded value at the list's shared component set after Base Year supplementation |
| `MinValue`, `MaxValue` | numeric order | — | ordered at the shared component set's own precision, a yearless operand by its supplemented date; DateTime by resolved instant ([§6](05-dates-and-time.md)) |
| `FieldValuesNotUnique` | the typed comparison: a scale-0 `5` equals a scale-2 `5.00`, in both operand orders | the stored value; a category projection is refused | the operand's exact stored text |
| `RepetitionNotUnique` | the normalized numeric value of [§5](04-numbers-and-decimals.md) | the exact internally stored text; an Enumeration key compares its stored token, not display text or a category projection | the exact stored text, never an instant |

**The distinct count.** Every overload has integral result scale `0`. Empty cells and declared-but-uninstantiated rows do not enter the set but leave its size growable; a reached filter makes the available count both-directionally fillable, because later filling can alter membership; the first reached formally unavailable or non-relevant selected cell makes the aggregate unavailable. Repeating a wildcard slot still consumes its stream again, but equal repeated values do not increase the count.

- **Temporal operands compare at the shared component set after Base Year supplementation, not at full calendar precision.** Two `yyyy-MM`-declared operands holding `2024-03` count as one value and `2024-03` beside `2024-04` as two, on a `DateType` whose declared format omits the day and on a `DateFragmentType` alike, both codegen strategies agreeing. Every omitting format reaches the count, yearless ones included: `MM` beside `MM` and `MM-dd` beside `MM-dd` are admitted and compared as yearless calendar positions. Under a declared Base Year a supplemented yearless operand compares at the supplemented precision: `MM` holding `03` and `yyyy-MM` holding `2024-03` are one value at Base Year 2024, and `03` beside `2024-04` are two. A consumer requiring a complete calendar date before counting refuses legal models. A component-omitting format is a different declaration from a **partially known** date, which carries a `datePrecision` and is refused as an operand of this operator outright ([§6](05-dates-and-time.md)); that refusal does not reach a component-omitting format.
- **A time-bearing operand folds on the same rule:** two TIME fields at `HH:mm:ss` separate on the clock, two DATETIME fields at the instant format separate on the instant, and a TIME beside a DATETIME declared the degenerate `HH:mm:ss` counts one value for one clock reading, so the identity follows the declared component set across the kind boundary as the admission gate does.
- **Whether a DATETIME's identity is the exact instant or the decoded local label makes no difference to this operator's answer.** Its operands are a field list, every value is read from a cell, and a stored or computed DATE_TIME is a model-format string with no offset or epoch component; wherever a label resolves, resolution selects one instant and the offset is recoverable from it, so two resolving labels agree exactly when their instants do. A spring-forward gap label arriving as stored text is refused: a stored `2024-03-31T02:30:00` on a `Europe/Berlin` model draws the format error and suppresses its referencing rule, and is not rolled forward onto the post-gap instant; a gap DateTime literal is refused too ([§11](09-computations.md)). The accounts would come apart for a value that retains an instant no label produced — a constructed or shifted DateTime compared in flight ([§6](05-dates-and-time.md)) — which this operator does not take as an operand.
- **A group operand's count uses the same expansion extent at runtime:** a nonrepeatable group declaring two equal dates plus a nested subgroup holding a differing one counts two, and three when all three differ, so the nested subgroup's field contributes. A declared-but-uninstantiated repeatable row contributes no value of its own.

**The extrema fold a component-omitting operand too, and order it at the shared set's own precision.** A `yyyy-MM` pair and a yearless `MM` pair are each admitted and ordered by `MinValue`/`MaxValue`, the yearless one both with no Base Year declared and under a declared one, so no interval domain is involved. Under a declared Base Year a yearless declaration is one shared set with a year-bearing one, so their operands carry different years inside a single list: `MinValue` over `MM` holding `03` beside `yyyy-MM` holding `2023-03` answers the 2023 operand at Base Year 2024, and both extrema move with that operand's year. A uniformly yearless list cannot separate this from ordering the yearless calendar position; the mixed list is the witness. A partially known declaration is the separate case those operators refuse.

**`FieldValuesNotUnique` compares a temporal operand's exact stored text**, which is what the dynamic runtime reads for this operator; it is a different reading from the decoded date `NumberOfDifferentValues` uses over the same entity lists. The generated-Java strategy's temporal comparison for this operator is unread, and both strategies were measured to agree on the surrounding skip and polarity rules. Under the mandatory single declared format the stored-text and decoded-value accounts agree **assuming one declared format admits one text per value**; that assumption is unmeasured — a leniently parsed `1.2.2020` stored beside `01.02.2020` under `dd.MM.yyyy` would separate them — and no such storable pair is known as of Kernel 30.8.1 probing at a12-dmkits `ddaf2e13`. ⚠ A comparison domain selected by whether the first operand is a Number field, which a source reading suggests, is measured absent: cross-scale Number equality holds in both operand orders.

### 3.7 Group operands and first-filled selection at evaluation

**At evaluation a group operand's extent belongs to the expansion, not to any one operator.** The recursive reach across a nested repeatable level holds for all seven field-fill quantifiers, and for `FieldValuesNotUnique` as §5 states.

- A group-scope fill quantifier evaluated from a rule authored on a repeatable level strictly *below* the operand still answers from the operand's extent, so `AllFieldsFilled(<group>)` is false from every row whenever any cell below the operand is empty.
- A starred operand `G*` read from a rule authored on `G` iterates `G`'s own level, and a doubly-starred operand iterates both starred levels whatever the consuming computation's own row is.

**`FirstFilledValue` selects the operand's first filled cell in the expansion's stable model declaration order.**

- **Filled means present, never truthy:** a Boolean source holding `false` is selected in preference to a later `true`, measured on both codegen strategies, while an *absent* first source falls through.
- Among two direct fields and among two fixed nested subgroups, the earlier declaration wins even when the later path sorts first; a filled direct field precedes the nested rows. For a terminal single-level starred group, traversal is declaration-major: every instantiated row of the earlier declaration precedes every row of the later declaration, so row 2 of `First` wins over row 1 of `Second`.
- An empty selector or an empty or no-match cell continues to the next candidate, a filled value terminates the scan, and reached formal unavailability terminates without being recast as ordinary emptiness.
- **An all-empty selection yields the operand kind's own not-given value**, not a third outcome state: every kind but NUMBER thereby clears its target, while NUMBER yields the fillable `0` ([§2 A.3](03-empty-and-required.md#a3-what-an-all-empty-selection-folds-to-the-aggregate-identities)). A seeded target makes the clear observable, since clearing an already-empty target reports nothing; measured on nine kinds with same-kind sentinel seeds and the NUMBER control.

**A group operand follows [the consuming operator's directional-fill rule](10-validation-and-polarity.md#4-the-directional-fill-machinery-behind-the-typing), not one complete-versus-incomplete flag for its whole expansion.** The fixed-group `FirstFilledValue` matrix shows it: direct-both is VALUE despite later empty nested declarations, while selecting the second direct field or either nested field after an empty direct prefix is OMISSION. The starred-group matrix agrees: an immediate first-row value is VALUE, the declaration-major cross-row selection is OMISSION after an empty earlier cell, and a no-row group star before a direct fallback makes that fallback OMISSION. The declaration-ordered expansion therefore enters the prefix scan without first collapsing whole-group missingness. ⚠ This is a different mechanism from the filter-reached escalation of `FieldValuesNotUnique` (§5), which keys on a reached `Having` and not on fill state; neither account is measured on the other's axis.

### 3.8 `SumOfProducts`

**`SumOfProducts(A*, B*)` is a specialized pair aggregate rather than an ordinary flattened entity list.** It accepts exactly two Number fields whose immediate **owning group is the same**; that group need not itself be repeatable, but each operand path must cross a repeatable level at one model-instance/root-sequence coordinate. Only the path's lowest repeatable level may carry an unrestricted `*`, and `Having` is rejected.

**Admission.** Two gates ahead of the operator's own branch apply: the same starless field twice reports `MVK_DUPLICATE_PARAM1` and a group beside a field inside it reports `MVK_DUPLICATE_PARAM2` — star-sensitively, so `Lines*/Qty, Lines*/Qty` is admitted where `Total, Total` is a duplicate — and a list of one or three operands reports `MVK_PARAMSIZE_INVALID_2`, whose underscore before the digit distinguishes it from the `MVK_PARAMSIZE_INVALID2` its siblings draw. A pair that reads a row on a level nothing binds meets that read first: the missing star `MVK_NO_WILDCARD` from the error field's own group, and containment `MVK_ERROR_FIELD_NOT_IN_RULEGROUP` from outside it; the reference reader answers a misplaced star with `MVK_NO_WILDCARD` first. The operator's own classes are pair-dependent:

| Shape | Class |
|---|---|
| different owning groups, including two operands that share one starred ancestor but whose fields sit at different depths | `MVK_DIFFERENT_GROUPS` |
| a filtered operand; an unstarred operand on a level the rule binds beside a starred one | `MVK_WILDCARD_AT_LOWEST_LEVEL_REQUIRED` |
| an operand below a repeatable level it leaves unstarred, including a plain descendant of the other's starred group and a star above the lowest repeatable level | `MVK_NO_WILDCARD` |
| a multi-star operand | `MVK_WILDCARD_ONLY_AT_LOWEST_LEVEL_ALLOWED` |
| a pair with no repeatable level | `MVK_REPEATABLE_LEVEL_REQUIRED` |

**These classes are ordered.** The chain runs owning groups, filter, stars, then the Number question, and keeps that order from outside the fields' groups; the filter and star gates are asked operand by operand from the left. The owning-group gate outranks the filter and repeatable-level gates, so a pair that shares no owning group reports `MVK_DIFFERENT_GROUPS` whether it also carries a filter or has no repeatable level anywhere.

- The bound-level case of the filter row needs no star at all once the level is bound — by the rule's iteration, its error field, its declaring group or a computation's target. `SumOfProducts(Rows/Amt, Rows*/Qty)` from a rule at the parent group reporting on `Rows/Amt` draws it, where `Sum` and `MaxValue` admit the same pair, and `Items/Count, Items/UnitWeight` draws it too, while `Items/Count, Items*/UnitWeight` beside an error field or target outside the group draws `MVK_NO_WILDCARD`.
- With both operands starring two levels, a `Having` on the left draws `MVK_WILDCARD_AT_LOWEST_LEVEL_REQUIRED` and the same `Having` on the right `MVK_WILDCARD_ONLY_AT_LOWEST_LEVEL_ALLOWED`. From a fixed sibling group a pair starring two levels draws `MVK_WILDCARD_ONLY_AT_LOWEST_LEVEL_ALLOWED`, with a String second operand too, while a starred operand beside that sibling's own field draws `MVK_DIFFERENT_GROUPS` and a filtered one `MVK_WILDCARD_AT_LOWEST_LEVEL_REQUIRED`. A star on a level the rule binds counts against the lowest-level bar, so the same pair draws the multi-star class from inside the outer repeatable group too.
- "No repeatable level" is necessary but not sufficient for `MVK_REPEATABLE_LEVEL_REQUIRED`: the owning-group gate outranks it.

**Evaluation.** The result scale is the sum of the two field scales. For two unkeyed operands evaluation constructs one common row environment stream and, in canonical row order, multiplies the two values from each environment and adds that product to the running total; every multiplication and addition uses the precision-50 boundary. An empty cell supplies numeric zero with its own declaration's directional missingness. A formal failure in **either** zipped list makes validation unavailable and computation poison; the offending cell's position does not change that verdict, and the formal pass emits every invalid cell regardless of the rule, so validation output carries no witness for an ordering here. An omitted row at either path makes a successful validation result both-directionally fillable.

**Two operands keyed independently below a semantic index pair by position instead**, each list read inside its own selected row. With `Packages` indexed by `Code`, `P1` holding `Items` weighing 2 and 5 and `P2` holding one weighing 3, `SumOfProducts` of `Packages/Items*/Weight For "P1"` with itself is 29, and `P1` against `P2` is 6 in either operand order, so a longer list's unpaired tail adds nothing to the value; the rows do not separate an unpaired value from one multiplied by an empty zero. An empty weight in a paired position contributes zero as any empty cell does, `P1` against a `P2` with no items is 0, and an absent key `P3` is 0 against itself and against `P1` in either operand order, where the comparison with 1 stays silent. A formally invalid cell in the unpaired tail still makes validation unavailable and computation poison, so the tail leaves the sum but not the formal check. These rows are validation firings on both runtime strategies and one computation, with every model admitted; a correlation, category or `Having` operand is unmeasured.

**Partial validation gates this operator by complete extent, per iteration row**, rather than by the normalized wildcard-only gate: an iteration row whose starred extent is enumerated in full evaluates, but the enumeration must cover the complete cross-product of row coordinates rather than merely every coordinate at each level independently, and a partial enumeration leaves the row UNKNOWN. The cover is taken over the union of the relevant entities addressing that row, so coverage spread across entities of different wildcard shapes counts. For a finite lowest starred level, complete extent means its **declared capacity**, including uninstantiated slots, not only the rows present in the document. Independently keyed operands each require that lower extent beneath their own selected parent. A missing selected parent additionally requires a wildcard at the keyed level; enumerating every concrete parent does not establish that absence, although concrete lower coordinates covering the complete declared capacity suffice beneath a wildcard parent. Covering only one of the two fields remains insufficient.

### 3.9 Filter traversal

**A filter can execute on a coordinate with no stored row.** The **filter traversal extent** of a filtered star runs each starred depth through the highest stored repetition at that depth across groups and parents, at least one and bounded by the operand's declared capacity; empty row objects count. Thus a lone stored row need not visit its missing capacity tail, while a sibling group with three rows or another parent's longer child group can make the same filter visit missing coordinates. Measured in the finite-capacity profile of three rows per leaf group and two per parent, on filtered `Sum`, the filled and value counts, `MaxValue`, first-filled, the fill quantifiers and uniqueness. Validation observes that sibling extent. In an instantiated-range field-fill predicate the filter is executed at such a coordinate while the coordinate never enters the tally; a declared-range predicate evaluates its filter at every declared coordinate instead ([§1 A.4.5](02-logic-and-formal-errors.md#a45-validation-filtered-field-fill-lists)).

**Computation uses the whole-programme cache scope.** Calculation traversal includes ancestor groups of every static operand and target in the complete computation programme, including unreached operands. Operands include the implicit group guards added before computation planning ([§11 §3.3](09-computations.md#33-what-compute-reports)): normally these contribute every descendant of the target's innermost repeatable group, including nested repeatable groups no operation names. An explicit conditional-group profile protecting that row or a narrower containing group suppresses the implicit guard; a narrower guard can thus exclude outer siblings. A target-only sibling can therefore widen a filter's extent before that target is computed, and a subplan must not narrow this inventory. Depth counts all path groups, including fixed groups. Target-only, unreached-operand, fixed-depth and nested-target controls are measured; a capacity-150 filter control agrees with the smaller profile.

**Each consumer selects its filter scan, and the presence of `Having` alone does not.** A **dense** scan tests every candidate of the extent in order. A **sparse-enabled** scan is dense while the product of the cache-bounded widths of the reopened suffix is at most 100, captured outer coordinates contributing width one; above 100:

1. The first search remains dense until a candidate satisfies the filter.
2. Afterwards, each later candidate is compared with the last kept candidate, its coordinate prefix through their first differing depth is taken, and the candidate is visited only if that prefix is present in the phase-visible occupancy cache.
3. Rejected candidates do not move the kept cursor, so advancing an outer coordinate starts a dense search over its lower coordinates until another candidate is kept.
4. Full coordinate depth includes fixed groups at coordinate one; group names do not partition occupancy, so explicit blank rows and rows of another group can supply the same prefix.
5. A skipped candidate evaluates neither its filter nor its payload.

A **declared** scan evaluates the filter at every declared coordinate. [The operator reference](14-operator-reference.md#traversal) assigns each consumer its scan.

**Every scan consumes the iterator incrementally, with one kept successor prefetched before the current payload is read.** Computation searches for the next kept candidate before consuming the pending candidate's payload, so a reached filter failure during that search precedes payload consumption; sparse traversal changes the search, not this order. A decisive current payload hides later filter failures beyond that successor and all later authored operands; materializing every selected row first is not equivalent. Full validation suppresses comparison on a reached unavailable `FirstFilledValue` payload, while computation propagates its unavailable result, and filter provenance remains attached to every reached operand, including one selecting no present payload. Validation still drops a filter whose semantic result is unknown, and a reached runtime failure remains a VALUE rule failure. For `FieldValuesNotUnique` the successor filter runs before the current selected payload is compared, but a deciding duplicate hides filters beyond that successor and all later authored operands, and empty and formally unavailable validation payloads leave the comparison prefix and its filter-derived polarity unchanged.

**The field-fill quantifiers select their scan per stage.** A later stage starts again at the first operand and runs only when the earlier result requires it:

| Quantifier | First stage | Conditional second stage |
|---|---|---|
| `AtLeastOneFieldFilled` | presence search | — |
| `NoFieldFilled` | presence search | — |
| `MoreThanOneFieldFilled` | second-witness search | — |
| `NotExactlyOneFieldFilled` | presence search | second-witness search when a filled value was found |
| `FieldsNotCollectivelyFilled` | presence search | declared-coordinate empty search when a filled value was found |
| `AllFieldsFilled`, `NotAllFieldsFilled` | declared-coordinate empty search | — |

A second computation matrix separates the consuming operators: Number, String and Boolean `NumberOfValueInFields` and exact and yearless `DateRangesOverlap` remain dense, while `AtLeastOneDateRangeOverlaps` enables sparse traversal; small-domain controls succeed for all, above 100 only scalar-versus-list overlap skips the missing tail, and explicit blank occupancy restores its reached failure. ## 4. Where a star binds — the anchor rules ⚠

A `*` in an operand path controls which enclosing indices are *fixed* (inherited from the current row) and which are *reopened* (iterated over).

### 4.1 Binding

**A starred operand read from an iterating row binds the enclosing indices only for the repeatable levels strictly above its first `*`; the starred level itself always iterates its full extent, and so does every level below it.** So a **same-group star spans all rows, not the current one**: only `$` correlates (§3.2), a bare star never does. A multi-star operand `A*/B*/F` binds at the levels above `A`.

- **A cross-subtree star binds only along the shared named ancestry.** An enclosing row's index is never applied positionally to an unrelated chain, so a cross-subtree count or presence reads identically from every iterating row.
- **A bare (unstarred) reference to a repeatable group in a group-scope quantifier is an iteration anchor of its own** — ancestor-or-self, per row, judging the current row's cells.
- **Where an operand names a chain of repeatable levels, the unstarred levels must form a prefix of that chain, and the error field must sit inside the innermost unstarred level.** A star does not cover the levels beneath it: an operand starring an outer level while leaving an inner repeatable level bare is rejected `MVK_NO_WILDCARD` at every polarity and every error-field placement. A fully starred chain has no unstarred level, hence no iteration, hence neither a locus requirement nor the negative-condition refusal of §1.8. Composing the wildcard gate and the iteration gate separately gets this row wrong, because the wildcard gate alone sees the outer level starred and the iteration gate alone sees an error field that could make the inner level iterable.

**Admission of a bare repeatable group operand is decided by the error field's locus:** the bare form is admitted exactly when the error field sits inside the operand. Otherwise the walk refuses it, and the error field's position names the class:

| Error field | Operand | Class |
|---|---|---|
| beside the operand's group, its own path declaring no index field | declaring an index field | `MVK_ERROR_FIELD_NO_INDEX` |
| beside the operand's group, its own path declaring no index field | any other | `MVK_NO_WILDCARD` |
| beside the operand's group, its own path keyed | any | the index gates of §2.2 decide |
| below the operand's group | any, index-keyed or not | `MVK_NO_WILDCARD` |
| outside the rule group | any | `MVK_ERROR_FIELD_NOT_IN_RULEGROUP` alone, from a fixed or repeatable rule group the error field lies outside; `MVK_NO_WILDCARD` from the one holding it |

- The containment refusal is not the quantifiers' own: measured on starred aggregates, on a field read and on the bare group operand itself, each of twenty-two group carriers naming a bare repeatable group draws it and nothing else, ahead of that carrier's own gates, the count's arity gate included — `FieldFilled`, `FieldNotFilled`, `GroupFilled`, `GroupNotFilled`, the group-list quantifiers, `NumberOfFilledGroups`, the field-fill quantifiers, `NumberOfFilledFields`, `Sum`, `FirstFilledValue`, `NumberOfValueInFields` and `CurrentRepetition` alike.
- **Every gate of an operator's own waits for its operands to be read**, and a refused read answers alone: the scalar star bar under `GroupFilled` and `GroupNotFilled`, the group-list star bar, the root gate, the exact and the nested duplicate, and the field-kind gate each give way to it. With a repeatable `Lines` below the root, `AllGroupsFilled(/Warehouse, Lines)` draws `MVK_NO_WILDCARD` with the error field outside `Lines` and `MVK_ROOT_GROUP_REFERENCED` with it inside.
- The starred form is admitted from any locus.
- Measured within one model built twice and differing in a single declaration, over four quantifiers, both spellings and three error-field loci none of them beside the operand, the matrix is identical with and without a declared `indexFieldName`, and identical whether or not the error field is that index field, so locus is the deciding variable there.

**The prefix rule holds beyond the group-scope quantifiers**, on every carrier measured on both arms and whatever binds the level, index-keyed or not on `Sum`, and ahead of a carrier's own star bar, wherever the error field lies inside the rule group; outside it the containment class `MVK_ERROR_FIELD_NOT_IN_RULEGROUP` answers first, on either side of the first star. Below the first star it is measured on validation carriers, from a fixed rule group that binds nothing and from a repeatable one binding the outer level: `Sum`, the group count, the seven field-fill quantifiers and `NumberOfFilledFields`; `NumberOfFilledFields` and `AtLeastOneFieldFilled` over a group, and `Sum` and `NumberOfFilledFields` over a filtered star; `FirstFilledValue` over a Number or String field; `FieldValuesNotUnique` and `NumberOfDifferentValues` over a Number, String or Date field; `MaxValue` over a Number or Date field and `MinValue` over a Date; `NumberOfValueInFields` over a Number, Boolean or String field; the three value-list quantifiers over a String field against literals, and `AtLeastOneFieldValueIncludedInValueList` over an Enumeration against a literal and against a field, whether a starred String on either side, a starred Number against a Number field or an Enumeration field against a starred Enumeration; every group-list quantifier; `DateRangesOverlap` and `AtLeastOneDateRangeOverlaps`, with and without a year; and `SumOfProducts`, ahead of its own lowest-level star bar.

> **Non-normative implementation note.** Encode the rule literally: given the current `Env` and an operand path, keep the `Env` bindings for levels strictly above the first starred segment, and reopen the starred level and everything below it. "Same-group star spans all rows" is then what reopening the starred level means when the star is at the current level. The cross-subtree rule is that only shared-ancestry prefixes carry a binding; unrelated chains start from a fresh iteration. Property-test the environment function against hand-computed small cases (one or two rows, one or two levels).

### 4.2 The open declared tail

**Declared-tail completeness follows the first-star boundary hierarchically.** For `A*/B*/C*/F`, missing declared capacity at `A`, beneath any actual in-scope `A` row at `B`, or beneath any actual in-scope `A/B` row at `C` leaves an **open declared tail**; so does an instantiated selected leaf whose `F` cell is empty. The unfiltered star is structurally complete only when every reopened repeatable level is exhausted under every actual parent and no selected leaf is empty. A reopened level with no finite `repeatability` is always open. A repeatable level strictly above the first star remains bound, so unused capacity outside that bound row does not taint the operand. Comparing the flattened leaf-row count only with the deepest cap is invalid: a dense branch can numerically hide a missing outer or middle branch.

The **declared capacity** domain of §1.3 is the slot set this completeness ranges over: every declared slot `1 .. repeatability` of each reopened level under each actual parent, a missing slot reading empty without creating a row.

> **Non-normative implementation note.** Define tail completeness recursively over the reopened repetition tree: compare each actual parent's child coordinates with that level's finite cap, recurse through actual children, treat an absent cap as unbounded and open, and inspect selected leaf emptiness. Do not materialize the declared Cartesian product, and do not replace the recursive predicate with one flattened count.

### 4.3 Capacity: rows beyond the declared repeatability

**The instantiated-rows domain** of a star or group operand is the in-capacity instantiated rows of each level it reopens. **An instantiated row beyond its level's declared `repeatability` remains in the physical topology and still supplies structural group content, but it is outside the evaluation domain of every operand that expands rows.** Its descendant cell contributes neither a value nor a formal poison, and the row does not increase a group count. This exclusion is separate from declared-tail completeness and does not erase the row from `GroupFilled`-style presence ([§1 §2.2](01-data-model.md#22-over-repetition-and-phantom-rows) and [§3 over-repetition](02-logic-and-formal-errors.md#over-repetition) own the structural codes).

**The row is removed from the domain rather than admitted and classified unavailable.** A malformed cell separates the two accounts: in capacity it makes `Sum` non-evaluable, while the identical cell one index above capacity leaves `Sum` answering its in-capacity total. An implementation that filters over-limit cells after classifying them agrees everywhere except on documents that mix a bad cell with a good one. Measured on the unstarred group operand and on the starred one, on `Sum` and on the count alike. **The exclusion never makes the aggregate non-evaluable**: over an in-capacity domain that the projection has emptied, every operator answers its all-empty identity ([§2 A.3](03-empty-and-required.md#a3-what-an-all-empty-selection-folds-to-the-aggregate-identities)) — the definite `0` for `Sum`, both Number extrema, `NumberOfDifferentValues` and `NumberOfValueInFields` alike — both where no repeatable row exists at all and where every present cell sits above capacity, so an emptied domain and an unavailable one stay distinct. The extrema remain free to move in either direction while empty in-capacity rows survive, which keeps their zero identity separate from the counts'.

**The exclusion reaches every consumer of the operand stream, on every operand form it admits.**

- Measured carriers: starred `Sum`, starred-field `NumberOfFilledFields` and starred-group `NumberOfFilledGroups` at one repetition level; a group operand for `NumberOfFilledFields`, `NoFieldFilled`, `AtLeastOneFieldFilled`, both `NumberOfValueInFields` overloads, `Sum`, `MinValue`, `MaxValue` and `NumberOfDifferentValues`; a starred field operand for `MinValue`, `MaxValue`, `NumberOfDifferentValues` and `NumberOfValueInFields`, each against its own in-capacity control, and `MinValue` additionally against a reversed document in which the over-limit row holds the smaller value.
- **The star makes no difference to a group operand**: the count and `Sum` answer identically over `G/Sub*` and over the unstarred `G`. Nesting does not change it for a fixed group operand: the excluded row may sit at an outer or an inner repetition level and the answer is the same either way.
- `FieldValuesNotUnique` on the Number and token carriers, `NumberOfDifferentValues` and `FirstFilledValue` answer from the in-capacity extent on a starred field, a starred group and a fixed group alike: a duplicate pair spanning an in-capacity row and an over-limit one stays silent, `A, A, B` over a `max 2` group answers a distinct count of `1` rather than `2`, and a document whose only filled cell sits above capacity makes `FirstFilledValue` answer the all-empty identity of its in-capacity projection — measured on an unseeded String target, which reports no computed outcome. The distinct count and `FirstFilledValue` settle removal against classification, because an admitted-and-unavailable row would make each of them unavailable. Uniqueness cannot settle it: that operator skips a formally unavailable operand exactly as it skips an empty, so both routes give the same verdict there.
- **A filtered Number star takes the same extent on both arms**, measured on `Sum` under full validation and computation: the over-limit row is never kept, even by a filter that would keep its value, and its position read does not make the filter unknown, so the answer is the filter applied to the in-capacity rows alone. Under full validation and a reflexive position filter the extrema, `NumberOfDifferentValues` and `NumberOfValueInFields` take the same extent; on the computation arm only `Sum` is measured.
- **`NumberOfValueInFields` takes the in-capacity extent on every measured carrier.** In computation, over a starred repeatable Number group, value-validating String group or single-axis Boolean group with no declaration below a deeper repeatable group, changing only over-capacity content between a non-match, a match and malformed input does not alter the result, while malformed content in an in-capacity row still suppresses the count and clears its target; measured `True` forms include Boolean-only, Confirm-only, Confirm-then-Boolean and Boolean-Confirm-Boolean groups, and `False` forms one, two and three Boolean declarations. In full validation a plain starred String field, a plain starred Boolean field under both constants and a plain starred Confirm field under `True` select the in-capacity extent: an over-limit match contributes nothing, two empty in-capacity cells beside an over-limit confirmation yield grow-only `0`, one confirmation beside one empty grow-only `1`, and two confirmations fixed `2`. The same projection holds with a `Having`, measured only with the reflexive `CurrentRepetition(Rows) == CurrentRepetition(Rows)` filter; other filters and the filtered Number overload are unmeasured, and whether capacity applies before or after the filter is not established. The full-validation projection is unmeasured for Enumeration and category stars, for `False` on the filtered Boolean form and under partial validation, and the plain starred String, Boolean and Confirm field projection is unmeasured under computation. Structural over-repetition findings remain beside each result.
- Whether the exclusion applies when an outer or inner axis of a nested *star* exceeds capacity is unmeasured; for computation targets it is settled below.

**The exclusion is a property of the operand, not of the validation arm.** An operand evaluated inside a computation answers from the same extent: over one starred field and one group carrier, `Sum`, `MinValue`, `MaxValue`, `NumberOfDifferentValues` and `NumberOfValueInFields` produce under computation the identical table they produce under full validation, on both codegen strategies. The engine reports `zuGrosseKontextnummer` for the over-limit cell among the computation's operand errors and still yields an uncleared, definite computed value, so a formal error is present in the operand and does not reach the result. **An unavailable computation is absent rather than zero**: an in-capacity malformed operand yields no computed outcome at all, where the identical cell one index above capacity leaves every computed value intact.

**The computation target domain.** A repeatable target's computation runs once per **in-capacity** instantiated row: a group declared `max 3` carrying constant computations produces exactly three rows of computed values whether the document instantiates three, four or five.

- The excess row stays in the clearing domain: a target cell holding a stored value in such a row is **cleared**, in the same run where its in-capacity siblings compute a value from a source present for both, exactly as an in-capacity row whose computation yields no value is. An implementation that drops the row leaves a stale value the Kernel removes.
- The run reports `zuGrosseZeile` on the row and `zuGrosseKontextnummer` on each node the document writes at or beneath the row, so the row is demonstrably present and simply not computed into. Two sibling over-limit rows each draw their own `zuGrosseZeile`; absorption applies to nesting, not to disjoint rows.
- **The exclusion reaches through an ancestor**: a row beyond an outer level's capacity contributes no target either, although its own coordinate at the target level is in range, so the excluded set is decided by the whole environment rather than by the target level's coordinate. Which level the excess row sits at does not matter: over three repetition axes, documents differing only in whether the outer, middle or inner level overflows produce identical computed results. Measured on three carriers and three topologies — a bare constant at one repetition level, a sibling-star `FirstFilledValue` under a repeatable ancestor, and a `DateFromDateTime` conversion across three axes.
- The physical row list and the target inventory therefore differ by exactly these rows, and an implementation sharing one enumeration between validation and computation will compute into rows the Kernel leaves untouched.

## 5. `GroupFilled` and the other repetition rules

### 5.1 Group presence

**Validation presence for one concrete group instance is a product of three independent dimensions**: `content` records formally admitted content, `erroneous` records whether a formally rejected descendant marked the group erroneous, and `relevance` is `NONE`, `PARTIAL` or `FULL`. Do not collapse that state to one Boolean.

- Formally admitted content comes from a formally valid valued descendant, a duplicate index value admitted before uniqueness reports its error, or an instantiated repeatable descendant row. A created-but-empty repeat row is therefore content for itself and its ancestors. An over-limit row still supplies that structural content even though it receives the structural codes [§3](02-logic-and-formal-errors.md#over-repetition) assigns by coordinate position and its ordinary row checks are suppressed.
- A malformed, custom-invalid or constraint-invalid value rejected by formal conversion is not content. It independently marks every ancestor group erroneous.
- For a **repeatable** `G`, an instantiated row itself establishes content. For a **non-repeatable** `G`, the group's own structural node is not content; only the admitted descendant sources above count.
- When a non-repeatable group is the written terminal below one or more starred ancestors, the first star still reopens the canonical ancestor topology, but the terminal remains non-repeatable. Evaluate the same group product once in each selected complete environment; do not reinterpret an instantiated ancestor row as terminal content and do not replace the product with a topology-row count.

Under full relevance, the scalar predicates are exactly:

| admitted content | erroneous | `GroupFilled` | `GroupNotFilled` |
|---|---|---|---|
| no | no | false | true |
| no | yes | false | unknown/non-firing |
| yes | no | true | false |
| yes | yes | true | false |

Admitted content decides `GroupNotFilled` false before an independent error is considered; a content-free erroneous group remains unknown. That leaf distinction is unmeasured: final condition evaluation collapses unknown and false leaves alike to non-firing, so no rule message separates the unknown account from a false one. `GroupNotFilled` is therefore not Boolean negation of `GroupFilled`. Group-list tally and plain numeric group-count consumption are specified in [§1 A.4](02-logic-and-formal-errors.md#a4-fill-quantifiers-group-scopes-and-the-two-iteration-ranges).

Under partial validation, any relevant descendant gives each ancestor group at least `PARTIAL` relevance. Admitted content observed in that relevant slice is enough to establish `GroupFilled`; absence requires `FULL` relevance plus no content and no error. `FULL` relevance comes from an explicitly relevant group or ancestor, or complete relevant coverage of all declared descendant fields across deeper repeatable axes. One relevant empty descendant cannot prove absence.

### 5.2 Repetition predicates

- **Some conditions are refused inside a per-row iteration** (`MVK_NEG_CONDITION_IN_ITERATION`), and a positive guard lifts the refusal; §1.8 owns the gate and its leaf classes.
- **The range a list predicate over a starred group ranges over is per operator**: [§1 A.4.2](02-logic-and-formal-errors.md#a42-the-two-iteration-ranges) assigns each field-fill quantifier the declared or the instantiated range.
- **An instance beyond the group's declared `repeatability`** draws structural errors (VALUE) at the address-formal gate before scalar conversion — `zuGrosseZeile` / `zuGrosseKontextnummer` for a group below the root, and `zuGrosseLfdNummer` throughout for a repeatable root group — and the over-limit rows' ordinary checks are suppressed ([§3](02-logic-and-formal-errors.md#over-repetition)); creating that row still supplies structural content to its non-repeatable ancestors, and §4.3 states its place outside operand domains.
- **"At least N rows" is expressible via the starred single-group count:** `NumberOfFilledGroups(G*)` counts one repeatable group's in-capacity instantiated rows, zero included, so `NumberOfFilledGroups(Items*) < N` fires at 0…N−1 rows; the aggregate-consumed star does not put the rule into per-row iteration. An over-limit physical row remains structural content but does not increase this numeric count. "At most N" stays structural (`repeatability`).

### 5.3 `FieldValuesNotUnique`

**In validation, `FieldValuesNotUnique(f1, f2, …)` — or the starred `FieldValuesNotUnique(G*/f)` over a repetition's rows — fires when two of the operands' compared values are equal, and it answers at the first duplicate it finds while scanning operands in authored order.** Empties are skipped (two empties are not a duplicate); equality is the operator's value identity (§3.6); and a formally invalid operand is **skipped exactly like an empty** — it does not suppress. So a duplicate on either side of an invalid cell still fires, while two equal invalid values are not a duplicate, because neither enters the comparison. This is a deliberate exception to the general rule that a formal error suppresses a referencing rule ([§3](02-logic-and-formal-errors.md)); the pair of observations separates skipping from suppressing, since both accounts predict silence for the equal-invalid case alone.

**Admission.** The operator takes the family's shared arity rule (§3.5), with a single group slot admitted even where its expansion is one cell; a single BOOLEAN or CONFIRM operand reports `MVK_PARAMSIZE_INVALIDN`, arity being the earlier gate. Two further gates then decide admission, and **the kind gate runs first**:

- **The kind gate** refuses BOOLEAN, CONFIRM and DATE_RANGE outright, `MVK_ONLY_STRING_ENUM_NUMBER_DATE_ALLOWED`; DATE_RANGE is excluded by kind even though it carries a declared format. Every other kind is admissible, CUSTOM included, and a Custom operand's registered type name is not part of the gate. A Boolean or Confirm beside another category reports the kind code with the mixing code absent. The gate applies to the **whole operand list**, so authored position does not select the class: an inadmissible operand authored last still reports the kind code, not the mixing code an earlier operand would have produced; both separating operand orders are measured.
- **Among temporal operands the kind gate also requires one identical declared `format` string**, keyed on the format rather than on the kind: a DATE declared `yyyy` beside a DATE_FRAGMENT declared `yyyy` is accepted across two kinds, while two DATE fields differing only in declared format are refused, and so is a cross-temporal pair such as Date beside Time, with the mixing code absent. The format-keying is intra-family: a DATE beside a DATE_RANGE is refused even when the DATE carries the range's own declared format, and two DateRanges differing in their legal (format, separator) pair are refused for the format reason. String, Enumeration and Number operands carry no format constraint, so differing Number scales stay admitted.
- **The mixing gate reads a comparability category**, not a declared kind: `{String, Custom}`, `{Enumeration}`, `{Number}` and `{Date, Time, DateTime, DateFragment}`. Mixing categories is rejected `MVK_VARYING_TYPES_NOT_ALLOWED`, which, unlike `NumberOfDifferentValues`, is stricter than token comparability, so even String beside stored Enumeration is refused, while Custom beside String is accepted and Date beside String or Number is refused. The temporal category is one category of four members, measured on four pairs sharing one identical declared format string: `Date` beside `DateFragment` at `yyyy`, `Time` beside `DateTime` at `HH:mm:ss`, and a `Date` declared `HH:mm:ss` beside each of those two, the edge that crosses between them. DATE_RANGE is not a fifth category here, because the kind gate refuses it before this gate.
- Every operand must be a value validation, and an Enumeration category projection is refused for this operator as for every field-list predicate, so only stored values are compared. The type name of a list is not otherwise constrained, and a mixed direct-plus-starred list of one category is admitted.
- **A group-scope operand is admitted**, non-repeatable and starred repeatable alike, and the two gates read it differently: arity is satisfied by the group slot, so a group whose expansion is a single field is admitted while that same field authored directly is rejected `MVK_PARAMSIZE_INVALIDN`, while the category gate reads the expansion, so a group expanding to a Number beside a String is rejected `MVK_VARYING_TYPES_NOT_ALLOWED` exactly as the equivalent explicit list is.

**A group operand is compared as a single value set over every `(row × field)` cell reachable below it**, descending through nested subgroups and iterating every row of any repeatable one. It is neither per-row nor per-field: a duplicate within one row across two fields, or between two rows of a nested subgroup, fires exactly as one across the operand's own rows does. The recursion needs no authored `*`, because the iteration comes from the model's repeatability; the same extent holds when the operand carries one. Empty cells are skipped as in an explicit list. No depth limit is measured: with two stacked repeatable levels below the operand, a duplicate at neither level's first row still fires, while an all-distinct control over that fixture stays silent.

**The compared set is bounded by the operand's own depth, not by the rule's row.** Repeatable levels above the operand stay bound at the rule's binding, and every repeatable level below the operand is reopened. A rule authored on a repeatable group whose operand names an ancestor group therefore compares that ancestor's whole subtree at the rule's binding of the ancestor's own levels, the rule's sibling rows included; an operand starring an inner level under a bound outer one compares only the rows the star reopened. An unstarred repeatable operand, admitted only with the error field inside it (§4.1), stays bound at the rule's row of its own level (unmeasured). The same depth governs the `referenced` set ([§1 §3.1](01-data-model.md#31-rules-validation)), so the compared set and the published references cannot disagree about one operand's extent.

**A firing over a group operand emits exactly one message, anchored at the error field's concrete first row**, and neither the count nor the address depends on where the duplicate lies: a duplicate spanning two of the operand's rows and one lying wholly inside its second row report identically. That holds with the rule authored on the root and on the repeatable group itself, and with the error field resolving above the operand's level and per row inside it; the per-row error field is what separates one evaluation over the operand from a per-row evaluation whose messages collapse onto a shared address. Every measured firing is VALUE. Both operand forms are measured and agree, the unstarred one including with the error field inside a nested repeatable subgroup and the duplicate wholly in that subgroup's later rows. The firing's `referenced` set carries the expansion at wildcarded coordinates for every repeatable level at or below the operand, while levels above it stay concrete. A filter cannot attach to a group operand (§3.1), so the group form has no reached-`Having` case.

**The starred form is aggregate-style: it evaluates once per surrounding bound prefix, not once per duplicate row.** For values `[7,5,5]` the Kernel emits one message, at the error field's concrete first-row address, even though the duplicated values occur in rows 2 and 3, and moving the rule between the repeating group and its parent does not change that result. An unfiltered firing is **VALUE**; a reached `Having` makes a firing OMISSION even when every retained value is filled ([§12](10-validation-and-polarity.md#4-the-directional-fill-machinery-behind-the-typing)). The `referenced` set contains the starred value field with its reopened group coordinate wildcarded plus any field operands used by `Having`; `CurrentRepetition` contributes no field pointer. `RepetitionNotUnique` (§6) is the per-row alternative and attributes each duplicate row instead.

**Filtered operands** are scanned as §3.9 states.

**In a computation precondition, `FieldValuesNotUnique` instead propagates a reached formally invalid or calculation-invalid operand.** The ordered scan still skips empties and stops at its first duplicate: a duplicate before an invalid operand selects the alternative without reading that operand, while the opposite order poisons the target. A filtered operand retains iterator lookahead, so a duplicate in row two can still reach an invalid row-three filter, while a row-four failure beyond that lookahead remains unread.

## 6. `RepetitionNotUnique`, precisely ⚠

**`RepetitionNotUnique(k1, k2, … [@From Group])` is a per-row predicate that fires at a row whose composite key duplicates another row's key within the reference group's scope.** The key list holds one or more direct plain field references; `@From` selects the scope (for example unique per order versus unique across all orders). Admission runs in three phases — every read, then the key-list gates, then exactly one branch — and evaluation builds the duplicate relation once over the whole scope before the per-row leaf composes with the rest of the condition.

### 6.1 Admission

**Reads first.** Every key and the `@From` scope are read before any gate, and a read answers every time, in either position:

| Read outcome | Class |
|---|---|
| an absolute path whose first segment names no root group | `MVK_INVALID_ROOT_GROUP` |
| any other unresolved path, a relative path included; a missing segment, whether a star on a repeatable segment precedes it or it carries its own | `MVK_INVALID_ENTITY` |
| a path above the root | `MVK_TOO_MANY_PARENT_GROUPS` |
| an ambiguous bare name | `MVK_FIELDNAME_NOT_UNIQUE` |
| a star on a nonrepeatable segment, whatever follows it | `MVK_INVALID_WILDCARD` |
| a key whose repetition the rule leaves unbound | `MVK_NO_WILDCARD` |

The unbound-key read answers ahead of every list gate: `Claims/ClaimRef` read from a rule reporting at the root's `Reference` draws `MVK_NO_WILDCARD` beside a category, a group, a star, a semantic-index key, a raw key or a group named twice. A semantic-index key whose index the resolver misses answers at the read as well. Separately, a non-repeatable error field draws `MVK_NO_WILDCARD`; its order against the other gates is not stated.

**Key-list gates, each over the whole list, in this order.** A gate reads the whole list before the next is asked: each adjacent pair of gates 1–5, and gate 3 beside gate 6, answers with the earlier gate's class in both key orders.

| Order | Gate | Class |
|---|---|---|
| 1 | a group or key named twice | `MVK_DUPLICATE_PARAM1` |
| 1 | a nested duplicate in either order, the root beside a key it holds included: `RepetitionNotUnique(Claims*/ClaimRef, Claims)`, `RepetitionNotUnique(Shipping, Shipping/Carrier)`, `Insured, Insured/InsuredName`, `/Policy, Claims/ClaimRef` | `MVK_DUPLICATE_PARAM2` |
| 2 | a category projection | `MVK_CATEGORY_NOT_ALLOWED` |
| 3 | a group, the root group included, since this operator asks no root-group gate | `MVK_NO_GROUPS_ALLOWED` |
| 4 | a starred key path that resolves (the operator forbids a star rather than requiring one) | `MVK_NO_WILDCARDS_ALLOWED` |
| 5 | a semantic-index key, whether or not it names the rule's error field | `MVK_SEMANTIC_INDEX_NOT_ALLOWED` |
| 6 | a String without value validation | `MVK_INVALID_RAW_TYPE` |

There is no Number/String-only kind gate: every otherwise value-validating field kind is admitted, Number included.

**Then exactly one branch runs, chosen by whether `@From` is present, and every key-list class a row places beside a branch gate answers first.**

*With `@From`.* The scope has been read with the keys, its walk before its emptiness, so an unpaired repetition is refused at its read rather than by containment:

| Scope | Class |
|---|---|
| reporting on `Crates/CrateRef`, `@From Pallets` over an index-free parallel `Pallets` | `MVK_NO_WILDCARD` |
| the indexed twin of that `Pallets` | `MVK_NOT_IN_GROUP` |
| reporting at the root's field: a keyed, an index-free or an empty repeatable scope | `MVK_NO_WILDCARD` |
| from a rule iterating `Claims`, the empty repeatable `Vacant` | `MVK_NO_WILDCARD`, ahead of the raw and duplicate gates |
| an empty fixed scope | `MVK_GROUP_IS_EMPTY`, ahead of the repeat gate |
| `Vacant*`, whose read passes | `MVK_GROUP_IS_EMPTY`, ahead of the star gate |
| a scope whose semantic index reads | `MVK_SEMANTIC_INDEX_NOT_ALLOWED`, ahead of containment |
| a starred scope whose read passes | `MVK_NO_WILDCARDS_ALLOWED`; the read answers first on an empty, a fixed and a keyed starred scope |
| a key or scope read per row by a rule reporting outside its group | `MVK_ERROR_FIELD_NOT_IN_RULEGROUP` |

After those, in order: the scope must be a group (`MVK_NO_FIELDS_ALLOWED`), it must repeat (`MVK_GROUP_NOT_REPEATABLE`), and it must hold every key (`MVK_NOT_IN_GROUP`). No shared-path check runs in this branch: `RepetitionNotUnique(Claims/ClaimRef, Payments/PayRef @From Claims)` draws `MVK_NOT_IN_GROUP` where the same keys unscoped draw `MVK_NOT_IN_SAME_PATH`; keys in sibling fixed groups of the scope are admitted; and keys in two repeatable groups inside it that iterate jointly on a shared index field meet the ban on parallel iteration beside this construct, `MVK_PARALLEL_ITERATION_NOT_ALLOWED`.

*Without `@From`.* Three placement gates run in order:

1. The keys' lowest repeatable groups must lie on one path (`MVK_NOT_IN_SAME_PATH`); keys in sibling fixed groups of one repeatable group are admitted, and this gate answers ahead of the next in both key orders.
2. Every key must lie inside the rule group (`MVK_NOT_IN_RULEGROUP`). An outsider whose read is clean and which passes the shared-path gate draws it: one under no repetition of its own; one in a repetition iterated jointly with the rule's, such as `/Policy/Payments/PayRef` read from a rule in `Claims` with both groups keyed on `ClaimRef`; and one in the repetition holding the rule group, such as `/Policy/Claims/ClaimRef` read from a rule in `Claims/Items`. An outsider in a repetition nothing addresses, index-free beside the rule's, draws `MVK_NO_WILDCARD` at its read instead.
3. Each key must have a repeatable group between it and the rule group (`MVK_REPEATABLE_GROUP_MISSING`), except at a repeatable root holding every key directly, whose rule is admitted.

**Three structurally different shapes collapse into `MVK_REPEATABLE_GROUP_MISSING`**: a second key in a non-repeatable group, a sole key whose group is not repeatable at all, and the rule authored at the repeated group instead of its parent, the last for both absolute and relative key spellings. A component whose group repeats nowhere draws it in either key position.

**Parallel key branches are classed by index-keying.** Two repeatable groups that share an index field iterate jointly and reach the containment gate, so the indexed fixture draws `MVK_NOT_IN_SAME_PATH` (and, under `@From`, `MVK_NOT_IN_GROUP` on the same construction); two that do not are an unpaired repetition, refused at the wildcard read before any containment question, so the index-free fixture draws `MVK_NO_WILDCARD`, a second key in a parallel repeatable group included. The rule's own position does not decide it: an index-free model in the same position was measured and draws `MVK_NO_WILDCARD`. Without index-keying, no witness reaching the containment gate is known.

**A model-legal condition contains at most one `RepetitionNotUnique` leaf.** A second occurrence is rejected during consistency checking with `MVK_INVALID_COMBINATION_OF_REPETITON_NOT_UNIQUE`; this is a model-legality constraint, not an evaluation rule and not a grammar restriction.

### 6.2 The duplicate relation

**The reference group.** With `@From`, the named group. Without it, the **first repeatable group below the rule group** on the key path, and uniqueness is checked per that group's **parent row**: a key two repeatable levels deep is checked across all inner rows of the whole outer scope, not per intermediate group. When the rule group is a repeatable root holding every key directly, there is none, and the reference group is the root, whose rows are compared across the whole document as an explicit `@From` of the root compares them; a key in a repeatable subgroup of the root keeps that subgroup and is compared per root row.

**The row domain is the uniqueness relation domain of §1.3, and composite-key order does not select it.** Key components may occur at different depths when their parent groups lie on one hierarchy path, and components in sibling fixed groups of one repeatable row are admitted and compare per that row, as `RepetitionNotUnique(Rows/K1/KA, Rows/K2/KB)` does. The deepest key parent supplies the row coordinates; shallower components resolve against that row's own ancestor coordinates. Reversing the authored key-component order therefore preserves the duplicate rows and VALUE/OMISSION polarity, including when an ancestor `@From` explicitly scopes the relation.

**Participation.** A composite key compares as the **tuple**, each component by the identity of §3.6: Number keys by normalized numeric value, every other kind by its exact internally stored text. Then:

- An **all-empty** key row is skipped. Among participants (at least one key field filled) **empties match empties**.
- **Row drop.** A formally invalid key cell drops its row from the relation, per key cell: malformed, duplicate-index, over-repetition and **required-empty** cells all count as unknown. The distinguishing property is requiredness, not emptiness: an optional-empty cell is a valid null participant. A formal error on a non-key field of the same row does not drop it.
- **Partial validation.** A row participates only when every instance of every composite-key field in that row is relevant. If any key component is nonrelevant, the row is excluded, so a duplicate cluster exists only among rows whose complete keys are relevant. An independently decisive relevant branch in the surrounding Boolean tree may still fire.

**The relation is branch-independent.** It is built over the full selected scope independently of every surrounding branch: a guard-false duplicate does not fire, yet still makes its partner a duplicate.

### 6.3 The leaf, its polarity and its references

**Each row's result is an ordinary three-valued predicate leaf in every model-legal `And`/`Or` tree**, composing through the verdict and polarity tables of [§12](10-validation-and-polarity.md#3-every-fired-message-is-typed--value-vs-omission-).

- **Key fillability.** A duplicate whose key components are all filled is **VALUE**; a duplicate with an empty fillable key component is **OMISSION**.
- An OMISSION firing under `Or` with a false sibling remains OMISSION, while an independently firing VALUE sibling wins.
- A negative-presence sibling that would let the iterating rule fire on a not-filled repetition is refused `MVK_NEG_CONDITION_IN_ITERATION` (§1.8).

When this leaf supplies the firing, `referenced` contains every key field in the current row and in every duplicate peer row. A VALUE firing has no `fillToFix` pointers; an OMISSION firing projects that same complete duplicate-cluster key set into `fillToFix`. References owned by independent composed branches remain resolved at the current evaluated row rather than expanding over the duplicate peers. **A leaf that does not fire contributes no reference at all**, not even its keys at the current row, while a firing sibling's references stand: under `RepetitionNotUnique(G1/Flag, G1/G2/S) Or FieldFilled(G1/G2/N)` a row with a unique key and a filled `N` refers to `N` alone. These are pointer sets, not ordered sequences.

> **Non-normative implementation note.** Keep two separate phases: first derive the duplicate multiset over the whole scope from the eligible rows and retain each duplicated key's complete peer cluster; then expose the per-row verdict as an ordinary leaf inside the complete Boolean tree and project peer pointers only when that leaf contributes to the firing. Folding a surrounding guard into the first phase breaks the branch independence above.
