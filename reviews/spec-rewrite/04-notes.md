## Behavioural decisions

1. **Static scale of a `−1` maximum (ch04-6).** Old 04:131: "A model that omits `maxFractionalDigits` gets scale **`0`**, never unbounded." Old 04:125: "A `−1` maximum fixes the count at the minimum `n ≥ 0`, an absent minimum reading as `0`" (runtime only; static scale unstated). Side taken: the static scale is the resolved maximum — the declared maximum, or for `−1` the minimum (`0` when absent); the `(−1, 0)` exception has scale 0. Lean: `readFieldType` (`scale := if maximumDigits = -1 then minFractionalDigits else maximumDigits.toNat`), `A12Kernel/Reference/Dm/Model.lean`. Marked unmeasured in the text. No other chapter decides it.
2. **Power-scale exponent shape (ch04-7).** Old 04:52: "only from a scale-0 base under a **nonnegative authored literal** exponent". Old 04:52 (later): "a scale-0 base raised to a syntactically simple nonnegative constant exponent derives scale 0". Side taken: an ungrouped numeric literal (a signed literal is one literal) with value ≥ 0; `{2}` and `BaseYear` derive unknown, `-0` derives 0, all three marked unmeasured. Lean: `AuthoredNumericExpr.isSimpleNonnegativeConstant`, `NumericScaleSummary.power?` (`A12Kernel/Semantics/NumericExpression.lean`); the group case is locked by `Proofs/NumericExpression.lean`. The exponent gate itself keeps the old text's "known scale no greater than 0" (04:52), which the live gate `NumericScaleSummary.validPowerExponent` implements; `exponentRefusal` in `A12Kernel/Elaboration/ArithmeticShape.lean` admits only scale 0 but takes `Option Nat`, cannot express a negative scale, and is used only by its own conformance and proof modules, so it is not a competing account of live admission.
3. **Capability of rounding and of `+`/`-` (ch04-1).** Old 04:59 (non-normative note): "addition/subtraction take the maximum known scale and preserve the capability only when both sides carry it". Old text is silent on rounding's capability (04:144: "Rounding replaces the static scale with its authored places"). Side taken: `+`/`-` `every operand` (now normative, marked unmeasured); rounding `none` (marked unmeasured), as the audit remedy states. Lean: `NumericScaleSummary.binary`/`union` and `NumericScaleSummary.rounded` (`canExpandScale := false`), `A12Kernel/Semantics/NumericExpression.lean`. Measured parts (× OR, operand-list `Min` AND, literal capable, fields, `BaseYear`, `RangeAsNumber` non-expandable) cite `src-numeric-extremum-call-boundary`, `src-fieldless-numeric-computation`, `src-string-integer-source-scale-suppression` and spec/05:181.
4. **Formal-read grammar (ch04-4).** Old 04:127: "a plus-signed number in the formal-read grammar (`zahlMitPlus`), unreadable text (`zahlHatUngueltigeZeichen`)". Old 04:129: "a decimal separator and optional decimal places … whose defaults supply none of them". Side taken: plus shape `+` digits [`.` digits]; otherwise optional `-`, ASCII digits, optional `.` and ASCII digits; anything else unreadable. Lean: `hasLeadingPlusShape`, `parseNumericFormalRead?`, `checkFormalRead` (`A12Kernel/Semantics/NumericInput.lean`). Measured (K16): plus shape on `+007`/`+00.00`, exponent text unreadable (`0e5`, `00e1`). Marked unmeasured: the ASCII-only digit class and the empty-part refusals.
5. **Power iteration order (ch04-8).** Old 04:96: "binary exponentiation rounds its intermediate squares and accumulator multiplications at working precision `50 + decimalDigits(exponent) + 1`, then rounds the result to precision 50". Side taken: unchanged algorithm, with the bit order (most significant set bit down, square then multiply-if-set) and `HALF_UP` stated. Lean: `positivePower`, `powerNumeric` (`A12Kernel/Semantics/NumericArithmetic.lean`); the peer's `DecimalPrecisionParityDiffTest` locks it against the Kernel (`src-addressed-numeric-binary`). Not a choice between statements; listed because the order is now explicit.
6. **`a ^ {b ^ c}` (ch12-3).** Old 04:108: "`{a ^ b} ^ c`, `a ^ {b ^ c}`, and separate powers joined by multiplication are legal." Checkpoint `src-arithmetic-shape-gates`: "`a ^ {b ^ c}` is refused for a different reason — the exponent gate". Side taken: it passes the nesting rule and meets the exponent gate. Outcome: over fields refused `MVK_INVALID_NUMBER_FOR_EXP` (`src-arithmetic-shape-gates`, power-gate claim); over literals `[N] ^ {2 ^ 2}` admitted (`src-number-operation-node-gates`); mixed field/literal shapes unmeasured. spec/12 §3, which says "admitted", is corrected by HIGH in the same commit. Decided by measurement, not Lean; Lean agrees (`power?` gives an unknown-scale inner power to the outer exponent check).
7. **Converted-zero literal (ch04-2).** Old 04:124: "on a scale-14 field `== 0.5` is accepted while `== 0.4` is rejected as converted-zero." Old spec/07 (now §1.9): the converted form applies "for the direct iterating Number-field-versus-immediate-number-literal shape". Side taken: spec/07 §1.9's precondition, cited.
8. **Constant-pair gate content (ch04-9).** Old 04:46: "a literal under any operation stops being immediate". spec/05 §1 (landed): "braces preserve constantness … unless the left operand has a temporal result type and exactly one operand is an ungrouped `Today` or `Now`". Both are kept, merged in §1.4; spec/05 already decides the brace and clock parts. Lean: `comparisonConstantPairAllowed`, `ComparisonEntryOperand.constantForm`, `checkComparisonEntry` (`A12Kernel/Elaboration/ComparisonEntry.lean`).
9. **Aggregate exponent and aggregate scale (correction item 2).** Old 04:52: "an aggregate exponent has known scale 0, so it passes the exponent gate silently". New §1.3: "an aggregate over scale-0 fields … passes the exponent gate", plus "over fields of nonzero scale the aggregate takes the largest declared scale and is refused `MVK_INVALID_NUMBER_FOR_EXP`, unmeasured". Side taken: Lean's — a field-list `Sum`, `MinValue` or `MaxValue` derives the maximum of its contributing fields' declared scales without the capability, so `[F] ^ Sum(G*/D2)` with a scale-2 `D2` is refused. Lean: `ResolvedNumericAggregateFields.scaleSummary` and `NumericAggregateOp.scaleSummary` (`A12Kernel/Elaboration/NumericSource.lean`). spec/14 R cells of `Sum`, `MinValue`, `MaxValue` (Number) set to `maximum`; `none`, marked unmeasured in the R measured-scope sentence and in §1.1's.
