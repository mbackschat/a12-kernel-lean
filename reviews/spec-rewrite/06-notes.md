## Behavioural decisions

1. `NotAll` pass order (ch06-1). Old checklist 06:193: "its fields-presence prepass exists on only one of two size-selected emission routes and is observationally equivalent to consuming the values side unconditionally". Old 06:150: "That order is observable when a values-side `Having` filter can fail: a failure on an unread side is suppressed". Side taken: 06:150/151 (observable; equivalence only for filter-free member classification). Lean: `ValueListQuantifier.evalValidationUsing`, `A12Kernel/Semantics/ValueList.lean` (presence pass first, values collected only after a present field). Decided within this chapter's own body, so no new rule.
2. Value-list partial extent (ch06-2). Old 06:146: "complete extent is established as soon as one relevant identifier covering the entry wildcards every repeatable level reopened from the first star downward". spec/10 §5.4: "declared slots … covers every declared slot … by a concrete coordinate or a wildcard". Side taken: spec/10 §5.4 (already decided there; cited, not re-decided).
3. Raw String under coercions (ch06-3). Old 06:41: "comparisons, value lists, computation operands, coercions, and any other value operation are rejected with `MVK_INVALID_RAW_TYPE`". spec/08 §3 (08:48): "`FieldValueAsNumber` `MVK_NO_CONVERT_IN_NUMBER` and `FieldValueAsString` `MVK_NO_NUMBER`". Side taken: spec/08 (measured, `src-field-value-read-predictions`); cited, not re-decided. Interpolation's class is spec/11 A.6's `INVALID_NO_VALUE_VALIDATION`.
4. Custom in scalar membership (ch06-4). Old 06:162: "The subject and member list admit only the String, Enumeration, and Number families". Old 06:134: "The multi-field family admits String, Enumeration, Number **and CUSTOM** fields". Side taken: Custom takes the String family's rules on the scalar forms too, including against a literal list, marked unmeasured. Lean: a Custom declaration carries the String kind (`customTypeRequiresString`, `A12Kernel/Elaboration/Flat/Model.lean`), so `FlatFieldDecl.valueListSlotKindAdmitted` (`A12Kernel/Elaboration/TokenEntityValueList.lean`) and the scalar kind check in `A12Kernel/Elaboration/HavingFieldValueList.lean` admit it as String.
5. Pattern blacklist predicate (ch06-10). Old 06:28: "an unescaped [ after an earlier unescaped [ with no ] between them"; old 06:27: "`\A \G \Z \z \a \e \p \Q \E`". Side taken: the character-level predicate of Lean `containsForbiddenPatternSequence` and `containsNestedClassOpen` (`A12Kernel/Semantics/StringPattern.lean`): "unescaped" means not immediately preceded by `\`; the escape form is any `\` immediately followed by a listed letter. The consequences `\\p` refused and `\\[` treated as escaped are marked unmeasured. No other spec chapter decides it.
6. Unavailable member of scalar `NotIncluded` in validation (ch06-11). Old 06:160: "A formally unavailable member is skipped by `Included` but poisons `NotIncluded`". Old 06:149 (NotAll): "consumes the complete values side with the same UNKNOWN/omission classification as `No`". Side taken: UNKNOWN in validation, poison kept for computation (B.5). Lean: `collectValidationMembers` returns its terminal on an unknown member for `notAll`, which `ValueListQuantifier.evalValidationUsing` maps to `.unknown` (`A12Kernel/Semantics/ValueList.lean`).
7. Trailing-blank finding code (feedback Q-005). Old 06:58: "then leading/trailing ASCII-space rejection" (no code). Side taken: `nachfolgendesBlank`, from Lean `UniversalFormalRefusal.errorCode` (`A12Kernel/Semantics/ValueFormalCheck.lean`) and the source checkpoint `src-universal-value-formal-precheck`; marked unmeasured. The order of steps 3–5 is likewise marked source-only (the checkpoint `src-checked-string-ingestion-k13` lists charset-versus-blank precedence and the trailing blank as source-grounded controls).
8. Added measured statements, for the ledger classification (no conflicting old text): the charset code `ZeichenNichtImZeichensatz` (capture `string-expressions-2026-10-04/fixed`); the String finding codes `stringMitNewline`, `stringFalschesMuster`, `stringZuKurz`, `stringZuLang` (`k22-message-keys-2026-10-24/keys.json`, rows `s1-0`–`s1-2`, `s2-0`, `e1-0`, `e2-0`); a raw String operand of named-type `Valid`/`Invalid` draws `MVK_INVALID_RAW_TYPE` (checkpoint `src-checked-string-ingestion-k13`, `raw-validity-admission`), which the old chapter never stated.
9. Column W assignments. The cells not measured follow spec/08 §3's general statement that a bracketed field-value read refuses a raw String wherever it stands (`value` slots → `raw class`) and spec/02 B.3's statement that raw content stays ordinary content for presence predicates (the fill and group predicates and the two presence counts → `presence only`); every `entity` slot no chapter decides is `not stated`. After the preservation check: `[F For key]` is `raw class` (spec/08 §4, a raw key field draws `MVK_INVALID_RAW_TYPE` in every selection carrier measured); `GroupFilled`, `GroupNotFilled`, `NumberOfFilledGroups` and `CurrentRepetition` are `own class` (`MVK_NO_FIELDS_ALLOWED` for a field operand, spec/02 A.4.9 and spec/08 §3; raw content inside a group operand still counts as content), and `ValueNotConsistent` is `own class` (`MVK_TABLE_ENUM_EXPECTED`, unmeasured for a raw subject); the `n/a` basis now covers only operators that take no operand naming a field. This cell set narrows old 06:41's blanket rule, see Rules not kept. Lean sites of the raw refusal for reference: `rawTypeOperandInvalid` in `TokenEntityValueList.lean`, `RepetitionNotUniqueAdmission.lean`, `CustomFieldValidity.lean`, `StringComputation.lean`, `SemanticIndexAdmission.lean`; `invalidLengthOfRawType` in `RawString.lean` and `IterationLegality.lean`.
