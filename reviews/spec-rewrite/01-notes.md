## Behavioural decisions

1. Error-field reference (ch01-2). Old 01:151: "The error field must be *referenced* by the condition (directly, or indirectly via an enclosing `GroupFilled`), or the model is rejected". spec/07 §1.4 (already decides): "The reference set of a condition is every reference outside every filter body, plus the `$`-marked references inside filter bodies" with its contributor table. Side taken: spec/07 §1.4 (pointer). Lean not reopened; spec/07's notes own it.
2. Scale capability (ch01-3). Old 01:177: "Plain equality is the special case that holds once any non-capable field reference enters the operation." spec/04 §1.1 (already decides): "`[A] * 100` over a scale-2 `A` derives scale 0 and stays capable". Side taken: spec/04 §1.1; the tolerance-band exemption is spec/09 §1.3 ("An alternative declaring a `toleranceRangeOp` … meets no scale agreement gate"), spec/09 decision 6.
3. Target self-read (xc-4). Old 01:178: "(guarding via its *containing group* is allowed)". spec/09 §5.2 (already decides): "The predicate is containment … The exemptions are closed". Side taken: spec/09 §5.2; Lean `forbidsTargetWith` per the audit.
4. Full validation and absent coordinates (ch07-5, map-6). Old 01:134: "Under **partial** validation only, the relevant set can name a row that does **not** physically exist … Full validation never does this." spec/07 §1.3 (already decides): full-validation rules "fire at both declared rows of the twice-repeating keyed `Gifts`" on `{}`. Side taken: spec/07; "phantom row" kept for the partial notion, "Full validation has no relevant set and so no phantom row".
5. Partial dispatch (ch01-1, ch10-7). Old 01:194: "evaluates only the rules whose **error-field instance is in the relevant set**". spec/10 §5.2 (already decides): "compressed into one selector … a rule that reports into a repeatable group it does not iterate runs when **any** of that group's rows is relevant". Side taken: spec/10 §5.2.
6. No match (ch09-3). Old 01:172: "No match ⇒ the target is **CLEARED**." spec/09 §5.3 (already decides): "no selected alternative yields a clean no value"; old 01:212: "CLEARED contains source-filled instances". Side taken: clean no value, CLEARED when the source target was filled.
7. Precondition gate scope (ch09-5). Old 01:172: "only the sole alternative may omit its precondition, while every row of a multi-alternative table is guarded". spec/09 §5.3 (already decides): "The empty-precondition gate is per declaration … The combined table may therefore hold unguarded rows". Side taken: per declaration (spec/09 decision 9).
8. Third cell state (ch02-3). Old 01:92: "**not-check-relevant** — a value is present but formally invalid." spec/02 B.2 (already decides): "carries a formal finding from one of the producers in B.3; it need not hold a value". Side taken: spec/02 B.2.
9. Rule 5 order (ch01-7). Old 01:63: "reported as an unordered set rather than in walk order … A field reports the maximum before the minimum". Old 01:70: "reports a multiset, not a sequence … so no order is claimed". Side taken: the `MVK_*` declaration classes are an unordered collection (identical ones once); the printed-bound checks report maximum before minimum on a field. Lean: `ModelConsistency` check 5 "the maximum's class, then the minimum's" (`A12Kernel/Elaboration/ModelConsistency.lean`, line 390 docstring) and `DeclarationReport` "The report is a multiset … the order here carries no claim" (`A12Kernel/Elaboration/DeclarationReport.lean`). The bound order is measured: the `src-model-consistency-k17` checkpoint body states "Within one field the maximum's bound class precedes the minimum's (`d1`, `d3`) and an identical class is reported once (`v0-both`, `d4`)", so it is not marked unmeasured.
10. Build exemptions (ch01-8). Old 01:57: "an element with an empty name … and a type reference with an empty id each fail the build". Old 01:82: "A Java-blank name … fails the build, unless the variant filter deletes that field, rule or computation"; old 01:142: a filtered field "draws a codeless refusal for an object-valued name or a typedef reference without its id". Side taken: the exemptions attach as the later sentences state; the empty type-reference id under a filter is `not stated` (01:142 speaks of an absent id only). No Lean def opened; decided by the old text itself.
11. `fillToFix` default and connectives (new closing rule). Old 01:159 lists only the narrowing cases ("The omission-responsibility inventory is narrower than the referenced inventory") and gives no rule for the remaining operators or connectives. Lean: `omissionLeafPointers` falls back to `leaf.referencePointers` for every other leaf, and `ValidationCondition.omissionPointers` concatenates both connective branches (`A12Kernel/Elaboration/ValidationCondition/Omission.lean`). Side taken: `ordinary` for every other operator and union for connectives, marked unmeasured in §3.1 and spec/14 column O. `CustomCondition` left `not stated` (its reference pointers are not opened here).
12. Variant filter lead (ch01-6). Old 01:142: "A declaration can be filtered out of the model before anything examines it". Same paragraph: "It is still present where the Kernel reads the model as authored". Side taken: the second (the old text's own measured rows); the lead now says "before code generation, its static checks and evaluation see it".
13. Repeatability refusal keys. Old 01:13: "with `0` and `null` drawing `zahlIstNullOvz` … a negative drawing `zahlMitVorzeichen`". Old 01:82: "the group alone also draws a codeless sentence, not-positive for zero or `null` and signed below zero". Not a conflict, and the two are different notifications: the wording keys belong to the per-element `MVK_MAX_VALUES_INVALID` refusal (inbound-group-operand-batches `text` row), while the group-only codeless notification is not-positive for zero or `null` and signed below zero. One table row (§1 Repeatability) now states both as the old sentences did; the draft's attachment of the keys to the codeless notification and its widening to "`0` or no value" were corrected after the preservation check.
