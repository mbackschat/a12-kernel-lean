## First probe

Encode bounded presence reachability for two exact flat conjunctions. The same-field `FieldFilled(A) And FieldNotFilled(A)` query should be solver-UNSAT and the different-field `FieldFilled(A) And FieldNotFilled(B)` query should be SAT. Decode the SAT assignment into an A12 presence witness and replay it through Lean.

Lean acceptance separates the two result directions. Replayed SAT is a verified witness. Raw Z3 UNSAT is only `solverReportedUnsatWithinBounds` unless the existing Lean contradiction certificate independently closes that exact shape. Wrong accounts are authored-error polarity reversal, absence/formal collapse, different-field aliasing, and presenting raw UNSAT as certified.

## Computation-cycle probe

Analyze a disposable language-neutral computation artifact as a target-field dependency graph. Detect a direct two-target cycle and an indirect three-target cycle, recover a dependency order for an acyclic chain even when its supplied order is reversed, and keep `CurrentRepetition(group)` structural rather than expanding it into dependencies on computed descendants. Every cycle path must carry its computation rule and read-site labels; every accepted acyclic order must satisfy all extracted edges.

This remains an Analyze probe rather than another consumer category or a public graph surface. It covers computation value dependencies only. Validation rules read a document snapshot and emit messages, so mutual validation references are not computation feedback cycles. Wrong accounts are pair-only detection, supplied-order rejection in place of cycle analysis, structural-group expansion, omitted precondition reads, and unchecked cycle paths.

The checked scalar numeric-table profile derives its cycle graph from each table's raw dependency inventory before the full-call formal-input projection removes every computed target. It traverses all alternatives and expands a fixed `NumberOfFilledGroups` operand to its declared fields. The full-call noncomputed input set remains a separate result and is never reused as the cycle graph.

The mixed String/Number successor starts from individually checked steps before run certification. Its projection preserves target, target family, and every raw dependency in candidate order, letting a consumer distinguish a genuine three-target cycle from an acyclic chain merely supplied in reverse dependency order. External guard fields remain in the raw lists but do not become computed graph nodes. This does not make graph reconstruction family-neutral: only the exact finite String/Number carrier is Lean-owned here.

## Generated-phase alias probe

Analyze whether one scalar-target generated computation may alias its immutable execution source with the later applied-destination validation snapshot. The bounded artifact contains one unfiltered repeatable Number sum and one correlated repeatable Number `FirstFilledValue`, with source and destination rows chosen so both the result and, for `FirstFilledValue`, the selected row differ between phases. The consumer must separate dependency roles, source execution, source-relative action classification, destination application, target-filled gating, and destination recomputation, then produce a concrete counterexample to snapshot aliasing.

The natural handover deliberately tests shipment sufficiency as well as semantic reconstruction. Its first version omitted Number signedness, Number scale, and the repeatable-group bound, so its mechanically correct result remained amber because aggregate mismatch polarity required an unstated assumption. The corrected artifact supplies those declaration facts explicitly and leaves the consumer to derive the phase and polarity semantics. General scheduling, repeatable targets, materialized topology, pointer rendering, and Kernel correspondence remain explicit insufficient-information results.

## Fixed scalar placement probe

Inventory one heterogeneous artifact of fixed scalar computation definitions across Number, String, Boolean, and Confirm. For every admitted target the consumer must report the authored **declaration group** separately from the **execution group** the computed target owns, keep every same-target row's own group in authored encounter order, and state the model-determined runtime instance count. Refusals produce no inventory entry and carry a Kernel code only where one is established.

Placement must not be reconstructed. The artifact therefore makes both tempting derivations unavailable: the cross-group definitions are operand-free literals, so no operand group can supply the answer, and the target's own group is a different fixed subtree, so the target path cannot either. A same-group Boolean control stops a consumer from simply always reporting a difference, and a declaration-group-only field that is never a target exposes any consumer that iterates declaration groups.

Lean acceptance is the checked declaration group retained on each family owner, the two same-target table order laws, and the refusal matrix. Wrong accounts are execution group read off the declaration group, declaration group read off the target, sorted, reversed, or first-row-only table rows, cross-group declaration treated as a refusal, an accepted invalid declaration group, an accepted Confirm `false`, an accepted repeatable constant target, an invented Kernel code for a locally classified refusal, and one runtime instance per definition rather than per fixed target.

## Addressed extremum scale and identity probe

Analyze A1–A3 as warning-suppressed single-operand extrema containing ordered division, power, and reversed division over two checked fields, then analyze the same literal-only power extremum with and without suppression. The fingerprint must retain ordered field dependencies separately from literal-bearing operation identity, unknown versus exact derived scale, multiplicative-constant capability, the suppression bit, and every candidate target scale `0..14` admitted through the canonical rule.

Lean acceptance is the exact addressed numeric-operation analysis plus its shared target-scale decision. The accepted consumer reports A1–A3 as unknown and non-expandable with all candidate scales admitted, A4 as exact scale `0`, non-expandable, unsuppressed, and admitted only at `0`, and A5 as the same operation with suppression and every scale admitted. It keeps A1/A2 source order `[5,4]`, A3 `[4,5]`, and A4/A5 field dependencies empty while retaining all literal spellings under operation identity.

## Flat mandatory-information analysis and explanation probe

Analyze eleven bounded flat rule sets into independent global fields, root-relative fields, and global roots while retaining count-threshold absence, authored decoded identity, and Java-rounded signed-32-bit value separately. The combined Analyze+Explain task covers a root-relative separator, root-seed promotion, reverse-authored dependency closure, standalone count thresholds around the `2^32` boundary, all three count-guard spellings in its retained basis, the direct and wrapped `-1` sentinel, and fail-closed malformed or unsupported shapes.

The successor task adds existential and universal filled-field-list guards in both truth states and reverse authored order, the exact filled-count versus distinct-count standalone and guarded identities, and the singleton negative-field ERROR/WARNING/INFO severity family. When an admitted filled-field or filled-count guard entails its target in this flat single-root carrier, that target enters both `mandatory` and `mandatoryForRootGroup`; its root also enters `mandatoryRootGroups`, idempotently when a direct premise already contributed it. A later cycle successor applies that same least monotone closure to direct, existential-list, and universal-list guard cycles, separating seeded, under-seeded, fully seeded, and unseeded components. The whole-rule exclusion successor retains `Filtered`, literal-key `SemanticIndexed`, two-group `ParallelIterated`, and two-root `CrossRoot` identities with their referenced fields while excluding them from checked contributions; a later supported direct rule still contributes, and the exact cross-root identity bypasses contributing-root admission. The generated-identity successor retains one optional repeatable String index requirement and one unconditional direct same-root nonrepeatable scale-0 Number-copy validation with their references while deriving no set member or global root seed. Those references participate in explanation and static single-root topology without changing another rule's count-shape isolation. The repeatable-presence successor retains the exact direct-unindexed-child-of-nonrepeatable-root scope, `And`/`Or`, all three singleton starred quantifiers, and both field references across the six measured results. Cross-root composition and every wider normalized scope are refused, while a wider syntax without a normalized identity remains insufficient rather than accepted empty. The count-dependency successor admits one exact direct-seeded field-guard target as a filled-count operand and permits an admitted count target to feed ordinary field guards; removing the other direct operand keeps the dependency-derived field but suppresses the count and downstream targets. The target-only filled-count successor establishes that `NumberOfFilledFields(A, B) >= 0 And FieldNotFilled(Target)` with isolated operands contributes only `Target` to both field sets plus its root, while the adjacent threshold `1` returns three empty sets. Replacing that operator with `NumberOfDifferentValues` yields an admitted no-contribution identity in both target-only arms. The distinct-count comparison successor retains `> -2`/`> 0`, `0 <=`/`1 <=`, and `-2 <`/`0 <` as the same exact accepted no-contribution pairs while preserving every authored spelling and scale-zero threshold. Deeper operand dependencies and count reuse through other roles remain refused. Empty or duplicate guard lists, unclassified cross-root topology, wider generated forms, and distinct-count guards outside the exact direct-seed `>= 2` and measured isolated target-only matrix remain unsupported rather than accepted empty.

Lean acceptance fixes every returned set, threshold pair, count-operator identity, generated identity, exact repeatable-presence scope, admitted count-dependency role, and refusal through the checked entry, the focused theorems, and the conformance matrix. Wrong accounts use exact mathematical magnitude without narrowing, collapse absence into authored `-1`, omit signed-int32 wrap, let comparison truth override the sentinel, erase authored comparison, count operator, generated, scope, connective, or starred-operator identity, merge the two field sets, reject or self-support cycles, stop after one pass, turn unsupported into accepted empty, treat explanation references as count-shape reuse, reject the admitted count operand or downstream target roles, collapse isolated distinct count into filled count, admit deeper or differently reused count dependencies, or claim general Kernel correspondence or shipment support. Wider repetition, wider indices, filter and join execution, wider filters and formulas, other generated rules, longer or multi-list-edge cycle correspondence, contributing or wider cross-root topology, other count sites and deeper or differently reused dependencies, protocol, shipment, compatibility, and general correspondence remain excluded.
