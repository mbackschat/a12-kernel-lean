## First probe

Produce a structured trace for three rows: formal source with malformed amount, absent source with malformed amount, and absent source with valid amount. The trace must name static dependencies separately from runtime reads, the first poison cause, exact addresses, result partition, and excluded later stages.

Lean acceptance checks the structured event and outcome fields. A human review checks whether the explanation is understandable without adding unsupported causality. Wrong accounts are eager dependency reads, conflating formal inventory with runtime trace, inventing a message from poison, and omitting insufficient-information boundaries.

## Cross-family formal-input probe

Explain the eager direct-field inventory for one nested Number-backed `Time(...)`, one root-source `DateFromDateTime` fanning out to two target rows, and direct-field versus literal addressed Enumeration. The artifact must preserve exact root, enclosing, and leaf placements; distinguish one static source placement from repeated runtime reads; keep a fieldless literal inventory empty; exclude computed targets and unrelated fields; and name the Time, FullDate, and String-shaped result channels separately.

Lean acceptance checks each exact placement, cause, exclusion, and result projection. Wrong accounts are per-read duplication, whole-document collection, leaf-normalized placement, automatic global abort or eager poison, invented rendered messages, and an unnamed result carrier shared across families. Group containment, generated preliminary findings, multi-operation union, scheduling, public shipment, and Kernel correspondence remain excluded.

## Whole-call formal-input probe

Analyze and explain the direct-field inventory for a homogeneous three-stage Enumeration call and a heterogeneous Number-to-DateTime call. The consumer must form the complete computed-target exclusion set before filtering the direct-operand union, retain authored dependency order as analysis information while treating the selected field sets extensionally, keep exact finding paths and causes, and separate the one call-global inventory from every typed phase-owned residual channel. A duplicate-dependency and reversed-operation control checks normalization and operation-order independence.

Lean acceptance checks the two exact whole-call inventories, the complete computed-target sets, the Enumeration phase separation, the DateTime no-copy theorem, and the Number value-less-target counterexample to universal residual emptiness. Wrong accounts are computed-intermediate inclusion, whole-document collection, dependency-occurrence duplication, incremental order-sensitive exclusion, phase copying, path erasure, and universal Number-residual emptiness. Group containment, generated index or preliminary findings, rendered messages, scheduling, runtime evaluation, structural failures, protocol, shipment, and Kernel correspondence remain excluded.

## Implicit self-validation message probe

Explain six Number computation message outcomes from the canonical clauses alone: an all-filled `Sum` below capacity and below its stored seed, its all-filled at-capacity control, a below-capacity group count above its seed, an at-capacity `Sum` whose row values are empty, an at-capacity group count, and an equal stored/computed control. ## Filtered token `Having` pointer probe

Explain a token star below one bound repeatable ancestor when its `Having` compares an unmarked candidate Number field with a `$`-captured outer Number field, then explain the same filter conjoined with `CurrentRepetition`. The consumer must return the selected token and unmarked Number field as partial pointers with the bound ancestor concrete and reopened level wildcarded, return the `$` field as an exact captured pointer, add no field for `CurrentRepetition`, treat collection order as nonsemantic, and refuse to recover authored operand form from addresses.

Lean acceptance fixes both complete normalized sets and proves that every successful token-star projection retains the selected source. Separate checked cases keep the otherwise analogous Number and Boolean/Confirm filtered-star carriers as `insufficient information`. Wrong accounts are selected-only projection, exactifying the reopened candidate, wildcarding `$`, omitting the selected source, and inventing a `CurrentRepetition` field pointer. Runtime filter truth, firing, message rendering, raw pointer spelling, `fillToFix`, `RepetitionNotUnique`, protocol, shipment, and wider correspondence remain excluded.

## Conclusion

The bounded Explain task is cheap and useful. Its static-versus-runtime distinction transports without renewed archaeology across DateTime shifts, nested Time construction, FullDate extraction, String-shaped direct/literal Enumeration, homogeneous and heterogeneous whole-call operation lists, and one generated-preliminary parent-local DateRange scan. Its message account also transports operator-local directional growth, the all-or-none `fillToFix` projection, normalized exact/wildcard pointers for the measured Sum and group-count carriers, and origin-sensitive filtered-token references without treating `CurrentRepetition` as a field or guessing unwitnessed carriers. Group containment beyond the exact checked shapes, wider DateRange profiles and generated preliminaries, raw pointer spelling and textual address kind, wider self-validation carriers, scheduling, general whole-model formal checking, public shipment, and broader Kernel correspondence remain outside the probes.
