<a id="src-partial-date-input-causes"></a>
#### Which formal cause a partially known Date draws, measured locally 2026-08-23

- `revision`: clean a12-dmkits `108d047b787f0e049dcd2f4902f24d7523347a00`, dmtool `0.13.0`, kernel `30.8.1` built and runtime, `producer.source.state` `CLEAN`, artifact schema 1; the sibling worktree was empty before and after every command.
- `route`: `:adapter:kernelProbe` observing `validateFull` over one dmtool-authored model declaring five `yyyy-MM-dd` DATE fields that differ **only** in precision — full, `DAY_OPTIONAL`, `MONTH_OPTIONAL`, `YEAR_OPTIONAL`, and one more `DAY_OPTIONAL` with the pre-1900 check enabled. Seventeen documents set every field to the same stored text, so one row reads the whole precision ladder at one spelling. Both codegen strategies agreed on every cell.
- `ladder-claim`: the precision ladder is exactly monotone and each step adds exactly one omission depth. A full value is admitted everywhere; an omitted day is admitted from `DAY_OPTIONAL` up; an omitted month **and** day from `MONTH_OPTIONAL` up; all three omitted only at `YEAR_OPTIONAL`. So the declared precision names the deepest admitted suffix rather than a set of independently enabled omissions.
- `cause-claim`: **the two causes do not split where a reimplementer would put them.** A *full-precision* declaration reports every omission marker as `datumFormatFalsch` — an omission is not a legal spelling for it at all — while a *partial* declaration reports every shape it cannot hold as `datumFalsch`. So the code is chosen by whether the declaration admits any omission, not by which rule the value broke.
- `cause-claim`: within a partial declaration the split is **reality against position in time**, and it is not "spelling against semantics". `datumFormatFalsch` covers a wrong component width and an unreal calendar date among the value's *present* components — including an impossible month standing beside a legally omitted day, which is the sharpest cell: the omission is fine, the month is not, and the month's cause wins. `datumFalsch` covers a zero pattern that is not a monotone suffix, a suffix deeper than the precision admits, and an admitted value whose earliest completion lies below the universal Gregorian floor or the enabled pre-1900 boundary.
- `boundary-claim`: the floor applies to the **earliest completion** of a partial value and yields the date cause, not the format cause. An omitted-day `1583-10-00` is refused while `1583-11-00` on the same declaration is admitted, so the boundary rather than the year is doing the work; enabling the pre-1900 check refuses `1583-11-00` and `1899-12-00` on that same field while `1900-01-00` stays admitted. The two thresholds are therefore indistinguishable from the cause alone and separable only from the declaration.
- `local-divergence`: one, found by this measurement and fixed before the capsule landed. The first implementation obtained an omitted-day value through a constructor that applies the floor internally, so a below-floor completion came back as "no value" and was reported as the *format* cause. Measured, it is the date cause. The classifier now judges reality, then position in time, then precision, in that order, and the constructor's failure can mean nothing but unreality. Thirty-five of thirty-six cells had already agreed, which is exactly why the row mattered: the disagreement was one cell wide and on the branch a reader is least likely to re-derive.
- `format-claim`: the rule is **independent of the declared spelling**. Four `dd.MM.yyyy` fields at the same four precisions reproduce every structural cell: the monotone ladder, the uniform format error from the full-precision declaration, the non-suffix refusal at the deepest precision, the unreal month beside an omitted day as a format error, and the below-floor omitted day as a date error.
