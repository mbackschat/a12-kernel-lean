# Rule-set meta-information source checkpoints

Checkpoints for the Kernel's rule-collection analysis services — derivations over a rule set rather than over a document. Document-level validation and computation routes start at the [`cross-layer-routes.md`](cross-layer-routes.md) overview; [`../SOURCES.md`](../SOURCES.md) remains the anchor registry for both and routes detailed checkpoints to their family shards.

<a id="src-mandatory-information-narrowing"></a>
#### Mandatory-information derivation reads a **32-bit-narrowed** threshold whose `-1` value collides with absence, measured locally through 2026-09-01

- `revision`: thirteen initial `:adapter:kernelProbe` requests at a12-dmkits `c2900fe7c91a55e0debd0124f847ee2de0f06186`, followed by the sentinel matrix at `47952f81e13fc63dd72d16f2bbbd24e8bb024654`; the sibling checkout was clean before and after, with `state: CLEAN` in every artifact. `dmtool` 0.13.0, Kernel `30.8.1` built and runtime. Model-level `mandatoryInformation` observation, no document and no rows — the capability a12-dmkits built for [`EXP-2026-08-30-01`](../A12-DMKITS-SPEC-SYNC-LEDGER.md#exp-2026-08-30-01).
- `question`: `FeldOperationUtil.getZahlKonstanteWert` returns `(int) Math.round(Double.parseDouble(value))` for a numeric constant and `-1` for "not a numeric constant", so a rounding **and** a 32-bit narrowing sit in front of one sentinel. The entry asked whether the derived output distinguishes an authored literal from absence.
- `shape-found`: the entry's own `>= z` shape derives **nothing at all**, `mandatoryRootGroups` included, so it cannot discriminate. The shape that reaches the arm is the error-condition spelling of the same requirement, `NumberOfFilledFields(A, B) < z` — which yields the root group and no field. The positive control is a different shape entirely: `FieldNotFilled(A)` derives `/S1_DM/A` into `mandatory` and `mandatoryForRootGroup` and `S1_DM` into `mandatoryRootGroups`, so an empty result is a reading rather than a broken route.
- `claim`: **the derived answer follows the narrowed value and the guard is `> 0`.** Over one two-field list, `< 1` and `< 3` derive the root group; `< 0` and `< -1` do not. Four adjacent literals around `2^32` reproduce that boundary exactly: `< 4294967295` (narrows to `-1`) and `< 4294967296` (to `0`) derive nothing, while `< 4294967297` (to `1`) and `< 4294967299` (to `3`) derive it. `< -0.6` rounds onto `-1` and derives nothing.
- `witness`: **`< 3` against `< 4294967295` is the isolating pair.** Both are trivially true over a two-field count, so satisfiability is held constant and cannot explain the split; the models are identical but for the literal. A reader takes `4294967295` as a *stronger* requirement, and the derivation drops the rule. `< 4294967297` against `< 4294967295` closes it from the other side: adjacent literals, opposite answers, following the narrowed value and nothing else.
- `sentinel`: **the follow-up reaches `EvaluatorVisitor`'s `z != -1` branch and separates an authored `-1` from an ordinary true threshold.** Base `FieldNotFilled(A)` and `FieldNotFilled(B)` rules establish two known mandatory fields. Each tested rule then conjoins a count comparison with `FieldNotFilled(target)`, making target membership the public derived-field discriminator. `count >= 0`, `count > -2`, and `0 <= count` derive their target fields; the adjacent `count >= -1`, `count > -1`, and `-1 <= count` rules do not. All six exact comparisons are true at count two, so comparison truth cannot explain the split.
- `narrowed-sentinel`: the `2^32` pair identifies the same mechanism after conversion: `count >= 4294967297`, narrowing to `1`, derives its target, while `count >= 4294967295`, narrowing to `-1`, does not. This closes both the direct sentinel collision and its reuse after signed-32-bit wrap rather than inferring one carrier from the other.
- `field-sets`: the sentinel matrix yields `/Sentinel/A`, `/Sentinel/B`, `/Sentinel/GeZero`, `/Sentinel/GtMinusTwo`, `/Sentinel/NarrowOne`, and `/Sentinel/ReverseZero` in both `mandatory` and `mandatoryForRootGroup`, omitting the four paired targets whose literal narrows to `-1`; `mandatoryRootGroups` contains `Sentinel`. The earlier standalone count rules still move only the root-group set, so field membership depends on the surrounding recognized conjunction rather than on a count comparison alone.
- `limit`: one nonrepeatable root with two established mandatory inputs and one target per count guard, `en_US`, no repetition and no `Having`. The matrix covers direct strict and inclusive comparisons plus the reversed inclusive form at the `EvaluatorVisitor` site; reversed strict comparison is not measured. Not measured: repeatable lists, the four `z > 0` collector sites beyond the earlier standalone-root-group shape, non-count rule families, or the complete composition rules for the three returned sets.
- `bytes`: [`mandatory-information-narrowing/`](../../evidence/kernel-30.8.1/captures/mandatory-information-narrowing/), eleven models with their requests and artifacts. The sentinel model, request, and artifact SHA-256 values are `f86a99451ff9c2279ca0b37b041c64bd2079a1bbfdd24f6703490f8420921d3d`, `46547d33b56c8435a1e2bd70b528a1ed0d5e120eec12424d35059c2f867d8699`, and `4523927ab35446f29a2005332867f6946be84594c58f1ceb7bf4313a830932ab`. The earlier isolating pair remains `< 3` against `< 4294967295`, with model hashes `87b9e61ae169ef051a6281d89a4f61ddb1170249e2a241aec81d656e0b50d4fb` and `d030f7d70631db76cfe64d99438fd213a48774c01e84e673283020bcd21f5948` and artifact hashes `ba63424d1cff1452eacaaee17eb1677f0dd244c99a1a679520b404591402afc7` and `2a98fde10a5069ecb78e006b5f5294dac4ec91f2188391e5b66a6b41ec94433f`. These are bounded raw captures with no typed local replay, so they establish neither `L` nor `C` coverage.
- `sync`: **no `spec/` change.** [`spec/`](../../spec/) has no section for rule-set meta-information, and opening one remains a scope decision rather than a clause edit; [SG14](../SEMANTICS-GAPS.md#sg14--mandatory-information-derivation) owns the broader obligation.
