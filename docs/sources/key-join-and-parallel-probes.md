- `unmatched`: Unmatched reads need wildcard coverage of both the index column and the referenced field. Enumerating both existing index rows is insufficient: the negative field-fill discriminator remains unknown on that side's unmatched key, while the opposite unmatched side can still prove absence. Formal invalidity and silent relevance unavailability remain separate.
- `groups`: An unmatched clean group's absence can be established by a relevant ancestor group or complete wildcard descendant-field coverage. Requiring an explicit group selector loses six negative-group results in the captured field-selector matrix. Joined-group content remains distinct from payload presence.
- `frames`: A one-sided ordinary frame with declared bound 3 visits its third, uninstantiated slot when far-side keys exist; bound 6 visits only occupied prefixes plus each reset's first coordinate. Full and partial calls agree under whole-root relevance. A concrete frame selector restricts dispatch; a concrete joined-row selector suppresses it. This reuses the [declared-product iteration domain](evaluation-and-application-routes.md#src-validation-iteration-domain), not the physical row list.
- `cache`: The duplicate-error winner under five outer rows changes from row 1 under whole relevance to row 2 when only the first outer row is relevant. Selecting only one duplicate index row removes the duplicate value conflict. Message multiplicity is retained even when two keys produce identical unknown pointers.
- `source`: Kernel `cb66e51fa7ab90b650698f861bf670754e2e1e66`: `ValidationCommand.compressRelevantFieldsForValidationCall` owns dispatch compression; the Java/Groovy `CodeGenRuleDefinition` templates conditionally apply iteration bounds; `IterationLimitCreatorBase` and `EbenenIterator` own declared-space pruning. `EntityUtil.isPruefungsRelevant` owns matched/unmatched index and leaf visibility.
