# Computation placement and constant source checkpoints

<a id="src-fixed-computation-target-scope"></a>
#### Fixed target owns cross-group computation scope

- `revision`: a12-dmkits `3adf0a7a77c8ec42045e8e85586f855d85ec24ed`, Kernel `30.8.1`; later maintenance changed fixture construction but not the asserted semantic matrix.
- `route`: [`CrossGroupConstantComputeScopeDiffTest`](../../../a12-rulekit/adapter/src/test/kotlin/io/github/mbackschat/a12/dm/adapter/laws/CrossGroupConstantComputeScopeDiffTest.kt) runs a Number constant declared under `/Rules` and targeting `/Store/StockLevel`. Its seeded-target row compares dynamic Groovy, generated Java, and the independent interpreter; its empty-document row compares dynamic Groovy with the interpreter.
- `route`: [`CrossGroupConstantComputeScopeTest`](../../../a12-rulekit/interpreter/src/commonTest/kotlin/io/github/mbackschat/a12/dm/interpreter/CrossGroupConstantComputeScopeTest.kt) retains the interpreter projection.
- `claim`: computation iteration is anchored to the target's repetition scope rather than the declaration group. An all-nonrepeatable target has one implicit instance, so both an instantiated target and an empty document produce the constant value even though the separate declaration group is uninstantiated.
- `separator`: declaration-group iteration would produce no outcome in both documents; target-owned fixed scope produces exactly one value.
- `limit`: the runtime discriminator is one Number constant across two fixed subtrees. Generated Java is measured only for the seeded target, not the empty document. The checkpoint does not directly calibrate Boolean or Confirm constants, repeatable cross-group targets, generated validation, retained result partitions, separate-destination application, or wider operations.

#### A Number constant: scale refuses at authoring, range errors per row, measured locally 2026-08-31

- `revision`: a12-dmkits `1be2d603c90be578fe7ea0de0b8c515cb2a479c4` (clean before and after; the artifact records `state: CLEAN`), `dmtool` 0.13.0, Kernel `30.8.1` built and runtime. Static rows are `computation add --dry-run` verdicts; runtime is one `:adapter:kernelProbe` request, two documents, both codegen strategies compared element-wise.
- `question`: the [String target-check checkpoint](#src-repeatable-string-constant-target-check) settled what a String target does to a constant it refuses. A Number target refuses on two independent grounds — decimal scale and declared range — and the [assignment-scale checkpoint](#src-unsuppressed-assignment-scale-reach) had measured the scale gate on *operators* only, recording explicitly that it established every authorable candidate refused rather than that none exists. A bare literal is the most obvious untested candidate.
- `model`: the cross-group `CrossRep_DM` extended with three Number fields in the repeatable `/Probe/Tasks` — `Whole` at `maxFractionalDigits: 0`, `Cents` at `2`, and `Bounded` at `0` with `min: "0"` and `max: "10"`. Model SHA-256 `b4e985dfc82c3118ba115a5755577ebc4d5f0828766749f69c40cebf3c2c9a14`, `model check` valid.
- `scale-static`: **a bare literal is refused at authoring when its natural scale exceeds the target's**, `MVK_INVALID_COMPARE_DEC_PLACES` with `source: KERNEL`. `Whole := 1.5` and `Cents := 1.555` are both refused; `Whole := -1` and `Cents := 1.5` are admitted `KERNEL_CONFIRMED`, so *fewer* fractional digits than the target declares is not a defect and the gate is one-sided. This adds a candidate class the operator matrix had not tested and it is refused too, which strengthens rather than defeats that checkpoint's no-known-witness claim.
- `range-static`: **the declared range is not an authoring gate.** `Bounded := 99`, `Bounded := -5`, and `Bounded := 5` are all admitted, the over-range one reported `ok: true` with `verification: KERNEL_CONFIRMED`, so the kernel gate arbitrated and accepted rather than being bypassed. Scale and range are therefore checked at different times, which is the asymmetry a reimplementer is most likely to flatten.
- `range-runtime`: the out-of-range constant behaves exactly as the over-long String does. On every instantiated row `Bounded` reports `value: "99"` with `errored: true` and `cleared: false` — not clamped to the declared maximum, not blanked, not cleared — while `Whole`, `NumOwn`, and `NumRoot` report `-1` with both flags false on the same rows. Two rows give two errored outcomes at `Tasks` and `Tasks[2]`; no rows give none.
- `authored-scale`: **a constant narrower than its target is not padded up to the declared maximum.** `Cents := 1.5` into a `maxFractionalDigits: 2` target stores `1.5`, not `1.50`, on every row. Every other Number row here has the constant's scale equal to the target's, so that variable had never been varied and a carrier rendering at the target's scale would have matched all of them. Do not read this row as *the authored scale is retained*: that generalization was written here and then falsified by the [scale-rendering checkpoint](#src-repeatable-number-constant-scale-rendering), which owns the actual store rule. Same request bytes, model SHA-256 `9c5edc6fdd104ad4fbb2b96a47fcbd09390aef068639254420263d0a6be39eb8`, artifact SHA-256 `9020e7672ffc7c0ed3fed6e1b46c7a61983d8ef03f62de279444e2fc98fd2157`.
- `local-consequence`: the Number carrier mirrors the String one, needing a runtime target check for range but never for scale, because an over-scale constant cannot reach runtime. Retained payload on rejection is the shape both carriers already share. The stored form is owned by the scale-rendering checkpoint below, not by this row.
- `limit`: one range bound pair, one over-range value, integral and two-digit scales, one repetition level, `en_US`. `validateFull` reported no message on any row; that is silence on a suppressed channel, not a positive observation. Not measured: a minimum-bound refusal at runtime, a constant refused by rendered-length rather than value, the applied document state after an errored write, and whether an existing stored value survives it.
- `bytes`: [`repeatable-number-constant-target-check/`](../../evidence/kernel-30.8.1/captures/repeatable-number-constant-target-check/); SHA-256 request `44fd81b283909b451b16fcf01c470036a73824ef2050d9b465846159bcaff890`, model `b4e985dfc82c3118ba115a5755577ebc4d5f0828766749f69c40cebf3c2c9a14`, artifact `60cc9fe59f62063b7f63112d80741ea77aab1c4fb0b916d99ed6a087bc91ec40`. A bounded raw calibration capture with no typed consumer: it does not run under `lake test` and establishes neither `L` nor `C` coverage.
- `sync`: the scale row extends a clause `spec/` already carries from the operator side to the literal side, and the range rows corroborate the retained-payload rule. No behavioral change, so no outbound entry follows.

<a id="src-repeatable-number-constant-scale-rendering"></a>
#### A Number constant's scale is read twice, differently, measured locally 2026-08-31

- `revision`: a12-dmkits `1be2d603c90be578fe7ea0de0b8c515cb2a479c4` (clean before and after; the artifact records `state: CLEAN`), `dmtool` 0.13.0, Kernel `30.8.1` built and runtime. The static row is a `computation add --dry-run` verdict; the runtime rows are one `:adapter:kernelProbe` request, one two-row document, both codegen strategies element-wise identical (`enginesAgree: true`).
- `question`: the [target-check checkpoint](#src-repeatable-number-constant-target-check)'s `authored-scale` row concluded a constant keeps its own scale, and that conclusion was about to become a Lean clause. But every target it was measured on declares `minFractionalDigits: 0` and every constant is written without trailing zeros, so *keeps its own scale*, *strips trailing zeros*, and *pads to the required minimum* are the same sentence on every row held. [`spec/09`](../../spec/09-computations.md) already carried the third reading — the fit branch renders at `max(naturalScale, minFractionalDigits)`, with `10` into a two-decimal field storing `10.00` — for computed operations. Whether a bare literal takes that same path was the untested variable.
- `model`: the `authored-scale` model extended with four Number fields in the repeatable `/Probe/Tasks` — `Padded` and `PadZero` at `minFractionalDigits: 2, maxFractionalDigits: 2`, `Trail` at `maxFractionalDigits: 2`, and `WholeTrail` at `maxFractionalDigits: 0`. Model SHA-256 `d425999654bbf191a5ec363b8446933f3e81e19266f0b173bcb776711430f6c7`, `model check` valid.
- `strip`: **the store strips trailing zeros.** `Trail := 1.50` into a `maxFractionalDigits: 2` target stores `1.5` on every row, so the literal's authored scale is not what is written. This is the row that falsifies the earlier generalization.
- `pad`: **the store then pads to the target's required minimum.** `Padded := 1.5` into a `minFractionalDigits: 2` target stores `1.50`, and `PadZero := 10` stores `10.00`, reproducing `spec/09`'s own example from the literal side. So a bare constant takes the ordinary computed-Number fit branch rather than any constant-specific path.
- `gate-unstripped`: **the authoring gate does not strip first.** `WholeTrail := 1.50` into a `maxFractionalDigits: 0` target is refused `MVK_INVALID_COMPARE_DEC_PLACES` with `source: KERNEL`, and the refusal text names the right-hand side as having **2** fractional digits — the trailing zero counted. The stored form would have been the integer `1`, so the gate and the store disagree about the same literal by construction rather than by ordering. The same literal into the `maxFractionalDigits: 2` target is admitted and then stripped, which is the pair that shows the disagreement is real.
- `local-consequence`: the carrier retains the authored constant for the gate and renders the store through the shared computed-Number rendering, so a constant and an operation producing the same amount cannot disagree. Both halves are needed: a carrier that only retained matches the `strip`-free rows, and one that only padded matches the `pad`-free rows.
- `limit`: two-digit and integral scales, one trailing zero, one repetition level, one locale. Not measured: a `minFractionalDigits` between zero and the maximum, a constant whose stripped scale fits while its authored scale does not *and* whose target requires padding, the scale-19 pre-round from the literal side, and any interaction with warning suppression.
- `bytes`: [`repeatable-number-constant-scale-rendering/`](../../evidence/kernel-30.8.1/captures/repeatable-number-constant-scale-rendering/); SHA-256 request `caff82b88191616f9664e69e1dc8b0900ea08341b33599f43855f362b577d73a`, model `d425999654bbf191a5ec363b8446933f3e81e19266f0b173bcb776711430f6c7`, artifact `6ad8a936e567eb80f2999ef169480b6d236e6bdd03f5004a07eacc03ffb95a19`. A bounded raw calibration capture with no typed consumer: it does not run under `lake test` and establishes neither `L` nor `C` coverage.
- `sync`: every row instantiates a clause `spec/` already carries. The store rows are [`spec/09`](../../spec/09-computations.md)'s fit branch reached from the literal side; the gate row is [`spec/04`](../../spec/04-numbers-and-decimals.md)'s literal-scale clause, which already states that a *fractional* literal contributes its authored fractional length while only an *integer* literal is stripped. The asymmetry is therefore two existing clauses meeting, not a new rule. No behavioral change, so no outbound entry follows.

#### A Date constant is classified by its own spelling and stored in the target's format, measured locally 2026-08-31

- `revision`: a12-dmkits `1be2d603c90be578fe7ea0de0b8c515cb2a479c4`, the sibling checkout clean before and after, `state: CLEAN` in the artifact. `dmtool` 0.13.0, Kernel `30.8.1` built and runtime. The static rows are `computation add --dry-run` refusals attributed by the pair `source: KERNEL` plus an `MVK_*` code; the runtime rows are `validateFull` and `compute` on both codegen strategies, `enginesAgree: true`.
- `question`: [SG4](../SEMANTICS-GAPS.md#sg4--computation-scheduling-and-state-transition) requires each remaining constant kind's target-check **timing** to be measured before a carrier, because String checks everything at runtime and Number splits its two grounds across authoring and runtime. Reading either timing across the kind boundary is a claim, not an inheritance. Date is the first of the remaining kinds.
- `format-not-a-gate`: the target's exact declared format is not a spelling-equality gate: one Date literal is admitted into the dotted, ISO, and year-only targets alike. Independent target policies were not varied in this batch; the later [pre-1900 checkpoint](#src-date-constant-pre-1900-target) proves that the runtime Date policy still applies after rendering.
- `literal-kind`: the static gate reads **only the literal's own spelling**. A double-quoted `"05.03.2024"` is admitted into all three targets — including one declared `yyyy` and one declared `yyyy-MM-dd`. Every other spelling is refused `MVK_INVALID_COMPARE_TO_DATE`, because it lexed as a String or Number constant and that cannot be assigned to a Date target. The refusal names a *comparison*, so the code does not announce which half is wrong.
- `iso-trap`: the ISO spelling `"2024-03-05"` is **refused**, and it is exactly the text an ISO-declared target *stores*. The one spelling a reimplementer would reach for first is the one that cannot be written, and the error code points at neither the format nor the literal.
- `calendar-validity`: the classification requires a **real calendar date**, not merely the `DD.MM.YYYY` shape. `29.02.2024` is admitted and `29.02.2023` is refused — one digit apart, differing only by whether the date exists — and `31.04.2024` is refused against an admitted `30.04.2024`. `00.01.2024` is refused. Zero padding is mandatory: `5.3.2024` is refused where `05.03.2024` is admitted.
- `omitted-year`: [`spec/12`](../../spec/12-concrete-syntax.md)'s lexer note admits "the omitted-year shape" beside `DD.MM.YYYY`. No witness for it was found on this route: `05.03.`, `05.03`, and `03.2024` are each refused. That is a missing witness and not a refutation — the shape may need a declared Base Year or a context these rows do not supply. No witness known as of this revision.
- `omitted-year-witnessed`: **the witness exists and this round's targets were what hid it.** `05.03.` is admitted into a `MM-dd` target, measured at the [composition checkpoint](#src-temporal-constant-literal-composition), and `05.03` and `03.2024` stay refused there too, so the trailing dot is load-bearing. Every target on this route carried a year, and a Base Year is required exactly when constant and target disagree about carrying one — so the three refusals were the year disagreement, correctly observed and wrongly generalized. The observations stand; only the "no witness on this route" conclusion falls, and it fell to the variable this route held constant ([`LF114`](../LEAN-FINDINGS.md)).
- `runtime-reformats`: **one authored constant stores three different strings.** `"05.03.2024"` written to targets declared `dd.MM.yyyy`, `yyyy-MM-dd`, and `yyyy` stores `05.03.2024`, `2024-03-05`, and `2024` respectively, on every instantiated row, with `cleared: false` and `errored: false` throughout and no message on either engine. The constant is one temporal value and the declared format is a **rendering** of it, which is the same value/rendering split the Number store already has.
- `lossy-is-silent`: the `yyyy` target discards day and month and reports nothing — not an error, not a clear, not a warning. A carrier that treated a component-omitting target as a refusal, or that stored the authored text, would diverge silently on the most common authoring mistake in this family.
- `rows-and-addresses`: the constant reaches every instantiated row and none when the group holds no row, matching the other three constant families. The first row renders unindexed (`Probe/Rows/DIso`) and the second as `Probe/Rows[2]/DIso`, the known repetition-one eliding dialect.
- `local-consequence`: these rows calibrate the [Date constant carrier](../implementation/repeatable-computations.md#cap-repeatable-date-constant-computation)'s literal classification and target rendering. The later component-omitting and pre-1900 checkpoints extend that carrier without reading either unvaried branch from this batch.
- `limit`: three declared formats, one repetition level at bounded repeatability 3, one complete-date literal, `en_US`, no Base Year. Not measured: DATE_FRAGMENT, TIME, DATETIME, and DATERANGE targets, a constant under a precondition, a seeded target cell, and whether a component-omitting target round-trips when later read.
- `bytes`: [`date-constant-target-formatting/`](../../evidence/kernel-30.8.1/captures/date-constant-target-formatting/); SHA-256 gate model `1f837fb2bfffc0f35fdacd3fcc6f6174020c1bd418e20d6ea71e7e95ffbc22ad` for the static rows, runtime model `68597809e3c0b847a844d7e52a06e9b7698f91f4c0f452b90b49fb868e243a58`, request `8822121784270318f2abc20ec9f21a213f537d80e05a2073b870a47de5f9b05c`, artifact `a40d9254721823c925e8643219b9d7f622073377011107de17a798ad5a72bee5`. The static table needs the computation-free model because `RK_NAME_EXISTS` pre-empts every code once a target already carries a computation. Bounded raw calibration captures with no typed consumer: they do not run under `lake test` and establish neither `L` nor `C` coverage.
- `sync`: behavioral and new. [`spec/09`](../../spec/09-computations.md) carries Date literal classification and target rendering; the literal-kind and calendar-validity rows refine [`spec/12`](../../spec/12-concrete-syntax.md)'s lexer note. Outbound as [`SPEC-2026-08-31-02`](../A12-DMKITS-SPEC-SYNC-LEDGER.md#spec-2026-08-31-02), whose universal timing claim is superseded by [`SPEC-2026-09-01-01`](../A12-DMKITS-SPEC-SYNC-LEDGER.md#spec-2026-09-01-01).

<a id="src-constant-literal-family-gate"></a>
#### A bare constant's admission is gated by the target's declared **format string**, never its kind, measured locally 2026-08-31

- `revision`: a12-dmkits `1be2d603c90be578fe7ea0de0b8c515cb2a479c4`, the sibling checkout clean before and after, `state: CLEAN` in the artifact. `dmtool` 0.13.0, Kernel `30.8.1` built and runtime. Static rows are `computation add --dry-run` refusals on a computation-free model, attributed by the pair `source: KERNEL` plus an `MVK_*` code; runtime rows are `validateFull` and `compute` on both codegen strategies, `enginesAgree: true`.
- `question`: [SG4](../SEMANTICS-GAPS.md#sg4--computation-scheduling-and-state-transition) requires each remaining constant kind's target-check timing measured before a carrier, and the [Date checkpoint](#src-date-constant-target-formatting) had just produced a timing neither String nor Number has. Rather than one kind at a time, this audits the six remaining kinds in one batch, with String and Number constants as live controls so an all-refusal table cannot pass for a finding.
- `authorable`: **TIME, ENUM, and DATE_FRAGMENT admit a bare constant; DATETIME and DATERANGE have no witness.** `"12:30:00"` into a TIME target, `"A"` into an ENUM declaring `A`, and `"05.03.2024"` into a `yyyy-MM` DATE_FRAGMENT are each admitted and each store on every instantiated row. `"2024-03-05T12:30:00"`, `"05.03.2024 12:30:00"`, and a hyphenated range literal are all refused; that is a missing witness rather than a proof of unauthorability, and the range's own `MVK_INVALID_COMPARE_TO_DATE_RANGE` differs from the others' code, so something classified there.
- `authorable-corrected`: **the DATETIME half is refuted — a witness exists and this round held the wrong spelling.** `"05.03.2024T12:30:00"` is admitted, measured independently at the [composition checkpoint](#src-temporal-constant-literal-composition). It is the German date literal, `T`, and the clock literal concatenated — both halves were already in this round's own admitted set, and only their composition was never tried. The three refused spellings above stand; DATERANGE stays unwitnessed. The `MVK_INVALID_COMPARE_TO_DATE_RANGE` reading is separately withdrawn, below.
- `family-gate`: **the declared format string decides admission, and the field's kind is measured irrelevant.** A complete 2×2 on one model: a TIME field declared `HH:mm:ss` admits `"12:30:00"` and refuses `"05.03.2024"`; a TIME field declared `yyyy-MM-dd` does the exact opposite; a **DATE** field declared `HH:mm:ss` admits the clock and refuses the date; a DATE field declared `yyyy-MM-dd` admits the date and refuses the clock. Each kind appears on both sides of both outcomes, which is what excludes the kind as the cause. The literal's temporal family must match the format's, and a mismatch is `MVK_INVALID_COMPARE_TO_DATE`.
- `within-family-rendering`: **inside one family the format is a rendering that may silently drop components.** `"05.03.2024"` into a `yyyy-MM` DATE_FRAGMENT stores `2024-03` — day discarded, nothing cleared, nothing errored, no message — reproducing on a second kind the rule the Date checkpoint measured for a `yyyy` DATE target. So the two halves are separate rules: the family gates, the format renders.
- `kind-irrelevant-at-runtime`: the two cross-kind cells **store**, and not merely admit. A **DATE**-kind field declared `HH:mm:ss` stores `12:30:00`, and a **TIME**-kind field declared `yyyy-MM-dd` stores `2024-03-05`, both unerrored and uncleared on every row. The declared kind therefore carries no part of the rule at either stage, which is what makes a kind-keyed target certificate strictly narrower than the Kernel rather than merely differently spelled.
- `enum-value-gate`: **ENUM is the one kind whose target constrains the constant's value statically.** `"A"` is admitted against a declaration listing `A` and `B`; `"Z"` is refused `MVK_INVALID_STRING_CONSTANT_FOR_ENUM_COMPARISON`. That static membership check is distinct from String's runtime policy, Number's split policy, and Date's component-family admission plus measured runtime pre-1900 branch.
- `time-literal`: the literal vocabulary includes `HH:mm:ss`, which [`spec/12`](../../spec/12-concrete-syntax.md)'s lexer note does not mention. `"12:30"` without seconds is refused, so the clock shape is exact in the same way the date shape is.
- `local-consequence`: the **ENUM constant carrier already existed** and was found implemented when this audit reached that kind, membership gate included; the rows supplied its refusal's Kernel identity `MVK_INVALID_STRING_CONSTANT_FOR_ENUM_COMPARISON`, which [`EnumerationComputation.lean`](../../A12Kernel/Elaboration/EnumerationComputation.lean) now maps, rather than justifying a second carrier. The TIME rows landed [their own carrier](../implementation/repeatable-computations.md#cap-repeatable-time-constant-computation).
- `local-consequence`: the [Date constant carrier](../implementation/repeatable-computations.md#cap-repeatable-date-constant-computation)'s stated exclusion of a component-omitting target is now understood rather than merely bounded — such a target is in-family and renders lossily, so a future carrier extending it needs a component-dropping renderer and not a new admission rule.
