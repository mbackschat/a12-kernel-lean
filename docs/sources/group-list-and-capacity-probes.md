#### `NumberOfDifferentValues` classifies by its **first** operand, unlike every sibling gate in the family, measured locally 2026-08-31

- `revision`: `dmtool` 0.13.0 at a12-dmkits `11d9d811657c3562299b463f3dc3ece12142c650`, the sibling checkout clean before the run, Kernel `30.8.1` built and runtime. Thirty-two `rule check` rows on one model, each envelope `verification: KERNEL_CONFIRMED` with `source: KERNEL` and an `MVK_*` code on every refusal. `rule check` persists nothing, so the verdicts are recorded below and the model is the retained byte.
- `question`: [`EXP-2026-08-31-03`](../A12-DMKITS-SPEC-SYNC-LEDGER.md#exp-2026-08-31-03)'s document run was blocked on a clean sibling tree, and its model needed a `NumberOfDifferentValues` ladder over a fixed group. That authoring step was refused, which turned a blocked run into a static-legality question the probe route can answer without a document.
- `claim`: **the mismatch code names the class of the operand list's first member, and every later operand must join it.** Number-first draws `MVK_NUMBER_AND_NON_NUMBER`, String-first `MVK_STRING_ENUM_AND_NON_STRING_ENUM`, Date-first `MVK_DATE_AND_NONDATE`. Both orders of every pair are measured — `(Number, String)` against `(String, Number)`, `(Date, String)` against `(String, Date)`, `(Number, Date)` against `(Date, Number)` — and each flips the code while the verdict stays refused.
- `claim`: **position, not offence, selects it.** `(Number, Number, String)`, `(String, String, Number)`, and `(Date, Date, Number)` each report their *first* operand's class rather than the offender's, and `(Number, Date, String)` — two different offenders after an admissible first — still reports the Number class.
- `separator`: **two groups differing in nothing but declaration order flip the code.** A nonrepeatable group declaring a NUMBER then a STRING draws `MVK_NUMBER_AND_NON_NUMBER`; one declaring a STRING then a NUMBER draws `MVK_STRING_ENUM_AND_NON_STRING_ENUM`. So the group operand is expanded in declaration order and the first expanded field is the one that fixes the class — which no homogeneous group and no single mixed group can show.
- `claim`: **a first operand outside the three comparable classes is refused before the homogeneity gate**, with a fourth code naming the admitted set: a BOOLEAN first draws `MVK_ONLY_STRING_ENUM_NUMBER_CMP_DATE_ALLOWED` whether the list is `(Boolean, Boolean)`, `(Boolean, String)`, or `(Boolean, Number)`, while `(Number, Boolean)` draws the ordinary `MVK_NUMBER_AND_NON_NUMBER` — the Boolean is merely "non-number" once an admissible operand leads.
- `contrast`: **the sibling carriers do not behave this way, and the codes are distinguishable.** `FieldValuesNotUnique` refuses every mixed order with one order-independent `MVK_VARYING_TYPES_NOT_ALLOWED` and rejects an all-BOOLEAN list with `MVK_ONLY_STRING_ENUM_NUMBER_DATE_ALLOWED` — the same class-admission code **without** the `CMP` token, so the two gates are separate mechanisms rather than one shared check. `FirstFilledValue` reports the varying-types code on a mixed list like uniqueness does.
- `control`: **the presence quantifiers have no homogeneity gate at all.** `NumberOfFilledFields` and `AllFieldsFilled` admit the mixed group, the explicit mixed list, and the all-BOOLEAN list alike. That is what makes the refusals above a property of reading operand *values* rather than of the operand list, and it is the row that keeps an implementer from gating the whole family.
- `admitted-controls`: the pure-Number group, the pure-String group, `(String, String)`, and `(Date, Date)` are each admitted, so no refusal above is the model failing to load.
- `local-consequence`: **this refuted a Kernel class this project had shipped.** `NumberEntityList.aggregateDiagnostic?` projected `MVK_STRING_ENUM_AND_NON_STRING_ENUM` for a Number entity list whose group expansion contains a String, and its conformance fixture `Probe/A` expands **Number-first**, so the locked class was the wrong one for that very fixture. The projection now claims no class for the distinct count, because the error value carries no first-operand kind and any single class is wrong for some list that reaches it.
- `not-reached`: `FirstFilledValue` over an all-BOOLEAN list reports `MVK_INVALID_COMPARE_TO_YESNO` — the comparison to the String literal refuses first — so that carrier's class-admission gate stays unmeasured.
- `limit`: NUMBER, STRING, DATE, and BOOLEAN operands only, one declared Date format throughout so the format gate never engages, nonrepeatable groups only, `en_US`, static admission with no runtime row.
- `limit`: not measured — ENUM, CUSTOM, CONFIRM, TIME, DATETIME, and DATERANGE as a first operand, a starred group's expansion order, and whether the extrema and `Sum` share the distinct count's positional rule or are genuinely order-free.
