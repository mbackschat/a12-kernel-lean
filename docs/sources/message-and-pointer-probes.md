#### The rule-message parameter grammar: paths, quoting, category, and Base Year, measured locally 2026-08-24

- `revision`: clean a12-dmkits `108d047b787f0e049dcd2f4902f24d7523347a00`, dmtool `0.13.0`, kernel `30.8.1` built and runtime; the sibling worktree was empty before and after every command. Source basis read at a12-kernel `cb66e51fa7ab90b650698f861bf670754e2e1e66`.
- `route`: at the measured revision, **`rule check` could not reach this surface at all** because it took no message, so the oracle was `rule add --dry-run`, which the tool documented as kernel-validated before and after and which therefore ran the rule error-text checker. Two dmtool-authored models share one root group with a nonrepeatable subgroup, a Number named `Amount` at **both** levels, a String named `For`, a String named `index`, and an Enumeration with one declared category; one declares Base Year 2020 and the other declares none. Thirty-one decisions vary only the message text, each with a condition that references exactly the fields its message names.
- `instrument-limit`: at that revision an error-text refusal at `rule add --dry-run` wrote **no result envelope**: stdout was empty, the verdict was a prose line on stderr carrying the Kernel's own bracketed class, and the exit code was 2. Every refusal below was therefore read from that line rather than from `diagnostics`. The [2026-08-23 reconciliation](../SOURCES.md#src-2026-08-23-reconciliation) records the later standard-envelope fix and read-only `rule check --message` route.
- `path-claim`: the parameter's entity spec is the shared path grammar, admitted in every form this fragment represents: a bare name in its own scope, a group-qualified relative path, an absolute path, a parent walk, and a parent walk with an explicit turning point. A **wrong** turning point is refused `INVALID_ENTITY` naming `..Nope`, which is the live control showing the turning point arbitrated rather than being ignored. The value suffix composes with a path.
- `path-claim`: two malformed shapes carry classes this project does not reproduce, in the same refusing direction. An absolute path with a single segment is not a parse failure but `INVALID_ROOT_GROUP` naming `/Amount`, so the absolute form's first segment is the **root group**. A bare `..` with no field is not a parse failure either but `INVALID_FIELD`, so it parses as an entity and then fails the reference check. An empty path segment *is* a parse failure, `MVK_UNEXPECTED_TOKEN`.
- `quoting-claim`: the single-quote escape is load-bearing and this producer's exemption is real. A field named `For` is admitted as `$'For'$` and refused as `$For$` with `MVK_UNEXPECTED_TOKEN` — a **parse** class, not a dedicated needs-quoting class, which is why this project maps its own class to none. A field named `index` is admitted **both** quoted and unquoted, which is the exemption's live separator on the same model. `$RuleGroup$` as the whole spec is refused `INVALID_PARAMETER`.
- `baseyear-claim`: the English terminal really is `BaseYear`. `$BaseYear$`, `$BaseYear+3$`, and `$BaseYear-1$` are admitted on the configured model and all refused `NO_BASE_YEAR` on the unconfigured one, so the model's Base Year is the whole gate. `$BaseYear*2$` is refused `MVK_LEXER_STANDARD_ERROR` naming the character and its position, and `$BaseYear+$` is refused `MVK_EXPECTED_TOKEN_NOT_FOUND` expecting a digit sequence, so the offset syntax is exactly a sign and digits. `$'BaseYear'$` is refused `INVALID_ENTITY`: quoting the terminal turns it into a field name, which confirms the escape mechanism from the other side.
- `baseyear-claim`: the German spelling is **not** a terminal in an English model. `$Referenzjahr$` is refused `INVALID_ENTITY` as an unknown group or field, so a consumer that reused the German spelling would resolve the wrong entity rather than interpolate the year.
- `category-claim`: all four category gates fire distinctly on one model. A declared name is admitted; an undeclared one is `INVALID_CATEGORY` naming both the category and the field; an empty name is `NO_CATEGORY`; and the suffix on a Number field is `FIELD_NO_ENUM`. The value suffix on the same Enumeration field is admitted, so the two suffixes are independent rather than one gating the other.
- `local-divergence`: the original doubled-arrow fixture used an undeclared first category and therefore observed `INVALID_CATEGORY`; the [2026-08-23 reconciliation](../SOURCES.md#src-2026-08-23-reconciliation) supplied the separating three-row matrix. A declared first category reaches the trailing-syntax `MVK_UNEXPECTED_TOKEN`, an undeclared one draws `INVALID_CATEGORY`, and a non-Enumeration field draws `FIELD_NO_ENUM`. The local checked parser now preserves the first suffix long enough to reproduce those gates. Combining the value suffix with an arrow, `$Status.value->Group$`, remains a parse failure at both, `MVK_UNEXPECTED_TOKEN`, which confirms the two suffixes are alternatives.
- `local-divergence`: a second, smaller one was found and fixed while writing this checkpoint: a parse refusal quoted the spec it had split from rather than the whole authored parameter, which would send an author looking at text they never wrote.
- `persistence`: one accepted candidate carrying **three** parameter forms in a single message — a relative path with the value suffix, an absolute path, and `$BaseYear+1$` — was persisted, read back byte-identical through `rule read`, and the model re-checked `valid:true`, `KERNEL_CONFIRMED`.
- `integrity`: configured model `499e5b59ad31d03861675081474e6122f2d4e69c0f2920b626b845f6d921155f` (Base Year 2020, the categorised Enumeration, and the persisted candidate) carries twenty-nine rows; unconfigured model `bbcfefe9fbe01add64a85d01831521b97ff50195d118efd0e5fcf1c16345542f` carries the two Base-Year-absent rows. Every retained row was re-run against the exact bytes named here after the last model edit, because an earlier state of the configured model had neither the Base Year nor the Enumeration. `rule add --dry-run` persists nothing, so these two model files are the whole retained input.
- `limit`: this **static grammar checkpoint itself** covers one locale, one nonrepeatable subgroup, and no runtime observation. Runtime rendering is separately measured at the [parameter-rendering checkpoint](../SOURCES.md#src-rule-message-parameter-rendering), while the [2026-08-23 reconciliation](../SOURCES.md#src-2026-08-23-reconciliation) adds the declared-first-category doubled-arrow row, labelled Enumeration value, minimum-fraction default control, bilingual matrix, and exact locale presentation table. Still unmeasured: a field literally named `BaseYear` beside the terminal, the offset's magnitude bound, the remaining non-field parameter forms, and a label-provider result.

- `baseyear-claim`: the offset arithmetic is exactly the obvious one and the rendering is the plain decimal. Against a declared Base Year of 2020, `$BaseYear$` renders `2020`, `$BaseYear+3$` renders `2023`, and `$BaseYear-1$` renders `2019`, in one message. `$$` renders one `$` in the same message, so the escape survives beside real parameters.
- `category-claim`: a category access renders the **category token the field's current stored value maps to**, not the category's name and not the stored value. With unlabelled `Status` holding the first declared value `open`, `$Status->Group$` renders `A`, the `Group` token aligned with that value. `$Status.value$` in the same message renders the unlabelled fallback `open`, so the two suffixes read different things from one field. - `name-claim`: an **unlabelled** field's `$Field$` renders its **short name** — `Amount` for `/Order/Amount` and `Status` for `/Order/Status` — on this route, which configures no label provider. A field carrying a declared label renders that label: `$Head/Amount$` renders `Head amount`. This narrows the canonical clause's last fallback, which says "the resolved identifier's path/index debug representation": on the kernel's own `validateFull` it is the short name. The route cannot distinguish "no provider" from "a provider returning the short name", so the claim is stated for this route rather than for the public service one.
- `value-claim`: a scale-0 Number renders bare — `$Head/Amount.value$` renders `7` — an **unfilled** String's value renders as the empty string, and an **unfilled** Number declaring two **minimum** fractional digits renders `0.00`, which is the canonical clause's stated per-format default reaching a real message on this route as well. The [2026-08-23 reconciliation](../SOURCES.md#src-2026-08-23-reconciliation) supplies the max-2/min-0 control that renders `0`.
- `empty-claim`: an **empty** Enumeration renders the empty string under **both** suffixes: `$Status->Group$` and `$Status.value$` each render nothing while `$Status$` still renders the short name in the same message. That was this project's own unmeasured default for the category access and is now the Kernel's.
- `polarity-claim`: the message's `type` channel separates the two polarities this project models. The rule whose condition carries a `FieldNotFilled` conjunct reports `OMISSION_ERROR` and lists both referenced fields in `fillToFix`; the three value-comparison rules report `VALUE_ERROR` with an empty `fillToFix`. That is a live cross-check of the omission/value distinction rather than a new rule.
- `local-divergence`: one, and it made the representation stronger. A category access had been represented as an opaque caller-supplied text run precisely because its rendering was unmeasured; it now renders through the declaration's own category mapping applied to the caller's stored token, so the policy sits in the theory instead of in the consumer. Its **empty** case then measured out to the same empty string this project had chosen, so that default stopped being a guess.
- `integrity`: model `342cb1338dec504ff6fe7a5f7db62848d228907537497eaffdf10a8723c8c8f1`; documents `f58245d871e7eef89694b06a237f199c3d4aca2b71fae543903e85d3f7b799fd` (filled) and `97f35aadf9cc7e2b7777b64b8ff06b196bf146539c4828fa8f9555132bc6cf59` (empty Enumeration and fraction); request `c79dbc7978c6c213c048bb92a4ca3e2016549d557c587224ef78f2d6d440a18e`; artifact `80c0f91d34bd697e6ecc44cbe495ff535fd8a0bb0b4d6bc0dbc1c3a4d0227f5c`. An earlier single-row run against a smaller model is superseded by these bytes and is not cited: the model gained the fractional field and two rules afterwards, so its hash no longer measures these rows.
- `limit`: one locale for *this* batch, one Enumeration with one category, no repeatable group, and no label provider. The [2026-08-23 reconciliation](../SOURCES.md#src-2026-08-23-reconciliation) separately closes the exact presentation map across ten locale tags and four presented kinds. #### The semantic-index suffix on a rule-message parameter, measured locally 2026-08-23

- `revision`: clean a12-dmkits `108d047b787f0e049dcd2f4902f24d7523347a00`, dmtool `0.13.0`, kernel `30.8.1` built; the sibling worktree was empty before and after every command.
- `route`: the model of the [parameter-grammar checkpoint](../SOURCES.md#src-rule-message-parameter-grammar), extended with a repeatable `/Order/Rows` (max 4) declaring `Key` and `Payload`, plus a nonrepeatable `/Order/Wanted` to serve as a field-valued key. Eleven `rule add --dry-run` decisions vary the message parameter and the condition together; the same instrument limit applies, so each refusal is read from the stderr line and its bracketed class.
- `subject-claim`: **the gate's subject is the semantic index, not the field.** `$Rows/Key For "k1"$` is admitted against a condition of `FieldNotFilled(Rows/Payload For "k1")`, in which `Rows/Key` never appears — so a keyed parameter may name a field the condition does not reference at all, provided the condition keys that group by that key. The Kernel's own refusal text says exactly this ("A semantic index `Rows/Payload For "k1"` can be used in an error text only if it is used in the rule condition in the same way"), but only the admitted row isolates the subject, because every refusing row quotes a field *and* a key together.
- `membership-claim`: condition membership therefore belongs to the **unkeyed** form alone. The unkeyed `$Rows/Payload$` against that same keyed condition is refused `INVALID_FIELD` naming the field as referenced wrongly or unused, which is the ordinary unkeyed gate rather than an index class. The pairing is exact in both directions: a plain-read condition refuses the keyed parameter `MVK_INDEX_FOR_ERROR_TEXT_INVALID`, and so does a condition keyed by a *different* literal.
- `admission-claim`: three further shapes are admitted, each `KERNEL_CONFIRMED`. A literal key matching the condition's; a **field-valued** key, `For Wanted`, where the condition keys the same group by that same field; and the **value suffix before the key**, `$Rows/Payload.value For "k1"$`.
- `grammar-claim`: the suffix precedes the key and nothing else does. `$Rows/Payload For "k1".value$` is refused `MVK_UNEXPECTED_TOKEN` naming the `.`, so a suffix after the key is a parse failure rather than a differently-ordered spelling. An **unquoted** key, `For k1`, is refused `INVALID_ENTITY` naming `k1` as an invalid group or field: an unquoted key is a field reference that failed to resolve, not a token that failed to lex, which is what makes the quoted and field spellings the only two. A key that is itself keyed is refused `ILLEGAL_SEMANTIC_INDEX`, quoting the **inner** index rather than the whole parameter.
- `composition-claim`: the key composes with the **category** suffix. `$Status->Group For "k1"$` on a plainly-referenced Enumeration with a declared category is refused `MVK_INDEX_FOR_ERROR_TEXT_INVALID` — the index gate, reached with the category itself valid — so the key neither consumes nor displaces the suffix.
- `local-divergence`: one, and it corrected a wrong gate before it shipped. The first implementation read the refusal texts alone and gated a keyed parameter on whether the condition referenced *that field* through that key, because every refusing row named a field. The admitted `subject-claim` row shows the subject is the index, and the `membership-claim` row shows the field's own membership is not required at all. Since a semantic index needs a repeatable group and the modeled message fragment is nonrepeatable, that gate could never be posed there: the fragment now decodes a keyed parameter and refuses it as outside its own boundary, and deliberately maps that refusal to **no** Kernel class rather than to the pairing class it cannot evaluate.
- `local-divergence`: The measured grammar in front of the gate — well-formedness, suffix order, key spelling, nesting, category composition — is modeled exactly and separately locked.
- `integrity`: model `dec9bb424bc201ec63dd88809ab3e24b3258ba935159e535362fdceec869df44` after the index additions `25ff01889c61a2b27ff354b4d97402904bc94dd7f033f121bb6974e7858b3b2a`; decision batches `65522f1adf5ce909cec60fb5fd0664ce38d1d6efa630d070de51a5894ef05758` (seven rows) and `98504a9378a184efc569bc73402728b55c3bb64418184eed37e02c3e9e246fd9` (four rows). `rule add --dry-run` persists nothing, so every row rests on those model bytes. All eleven rows were re-run against this exact state when the checkpoint was written, rather than transcribed from the first run.
- `limit`: one repeatable level, one index field, validation phase only, and static admission only — nothing here is a **rendering** claim, so what a keyed parameter interpolates at runtime is unmeasured. Also unmeasured: whether a resolvable key field the condition never names is admitted (the measured field-valued row keys by a field the condition also carries), and which class a parameter violating the index gate *and* a category gate together draws.
- `sync`: locally originated and behavioral. Recorded on [SPEC-2026-08-24-01](../archived/A12-DMKITS-SPEC-SYNC-LEDGER-THROUGH-2026-08-28.md#spec-2026-08-24-01) with the two grammar checkpoints it extends.

#### The rule-message group parameter `$#…$`, measured locally 2026-08-29

- `revision`: a12-dmkits `4e78f8254bcf12f6d94fc23c5c3cd5e4906c8d04` (clean before and after), `dmtool` 0.13.0, Kernel `30.8.1` built and runtime. Every row is one `rule check --message en_US=…` verdict, the real Kernel error-text checker, dispatched through a caller-tagged `batch`.
- `model`: the `FixedStar_DM` probe model, English condition language, one root `Probe` with repeatable `/Probe/Rows` (containing `Marker` and the subgroup `/Probe/Rows/Deeper`) and fixed `/Probe/Store` and `/Probe/Beside`. Every row uses the same rule: error field `/Probe/Rows/Marker`, condition `Length(Marker) > 3`.
- `confound`: the first attempt used `FieldNotFilled(Marker)` and every row — including the plain-text control — refused `MVK_NEG_CONDITION_IN_ITERATION`. The condition gate pre-empts the error-text checker entirely, so no message row means anything until a positive condition is used. The uniform control failure is the tell.
- `position`: `$#…$` is a **group** parameter position, distinct from the `$Field$` name position. The same word behaves differently in each: bare `$RootGroup$` draws `INVALID_ENTITY` as an entity lookup, while `$#RootGroup$` is admitted.
- `matrix`: the admitted set is the rule's own group and its ancestors. `$#/Probe/Rows$` (own) and `$#/Probe$` (root) are admitted; `$#/Probe/Rows/Deeper$` (a **declared** descendant), `$#/Probe/Store$` (sibling), and `$#/Probe/Nope$` (unknown) all draw `INVALID_GROUP`. Containment runs the opposite way from the computation declaring-group gate: here the *named* group must contain the rule's group.
- `spelling`: the path must be absolute. `$#Rows$` names a real group relative to the rule and still draws `INVALID_GROUP`, as do `$#Probe$`, `$#Store$`, and the field `$#Marker$`.
- `keywords`: `$#RootGroup$` and `$#RuleGroup$` are admitted keyword shorthands for the two endpoints of that chain. `$#LfdNr$`, the German spelling, draws `INVALID_GROUP` under an English condition language, matching the terminal-language rule the clause already states for the name position.
- `retired`: `$#Zeile$` and `$#Usb$` draw `PARAM_INVALID_IN_NEW_WORLD`, a code distinct from `INVALID_GROUP`. The Kernel recognizes both terminals and refuses them on the modern route, which supplies the exact code for the clause's existing assertion that they are not permitted in an A12 model.
- `unrecognized`: `$#Vordruckzeile$`, `$#Vordruckname$`, and `$#index(Rows)$` draw `INVALID_GROUP`, the same code as an arbitrary unknown name, so on the rule-owned carrier they are not terminals in this position at all.
- `controls`: `$Marker$`, `$Marker.value$`, and parameterless text are admitted in the same batch, and `$#NotATerminal$` is refused, so the admissions are not an unreachable-checker artifact.
- `limit`: static admission only, one carrier, one condition language, one root, and one nesting level. What each admitted parameter *renders* is unmeasured, as is the German condition language and every non-rule parameter owner that shares the terminal bundle.

<a id="src-message-group-parameter-resolution"></a>
#### How the rule-message group parameter resolves, measured locally 2026-08-29

- `revision`: a12-dmkits `4e78f8254bcf12f6d94fc23c5c3cd5e4906c8d04` (clean before and after), `dmtool` 0.13.0, Kernel `30.8.1` built and runtime. Every row is one `rule check --message en_US=…` verdict through a caller-tagged `batch`, all `KERNEL_CONFIRMED`. It refines the [admission checkpoint](../SOURCES.md#src-message-group-parameter), which used a one-root model and no quoted spelling.
- `model`: `GroupPos_DM`, authored with the structured verbs, kernel-valid by `model check`, with **two root groups**: `/Probe` (repeatable `/Probe/Rows`, its subgroup `/Probe/Rows/Deeper`, and fixed `/Probe/Store`) and `/Second` (with `/Second/Inner`). Rules carry a positive condition on their own group's field.
- `two-roots`: a model with more than one root group is authorable and kernel-valid. `group add --parent ""` is accepted `KERNEL_CONFIRMED`, the terminal `apply` gate committed it, and `model check` reports the model valid. This is the witness that makes the root shorthand's meaning measurable at all.
- `root-shorthand`: `$#RootGroup$` names the root of the **rule's own** ancestor chain, not a model-wide root. For a rule under `/Second/Inner` the shorthand is admitted while `$#/Probe$` and `$#/Probe/Rows$` — the other root and its subgroup — both draw `INVALID_GROUP`. Symmetrically a `/Probe/Rows` rule refuses `$#/Second$`. Admission alone cannot separate "resolves to the chain root" from "always admitted", since the chain root always contains the rule's group; what it does settle is that the primary root is not what the shorthand means.
- `two-stage`: an absolute path resolves in two gates the Kernel reports **apart**. An undeclared first segment draws `INVALID_ROOT_GROUP` whatever follows it — `$#/Nope$` and `$#/Nope/Rows$` alike, and `$#/probe$` too, so the root match is case-sensitive. A **declared** root followed by an unknown group (`$#/Probe/Nope$`, `$#/Second/Nope$`) or by a group that does not contain the rule draws `INVALID_GROUP`. Root existence therefore precedes containment and is a separate gate, which corrects this project's first account that one code covered the whole refusal.
- `quoting`: each segment takes the name grammar's single-quote escape and the quotes are erased before lookup: `$#/'Probe'/'Rows'$`, `$#/'Probe'/Rows$`, `$#/Probe/'Rows'$`, and `$#/'Probe'$` are all admitted, and `$#/Probe/'Nope'$` draws the ordinary `INVALID_GROUP`.
- `quoting-suppresses-terminals`: quoting is **not** merely erased first. `$#'RootGroup'$` and `$#'RuleGroup'$` draw `INVALID_GROUP` naming a group `RootGroup`/`RuleGroup`, and `$#'Zeile'$` draws `INVALID_GROUP` rather than the retired class its bare spelling draws. So the quote decides whether the word is a terminal at all, and the terminal match is on the raw argument.
- `lexical`: a malformed spelling is refused before any group is looked up, on codes distinct from both group classes: an unbalanced quote and an empty quoted segment draw `MVK_LEXER_STANDARD_ERROR` with a character position, a trailing separator draws `MVK_INCOMPLETE_INPUT`, and a doubled separator draws `MVK_UNEXPECTED_TOKEN`.
- `chain-depth`: a rule at `/Probe/Rows/Deeper` admits its own group, `/Probe/Rows`, `/Probe`, and `$#RootGroup$`, and refuses the sibling `/Probe/Store`, so the admitted set is the whole ancestor chain at any depth rather than one level up.
- `controls`: plain-text rows and `$Tag$`/`$Marker$` name-position rows are admitted in each batch, and every refusal carries a Kernel diagnostic, so no admission is an unreachable-checker artifact and no refusal is a front-end rejection.
- `limit`: static admission only, one condition language, and no runtime observation — what any admitted group parameter **renders** is still unmeasured, as is whether the retired-terminal set is selected by condition language, and whether a quoted segment may carry characters a bare one may not. `INVALID_ROOT_GROUP` was reached only through the absolute form; no keyword spelling can name a root the model does not declare, so that combination has no witness here.
- `sync`: locally originated and behavioral. It corrects and extends [`SPEC-2026-08-29-04`](../A12-DMKITS-SPEC-SYNC-LEDGER.md#spec-2026-08-29-04) rather than opening a second entry, because that entry is still pending outbound.

<a id="src-message-address-dialects"></a>
#### A message address is written in one of two dialects, and which one depends on the operand, re-read locally 2026-08-31

- `route`: no new kernel run. Every row below is re-read from artifacts already retained under [`evidence/kernel-30.8.1/captures/`](../../evidence/kernel-30.8.1/captures/), each produced by `:adapter:kernelProbe` on both codegen strategies at its own recorded revision. The claim is about bytes this project already held; the re-reading is what is new.
- `two-dialects-claim`: **a `referenced` or `fillToFix` entry is written in one of two spellings, and one message routinely carries both.** The **instance** dialect is bare, index-one-elided, and varies with the document: `Order/Lines[2]/Produced`. The **declaration** dialect leads with a slash, elides nothing, and marks the iterated level: `/Order[1]/Lines[0]/Produced`. Across every retained artifact, 292 messages carry both spellings in one list, 60 carry only the slash form, and 876 only the bare form, over 22 captures.
- `framing-retracted`: **every row below is a correct reading of these artifacts and a wrong reading of the kernel, on the one point of what a "dialect" is** — the observing probe renders one typed pointer two ways, so the counts and exclusions hold about the bytes while the kind they distinguish is exact-versus-partially-known. Read "dialect" that way; the [selector checkpoint](#src-address-dialect-selector) owns the correction and [`LF130`](../LEAN-FINDINGS.md) the lesson.
- `bracket-claim`: **the slash dialect's `[0]` is not row zero — it marks the iterated level.** `/Order[1]/Lines[0]/Produced` is byte-identical across four documents of the same capture holding two rows, two rows, two rows, and **no rows at all**, so the number cannot be an instance coordinate. `Order` is nonrepeatable and still carries `[1]`.
- `ancestor-claim`: the levels *above* the iterated one carry their concrete **1-based** coordinate rather than a constant. One capture emits `/FullDateParentProbe_DM[1]/Projects[1]/Choices[0]/PromiseDate`, `.../Projects[2]/...`, and `.../Projects[3]/...` for a `Projects` group declared `max 3` — so `[3]` is the third row and not a fourth, which fixes the base as one and rules out the 0-based reading the `[0]` suffix invites.
- `separator`: two levels can be iterated at once. `/Probe[1]/Rows[0]/Inner[0]/I` comes from a two-level starred operand, so `[0]` is per-level rather than a single marker for the innermost, and an account reading it as "the last segment before the field" would produce `Rows[1]` there.
- `correlation`: the slash dialect appears where the address names a **resolved starred or group-scope operand** — group counts, aggregates over a repeatable group, and the source side of a first-filled scan — while the rule's own target field is written bare in the same message. That is a correlation over 22 captures rather than a measured cause; a message whose starred operand is written bare, or whose plain target field is written with a slash, would defeat it, and no retained row does either.
- `cause-narrowed`: **one candidate cause is excluded, on bytes retained 2026-08-31.** The [capacity consumer sweep](group-list-and-capacity-probes.md#src-capacity-consumer-sweep) carries three rules over the same repeatable `Tag` field — `FieldValuesNotUnique` over the **starred field**, the same operator over the **fixed unstarred group** `/Cap/TShell`, and a `NumberOfDifferentValues` ladder over both forms — and every one of them emits the byte-identical `/Cap[1]/TShell[1]/TRows[0]/Tag`. ### Message construction

At kernel revision `cb66e51fa7ab90b650698f861bf670754e2e1e66`, [`RuleErrortextChecker`](../../../a12-kernel/kernel-tool/kernel-core-service/src/main/java/com/mgmtp/a12/kernel/core/service/internal/errortext/RuleErrortextChecker.java) and [`FehlertextUtil`](../../../a12-kernel/kernel-tool/kernel-core-service/src/main/java/com/mgmtp/a12/kernel/core/service/internal/errortext/FehlertextUtil.java) own nonempty text, line/control/encoding checks, even-dollar admission, and parameter checking in that order.

[`GrammarOnly_ErrorTextParameterParser.g4`](../../../a12-kernel/kernel-tool/kernel-core-service/src/main/antlr4/com/mgmtp/a12/kernel/core/service/internal/errortext/grammar/gen/GrammarOnly_ErrorTextParameterParser.g4) plus [`FullChecks_ErrorTextParameterParser`](../../../a12-kernel/kernel-tool/kernel-core-service/src/main/java/com/mgmtp/a12/kernel/core/service/internal/errortext/grammar/gen/FullChecks_ErrorTextParameterParser.java) own token grammar, model lookup, and condition-reference legality. The selected Lean capsule deliberately supports only printable ASCII plus one bare nonrepeatable field name; wider legal syntax is explicit insufficiency, not a claimed kernel rejection.

[`FehlertextBuilder`](../../../a12-kernel/kernel-tool/kernel-core-codegen-rules/src/main/java/com/mgmtp/a12/kernel/core/codegen/internal/generator/backingbeans/meta/FehlertextBuilder.java) splits accepted text while preserving empty dollar-delimited segments, normalizes name/value references, and retains `$$` for runtime decoding. The Java, Groovy, and JavaScript [`CodeGenRuleDefinition.st`](../../../a12-kernel/kernel-tool/kernel-core-codegen-rules/src/main/resources/internal/templates/validation/java/rulesDir/CodeGenRuleDefinition.st) dialects attach messages only in the fired branch.

[`MainValidatorController.substFehlertext`](../../../a12-kernel/kernel-rt/kernel-core-runtime/src/main/java/com/mgmtp/a12/kernel/core/rt/_30_8/internal/core/MainValidatorController.java) performs one split/substitute/join pass: an empty parameter becomes one literal `$`, field name/value parameters resolve once, and inserted bytes are not reparsed.

Field-owned type-format and requiredness messages use distinct routes. [`FieldErrortextChecker`](../../../a12-kernel/kernel-tool/kernel-core-service/src/main/java/com/mgmtp/a12/kernel/core/service/internal/errortext/FieldErrortextChecker.java) runs the common encoding, line/control, and even-dollar checks before comparing delimited parameters with the locale-fixed words supplied by [`CommonUtils.CONST_FIELD`](../../../a12-kernel/kernel-tool/kernel-core-base-utils/src/main/java/com/mgmtp/a12/kernel/core/utils/internal/CommonUtils.java): `field`/`field.value` for US English and `Feld`/`Feld.Wert` for German.

The Java runtime helper [`FehlerHandler.transformFehlerText`](../../../a12-kernel/kernel-rt/kernel-core-runtime/src/main/java/com/mgmtp/a12/kernel/core/rt/_30_8/internal/formatdef/error/FehlerHandler.java) performs fixed name replacement and display-value replacement directly, with a null display falling back to the raw supplied value, and contains no visible call to the rule path's empty-parameter decoder. a12-dmkits revision `ed0b0cd9f7110daa354c2404e7b9ca6df4f42fa3` supplies the missing observation: the `en_US` String-pattern producer accepts only lowercase `$field$`/`$field.value$`, rejects `$$` as an empty parameter, and inserts token-looking value bytes once; the measured requiredness producer instead accepts and preserves `$$`.

Dynamic Groovy and generated Java agree under the same explicit label-or-name provider profile.

Validation messages are rendered before public result assembly. `FehlerHandler` selects locale resources and `CheckCommand.ersetzeFeldParameter` performs the computation-target field token replacement. Authored `$Field$`/`$Field.value$` template handling is a different syntax and must not be reused for generated target text. Read-only inspection of a12-dmkits [`Message.kt`](../../../a12-rulekit/interpreter/src/commonMain/kotlin/io/github/mbackschat/a12/dm/interpreter/eval/Message.kt) at revision `351bf9f28138783ef7ddc7d8c76db2ab4891a5d8` establishes a current peer gap: its nonempty placeholder regex covers name/value tokens but cannot decode `$$`, so the canonical literal-dollar case still needs an upstream implementation and maintained JVM/Node lock.

Computation produces one formal-message stream. `DocumentComputationResultImpl` partitions it solely by exact error pointer against nonempty computed instances. `PartiallyKnownDocumentMultiPointer` admits concrete coordinates plus wildcard and unknown; `CellAddr` alone cannot represent the full message-pointer domain. Payload text, code, and locale do not affect partition membership.
