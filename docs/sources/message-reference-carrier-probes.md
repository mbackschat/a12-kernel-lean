# Message-reference carrier probes

Checkpoints for `referenced` and `fillToFix` on carriers beyond the [messages and pointers](message-and-pointer-probes.md) family, whose shard is at its size bound.

<a id="src-message-reference-carriers"></a>
#### An upward filtered distinct count leaves only its filter reads to fill, and unstarred repeatable group presence is admitted only where the rule iterates that group, measured 2026-10-14

- `producer`: a12-dmkits `a4091041fe4d0de02053517f11d12f480b5c2cbc`, clean before and after, dmtool `0.13.0`, Kernel `30.8.1`. One model (`R5_DM`) took `model check`, ten static rows and one `:adapter:kernelProbe` full-validation request over four documents (`base`, `sparse`, `norows`, and `dup` with a duplicated key `a`).
- `fixture`: root `P` holds `Total`, `S` and a Date `D`; repeatable `Rows` holds `Amt`, `S`, Date `RD`, Time `RT` and a repeatable `Sub/X`; `Items` is keyed by `Sku` with `Label`, a digit-pattern `Code`, `Count` and Time `Tm`. Every root rule also compares `Total`, which therefore appears in both channels.
- `filtered-distinct`: an upward `NumberOfDifferentValues(Rows*/… Having [Rows/Amt] > 0)` over String, Number, Date (mirrored, `1 < …`) and Time columns (`a01`–`a04`) fires OMISSION with the counted column only in `referenced`; `fillToFix` holds the wildcarded filter read and `Total`. The downward controls (`a05`, `a06`) keep the column in both channels. The R3 row `Rf06` has the same shape.
- `selected`: keyed reads under conversion, pattern, Time comparison, String concatenation, value count, a two-key `Sum` and a distinct count (`b01`–`b07`) reference the selected column and the index field at the matched row; the duplicated key silences every one of them beside the unique-index message.
- `group-presence`: `GroupFilled(Rows)` from a root rule, `GroupFilled(Rows/Sub)` or `GroupNotFilled(Rows/Sub)` with the error field in `Rows`, and `GroupFilled(Sub)` declared inside `Rows` all draw `MVK_NO_WILDCARD` (`s01`, `s03`–`s05`). `GroupFilled(Rows)` and `GroupNotFilled(Rows)` with the error field in `Rows` are admitted (`s02`, `s06`). The firing `c02` references every `Rows` field at the firing row and `Sub/X` with its own level wildcarded.
- `expanded-amounts`: `AddDays(D, …)` with a starred count amount, filtered or not (`a07`–`a11`, static `s09`, `s10`), is admitted; an upward firing keeps only the filter read and `Total` in `fillToFix`. These rows are evidence for the ordinary expanded shift amounts that [K19 R8](../PLAN.md#k19-returned-omissions) owns.
- `local`: before this batch Lean refused the String, Date and Time upward pointers (`filteredStarOperand`); the [omission selector](../../A12Kernel/Elaboration/ValidationCondition/Omission.lean) now collects their filter reads as it does for the Number and value-count carriers. The 120 replay rows outside `a07`–`a11` and the static rows `s01`–`s08` match; `a07`–`a11` remain Lean admission refusals and `s09`, `s10` are deferred to R8.
- `limit`: full validation, fixed-root and one-level row rules, one nested repeatable level below the iterated group. Partial validation of these carriers and deeper unbound presence levels are outside this matrix.
- `bytes`: [capture](../../evidence/kernel-30.8.1/captures/message-references-2026-10-14/) with model, ops, observations, request and artifact (Kernel message texts redacted) and `MANIFEST.sha256`.
