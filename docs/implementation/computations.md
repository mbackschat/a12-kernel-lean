#### Boolean/Confirm constant computation target and result/application

- `boundary`: A fixed nonrepeatable target admits one unconditional Boolean constant while retaining its computation declaration group independently. The declaration and target may occupy different fixed subtrees because target placement owns execution scope.
- `boundary`: Boolean admits `True` and `False`; Confirm admits only `True`, while Confirm with `False` is refused as `MVK_INVALID_COMPARE_TO_YES`. Other target kinds remain local unsupported refusals with no invented Kernel code.
- `boundary`: The **fixed** carrier checks fixed placement before the constant, so a repeatable Confirm target is routed away before the Confirm asymmetry is reached; the asymmetry applies only once the target is fixed. That routing is now a carrier choice rather than a refusal of the shape: the repeatable carrier below owns it.
- `boundary`: A **repeatable** Boolean or Confirm target takes the same target-kind-certified constant over the shared [repeatable-target certificate](../../A12Kernel/Elaboration/AddressedRepeatableTarget.lean), so placement is containment — the target's own group and every ancestor admit it, a group the target does not lie below is refused, and that refusal carries the measured `MVK_ERROR_FIELD_NOT_IN_RULEGROUP`. Execution emits the constant once per physical target row under an exact `CellAddr`, and a group with no instantiated row yields no outcome at all rather than one implicit instance. Result classification and application reuse the same typed Boolean channels keyed by address. The two carriers stay separate rather than one widened gate: their result domains differ — one value under a `FieldId`, one per row under a `CellAddr` — so a shared certificate would erase the distinction their consumers exist to read.
- `boundary`: A checked constant executes to its exact typed value, classifies that value against the immutable Boolean or Confirm source target, and applies only a retained change to a separate same-model checked destination. Source-identical values remain inert even when the destination differs; absent or different source values produce an exact typed change. Constants have no operand, target-error, or clear channel.
