#### The wrong-kind constant assignment's diagnostic ladder

- `boundary`: Which class the Kernel reports for a bare constant assigned to a target of the wrong kind is a total function of the **(constant family, target kind) pair**, in three rungs. A Boolean target reports `MVK_INVALID_COMPARE_TO_YESNO` and a Confirm target `MVK_INVALID_COMPARE_TO_YES` whatever the constant is; a temporal constant then reports `MVK_INVALID_COMPARE_TO_DATE` at every remaining target; otherwise the target's declared kind decides.
- `boundary`: Exactly two positions read the constant. Rung 2 inverts the table for all three temporal families, and the Number target reports `MVK_INVALID_COMPARE_TO_ENUM_OR_STRING` for a string-like constant against `MVK_INCONSISTENT_TYPES_COMPARED` for a Boolean one. Every other cell is a function of the target alone, so a per-carrier table read off one measured constant family reproduces the grid everywhere but those two.
- `boundary`: The function answers a **kind** question only, and returns `none` for the four pairs no kind gate refuses. Three are outright admissions; the fourth, a string-like constant at an Enumeration target, is gated on the literal's membership in the declared stored-token domain, which this function is not given the domain to decide. A temporal target is deliberately absent from that list: its admission reads the declared format string rather than the kind, so a caller arriving with one has already been refused by format, and the ladder records that the refusal draws the same class.
- `boundary`: the function is over literal families, not field kinds. A field source reaches the same generated comparison and leaves the ladder on two Boolean field cells, into a String and into a Confirm ([source](../sources/inbound-handbacks.md#inbound-2026-09-26c-joined-comparison)), so no field-source carrier may reuse it; the [field-copy comparison](#cap-field-copy-comparison) owns those refusals.
- `owner`: [`LiteralComparisonDiagnostic.lean`](../../A12Kernel/Elaboration/LiteralComparisonDiagnostic.lean) and [cases](../../A12Kernel/Conformance/LiteralComparisonDiagnostic.lean)
- `owner`: six specializing carriers — the fixed [Boolean/Confirm](#cap-boolean-confirm-constant-computation-target-admission) one and the five repeatable [String, Number, Date, Time, and DateTime](repeatable-computations.md) constants
- `spec-and-source`: [§11 ground rules](../../spec/09-computations.md#1-the-ground-rules) and the [source](../sources/static-admission-and-class-probes.md#src-constant-assignment-diagnostic-ladder)
- `assurance`: E closes the complete kind-decided table as one case, plus a separating row per structural claim: rung 1's dominance over every family including the temporal one, rung 2's inversion against the four targets that disagree, the single pair-dependent rung-3 cell, and the exact Kernel identifier strings so the classes are pinned to the observable rather than to constructor names.
- `assurance`: L is the [source](../sources/static-admission-and-class-probes.md#src-constant-assignment-diagnostic-ladder) — eighty `computation add --dry-run` children in one batch, a complete eight-constant by ten-target grid, every cell of the implemented function checked against the retained result bytes. a12-dmkits' `KF222` and `KF239` independently own the temporal half's mechanism and are cited rather than re-derived. P/C/X none: the table is finite and executable, so a law would restate the cases.
- `consumer`: an **Explain** probe over the same table establishes that the pair is sufficient for the task and the class is not. Pointing an author at the wrong operand is the failure mode, and `MVK_INVALID_COMPARE_TO_DATE` names the *field* at a temporal field and the *literal* at a String one — same class, opposite side. The error arms retain the kind, so a consumer reading them decides correctly; one reading only the projection cannot. a12-dmkits shipped a corrective on the class alone and withdrew it the same day, which is the concrete cost of the lossy step.
- `remains`: CUSTOM targets and extensible-enumeration Strings are outside the measured grid. The literal-**value** gates beneath the ladder are named only where a cell exposed one; characterising them belongs to their own carriers.

- `boundary`: A sole String or Number row may omit its precondition and then selects without a condition read; every row in a multi-row source table is guarded. - `boundary`: a common precondition is no row's guard. - `boundary`: the common-precondition rows measured write a Number target, and the String table carries the same walk by assumption. Both tables share the join `ComputationCondition.withCommon`. Where a joined guard is not admitted the Number table refuses it ahead of unguardedness and the String table after, and neither order is measured.
- `owner`: String/Number/Enumeration table owners, especially [`StringComputationTable.lean`](../../A12Kernel/Elaboration/StringComputationTable.lean), [`StringComputationRunPlan.lean`](../../A12Kernel/Elaboration/StringComputationRunPlan.lean), [`NumericComputation/Table.lean`](../../A12Kernel/Elaboration/NumericComputation/Table.lean), [`NumericComputation/RunPlan.lean`](../../A12Kernel/Elaboration/NumericComputation/RunPlan.lean), and [`ParallelNumericAlternativeTable.lean`](../../A12Kernel/Elaboration/ParallelNumericAlternativeTable.lean)
