<a id="cap-unraised-diagnostic-keys"></a>
#### Catalog keys the Kernel never reports

- `owner-and-boundary`: [`UnraisedDiagnostic.lean`](../../A12Kernel/Elaboration/UnraisedDiagnostic.lean) owns the negative complement of the vocabulary above: fifteen keys that exist in the Kernel's catalogs, resolve to localized text, and correspond to no diagnostic any code path emits. Eight are declared in an error-type enum and passed to no reporting call; seven are live but resolve through the bare-message lookup to name an operand *inside* another diagnostic's text. The two mechanisms are kept apart because only the first is a gap in the Kernel and only the second has words a consumer will actually see. This module carries no rendered message text, by the licensing boundary.
- `assurance`: E locks key distinctness, the partition, and the property the module exists for — that no key is claimed by both this vocabulary and the reported one — in [`Conformance/UnraisedDiagnostic.lean`](../../A12Kernel/Conformance/UnraisedDiagnostic.lean); the two near-miss pairs, where a dead key differs from a live one by a suffix or shares its enum, are locked individually. The status is measured by exhaustive source search over the `../a12-kernel` checkout and retained as a file-and-line record at the [checkpoint](../SOURCES.md#src-unraised-diagnostic-vocabulary); it is a statement about that source tree, not a proof that no engine configuration emits these keys. No `L`, `C`, `X` or `Q`.

<a id="cap-charset-spec"></a>
#### The declared-charset gates

- `owner-and-boundary`: [`CharsetSpec.lean`](../../A12Kernel/Elaboration/CharsetSpec.lean) owns the six refusal classes over a String field's declared restricted charset, as **two stages of one function**: a parse stage classifying each entry into range, combined grapheme, atomic, or none of those, and a validate stage that runs only on a charset the parse accepted. Its six classes join the shared [`KernelStaticDiagnostic`](../../A12Kernel/Elaboration/StaticDiagnostic.lean) vocabulary. It owns **no** grapheme segmentation: UAX #29 is Unicode's contract, so each entry carries its cluster decomposition as an input and every gate reads only that list's length or members. It owns no charset *simplification* either — range merging and composable filtering are a transformation rather than a refusal, and the parse result is deliberately left unsimplified because the validate stage must still see an entry simplification would delete.
- `assurance-L`: proves that a range entry can **never** report the surrogate class, which is not visible from the source. A range is three UTF-16 units with a hyphen at index 1; a supplementary code point occupies two *adjacent* units, so in a three-unit list either placement lands one half of that pair where the hyphen must be. The consumer consequence is direct: skip the surrogate test on the range shape ([`Proofs/CharsetSpec.lean`](../../A12Kernel/Proofs/CharsetSpec.lean)).
- `assurance-L2`: proves that `CHARSET_PARSE_ERROR`, whose name promises a general parse failure, fires on **exactly** the empty entry — the three shape tests being jointly exhaustive over nonempty strings; that the too-long class is a combined grapheme's alone, a range being exactly the maximum length and an atomic entry exactly one unit; and that the two stages shadow in both directions, so a charset with any parse refusal reports only those and a parsing one reports none of them. Six classes, never all live at once.
- `assurance-E`: locks the shape cascade including the order that makes `a-c` a range rather than a three-character grapheme, each parse class against a control differing in one axis, the supplementary code point's passage *through* the parse stage into validate, both validate classes together on one entry in stage order, the shadowing, and the overlap gate against three controls that each remove one of its conditions ([`Conformance/CharsetSpec.lean`](../../A12Kernel/Conformance/CharsetSpec.lean)). Fixtures are built from explicit code points, a combining sequence and its precomposed form being indistinguishable in a source file and measuring differently. No `C` or `Q`. Fourteen mutations run, fourteen caught.
- `external-evidence`: **none.** `external evidence pending` for all six classes: the account is read from the Kernel's charset utility and its own documented restrictions, and no probe here authors a restricted charset — `dmtool` has no measured route to declare one. The UTF-16 reading is the load-bearing assumption, since a code-point reading admits a supplementary entry outright and never reaches the surrogate class at all.

<a id="cap-semantic-index-admission"></a>
#### The semantic-index admission cascade

- `owner-and-boundary`: [`SemanticIndexAdmission.lean`](../../A12Kernel/Elaboration/SemanticIndexAdmission.lean) owns the **order** in which the Kernel refuses a `[Field For key]` operand — thirteen positions in one strict first-hit cascade, of which six classes are new to the shared [`KernelStaticDiagnostic`](../../A12Kernel/Elaboration/StaticDiagnostic.lean) vocabulary and seven already had owners.
