<a id="cap-document-temporal-coherence"></a>
#### Placed-temporal-cell coherence property

- `state`: implemented as an opt-in property, `CheckedDocument.temporallyCoherent`, reporting whether every placed cell whose declaration a Date or DateTime input classifier owns agrees with the value that classifier derives from the cell's own stored text. Deliberately **not** a construction gate.
- `boundary`: `checkDocument` does enforce stored/value correspondence for Boolean, Confirm, Number, and DateRange cells; temporal cells are the documented exception for two independent reasons. Semantically, the duplicate-value clause compares a temporal cell's *exact stored text*, so pinning which account that clause states requires a pair whose text and decoded value disagree, and a gate would delete the clause's own subject from the representation. By coverage, only a full-precision Date and a DateTime have an owning classifier, so a gate could reach at most half a temporal family; a partial Date denotes an interval with no `Value` form and a Time carries no instant of its own. - `boundary`: the comparison is **not** `RawCell` equality. - `consumer`: a Verify or Qualify consumer of the normalized reference process that needs to know a document is kernel-reachable requires this explicitly, rather than inheriting an invariant that could only ever hold for two of four temporal kinds.
- `assurance`: **E closed** for the separating matrix — coherent baseline, a rejection carrying the wrong versus the right cause, the stored-versus-decoded separator in both directions, the millisecond tolerance at 999 and 1000 in both signs beside a whole-hour zone error, and the three declaration shapes no classifier owns. **Internal, not measured:** nothing here reads a kernel output, so L/C/X/Q are none and no ledger entry follows.
