Shared ordered-evaluation laws now preserve arbitrary structural fault types; a new law excludes target self-dependencies universally. Cases distinguish fixed/outer/inner values, mixed field arithmetic, shorter source paths, source identity forgery, missing bindings, left-poison read order, scale suppression, target rejection, physical over-limit clearing, and per-endpoint poison in each of the three difference families.
- `shared-reader`: every addressed source — single field, difference pair, and field list — reads through one list-keyed reader that resolves each member's row address from that member's own declaration before evaluating the atom. Keying the association by id is what makes a repeated member read one cell rather than two, and what lets the shared resolved evaluator answer without a stand-in cell for an operand the atom never names.
- `consumer`: Execute receives the shared sourced Number outcome at each exact target address. Analyze retains structural paths separately from real field dependencies; a group containing the target creates no self-reference, and the dependency query now answers through the shared atom walk, so a source that is not a plain field reference reports its edge instead of silently answering `false`. The self-exclusion law is stated over that corrected query rather than over the plain-field subset it used to inspect. Transform cannot replace a fixed repetition operand with a literal before authoring checks. Raw per-environment evaluation validates only reached source bindings; the target executor separately validates each complete target address.
- `reader-route`: The DM reader never lowers onto this table-less carrier: an authored row computation, `Now` and guards included, runs on the [complete row table](computations.md#cap-authored-repeatable-number-plans) ([calibration](../sources/model-structure-and-declaration-probes.md#src-row-plan-calibration)).
- `assumption`: This computation carrier supplies the target's complete scope to structural resolution, whereas validation supplies its host scope. That is now **measured** rather than assumed on the declaring-group axis: a declaring group containing the target is admitted at any depth, changes no computed value, and leaves an ancestor-level operand holding the ancestor's coordinate while the target iterates below it, with a non-containing repeatable sibling refused ([source](../sources/group-and-iteration-probes.md#src-ancestor-declared-repetition-computation)). Fixed descendants on this arm and arithmetic-to-target composition remain external evidence pending; the existing direct-field target-binding measurements are not transferred as repetition-specific correspondence.
- `evidence`: The [source](../sources/group-and-iteration-probes.md#src-currentrepetition-operand-carriers) retains same-group static admission for bare repetition, multiplication, and addition to a Number field; the [source](../sources/group-and-iteration-probes.md#src-repetition-source-kinds-runtime) retains the one-level mixed-source outcomes. Neither supplies the ancestor-declaration discriminator or a nested-level row. Structural callback faults are library results, not claimed Kernel diagnostic classes.
- `source-set`: **Mixing does not narrow the set** — every kind admitted alone is admitted beside a repetition operand, with the `FieldValueAsNumber` String/Enumeration pair separating an operand-kind refusal from a mixing one ([source](../sources/group-and-iteration-probes.md#src-repetition-numeric-source-kinds)). One shared scope rule gates all four new kinds: the declaration must be model-owned, must not be the target, must re-derive the atom's own payload, and must be bound by the target's repeatable scope. Admission is static only; the measurement establishes no runtime outcome, and every measured source sat in the target's own repeatable group.
- `source-set-surface`: the widened kinds are reachable from the authored surface, not only from the admission predicate: the operand resolver elaborates them against the target's own declaring group, which is what admits an in-row source where the shared nonrepeatable scalar resolver refuses it. A `BaseYear` operand in a model declaring none draws its own elaboration refusal rather than the generic unsupported-expression one; which class the Kernel draws there is unmeasured and nothing is claimed for it.
- `two-endpoint-source`: all three difference families — completed-period `DifferenceInMonths`/`DifferenceInYears`, calendar-day `DifferenceInDays`, and sub-day `DifferenceInHours`/`DifferenceInMinutes`/`DifferenceInSeconds` — are now **modelled** on this carrier, the first sources whose operands are not one field. Each endpoint answers the same scope rule separately, so a pair that satisfies its own component agreement while one side sits on an unbound level is refused. Runtime rows poison from one endpoint at a time, which is what separates the two-cell read from a reader that resolves one cell and serves it for every id.
- `row-bound-law`: **every field a checked operation reads is bound by the target's own repeatable scope**, proved once over the whole dependency walk rather than per family. Stating it there is what removes the per-family versions: a two-endpoint source is covered in whichever position the unbound endpoint sits, and a later source kind inherits the law instead of needing its own. It is not vacuous — a Date field on a disjoint repeatable level is refused where the same declaration on the target's level is admitted, which is the separator that attributes the refusal to the scope rule rather than to the operand kind.
- `difference-family-separation`: the three differ only in their pair gate and in which half of the stored temporal value they read, and one fixture separates all of them: the complete instant is admitted at the day and sub-day units and refused at the completed-period one, the date-only declaration is the mirror, and the day answer and the completed-period answer over the same two cells disagree, so they cannot both come from the same half. The day family certifies its model-zone profile against the model's own declared zone, which is why it needs no evaluation world. A Base-Year endpoint reads nothing and is admitted only at the year the model declares; `Now` is refused in every family, because this carrier's row read carries no evaluation world, and the sub-day family refuses `BaseYear` too.
- `direct-field-list-aggregate`: the direct field-list form of `Sum`, `MinValue`, `MaxValue` and `NumberOfDifferentValues` is **modelled**, and it needed no new scope rule: each member answers the same shared predicate a single field answers, with the list's own arity and duplicate gates beside it. The Kernel decides all four scope rows the same way — a nonrepeatable field outside the target's row is admitted, an unstarred read of a disjoint repeatable group is refused as a missing wildcard, a row-local field is admitted, and the target's own field is refused as a calculated-field reference ([source](../sources/group-and-iteration-probes.md#src-repetition-aggregate-operand-scope)) — which is exactly what `repetitionBoundBy` computes, because an empty repeatable scope is bound by any scope. The row-bound law therefore reaches through this arm instead of acquiring an exception.
- `measured-admitted-and-unmodelled`: the **starred** aggregate forms and the starred `NumberOfFilledFields` are measured admitted beside a repetition operand ([source](../sources/group-and-iteration-probes.md#src-repetition-numeric-source-kinds)) and stay unmodelled, because a star reads a whole declared extent that this carrier's row-scoped read cannot enumerate, and because a starred operand answers **no** scope rule at all — a star over a disjoint repeatable group and over a second root are both admitted. That freedom is the star's, not the aggregate family's, which is why the direct list above keeps the ordinary rule. `NumberOfFilledGroups` naming the target's own repeatable group is separately refused by the Kernel's calculated-field gate whatever the operand order.
- `remains`: Those, computation alternatives and scheduling, generated validation, parser/protocol exposure, and independent consumer qualification remain outside this capsule. [SG19](../gaps/paths-and-groups.md#gap-sg19) owns wider operand/binding work; [SG4](../gaps/keystone.md#gap-sg4) owns computation composition.
