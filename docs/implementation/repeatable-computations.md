### §11 — calculations and formal checking

<a id="cap-typed-result-application"></a>
#### Typed source-relative result and application

- `boundary`: Number, Boolean/Confirm and Enumeration retain their existing result and application folds: complete successes, source-relative changes, errors and retained clears remain distinct. Fixed Enumeration literals/direct/category operations now enter the same [target-instance table](../../A12Kernel/Elaboration/RowComputationTable.lean) as addressed operations through their existing ordinary checked certificate; no repeated-target certificate is weakened. Guard evaluation, dependency reads and first-selection semantics remain shared.
- `assurance`: [Enumeration reader locks](../../A12Kernel/Reference/Dm/EnumerationTableLocks.lean) separate fixed/repeated literal and direct-copy admission, guard clearing and invalid-domain refusal. [Application locks](../../A12Kernel/Reference/Dm/ApplicationKindLocks.lean) execute the mixed plan, project actual typed outcomes, apply the owning folds to separately checked same-model destinations, then check and execute an explicit validation rule over the resulting cell states. They cover fresh/seeded/unchanged values, source-classified clear versus no action, Number attempted-value retention/rejection, fixed/two-row addresses, mixed row guards and downstream poison versus clean absence. Existing result/application laws own the generic folds; these are composition checks, not new universal correspondence proofs.
- `ingress-identity`: [Checked input](../../A12Kernel/Elaboration/CheckedDocument.lean) retains original unconverted-text representation independently of formal parsing. Boolean/Confirm, complete and component-omitting Date, DateTime, Time and DateRange source adapters preserve it through complete successes, source-relative changes, clears and independent application. A typed success equal to its source remains in the complete result without a change; the same text from unconverted ingress changes. String, Custom and Enumeration retain ordinary token identity. Number keeps its explicit decimal/text identity and refuses contradictory provenance.
- `ingress-assurance`: [Boolean/Confirm reader-to-application locks](../../A12Kernel/Reference/Dm/ApplicationKindLocks.lean), [Time construction](../../A12Kernel/Conformance/TimeComputation.lean), [DateFragment selection](../../A12Kernel/Conformance/DateFragmentFirstFilledComputation.lean) and the existing full Date/DateTime/DateRange result owners separate the two ingress modes. Changed application writes typed identity; an unchanged result preserves an independent destination's original identity. [Temporal](../../A12Kernel/Proofs/TemporalComputationResult.lean) and [String-shaped](../../A12Kernel/Proofs/StringApplication.lean) laws keep unconverted inputs filled for clearing without equating them to computed objects. These checks instantiate the retained [ingress-route measurement](../sources/temporal-and-message-probes.md#src-temporal-construction-route); they add no public V1 transport endpoint or new Kernel capture.
- `application-composition`: The existing [Number](../../A12Kernel/Conformance/NumericComputation/NestedApplication.lean) and [String](../../A12Kernel/Conformance/StringComputationNestedApplication.lean) controls retain exact one-/two-level predecessor materialization and destination sentinels. [Generated validation after application](../../A12Kernel/Conformance/GeneratedComputationValidation/RepeatableAppliedValidation.lean) reads different source/destination operands, while the reader locks above cover explicit later validation and same-call dependent reads. These finite topology representatives and the source-owned type-independent action mechanism discharge application composition; additional temporal interpretation/rendering profiles remain with their target-policy owners.
- `evidence`: The [C03 capture and application source mechanism](../sources/computation-placement-and-constant-probes.md#src-application-kinds-c03) establish per-kind computation, same-source application and subsequent explicit-validation observations. Separate-destination composition is checked internally against the type-independent Kernel action mechanism, with maintained Number destination controls; no per-kind independent-destination capture is claimed. Execute/Explain consumers must retain immutable source classification when applying to another destination. Public protocol and independent-consumer qualification are unchanged.

- `boundary`: One repeatable ordinary String target takes a bare authored literal over the shared [repeatable-target certificate](../../A12Kernel/Elaboration/AddressedRepeatableTarget.lean), so placement is containment: the target's own group and every ancestor admit it, and a group the target does not lie below is refused with the measured `MVK_ERROR_FIELD_NOT_IN_RULEGROUP`. The literal has no operand, so the target's own repeatable scope is the only source of iteration.
- `boundary`: Execution writes the one root attempt once per physical target row under an exact `CellAddr`, and a group with no instantiated row yields no outcome at all. The root attempt reuses `StringTerm.store`, so an empty literal is a no-value rather than an accepted empty string, by the same clause concatenation uses. Each row is then classified by the declaration's own policy and prepared matcher; the family adds no acceptance or rejection logic, and a missing prepared matcher fails closed at the target.
- `boundary`: A rejected write retains its exact attempted payload rather than being truncated, blanked, or cleared. Result classification and application reuse the shared typed String channels keyed by address. The fixed Boolean/Confirm constant carrier stays separate: result domains differ, one value under a `FieldId` against one per row under a `CellAddr`.

A precondition-cleared target and a rejected one end in the same state on every input, while the result collection separates them exactly — the rejection mints an outcome on every row, the quiet clear only where a prior value existed. Both halves were already locked, the applied side by [`Conformance/StringApplication.lean`](../../A12Kernel/Conformance/StringApplication.lean) and the minting side by [`Conformance/StringComputation.lean`](../../A12Kernel/Conformance/StringComputation.lean).
- `boundary`: The DM reader now composes ordinary String constants and the existing Enumeration literal/direct/category operations through one [checked row table](../../A12Kernel/Elaboration/RowComputationTable.lean). It retains authored order, common and own conditions, target/scope/family certificates, operation reads, and the complete guard inventory. Each in-capacity row uses the shared first-selected selector before evaluating its chosen operation; no selection clears, poison propagates, and a selected empty or rejected operation never retries a later alternative.
- `boundary`: The shared [row step](../../A12Kernel/Elaboration/RowComputationStep.lean) keeps operand membership separate from scheduling dependencies. Guard-only producers participate in the mixed plan; positive containing-group guards use the existing producer-protection rule. Over-limit rows clear without evaluating guards or operations, and an absent row produces no result.
- `assurance`: E in [RowAlternativeLocks](../../A12Kernel/Reference/Dm/RowAlternativeLocks.lean) separates per-row repetition, guard-only producer ordering, fixed-child group protection below a repeatable group, unreachable-operation cycle rejection, common/own conjunction, reached poison versus clean clearing through a dependent count, selected empty/rejected results, Enumeration domain refusal, skipped invalid sources, no rows and over-limit clearing. The shared selector's existing laws own first-selection semantics; these composition locks are executable checks, not new external correspondence proofs.
- `assurance`: The unchanged 6,310-entry population gains eight matches: four [peer-authored repetition-tiered String cases](../sources/evaluation-and-application-routes.md#src-peer-ba-computations-replay), two [guarded clearing cases](../sources/evaluation-and-application-routes.md#src-valueless-outcome-minting-and-application), and two [Enumeration literal cases](../sources/temporal-constant-and-base-year-probes.md#src-constant-literal-family-gate). <a id="cap-repeatable-time-constant-computation"></a>
#### Repeatable Time constant

- `boundary`: One repeatable complete-clock target takes a bare authored clock over the same shared [repeatable-target certificate](../../A12Kernel/Elaboration/AddressedRepeatableTarget.lean) the sibling constant families use, writing once per instantiated target row from the target's own group or any ancestor of it, and nothing at all when the group holds no row.
- `boundary`: **The target is checked at neither time, and every row is accepted unconditionally.** `TimeTargetOutcome` carries no error branch, matching a target domain whose every admitted clock passes the basic check, so `checkedRepeatableTimeConstantComputation_execute_alwaysAccepts` holds with no hypothesis. Unlike the Number and Date siblings there is no attempted-value retention rule here, and a consumer may read the store without a failure case.
- `boundary`: The stored text is the declaration's own format applied to the clock and nothing else, so a constant and a computed Time producing the same clock cannot store different text. A clock carries no date and no zone: it reaches the renderer directly and never an `Instant`.
- `boundary`: **This carrier follows the Kernel's own rule on the cross-kind cell, and it is the only clock family that may.** The gate is the target's declared *format string* and never the field's kind: a DATE-declared field at `HH:mm:ss` is admitted and stores `12:30:00`, while a TIME-declared field at `yyyy-MM-dd` is refused. It therefore takes `CheckedClockFormatTarget`; `CheckedTimeTarget` is that certificate narrowed to a TIME declaration and stays with the six families that have no cross-kind row of their own.
- `owner`: [`RepeatableTimeConstantComputation.lean`](../../A12Kernel/Elaboration/RepeatableTimeConstantComputation.lean), [proofs](../../A12Kernel/Proofs/RepeatableTimeConstantComputation.lean), [cases](../../A12Kernel/Conformance/RepeatableTimeConstantComputation.lean).
- `assurance`: E is the [literal-family gate checkpoint](../sources/temporal-constant-and-base-year-probes.md#src-constant-literal-family-gate) on both codegen strategies — the admitted `HH:mm:ss` literal against the refused `"12:30"`, the per-row store against a no-row control, and both cross-kind cells storing rather than merely admitting — plus the [cross-group carrier checkpoint](../sources/computation-placement-and-constant-probes.md#src-cross-group-repeatable-constant-target) for placement. P is the three laws above. Not measured for this family: a seeded target cell, a constant under a precondition, and the literal's own lexical gate, which [`spec/12`](../../spec/12-concrete-syntax.md) owns. C/X/Q none.

<a id="cap-repeatable-datetime-constant-computation"></a>
#### Repeatable DateTime constant

- `boundary`: One repeatable complete-DateTime target takes a bare authored wall label over the same shared [repeatable-target certificate](../../A12Kernel/Elaboration/AddressedRepeatableTarget.lean) the sibling constant families use. Execution is addressed from the target's own group or any ancestor of it; each in-capacity row attempts the label, an excess physical row takes the capacity clear branch without evaluating it, and a group with no row yields neither outcome nor residual.
- `boundary`: **The literal's spelling owes nothing to the format the target renders into.** `"05.03.2024T12:30:00"` — the German date literal, `T`, and the clock literal concatenated — is admitted into a target declaring `yyyy-MM-dd'T'HH:mm:ss`, the one DateTime declaration format this project's renderer admits. Admission is static and the literal is upstream of this carrier, which takes an already-classified `LocalDateTime`; [`spec/12`](../../spec/12-concrete-syntax.md) owns the lexical rule.
- `boundary`: **Static and runtime checks read different zones.** The same Berlin-model bytes are valid under a UTC JVM default and refused at the gap computation under a Berlin JVM default. Once admitted under UTC, runtime still validates the wall label against the model's Berlin profile. An ordinary label stores in target format; a spring-forward gap produces no computed outcome and one addressed `berechnungsWertFehler` residual per in-capacity row. An over-capacity physical row remains a capacity clear.
- `boundary`: The run result preserves those public channel identities rather than collapsing the gap into a clear or an errored value: `outcomes` carries accepted stores and over-capacity clears, while `formalErrorsInOperands` carries the exact target addresses whose labels the model zone cannot resolve.
- `boundary`: **The target is admitted by its declared format, not its kind**, through `CheckedDateTimeFormatTarget`: a DATE-declared field carrying `yyyy-MM-dd'T'HH:mm:ss` is a legal target here and stores `2024-03-05T12:30:00`, both halves measured ([checkpoint](../sources/computation-placement-and-constant-probes.md#src-datetime-carrier-stores-by-its-format)). The components gate still applies at that same format, which is the control that keeps the admission from reading as no gate at all. The DATETIME-only narrowing survives as `CheckedDateTimeTarget` for the families with no cross-kind row.
- `owner`: [`RepeatableDateTimeConstantComputation.lean`](../../A12Kernel/Elaboration/RepeatableDateTimeConstantComputation.lean), [proofs](../../A12Kernel/Proofs/RepeatableDateTimeConstantComputation.lean), [cases](../../A12Kernel/Conformance/RepeatableDateTimeConstantComputation.lean).
- `assurance`: E is the [zone-split checkpoint](../sources/temporal-constant-and-base-year-probes.md#src-datetime-constant-zone-split), which fixes the static host-zone discriminator, ordinary stored text, missing gap outcome, exact two-row residuals, and agreement of both codegen strategies; the [literal-composition checkpoint](../sources/temporal-constant-and-base-year-probes.md#src-temporal-constant-literal-composition) fixes the spelling against the refused ISO spelling, and the [cross-group carrier checkpoint](../sources/computation-placement-and-constant-probes.md#src-cross-group-repeatable-constant-target) covers placement.
- `proof`: P keeps declaration-group independence, proves the resolvable and unresolvable outcome branches separately, and bounds cross-route agreement to rendering where an exact instant maps to the literal label. Not measured: a seeded target cell, a constant under a precondition, an overlap label, the unresolved over-capacity interaction, result application, and every DateTime format other than the one admitted here. C/X/Q none.

<a id="cap-repeatable-date-constant-computation"></a>
#### Date literal computation

- `boundary`: The existing year-bearing carrier writes one repeatable FULL Date target from a bare authored date over the same shared [repeatable-target certificate](../../A12Kernel/Elaboration/AddressedRepeatableTarget.lean) the three sibling constant families use, writing once per instantiated target row from the target's own group or any ancestor of it, and nothing at all when the group holds no row.
- `boundary`: **The target's exact format is a rendering rather than a spelling-equality gate, but the target is not unchecked.** The temporal component family and Base-Year state participate in admission; after rendering, the measured opt-in pre-1900 policy runs. A guarded ISO target retains `1899-12-31` as errored while its otherwise identical unguarded sibling accepts it, so the carrier delegates rather than owns that runtime branch.
- `boundary`: **The declared format is a rendering of one literal date, never a constraint on it.** The same `05.03.2024` reaches an ISO-declared target as `2024-03-05` and a dotted one as `05.03.2024`. `checkedRepeatableDateConstantComputation_accepted_rendersInTargetFormat` states that the stored text is the target's format applied to the constant and nothing else, which is what a carrier retaining the authored spelling would violate while still passing every same-format fixture.
- `boundary`: The constant carries **no zone and never becomes an `Instant`**. It reaches `CheckedFullDateTarget.evaluateCivil` directly, so no model-zone decoding can move a literal across a day boundary. The declaration's ordered pre-1900 and Gregorian-floor gates are reached through that same call rather than restated here; the pre-1900 branch is measured on this carrier, while the always-on floor remains shared computed-Date correspondence.
- `boundary`: A **component-omitting** target renders the same literal into its own declared subset and is admitted here: `yyyy` stores `2024`, `yyyy-MM` stores `2024-03`, `yyyyMM` stores `202403`, the discarded components reported nowhere. One constant therefore produces a different stored text for each admitted format, which is what makes the declared format a rendering rather than a gate. `OmittingDateFormat` owns that rendering and stays a **separate type** from `FullDateTargetFormat` because the two admit disjoint format strings, not because the readback is open — the row below owns the readback, and it is measured and closed.
- `boundary`: For a **year-bearing literal**, the yearless `MM` and `MM-dd` formats are admitted exactly when the model declares a Base Year, and the Base Year is consumed by that gate alone: the store keeps no year either way, so `MM` writes `03` and `MM-dd` writes `03-05` for a constant supplying 2024. Without a declared Base Year the target is refused, claiming the Kernel's own `MVK_INVALID_COMPARE_TO_DATE` because the same target admits the constant once one is declared.
- `boundary`: `checkedOmittedComponentDateTarget_yearless_hasBaseYear` makes the year-bearing-source specialization at a yearless target unbuildable without a Base Year, and `omittingDateFormat_yearless_renderCivilText_yearIrrelevant` states the store's year-independence — the half a carrier completing the store from the Base Year would fail while passing every year-leading row.
- `boundary`: [`DateConstantTarget.lean`](../../A12Kernel/Elaboration/DateConstantTarget.lean) now parameterizes both renderer certificates by the source’s written year presence. A Base Year is required exactly when literal and target disagree about carrying a year. [`DateLiteralComputation.lean`](../../A12Kernel/Elaboration/DateLiteralComputation.lean) uses the existing `AuthoredDateLiteral` for fixed and repeatable assignments, checks a yearless literal against a common year, then completes it with the model’s Base Year or existing default anchor. The target format still owns the stored text.
- `boundary`: The seven component-omitting formats in the retained constant matrix render, through the **one** format table [`cap-omitting-date-input`](temporal.md#cap-omitting-date-input) already owned for reading such a cell back. Every one of the seven stores is measured, the compact pair last: `MMdd` writes `0611` where `ddMM` writes `1106` for the same 11 June, exact reverses that no dashed sibling could have settled. An exhaustive round-trip case over every yearless-real month/day pair keeps the writing and reading directions from drifting apart under later change.
- `boundary`: A component-omitting target reaches the **declaration's own** ordered pre-1900 and floor gates, exactly as a complete one does. Reuse across that target-shape boundary remains an **assumption, not a measurement**: the pre-1900 constant row covers the complete ISO target only. The gates are declaration-owned and their flag sits on the policy whatever the format, which is why they are applied rather than dropped.
- `boundary`: the target's declared **format string** decides admission and the declared kind carries no part of it, at either stage: a TIME-declared field at `yyyy-MM-dd` takes a date constant and stores `2024-03-05` exactly as the DATE declaration beside it does. This carrier therefore takes `CheckedDateFormatTarget`, and `CheckedFullDateTarget` is that certificate narrowed to a DATE declaration for the families with no cross-kind row.
- `owner`: [`RepeatableDateConstantComputation.lean`](../../A12Kernel/Elaboration/RepeatableDateConstantComputation.lean), [proofs](../../A12Kernel/Proofs/RepeatableDateConstantComputation.lean), [cases](../../A12Kernel/Conformance/RepeatableDateConstantComputation.lean).

<a id="cap-repeatable-number-constant-computation"></a>
#### Repeatable ordinary Number constant

- `boundary`: One repeatable ordinary Number target takes a bare authored decimal over the same shared [repeatable-target certificate](../../A12Kernel/Elaboration/AddressedRepeatableTarget.lean) the String constant uses, so placement is containment and a group the target does not lie below is refused with the measured `MVK_ERROR_FIELD_NOT_IN_RULEGROUP`. The constant has no operand, so the target's own repeatable scope is the only source of iteration, and execution writes the one root attempt once per physical target row under an exact `CellAddr`.
- `boundary`: The target's two refusal grounds are checked at **different times**, and that asymmetry is what this carrier exists to hold. Excess decimal scale is a static authoring gate carrying `MVK_INVALID_COMPARE_DEC_PLACES`, so an over-scale constant is unrepresentable here rather than a runtime branch; the checked structure carries the scale admission as a proof field. The declared range is not a gate at all, so an out-of-range constant elaborates and then rejects on every row, retaining its exact attempted value uncapped rather than clamped, blanked, or cleared.
- `boundary`: Scale is read **twice, differently**. The static gate compares the literal's *authored* scale with trailing zeros counted, so `1.50` is refused by a scale-0 target even though its stored form would be the integer `1`. The store then takes the ordinary computed-Number fit branch — strip trailing zeros, then pad up to the target's `minFractionalDigits` — so the same `1.50` into a two-digit target keeps `1.5` while `1.5` into a target requiring two digits becomes `1.50`. Stripping never feeds back into the gate. The carrier therefore retains the authored constant for the gate and renders the store through `StoredNumber.fromComputed`, which is what keeps a constant from drifting away from an operation producing the same amount.
- `boundary`: Each row is then classified by `NumericTargetPolicy.checkAttempt` on the declaration's own policy; the family adds no acceptance or rejection logic. Result classification reuses the shared typed Number channels keyed by address. The model-indexed result wrapper applies those retained exact-address actions to a separately supplied same-model checked destination through the shared Number application projection, so a rejected action clears a placed target without creating an absent one. The fixed Boolean/Confirm and repeatable String constant carriers stay separate: result domains differ, and only a second family with the same meaning and result domain would justify a shared carrier.
- `owner`: [`RepeatableNumberConstantComputation.lean`](../../A12Kernel/Elaboration/RepeatableNumberConstantComputation.lean), [proofs](../../A12Kernel/Proofs/RepeatableNumberConstantComputation.lean), and [cases](../../A12Kernel/Conformance/RepeatableNumberConstantComputation.lean)
- `assurance`: E closes containment admission at the target's own group and at an ancestor with the refusal's Kernel identity, the declined nonrepeatable target, the zero/one/two-row matrix, an ordinary negative constant on a signed target, over-maximum rejection retaining the exact attempted value against its in-range control, and the static scale gate against both an in-scale control and the admitted out-of-range constant that separates the two check times. Two paired targets separate the store's directions: `1.5` and `1.50` both store `1.5` on a `maxFractionalDigits`-only target while `1.5` and `10` store `1.50` and `10.00` on one requiring two digits, so a carrier that only retained or only padded fails a column. A further pair shows the gate is unstripped, refusing `1.50` into a scale-0 target while the two-digit target admits and then strips the same literal.
