# Repeatable computation capabilities

The exact-address repeatable half of §11. Scalar, fixed, and nonrepeatable computation families, together with the shared plan, formal-input, result, and generated-validation records these entries delegate to, stay in [`computations.md`](computations.md).

### §11 — calculations and formal checking

<a id="cap-repeatable-string-constant-computation"></a>
#### Repeatable ordinary String constant

- `boundary`: One repeatable ordinary String target takes a bare authored literal over the shared [repeatable-target certificate](../../A12Kernel/Elaboration/AddressedRepeatableTarget.lean), so placement is containment: the target's own group and every ancestor admit it, and a group the target does not lie below is refused with the measured `MVK_ERROR_FIELD_NOT_IN_RULEGROUP`. The literal has no operand, so the target's own repeatable scope is the only source of iteration.
- `boundary`: Execution writes the one root attempt once per physical target row under an exact `CellAddr`, and a group with no instantiated row yields no outcome at all. The root attempt reuses `StringTerm.store`, so an empty literal is a no-value rather than an accepted empty string, by the same clause concatenation uses. Each row is then classified by the declaration's own policy and prepared matcher; the family adds no acceptance or rejection logic, and a missing prepared matcher fails closed at the target.
- `boundary`: A rejected write retains its exact attempted payload rather than being truncated, blanked, or cleared. Result classification and application reuse the shared typed String channels keyed by address. The fixed Boolean/Confirm constant carrier stays separate: result domains differ, one value under a `FieldId` against one per row under a `CellAddr`.
- `owner`: [`RepeatableStringConstantComputation.lean`](../../A12Kernel/Elaboration/RepeatableStringConstantComputation.lean), [proofs](../../A12Kernel/Proofs/RepeatableStringConstantComputation.lean), and [cases](../../A12Kernel/Conformance/RepeatableStringConstantComputation.lean)
- `assurance`: E closes containment admission at the target's own group and at an ancestor with the refusal's Kernel identity, the declined nonrepeatable and non-ordinary targets, the zero/one/two-row matrix, maximum-length rejection retaining the exact payload, the empty-literal no-value against its fitting control, and the fail-closed missing-matcher input. P closes the two laws a consumer needs: execution is independent of the declaring group given the same target and literal, and every row's outcome is exactly the declaration's own target check applied to the one root attempt.
- `assurance`: L is the [cross-group carrier](../SOURCES.md#src-cross-group-repeatable-constant-target) and [target-check](../SOURCES.md#src-repeatable-string-constant-target-check) checkpoints, matching row counts, addresses, and the retained over-long payload on both Kernel strategies. The delegation law is what lets the measured length row stand for the target policy rather than for one clause of it; pattern and minimum-length refusals are not separately measured. Result and application correspondence, and the applied document state after a rejected write, remain external evidence pending. C/X none.
- `remains`: Number and other-kind bare constants, a rejected write's applied state, a stored prior value's survival, and wider scheduling remain with [SG4](../SEMANTICS-GAPS.md#sg4--computation-scheduling-and-state-transition).

<a id="cap-repeatable-time-constant-computation"></a>
#### Repeatable Time constant

- `boundary`: One repeatable complete-clock target takes a bare authored clock over the same shared [repeatable-target certificate](../../A12Kernel/Elaboration/AddressedRepeatableTarget.lean) the sibling constant families use, writing once per instantiated target row from the target's own group or any ancestor of it, and nothing at all when the group holds no row.
- `boundary`: **The target is checked at neither time, and every row is accepted unconditionally.** `TimeTargetOutcome` carries no error branch, matching a target domain whose every admitted clock passes the basic check, so `checkedRepeatableTimeConstantComputation_execute_alwaysAccepts` holds with no hypothesis. Unlike the Number and Date siblings there is no attempted-value retention rule here, and a consumer may read the store without a failure case.
- `boundary`: The stored text is the declaration's own format applied to the clock and nothing else, so a constant and a computed Time producing the same clock cannot store different text. A clock carries no date and no zone: it reaches the renderer directly and never an `Instant`.
- `boundary`: **This carrier is strictly narrower than the Kernel on one measured cell, deliberately.** The Kernel gates a constant on the target's declared *format string* and never reads the field's kind: a **DATE**-declared field whose format is `HH:mm:ss` admits this constant and stores `12:30:00`, while a TIME-declared field whose format is `yyyy-MM-dd` refuses it. The shared `CheckedTimeTarget` additionally requires `kind = .time`, so the first cell is declined here. Widening it would change every family built on that certificate, none of which has a measurement for the cross-kind cell; the decline therefore claims **no** Kernel class, since claiming one would assert a refusal the Kernel does not make.
- `owner`: [`RepeatableTimeConstantComputation.lean`](../../A12Kernel/Elaboration/RepeatableTimeConstantComputation.lean), [proofs](../../A12Kernel/Proofs/RepeatableTimeConstantComputation.lean), [cases](../../A12Kernel/Conformance/RepeatableTimeConstantComputation.lean).
- `assurance`: E is the [literal-family gate checkpoint](../SOURCES.md#src-constant-literal-family-gate) on both codegen strategies — the admitted `HH:mm:ss` literal against the refused `"12:30"`, the per-row store against a no-row control, and both cross-kind cells storing rather than merely admitting — plus the [cross-group carrier checkpoint](../SOURCES.md#src-cross-group-repeatable-constant-target) for placement. P is the three laws above. Not measured for this family: a seeded target cell, a constant under a precondition, and the literal's own lexical gate, which [`spec/12`](../../spec/12-concrete-syntax.md) owns. C/X/Q none.

<a id="cap-repeatable-date-constant-computation"></a>
#### Repeatable Date constant

- `boundary`: One repeatable FULL Date target takes a bare authored date over the same shared [repeatable-target certificate](../../A12Kernel/Elaboration/AddressedRepeatableTarget.lean) the three sibling constant families use, writing once per instantiated target row from the target's own group or any ancestor of it, and nothing at all when the group holds no row.
- `boundary`: **The target is checked at neither time, and that is a third timing rather than a variant of the sibling two.** String checks everything at runtime and Number splits its two grounds across authoring and runtime; nothing about a Date target's declared format participates in admission, and nothing errors at runtime for the constant. So this carrier owns no gate of its own — its only refusals are the shared placement certificate's.
- `boundary`: **The declared format is a rendering of one literal date, never a constraint on it.** The same `05.03.2024` reaches an ISO-declared target as `2024-03-05` and a dotted one as `05.03.2024`. `checkedRepeatableDateConstantComputation_accepted_rendersInTargetFormat` states that the stored text is the target's format applied to the constant and nothing else, which is what a carrier retaining the authored spelling would violate while still passing every same-format fixture.
- `boundary`: The constant carries **no zone and never becomes an `Instant`**. It reaches `CheckedFullDateTarget.evaluateCivil` directly, so no model-zone decoding can move a literal across a day boundary. The declaration's own ordered pre-1900 and Gregorian-floor gates are reached through that same call rather than restated here; the Kernel rows measured no such target for a constant, so that branch's correspondence is the shared computed-Date check's and not this family's.
- `boundary`: A **component-omitting** target renders the same literal into its own declared subset and is admitted here: `yyyy` stores `2024`, `yyyy-MM` stores `2024-03`, `yyyyMM` stores `202403`, the discarded components reported nowhere. One constant therefore produces five different stored texts across the five admitted formats, which is what makes the declared format a rendering rather than a gate. `OmittedComponentDateFormat` owns that rendering and is deliberately a **separate type** from `FullDateTargetFormat`: the latter carries `parseComponents?`, so widening it would force an answer to how a stored `2024` reads back, which is unmeasured.
- `boundary`: The **yearless** `MM` and `MM-dd` formats are admitted exactly when the model declares a Base Year, and the Base Year is consumed by that gate alone: the store keeps no year either way, so `MM` writes `03` and `MM-dd` writes `03-05` for a constant supplying 2024. Without a declared Base Year the target is refused, claiming the Kernel's own `MVK_INVALID_COMPARE_TO_DATE` because the same target admits the constant once one is declared.
- `boundary`: `checkedOmittedComponentDateTarget_yearless_hasBaseYear` makes the yearless certificate unbuildable without the declaration, and `omittedComponentDateFormat_yearless_renderCivilText_yearIrrelevant` states the store's year-independence — the half a carrier completing the store from the Base Year would fail while passing every year-leading row.
- `boundary`: The compact `MMdd` and `ddMM` spellings stay excluded here, but **not** for want of a declarable witness: [`cap-omitting-date-input`](numeric-and-temporal.md#cap-omitting-date-input) measured all seven declarations. What is unmeasured is what a constant *stores* into those two, and their component order cannot be inherited from the dashed siblings because the compact pair differs from each other in exactly that.
- `boundary`: A component-omitting target reaches the **declaration's own** ordered pre-1900 and floor gates, exactly as a complete one does. That reuse is an **assumption, not a measurement**: the constant rows covered only targets with no additional check. The gates are declaration-owned and their flag sits on the policy whatever the format, which is why they are applied rather than dropped, and the assumption is recorded here so it is visible rather than silent.
- `owner`: [`RepeatableDateConstantComputation.lean`](../../A12Kernel/Elaboration/RepeatableDateConstantComputation.lean), [proofs](../../A12Kernel/Proofs/RepeatableDateConstantComputation.lean), [cases](../../A12Kernel/Conformance/RepeatableDateConstantComputation.lean).
- `assurance`: E is the [Date-constant](../SOURCES.md#src-date-constant-target-formatting) [component-omitting](../SOURCES.md#src-component-omitting-date-formats), and [Base Year store](../SOURCES.md#src-base-year-yearless-store) checkpoints on both codegen strategies — one constant's five stored texts across the two complete and three year-leading formats, the yearless refusal, and the per-row reach against a no-row control — plus the [cross-group carrier checkpoint](../SOURCES.md#src-cross-group-repeatable-constant-target) for placement. P is the three laws above, `accepted_rendersInTargetFormat` now quantified over both target shapes. Not measured for this family: a pre-1900 target on either shape, what a yearless target stores under a declared Base Year, a seeded target cell, a constant under a precondition, and the literal's own lexical gate, which [`spec/12`](../../spec/12-concrete-syntax.md) owns. C/X/Q none.

<a id="cap-repeatable-number-constant-computation"></a>
#### Repeatable ordinary Number constant

- `boundary`: One repeatable ordinary Number target takes a bare authored decimal over the same shared [repeatable-target certificate](../../A12Kernel/Elaboration/AddressedRepeatableTarget.lean) the String constant uses, so placement is containment and a group the target does not lie below is refused with the measured `MVK_ERROR_FIELD_NOT_IN_RULEGROUP`. The constant has no operand, so the target's own repeatable scope is the only source of iteration, and execution writes the one root attempt once per physical target row under an exact `CellAddr`.
- `boundary`: The target's two refusal grounds are checked at **different times**, and that asymmetry is what this carrier exists to hold. Excess decimal scale is a static authoring gate carrying `MVK_INVALID_COMPARE_DEC_PLACES`, so an over-scale constant is unrepresentable here rather than a runtime branch; the checked structure carries the scale admission as a proof field. The declared range is not a gate at all, so an out-of-range constant elaborates and then rejects on every row, retaining its exact attempted value uncapped rather than clamped, blanked, or cleared.
- `boundary`: Scale is read **twice, differently**. The static gate compares the literal's *authored* scale with trailing zeros counted, so `1.50` is refused by a scale-0 target even though its stored form would be the integer `1`. The store then takes the ordinary computed-Number fit branch — strip trailing zeros, then pad up to the target's `minFractionalDigits` — so the same `1.50` into a two-digit target keeps `1.5` while `1.5` into a target requiring two digits becomes `1.50`. Stripping never feeds back into the gate. The carrier therefore retains the authored constant for the gate and renders the store through `StoredNumber.fromComputed`, which is what keeps a constant from drifting away from an operation producing the same amount.
- `boundary`: Each row is then classified by `NumericTargetPolicy.checkAttempt` on the declaration's own policy; the family adds no acceptance or rejection logic. Result classification reuses the shared typed Number channels keyed by address. The fixed Boolean/Confirm and repeatable String constant carriers stay separate: result domains differ, and only a second family with the same meaning and result domain would justify a shared carrier.
- `owner`: [`RepeatableNumberConstantComputation.lean`](../../A12Kernel/Elaboration/RepeatableNumberConstantComputation.lean), [proofs](../../A12Kernel/Proofs/RepeatableNumberConstantComputation.lean), and [cases](../../A12Kernel/Conformance/RepeatableNumberConstantComputation.lean)
- `assurance`: E closes containment admission at the target's own group and at an ancestor with the refusal's Kernel identity, the declined nonrepeatable target, the zero/one/two-row matrix, an ordinary negative constant on a signed target, over-maximum rejection retaining the exact attempted value against its in-range control, and the static scale gate against both an in-scale control and the admitted out-of-range constant that separates the two check times. Two paired targets separate the store's directions: `1.5` and `1.50` both store `1.5` on a `maxFractionalDigits`-only target while `1.5` and `10` store `1.50` and `10.00` on one requiring two digits, so a carrier that only retained or only padded fails a column. A further pair shows the gate is unstripped, refusing `1.50` into a scale-0 target while the two-digit target admits and then strips the same literal.
- `assurance`: P closes three laws: execution is independent of the declaring group given the same target, policy, and constant; every row's outcome is exactly the target policy's own attempt check applied to that one stored constant; and, on the fit branch, that outcome is exactly what the shared computed-Number target check produces for an operation yielding the same amount. That third law takes the fit branch as a hypothesis rather than deriving it from the scale certificate, because the certificate bounds the authored scale while the branch is chosen by the stripped one.
- `assurance`: L is the [cross-group carrier](../SOURCES.md#src-cross-group-repeatable-constant-target), [target-check](../SOURCES.md#src-repeatable-number-constant-target-check), and [scale-rendering](../SOURCES.md#src-repeatable-number-constant-scale-rendering) checkpoints, matching row counts, addresses, the static scale refusal with `source: KERNEL` including the unstripped `1.50` refusal whose Kernel text counts two fractional digits, the admitted out-of-range constant, the retained uncapped `99` on every row, and all four store values across the two targets on both codegen strategies. The delegation law is what lets the measured maximum row stand for the target policy rather than for one clause of it; a minimum-bound refusal, a rendered-length refusal, a `minFractionalDigits` strictly between zero and the maximum, and the applied document state after a rejected write are not measured. Result and application correspondence remain external evidence pending. C/X none.
- `remains`: Other-kind bare constants, a rejected write's applied state, a stored prior value's survival, and wider scheduling remain with [SG4](../SEMANTICS-GAPS.md#sg4--computation-scheduling-and-state-transition) and [SG5](../SEMANTICS-GAPS.md#sg5--numeric-authoring-and-target-completion).
