# Open semantic gaps

This is the open-only work index for convergence toward complete semantic conformance with A12 Kernel 30.8.1. [`IMPLEMENTATION-MAP.md`](IMPLEMENTATION-MAP.md) owns implemented, proved, and evidenced coverage. Working context selects uninterrupted work from this index. [`PLAN.md`](PLAN.md) persists a selection only for cross-session handoff.

## Query contract

Open the selected `gap-` record where one exists. Otherwise open the matching `SG<n>` entry.

```sh
rg -n '^<a id="gap-' docs/SEMANTICS-GAPS.md
rg -n '^### SG' docs/SEMANTICS-GAPS.md
rg -n '^- `state`:|^- `blocked-on`:|^- `reopen-when`:|^- `remaining`:|^- `route-state`:' docs/SEMANTICS-GAPS.md
```

A gap carries only current missing behavior, prerequisites, discriminators, consumer consequences, evidence needs, route state, and reopening triggers. Implemented detail stays behind an implementation-map link, exact source revisions stay behind a source-record link, and completed narrative is deleted.

## Hard-frontier critical path

The binding construction order is **SG1 → SG2 → SG4**. SG1 and SG2 are closed. [Immutable checked-document construction](IMPLEMENTATION-MAP.md#immutable-checked-document-construction) supplies one model-certified input, and the [repetition/iteration boundary](IMPLEMENTATION-MAP.md#9--repetition-and-iteration) supplies canonical addressed operands. SG4 must consume both with an explicit processing context rather than redefine document or address state.

### SG5 — numeric authoring and target completion

- `state`: open
- `remaining`: **the derived-scale gate's suppression branch is unmodelled, and that is an over-refusal.** `MVK_INVALID_COMPARE_DEC_PLACES` is the Kernel's one suppressible code, so a condition carrying `@SuppressWarning(MVK_INVALID_COMPARE_DEC_PLACES)` is admitted where a carrier applying the gate unconditionally refuses. The addressed DateRange bound part is one such carrier — it now reports the class, which was the separate defect, but still refuses without consulting suppression. `AddressedNumberDivision` shows the shape a fix takes: it carries `suppressExactScaleWarning` as a certificate rather than assuming the gate.
- `remaining`: that fix's **validation-side discriminator is settled**: the `@SuppressWarning` preamble's scope is the **whole condition**, neither per model nor per next comparison, and it is a leading position rather than a modifier ([checkpoint](sources/static-admission-and-class-probes.md#src-suppress-warning-directive-scopes-the-whole-condition)). So on a validation carrier the certificate belongs on the checked condition and every comparison inside reads it; a refactoring consumer may not lift a suppressed comparison out of its condition without carrying the directive.
- `remaining`: **the computation side is a different channel and is not discharged.** The addressed DateRange bound part is a *computation*, and a computation carries suppression as `errorCodesToSuppress` on the operation rather than as a condition preamble; `dmtool schema computation add` states that the Kernel accepts only `MVK_INVALID_COMPARE_DEC_PLACES` there, which is a catalog claim this project has not measured. Do not carry the preamble's scope across to it: the two are different surfaces on different carriers, and a wrong relaxation here is the over-admission class that produces no failing case. `discriminator`: one `computation add --dry-run` pair over a scale-mismatched assignment, with and without `errorCodesToSuppress`.
- `remaining`: also unmeasured is whether the gate this carrier applies is exact scale **0** or the shared capable-padding rule the addressed Number carriers use. Its certificate demands exactly 0, and adopting `exactNumericScaleComparisonAllowedWithSuppression` would silently admit a scale-2 target beside a scale-0 source — a widening no observation covers and one the suppression work must not smuggle in.
- `missing`: close remaining numeric authoring shapes, computation wrappers, repeated and group aggregates, temporal or aggregate overloads, concrete ingestion and rendering, and partial or repeatable integration through the shared owners.
- `baseline`: [§5](IMPLEMENTATION-MAP.md#5--numbers-and-decimals) owns scalar and addressed numeric execution. The bounded group capabilities start at [shared admission](IMPLEMENTATION-MAP.md#cap-shared-entity-list-group-admission).
- `remaining`: the power rows are **measured and the account is not the obvious one** ([checkpoint](sources/computation-placement-and-constant-probes.md#src-power-derived-scale-and-operand-shapes)): `^` restricts neither operand's shape — a grouped expression and an aggregate are legal as base and as exponent — and what a non-literal exponent does is derive an **unknown** scale, which the existing equality-scale gate then refuses. The computation arm alone reads as "the exponent must be a literal", and the validation arm refutes that.
- `remaining`: grouped addressed power inside addressed extrema is **measured and admitted**, and the derived scale composes rather than being absorbed: inside `Min(…, [F])` a literal exponent and a grouped base are admitted, a field exponent is refused, and the same `errorCodesToSuppress` waives it ([checkpoint](sources/computation-placement-and-constant-probes.md#src-power-derived-scale-and-operand-shapes)). What stays open is any nesting **bound** — depth three is what was measured and no search for a ceiling was made — and that is a parser limit rather than a semantic rule, so it waits for a consumer that needs it.
- `remaining`: host wire ingestion, remaining group or addressed expression placements, third-level external correlation, and external calibration of operand shapes beyond direct Number copy.
- `remaining`: **two different refusals answer to the name "locus refusal" here, and only one of them is the open one.** The *measured* class is already projected at every carrier: an unstarred repeatable reference from a non-iterating locus fails in the shared reference resolver as `ResolveError.repeatableReference`, which projects `MVK_NO_WILDCARD` once for all of them, and the [DateRange-endpoint rows](../A12Kernel/Conformance/DateRangeBoundComponent.lean) lock both that class and its precedence over the component gate. What is unprojected is `fieldOutsideRowGroup`, a **cross-group** refusal on a reference that resolved cleanly but whose declaration sits outside the rule's row group. Match on the error constructor rather than the English name: projecting `MVK_NO_WILDCARD` from the second because the first was measured would claim a class for a gate no row has exercised, at any of its ten carriers.
- `remaining`: **cross-group is not the axis, so this row was framed wrong.** a12-dmkits measured that an operand is admitted by whether the target's repetition scope *binds* every repeatable level the operand crosses — not by scope equality and not by siblinghood — across five operand shapes, so the claim is about scope rather than operand kind. A sibling repeatable operand gives three outcomes by index-field naming alone: same-named index admitted, differently-named `MVK_ERROR_FIELD_INVALID_INDEX`, no index field `MVK_NO_WILDCARD`, and a starred aggregate over it admitted. The 2026-09-05 row here was the third of those, so there is one gate rather than two and a nonrepeatable cross-group operand would simply be admitted.
- `unblocked`: the carrier caveat is discharged. a12-dmkits measured the binding relation on the **rule** carrier against the computation law's verbatim fixture, and the transfer holds on every cell including the sibling index triple ([inbound](SOURCES.md#inbound-2026-09-06a)); seven of their nine rows re-derive here on a different model, plus a depth-2 row their table lacks ([checkpoint](sources/static-admission-and-class-probes.md#src-filtered-star-temporal-carriers-and-binding-depth)). The relation is decided by the operand and the target locus alone — it does not read the carrier, and it does not count operands, even though a rule condition necessarily carries one more than a computation does.
- `evidence-needed`: `fieldOutsideRowGroup` itself remains unprojected at all ten carriers, and the transfer result does not change that. Every measured row — theirs and mine — exercises the *resolver* refusal, `MVK_NO_WILDCARD` on an unstarred repeatable reference. None exercises a reference that resolved cleanly into a group outside the rule's row group, which is the distinct gate this row needs. Keeping the two apart is the whole point of the entry above.
- `discriminator`: keep authored literal scale, derived scale, warning suppression, source scope, target scope, and operator-local poison timing independent.
- `consumer`: Execute and Transform require exact tree shape, rounding stages, target policy, and unsafe-reassociation boundaries.
- `forbidden`: do not introduce a general recursive expression tree until two completed semantic users require the same representation.

- `state`: open
- `missing`: which references a `Having` condition may name, across both arms, every leaf carrier, and every position a level can occupy relative to the filtered operand's path — and which of the two refusals each illegal shape draws, since the two differ in whether any conjunct can satisfy them.
- `baseline`: split out of [SG17](#sg17--having-filter-leaf-and-connective-completion) when that record hit its byte ceiling a second time, which keeps the filter's leaf and connective **domain**; the reference **environment** question is [SG19](#sg19--repetition-reference-binding)'s, and this record owns only the gates that decide admission.
- `settled-rule`: two gates, told apart by satisfiability. The **scope gate** asks whether the condition names anything in the filtered operand's own reopened level, is drawn as `MVK_NO_ITERATION_FOR_WILDCARD`, and one in-scope reference anywhere satisfies it in either conjunct order. The **iteration gate** prohibits naming a repeatable level off the operand's path, is drawn as `MVK_INVALID_ITERATION_IN_FILTER_CONDITION`, and no conjunct rescues it.
- `settled-rule`: the marker is the iteration gate's only remedy, and it needs an outer coordinate or becomes `MVK_NO_WILDCARD`. An unstarred repeatable **ancestor** on the operand's path sits on the satisfiable side ([checkpoint](sources/having-filter-probes.md#src-filter-scope-versus-iteration-gates), [reconciliation](sources/computation-placement-and-constant-probes.md#src-2026-09-05-second-reconciliation)).
- `remaining`: the **above-the-star** position is **closed** ([checkpoint](sources/having-filter-probes.md#src-filter-reference-above-the-star)) and it confirms the path-membership predicate on the direction that had no witness. With the operand `/Rep/Rows/Items*/Val` from a host binding `/Rep/Rows`, a filter naming `[/Rep/Rows/Gate]` — on the operand's path, above the star, bound but not reopened — draws the **satisfiable** `MVK_NO_ITERATION_FOR_WILDCARD` and is admitted beside one in-scope conjunct, rather than the unrescuable `MVK_INVALID_ITERATION_IN_FILTER_CONDITION` a level off the path draws. The marked spelling behaves identically in both rows. So the two gates split by path membership and not by direction along it.
- `measured`: **both runtime rows are closed and Lean already agreed.** An admitted reference the star does not reopen is a constant — per host row for an above-level one, per document for a nonrepeatable leaf — so the filter is all-or-nothing, and an emptied domain yields the aggregate's zero rather than a clear ([checkpoint](sources/having-filter-probes.md#src-filter-reference-level-runtime)). Proved generically as `correlatedHaving_selectEnvironments_all_or_none`, since selection filters candidates on a truth function that a non-reopened level cannot make vary. Outbound as [`SPEC-2026-09-06-07`](A12-DMKITS-SPEC-SYNC-LEDGER.md#spec-2026-09-06-07).
- `remaining`: the candidate-varying case is **not** open and was never this record's — a reference the star reopens drops its own row and leaves the aggregate at its ordinary value, measured at the [non-true conjunct checkpoint](sources/having-filter-probes.md#src-having-filter-nontrue-row). Together with the all-or-nothing row above, both sides of the reopened/non-reopened split now have their runtime behaviour.
- `remaining`: the two narrower arms are closed too: the marked `$` spelling computes the identical values at a non-reopened level, and the validation arm fires on exactly the gated-off host row, so the rule is not a computation-only effect. **A level two above the star is now measured too, and it sharpens the rule** ([checkpoint](sources/having-filter-probes.md#src-filter-reference-two-levels-above)): the constant is keyed to the **referenced** level's coordinate, so it holds across every host row sharing it, which one nesting depth could not distinguish from "constant per host row". No aggregate other than `Sum` is run.
- `remaining`: the bare-outer-scalar discriminator is **closed** and its rule is now **narrowed**: it splits by level *and* by path membership. On a level the star reopens, `$` reads the captured coordinate and the unmarked reference the candidate's; on an unstarred repeatable **ancestor of the operand's own path** both spellings are admitted and read the same row; off that path the unmarked spelling is refused and only `$` is admitted ([checkpoint](sources/having-filter-probes.md#src-bare-outer-reference-redundant-marker), [narrowing](sources/computation-placement-and-constant-probes.md#src-2026-09-05-second-reconciliation)). The inheritance is proved at the addressing rather than assumed.
- `remaining`: the **group-leaf analogue** is narrowed, not closed as first recorded: `GroupFilled` behaves exactly as a field reference does, which means it obeys **both** gates — admitted in either spelling beside a conjunct for a nonrepeatable group, and refused `MVK_INVALID_ITERATION_IN_FILTER_CONDITION` in the unmarked spelling for a repeatable sibling, sole and beside a conjunct alike ([reconciliation](sources/computation-placement-and-constant-probes.md#src-2026-09-05-second-reconciliation)). **Both are now closed** ([checkpoint](sources/having-filter-probes.md#src-filter-reference-two-levels-above)): all four rows repeat on the computation arm, and the leaf obeys the same gate two levels above the star — refused satisfiably alone, admitted beside an in-scope conjunct — as does a nonrepeatable group with no repeatable ancestor at all. Left open: an off-path *group* leaf in the marked spelling.
- `remaining`: the asymmetry is **proved, not only locked**: the reopened-level gate is a leaf disjunction and environment well-formedness a leaf conjunction, so an added conjunct satisfies the first from either side and can never rescue the second (`correlatedHaving_conjunct_repairs_only_the_reopened_level_gate`). That generalizes the measured rows from two shapes to every condition, which is what a rewriting consumer needs before repairing a filter by adding a reference.
- `remaining`: both gates are **locked on both arms** — validation through the presence-leaf route and computation through the aggregate-source elaborator, each with the exact error arm and both environment lists, and the computation arm measured on the Kernel rather than inherited from the shared lowering step. `accepted` as [`SPEC-2026-09-05-01`](A12-DMKITS-SPEC-SYNC-LEDGER.md#spec-2026-09-05-01). The gate is measured to read **path membership and nothing weaker**: a repeatable level nested under the operand's own reopened outer level is refused in both positions, while the reopened outer level's own field is admitted alone.
- `remaining`: the gate reads **nothing about depth** — a reference two repeatable levels above the star gives verdicts byte-identical to the one-above control on both arms and in both spellings, and one whose path crosses two repeatable levels *off* the operand's path stays unrescuable ([checkpoint](sources/having-filter-probes.md#src-filter-reference-two-levels-above)). That confirms the accepted account on a position its denominator excluded and adds no request.
- `remaining`: A level **above** the operand's declaring group needs no separate row: it is off the operand's path and bound by the enclosing iteration, which is the peer grid's own shape — refused unmarked whether or not the host iterates it, admitted `$`-marked beside an in-scope conjunct — and all three are locked here. The off-path `$` reference's **runtime is now measured too**: it reads the host's own row, so the filter's selection varies by host row, with the whole-aggregate rung persisted and never firing and a liveness control firing at both host rows ([checkpoint](sources/having-filter-probes.md#src-off-path-captured-filter-runtime)). Left open on this record: a condition naming **two different** off-path levels, an off-path `$` on the computation arm at runtime, and a host row whose captured cell is malformed rather than absent.
- `remaining`: a single reference whose path crosses two off-path repeatable levels is measured and unrescuable, and marked it draws `MVK_NO_WILDCARD` when the host's iteration binds no coordinate for it — which is the complement of this row's admitted case, not the same configuration.
- `remaining`: a second, narrower collapse sits beside it: `.fieldOutsideEnvironment` covers two Kernel codes — the off-path filter code and `MVK_NO_WILDCARD` for a marker with no outer coordinate — told apart by the arm's own empty available-environment payload. Splitting it needs no new measurement, because a12-dmkits' iteration-gate laws assert **codes** and separate exactly that pair; the [reconciliation](sources/computation-placement-and-constant-probes.md#src-2026-09-05-second-reconciliation) names the three rows a collapsed arm fails. Open until a consumer needs the code.
- `remaining`: one route limit follows from it and is deliberately not fixed here — the normalized public protocol maps `.fieldOutsideEnvironment` to a generic `incoherentCore`, losing a code the Kernel does make, where the protocol already carries a class that projects to it. Extending the published diagnostic set is a [protocol](PROTOCOL.md) decision with a consumer behind it, not a capsule edit; open until an Explain or Analyze consumer needs the code.
- `discriminator`: a gate claim must vary **two** axes, never one: the referenced level's position relative to the operand's path, and the presence of an in-scope conjunct beside the offending reference. Either axis alone leaves the single-gate account standing, which is how both estates first stated it. Two carriers do not substitute for the second axis ([`LF136`](LEAN-FINDINGS.md)).
- `consumer`: an Explain or Analyze consumer mapping refusal to repair needs the split, because "add an in-scope reference" repairs the first gate and does nothing for the second, whose only repairs are to star the level or stop naming it. A Compile or Translate consumer implementing one gate admits illegal models or refuses legal ones depending on which it kept.
- `forbidden`: do not merge the two gates into one out-of-scope rule, do not state the iteration gate by a mechanism — no legal model separates "off the operand's path" from "bound by no enclosing iteration" — and do not give the group-presence leaf a gate account of its own.
- `route-state`: discovery-required

### SG19 — repetition-reference binding and its two sources

- `state`: open
- `missing`: which environment must carry a repetition coordinate for a reference to be legal, across every host that can iterate and every reference spelling. The rule is not the filter's leaf domain and not addressing arithmetic: it decides *admission* of `CurrentRepetition` and the `$` marker before either is evaluated.
- `baseline`: split out of [SG17](#sg17--having-filter-leaf-and-connective-completion) when that record hit its byte ceiling, which owns the filter's leaf kinds and connectives; [star selection and correlation](implementation/repetition-and-paths.md#cap-star-selection-and-correlation) owns the implemented fragment and its assurance, and the [host-iteration checkpoint](sources/having-filter-probes.md#src-currentrepetition-host-iteration) the measured surface.
- `remaining`: **both gates read the reference's path rather than the named group, and only the scope half is a live Lean divergence.** Measured ([carriers](sources/group-and-iteration-probes.md#src-currentrepetition-operand-carriers), [filter](sources/having-filter-probes.md#src-filter-repetition-reference-reads-its-path)): binding requires every repeatable level of the named group's path to be bound, with the refusal naming the unbound ancestor; and the scope gate is satisfied alone by a **nonrepeatable** group nested under the starred level, while a nonrepeatable group with no repeatable ancestor needs an in-scope conjunct. `FlatModel.resolveHavingRepetitionInEnvironment` resolves through `lookupUniqueRepeatablePath`, so a nonrepeatable group stays unrepresentable — that half is real and unchanged.
- `remaining`: the **binding** half is not a divergence after all, which drops it from that capsule's scope. The resolver tests `available.contains group.level` where the field resolvers beside it test `repeatableScopeAvailable` over the whole scope, yet the two agree on every input the public entry can build. Three carried facts settle it: `available` is always a `repeatableScopeForGroupPath` result — directly for the captured environment, and for the candidate one through `CheckedStarFieldPath.ancestryOwned`; that function derives a scope from the path's own prefixes; and validation rejects a duplicate level. So a level found in `available` was found at a prefix, which by uniqueness is the named group's own path. Align the predicate when the scope capsule lands and lock the equivalence as a law; changing it alone buys no behavior.
- `remaining`: widening that resolver is a **representation** change rather than a predicate edit — `HavingRepetitionRef` carries a `RepeatableLevel` a nonrepeatable group does not have, so the result type, its evaluation, and the proofs over it move together, and the evaluated value of a nonrepeatable leaf inside a filter is itself unmeasured. Do it as its own capsule with the sole-condition nonrepeatable-descendant row as the separator, not as a fix folded into another unit.
- `settled-rule`: the reference is admitted exactly where the environment its spelling names carries the coordinate. **Unmarked** reads the candidate environment, which either the enclosing iteration or an operand's own star populates; **marked** reads the captured environment, which only the enclosing iteration fills. `wellFormedForEnvironments` already decided this structurally, so the measurements confirmed a clause rather than changing one.
- `remaining`: `CurrentRepetition` naming a group other than the filtered one is **closed for the marked spelling** by the 2026-09-03 handback ([reconciliation](sources/computation-placement-and-constant-probes.md#src-2026-09-03-reconciliation)): a rule iterating `Lines` whose operand stars only `Items` draws `MVK_NO_WILDCARD` for `CurrentRepetition($Items)`, so the marker rule governs a pointer-free operand exactly as it governs a field one, and [`spec/07`](../spec/07-repetition-and-iteration.md) §3 now carries that topology precondition.
- `remaining`: whether a **repeatable computation instance** binds `CurrentRepetition` as it binds `$` is **closed** by the 2026-09-04 handback ([reconciliation](sources/computation-placement-and-constant-probes.md#src-2026-09-04-reconciliation)): it does, and the control is the identical calculation with the computed target moved to the root, refused `MVK_NO_WILDCARD`. So the binding condition is the enclosing iteration for both constructs and [`SPEC-2026-09-03-06`](A12-DMKITS-SPEC-SYNC-LEDGER.md#spec-2026-09-03-06)'s correction generalizes past `$`; [`spec/07`](../spec/07-repetition-and-iteration.md) §3 carries it. The rule host is measured here too and closes the seam's other half.
- `remaining`: on the **rule** host the operand is admitted when the error field lies inside the named group and refused `MVK_NO_WILDCARD` from a rule placed above it, each placement's plain-condition control being admitted so the operand alone is isolated. A **nonrepeatable** group is admitted at its own locus with a constant index, separating the binding account from a repeatability one that every other row satisfies equally ([checkpoint](sources/having-filter-probes.md#src-currentrepetition-host-iteration)). Left on this seam: a two-level host binding only an outer level.
- `remaining`: the filter-under-a-non-iterating-host row is the seam's sharper finding. An operand's **star** is a binding source in its own right for an *unmarked* reference, so that shape is admitted, while the marked form still needs the host. That demotes this seam's earlier pair precondition to a consequence of two simpler rules and corrects a peer catalog line, `accepted` as [`SPEC-2026-09-04-03`](A12-DMKITS-SPEC-SYNC-LEDGER.md#spec-2026-09-04-03) with the catalog line widened and a CI claim probe now guarding it.
- `remaining`: the seam's **runtime** half is closed by the 2026-09-04 letter ([reconciliation](sources/computation-placement-and-constant-probes.md#src-2026-09-05-reconciliation)) rather than still open: such a rule reports **once**, at its own error field, so the operand's star binds the filter and not the rule. [`spec/07`](../spec/07-repetition-and-iteration.md) §3 carries it. The row is worth reading for its instrument point — a message *count* cannot separate a once-firing rule from a per-row rule deduplicated later, so the error pointer of each fired message is the observation.
- `remaining`: the **two-level** host is measured and the sources compose: candidate carries the reopened level and inherits the bound one, captured carries the bound one alone, so the marker decides only on a reopened level and both spellings are admitted on a bound-but-not-reopened one — the redundant-marker rule holding for a repetition reference ([checkpoint](sources/having-filter-probes.md#src-currentrepetition-host-iteration)). The round also separated the filter's **scope gate** from binding: an outer-only condition draws `MVK_NO_ITERATION_FOR_WILDCARD` rather than a binding verdict, so every binding row needs the in-scope conjunct.
- `remaining`: left on this seam — whether any construct other than `$` reads the captured environment the same way.
- `discriminator`: a candidate-environment claim must be separated from a host-environment one by holding the level fixed and varying only the marker, and a binding claim from a repeatability one by a nonrepeatable group at its own locus. A row that varies both establishes neither.
- `consumer`: a normalizing or rewriting consumer needs this to know when the marker is erasable — it is not, on a reopened level, where adding or dropping it changes which rows are kept or whether the model is legal at all.
- `forbidden`: do not fold the two sources into one availability list, and do not re-derive the self-exclusion pair's requirement as a rule of its own; it is a consequence of the two.
- `route-state`: discovery-required

### SG15 — bare-constant target families

- `state`: open
- `missing`: one bare authored constant per declared kind reaching a repeatable target, with that kind's admission rule, its stored rendering, and its target-check timing each measured rather than carried across a kind boundary.
- `baseline`: [`repeatable-computations.md`](IMPLEMENTATION-MAP.md#11--calculations-and-formal-checking) owns the landed carriers; [SG4](#sg4--computation-scheduling-and-state-transition) keeps scheduling, poison, and clearing, while [SG16](#sg16--computation-result-projection-and-application) owns result projection and application.
- `unblocked`: **a constant computation's repeatable target is admitted by the Kernel**, at every declaring-group choice, and only a star inside a precondition refuses — with the wildcard class rather than a placement one ([checkpoint](sources/static-admission-and-class-probes.md#src-constant-computation-admits-a-repeatable-target)). A constant reads nothing, so no iteration is derived and the placement rule that governs operand-reading computations has nothing to bind.
- `remaining`: the **result domain**, which is what still refuses it here. `executeResult` produces one `(target.id, value)` pair while a repeatable target writes one cell per instantiated row, so the change is a per-row result rather than dropping the `targetFixed` certificate. Refusing meanwhile is the deliberate direction: a wrong extent on a right value is the silent failure, and the refusal is the loud one.
- `remaining`: the **wrong-kind refusal now carries its measured class** on all six carriers, through one shared ladder over the (constant family, target kind) pair ([checkpoint](sources/static-admission-and-class-probes.md#src-constant-assignment-diagnostic-ladder)). What stays open on that axis is representation, not diagnosis: the repeatable String carrier refuses an **Enumeration** target outright where the Kernel admits a declared stored token, and refuses a **raw** String target the Kernel's kind gate does not object to at all. Both are stated boundaries the ladder projects `none` for, not unmeasured declines. A **CUSTOM** target is outside the measured grid and is the one rung the ladder does not claim.
- `measured`: the runtime extent is **exactly the instantiated rows**, with an in-capacity stored value overwritten ([checkpoint](sources/group-list-and-capacity-probes.md#src-repeatable-computation-row-extent)). `computationRowOutcomes` walks `actualRowEnvironments`, which is that list, so the clause was already right and the assumption is discharged rather than a clause changed.
- `remaining`: four sibling carriers — Boolean, String, Custom and temporal first-filled — ship the identical `targetFixed` restriction, and it is now **measured to be an over-refusal**. The Kernel admits a starred-source first-filled computation into a repeatable target on String, Boolean, temporal and Number alike, in the source's own group and in a different repeatable group, from the default declaring group and from the root ([checkpoint](sources/static-admission-and-class-probes.md#src-first-filled-admits-a-repeatable-target)). Custom stays inferred rather than measured, the fixture declaring no custom type.
- `measured`: the starred-source carrier's **extent agrees with the constant's** ([checkpoint](sources/group-list-and-capacity-probes.md#src-repeatable-computation-row-extent)'s `second-carrier` row), but its **over-limit clear is not measured** — the seeded pair settling that arm ran only the constant target, so it rests on the target-inventory assumption ([`LF158`](LEAN-FINDINGS.md#lf158--a-negative-existential-needs-the-surfaces-arms-named-before-it-is-asserted)).
- `remaining`: what remains before lifting that restriction is therefore **neither admission nor extent but the result domain** — `executeResult`'s single `(target.id, value)` pair, named above. That is a Lean change, not a measurement; do not lift the certificate on the admission row alone, since the starred clear stays a carrier crossing rather than an inheritance.
- `remaining`: **target handling does not reduce to one timing.** String applies its target policy at runtime; Number splits its grounds across authoring and runtime; Date applies component-family and Base-Year admission before its measured runtime pre-1900 branch; the bounded Time carrier accepts every admitted clock; ENUM checks the constant's value statically. No account may be read across a kind or carrier boundary.
- `remaining`: the **yearless constant is unrepresentable** here, which makes the Base Year rule's symmetry half-implemented. `DateParts.year` is an `Int` rather than an option, so `CivilDate` always carries a year and `CheckedOmittedComponentDateTarget` states the Base Year requirement on the *target alone* — sound for every existing carrier, since each supplies a year-bearing constant, and over-refusing for a carrier that gains the yearless literal the Kernel admits ([checkpoint](sources/computation-placement-and-constant-probes.md#src-temporal-format-gate-not-component-sets)). Treat it as a constraint on the next family: whichever carrier represents a yearless constant must move the requirement onto the constant/target pair in the same change.
- `remaining`: that next family now has its **anchor rule measured in advance**, so it need not rediscover it ([checkpoint](sources/computation-placement-and-constant-probes.md#src-yearless-anchor-is-the-base-year)). The anchor a yearless value resolves against is the model's **Base Year**, measured in both directions, and it reaches a stored yearless field as well as a constant — so the carrier must thread `FlatModel.baseYear` into yearless arithmetic rather than pick a constant. With **no** Base Year the anchor is a default leap year, so the carrier owes the unconfigured case a total answer rather than a refusal.
- `remaining`: the same round pins the yearless literal's **validity** bound, and it is not the one the stored value uses. The literal's calendar check is evaluated in a **common** year and consults no Base Year, so `29.02.` must be refused at classification even under Base Year 2024, while the stored yearless value takes the month's greatest possible day and admits `02-29`. The two must not share one predicate. This is the subtle one: collapsing them lets a model name a day its own arithmetic then places differently.
- `remaining`: **DATE is measured and implemented**, and [`cap-repeatable-date-constant-computation`](implementation/repeatable-computations.md#cap-repeatable-date-constant-computation) owns its coverage. The target's exact format is a rendering, not a spelling-equality gate, while component-family and Base-Year admission still apply and the measured opt-in pre-1900 branch runs at runtime. Component-omitting rendering is closed across all seven formats; the implementation record keeps every unmeasured target-policy and carrier axis explicit rather than implying wider external closure.
- `remaining`: **the widening prerequisite this record named is now satisfied** ([checkpoint](sources/computation-placement-and-constant-probes.md#src-computed-temporal-target-reads-the-format-not-the-kind)). The cross-kind cell is measured for **both** computed families and they agree: a computed `Time(...)` is admitted into a DATE-declared field whose format is `HH:mm:ss` and refused into a DATE-declared `dd.MM.yyyy` one, while a computed `Date(...)` is admitted into a TIME-declared `dd.MM.yyyy` field and refused into both clock-formatted targets. Same kind with different formats flips the verdict; same format with different kinds does not.
- `remaining`: so the declared **format string** is the whole gate for a computed temporal target, compared as a whole rather than by fragment — a `DATETIME` target containing the clock pattern is still refused.
- `remaining`: the **DateTime** certificate is now split and widened like its two siblings, and the carrier with the rows takes the format-keyed one. Its cross-kind store was the missing half and is measured — a DATE declared with the DateTime format stores `2024-03-05T12:30:00`, a DATETIME declared `yyyy-MM-dd` stores `2024-03-05`, each against an aligned control ([checkpoint](sources/computation-placement-and-constant-probes.md#src-datetime-carrier-stores-by-its-format)).
- `remaining`: what is still narrowed is narrowed by **carrier count**, not by missing evidence: `CheckedTimeTarget`, `CheckedFullDateTarget`, `CheckedDateTimeTarget`, and the omitted-component Date target remain the kind-keyed versions for every family without a cross-kind row — the shift, first-filled, world-time, and addressed ones. Each keeps an honest exclusion claiming no Kernel class, and one measurement batch could close them together.
- `remaining`: the three bare-constant carriers — Time, Date, DateTime — are no longer narrower than the Kernel at this gate; all three read the declared format, with both admission and store measured for each.
- `remaining`: **ENUM is the exception worth its own carrier decision.** Its target constrains the constant's *value* statically — an undeclared literal is refused `MVK_INVALID_STRING_CONSTANT_FOR_ENUM_COMPARISON` — so its carrier must enforce declaration membership at elaboration rather than delegate that check to a renderer.
- `remaining`: **ENUM was already implemented** and the audit found it so — [`cap-enumeration-result-and-application`](implementation/strings-and-enumerations.md#cap-enumeration-result-and-application) owns it, membership gate included. The rows added only its refusal's Kernel identity.
- `remaining`: **DATE_FRAGMENT is closed by the Date carrier rather than by a carrier of its own.** The Kernel decides this shape from the declared format string alone, so a `yyyy-MM` DATE and a `yyyy-MM` DATE_FRAGMENT take the same constant and store the same text; the [Date carrier](implementation/repeatable-computations.md#cap-repeatable-date-constant-computation) now admits all three year-leading component-omitting formats and needs no second owner.

- `remaining`: **DATETIME storage and its spring-forward gap branch are measured and implemented**, and [`cap-repeatable-datetime-constant-computation`](implementation/repeatable-computations.md#cap-repeatable-datetime-constant-computation) owns the coverage. The ordinary `"05.03.2024T12:30:00"` literal stores `2024-03-05T12:30:00` per row. The exact same Berlin-model bytes pass static checking under a UTC JVM default and fail the gap computation under a Berlin JVM default; once admitted under UTC, the Berlin model produces no gap outcome and one addressed `berechnungsWertFehler` residual per row ([checkpoint](sources/computation-placement-and-constant-probes.md#src-datetime-constant-zone-split)). Those axes stay explicit rather than inheriting from the measured complete-DATETIME two-row route.

An earlier reading of the refused range row as evidence that *something* classified there is withdrawn: `MVK_INVALID_COMPARE_TO_DATE_RANGE` is the declared-component-set mismatch, which this project's own [DateRange fragment control](sources/date-range-construction.md#src-date-range-fragment-first-filled) draws with no literal in the condition, and the peer measured that an unclassifiable `"HELLO"` draws the same code as a well-formed literal of the wrong family — so a refusal code carries no information about what reached it.
