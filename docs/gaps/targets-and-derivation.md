# Target and derivation gaps

Bare-constant target families, mandatory-information derivation, and the refusal-class denominator this project shares with its peer.

One family shard of the open-gap index. [`SEMANTICS-GAPS.md`](../SEMANTICS-GAPS.md) is the hub and owns selection, the query contract, and the hard-frontier order; this file owns the detailed obligations below. The record contract is unchanged: current missing behaviour, prerequisites, discriminators, consumer consequences, evidence needs, route state, and reopening triggers only.

### SG15 — bare-constant target families

- `state`: open
- `missing`: one bare authored constant per declared kind reaching a repeatable target, with that kind's admission rule, its stored rendering, and its target-check timing each measured rather than carried across a kind boundary.
- `baseline`: [`repeatable-computations.md`](../IMPLEMENTATION-MAP.md#11--calculations-and-formal-checking) owns the landed carriers; [SG4](keystone.md#sg4--computation-scheduling-and-state-transition) keeps scheduling, poison, and clearing, while [SG16](keystone.md#sg16--computation-result-projection-and-application) owns result projection and application.
- `unblocked`: **a constant computation's repeatable target is admitted by the Kernel**, at every declaring-group choice, and only a star inside a precondition refuses — with the wildcard class rather than a placement one ([checkpoint](../sources/static-admission-and-class-probes.md#src-constant-computation-admits-a-repeatable-target)). A constant reads nothing, so no iteration is derived and the placement rule that governs operand-reading computations has nothing to bind.
- `remaining`: the **result domain**, which is what still refuses it here. `executeResult` produces one `(target.id, value)` pair while a repeatable target writes one cell per instantiated row, so the change is a per-row result rather than dropping the `targetFixed` certificate. Refusing meanwhile is the deliberate direction: a wrong extent on a right value is the silent failure, and the refusal is the loud one.
- `remaining`: the **wrong-kind refusal now carries its measured class** on all six carriers, through one shared ladder over the (constant family, target kind) pair ([checkpoint](../sources/static-admission-and-class-probes.md#src-constant-assignment-diagnostic-ladder)). What stays open on that axis: the repeatable String carrier refuses an **Enumeration** target outright where the Kernel admits a declared stored token, and it, the String first-filled carriers and the addressed `FieldValueAsString` carrier refuse a **raw** String target without a class. The Kernel refuses a raw target by the generated comparison's read of it, `MVK_INVALID_RAW_TYPE`, measured with a String field copied into a nonrepeatable target ([inbound](../SOURCES.md#inbound-2026-09-26c-target-read)), but this carrier's error does not separate a raw target from a custom one. A **CUSTOM** target is outside the measured grid and is the one rung the ladder does not claim.
- `remaining`: a **field source** of another kind than its target is refused by the same generated comparison on every kind pair measured, a Number into an Enumeration included, while at an Enumeration target a String source draws the comparison class when the target is labelled and the calculation's own class otherwise ([inbound](../SOURCES.md#inbound-2026-09-26e-labelled-target)), and Lean's String and Number expression computations refuse it without a class, their field-kind refusals carrying no diagnostic arm ([inbound](../SOURCES.md#inbound-2026-09-26c-joined-comparison)). The ladder is not the pair function to reuse: a Boolean field into a String draws `MVK_INVALID_COMPARE_TO_YESNO` and one into a Confirm `MVK_INVALID_COMPARE_TO_YES`, where a Boolean constant draws the text class and `True` is admitted. The nonrepeatable String computation projects only the raw target's read class, a literal source taking it by assumption.
- `remaining`: a computation's members are judged as one joined text, the parse class first in that order answering ([inbound](../SOURCES.md#inbound-2026-09-26c-target-read)). Lean's Number and String tables assemble already-checked operations beside preconditions checked without a class, so no class is ordered across members, and a partially known Date or raw String *source* into a Number, which draws its read class rather than a comparison class, projects none.
- `measured`: the runtime extent is **exactly the instantiated rows**, with an in-capacity stored value overwritten ([checkpoint](../sources/group-list-and-capacity-probes.md#src-repeatable-computation-row-extent)). `computationRowOutcomes` walks `actualRowEnvironments`, which is that list, so the clause was already right and the assumption is discharged rather than a clause changed.
- `remaining`: four sibling carriers — Boolean, String, Custom and temporal first-filled — ship the identical `targetFixed` restriction, and it is now **measured to be an over-refusal**. The Kernel admits a starred-source first-filled computation into a repeatable target on String, Boolean, temporal and Number alike, in the source's own group and in a different repeatable group, from the default declaring group and from the root ([checkpoint](../sources/static-admission-and-class-probes.md#src-first-filled-admits-a-repeatable-target)). Custom stays inferred rather than measured, the fixture declaring no custom type.
- `measured`: the starred-source carrier's **extent agrees with the constant's** ([checkpoint](../sources/group-list-and-capacity-probes.md#src-repeatable-computation-row-extent)'s `second-carrier` row), but its **over-limit clear is not measured** — the seeded pair settling that arm ran only the constant target, so it rests on the target-inventory assumption ([`LF158`](../LEAN-FINDINGS.md#lf158--a-negative-existential-needs-the-surfaces-arms-named-before-it-is-asserted-a-simple-paths-help-is-not-the-surface)).
- `remaining`: what remains before lifting that restriction is therefore **neither admission nor extent but the result domain** — `executeResult`'s single `(target.id, value)` pair, named above. That is a Lean change, not a measurement; do not lift the certificate on the admission row alone, since the starred clear stays a carrier crossing rather than an inheritance.
- `remaining`: **target handling does not reduce to one timing.** String applies its target policy at runtime; Number splits its grounds across authoring and runtime; Date applies component-family and Base-Year admission before its measured runtime pre-1900 branch; the bounded Time carrier accepts every admitted clock; ENUM checks the constant's value statically. No account may be read across a kind or carrier boundary.
- `remaining`: the **yearless constant is unrepresentable** here, which makes the Base Year rule's symmetry half-implemented. `DateParts.year` is an `Int` rather than an option, so `CivilDate` always carries a year and `CheckedOmittedComponentDateTarget` states the Base Year requirement on the *target alone* — sound for every existing carrier, since each supplies a year-bearing constant, and over-refusing for a carrier that gains the yearless literal the Kernel admits ([checkpoint](../sources/temporal-constant-and-base-year-probes.md#src-temporal-format-gate-not-component-sets)). Treat it as a constraint on the next family: whichever carrier represents a yearless constant must move the requirement onto the constant/target pair in the same change.
- `remaining`: that next family now has its **anchor rule measured in advance**, so it need not rediscover it ([checkpoint](../sources/temporal-constant-and-base-year-probes.md#src-yearless-anchor-is-the-base-year)). The anchor a yearless value resolves against is the model's **Base Year**, measured in both directions, and it reaches a stored yearless field as well as a constant — so the carrier must thread `FlatModel.baseYear` into yearless arithmetic rather than pick a constant. With **no** Base Year the anchor is a default leap year, so the carrier owes the unconfigured case a total answer rather than a refusal.
- `remaining`: the same round pins the yearless literal's **validity** bound, and it is not the one the stored value uses. The literal's calendar check is evaluated in a **common** year and consults no Base Year, so `29.02.` must be refused at classification even under Base Year 2024, while the stored yearless value takes the month's greatest possible day and admits `02-29`. The two must not share one predicate. This is the subtle one: collapsing them lets a model name a day its own arithmetic then places differently.
- `remaining`: **DATE is measured and implemented**, and [`cap-repeatable-date-constant-computation`](../implementation/repeatable-computations.md#cap-repeatable-date-constant-computation) owns its coverage. The target's exact format is a rendering, not a spelling-equality gate, while component-family and Base-Year admission still apply and the measured opt-in pre-1900 branch runs at runtime. Component-omitting rendering is closed across all seven formats; the implementation record keeps every unmeasured target-policy and carrier axis explicit rather than implying wider external closure.
- `remaining`: **the widening prerequisite this record named is now satisfied** ([checkpoint](../sources/computation-placement-and-constant-probes.md#src-computed-temporal-target-reads-the-format-not-the-kind)). The cross-kind cell is measured for **both** computed families and they agree: a computed `Time(...)` is admitted into a DATE-declared field whose format is `HH:mm:ss` and refused into a DATE-declared `dd.MM.yyyy` one, while a computed `Date(...)` is admitted into a TIME-declared `dd.MM.yyyy` field and refused into both clock-formatted targets. Same kind with different formats flips the verdict; same format with different kinds does not.
- `remaining`: so the declared **format string** is the whole gate for a computed temporal target, compared as a whole rather than by fragment — a `DATETIME` target containing the clock pattern is still refused.
- `remaining`: the **DateTime** certificate is now split and widened like its two siblings, and the carrier with the rows takes the format-keyed one. Its cross-kind store was the missing half and is measured — a DATE declared with the DateTime format stores `2024-03-05T12:30:00`, a DATETIME declared `yyyy-MM-dd` stores `2024-03-05`, each against an aligned control ([checkpoint](../sources/computation-placement-and-constant-probes.md#src-datetime-carrier-stores-by-its-format)).
- `remaining`: what is still narrowed is narrowed by **carrier count**, not by missing evidence: `CheckedTimeTarget`, `CheckedFullDateTarget`, `CheckedDateTimeTarget`, and the omitted-component Date target remain the kind-keyed versions for every family without a cross-kind row — the shift, first-filled, world-time, and addressed ones. Each keeps an honest exclusion claiming no Kernel class, and one measurement batch could close them together.
- `remaining`: the three bare-constant carriers — Time, Date, DateTime — are no longer narrower than the Kernel at this gate; all three read the declared format, with both admission and store measured for each.
- `remaining`: **ENUM is the exception worth its own carrier decision.** Its target constrains the constant's *value* statically — an undeclared literal is refused `MVK_INVALID_STRING_CONSTANT_FOR_ENUM_COMPARISON` — so its carrier must enforce declaration membership at elaboration rather than delegate that check to a renderer.
- `remaining`: **ENUM was already implemented** and the audit found it so — [`cap-enumeration-result-and-application`](../implementation/strings-and-enumerations.md#cap-enumeration-result-and-application) owns it, membership gate included. The rows added only its refusal's Kernel identity.
- `remaining`: **DATE_FRAGMENT is closed by the Date carrier rather than by a carrier of its own.** The Kernel decides this shape from the declared format string alone, so a `yyyy-MM` DATE and a `yyyy-MM` DATE_FRAGMENT take the same constant and store the same text; the [Date carrier](../implementation/repeatable-computations.md#cap-repeatable-date-constant-computation) now admits all three year-leading component-omitting formats and needs no second owner.

- `remaining`: **DATETIME storage and its spring-forward gap branch are measured and implemented**, and [`cap-repeatable-datetime-constant-computation`](../implementation/repeatable-computations.md#cap-repeatable-datetime-constant-computation) owns the coverage. The ordinary `"05.03.2024T12:30:00"` literal stores `2024-03-05T12:30:00` per row. The exact same Berlin-model bytes pass static checking under a UTC JVM default and fail the gap computation under a Berlin JVM default; once admitted under UTC, the Berlin model produces no gap outcome and one addressed `berechnungsWertFehler` residual per row ([checkpoint](../sources/temporal-constant-and-base-year-probes.md#src-datetime-constant-zone-split)). This corrects the former local claim that a bare wall label bypasses the model zone.
- `remaining`: open on that carrier: a non-DATETIME declaration carrying a DateTime format, another DateTime format, an overlap label, unresolved over-capacity interaction, a seed or precondition, result application, and generated localized message payload. Those axes stay explicit rather than inheriting from the measured complete-DATETIME two-row route.
- `remaining`: **DATERANGE stays unwitnessed**, now an absence over six spellings against a `(dd.MM.yyyy, -)` target, measured by a12-dmkits — a missing witness, not a proof. An earlier reading of the refused range row as evidence that *something* classified there is withdrawn: `MVK_INVALID_COMPARE_TO_DATE_RANGE` is the declared-component-set mismatch, which this project's own [DateRange fragment control](../sources/date-range-construction.md#src-date-range-fragment-first-filled) draws with no literal in the condition, and the peer measured that an unclassifiable `"HELLO"` draws the same code as a well-formed literal of the wrong family — so a refusal code carries no information about what reached it.

### SG28 — refusal-class reachability and the shared denominator

- `state`: open
- `owner`: this project's conformance denominator, reported by [`CONFORMANCE-COVERAGE.md`](../CONFORMANCE-COVERAGE.md); the peer's equivalent is a12-dmkits `docs/MVK-LEDGER.md`, whose bucket vocabulary (`erased`, `n/a-structural`, `kernel-delegated`, `pre-checked`, `pending`, `unclassified`) already names this distinction.
- `closed`: the code-generation catalog's carrier ([checkpoint](../sources/diagnostic-class-vocabulary-and-sweeps.md#src-codegen-classes-reach-ordinary-authoring)) and the fifteen keys no Kernel path reports ([checkpoint](../sources/diagnostic-class-vocabulary-and-sweeps.md#src-unraised-diagnostic-vocabulary), [owner](../IMPLEMENTATION-MAP.md#cap-unraised-diagnostic-keys)). Both stay in the denominator as modelled rather than leaving it, because a consumer enumerating the catalogs still meets them.
- `missing`: a per-class reachability verdict with a citation, separating two categories this project conflated once already and must not conflate again. **Structurally unreachable** means no A12 model can produce it — dead Kernel code with zero emitters, a feature with no DM-JSON representation, an H-model-only construct. **Instrument-limited** means the Kernel computes the diagnostic and the tooling discards or cannot author it, which a tool change fixes. Only the first kind may leave the denominator.
- `closed`: the codegen-enum reconciliation, in this project's favour. a12-dmkits re-measured it and their scope note was the wrong one: `NoMetaModelChecks` exposes a single `check()` entry point raising all 26 `NoMetaModelCheckErrorType` classes, and `checkConsistency` opens that door — an unparseable `modelConfig.timeZone` draws `MVK_INVALID_TIME_ZONE` from `checkConsistency` with a within-model admitted control ([inbound](../SOURCES.md#inbound-2026-09-21-corrections)). One reachable class settles the tier because the question was the entry point, never the individual class. The whole enum therefore stays in this denominator.
- `missing`: **a fourth refusal tier this denominator does not distinguish** ([inbound](../SOURCES.md#inbound-2026-09-21-corrections)). A12 refuses in four observable tiers and this project's classification separates only the last. The reader refuses the bytes, so nothing was examined. `checkConsistency` throws and the model is never built, so nothing was judged. `checkConsistency` reports a notification carrying **no class key**, so the declaration *was* judged and A12 names no class for it. Or it reports one carrying an `MVK_*` or unprefixed key.
- `missing`: the consequence of that tier split. The middle two are different claims, and conflating them turns a real verdict about a declaration into "A12 said nothing" — the peer moved eighteen recorded rows across seven law classes on exactly that confusion. A codeless verdict is reportable, but a consumer may not attribute one of A12's classes to it. A JSON container in a string-bound member makes the model unreadable on every carrier, which is the first tier rather than a refusal class.
- `closed`: **the variant filter, and this project's rows were never conditioned by it.** A `dmtool`-authored model carries no `variantFilter` member at all, and the kernel serializers write it only when present, so every admission and refusal row this denominator rests on is unconditioned ([checkpoint](../sources/static-admission-and-class-probes.md#src-variant-filter-declaration-omission)). The mechanism itself is now a clause ([`01-data-model.md` §3](../../spec/01-data-model.md#3-rules-and-computations)): at the default variant the filter *type* alone decides, a rejected rule or computation is absent and so reports clean however broken it is, and a rejected field is absent and so breaks every surviving reference to it. The peer owns the fuller matrix and measured it first; these rows reproduce the two carriers on this project's pinned instrument.
- `remaining`: no Lean carrier represents a variant filter, deliberately. `FlatModel` has no variant concept, and giving it one is a core-type change with no current consumer; the clause states the law for a reimplementer, and this project's own models never carry the member. Select it only when a named consumer needs a filtered declaration represented — an importer reading a real customer model is the likeliest first.
- `missing`: a verdict for the six in-denominator classes the Kernel's analyst documentation marks H-model-only, four of which have raising sites outside any H-model-scoped package — so that marker alone does not establish that an A12 model cannot reach them. Each needs a guard reading in its emitter or one authoring probe.
- `missing`: **declaration-level laws with no home in `spec/` at all**, each measured by the peer and each a refusal class in this denominator ([inbound](../SOURCES.md#inbound-2026-09-21-corrections)). They are listed together because they share a carrier axis rather than a semantic family, and because several of the laws beside them were measured **unreachable**, which is this gap's own subject.
- `missing`: the String type's `hintList` and its four value laws, three of them live. `rg -n hintList spec docs` returns 0.
- `missing`: a group's **sort list**, which needs a repeatable carrier, and its own two verdicts beside the group's two ordering members.
- `closed`: a group's **repetition cap**, carrier-dependent, and A12's reservation of the single whole name `Id` on the root carrier alone. Both are stated in [`spec/01` §1](../../spec/01-data-model.md#1-model--a-typed-tree), enforced by `FlatModel.validate`, and locked at their boundary rows ([owner](../implementation/data-and-core.md#cap-model-declaration-legality), [inbound](../sources/inbound-group-operand-batches.md#src-group-declaration-admission-peer-measurement)). Consumed from the peer's measurement; this project ran no probe of its own and claims none.
- `missing`: the `fieldType` vocabulary of thirteen names, and which five of them tolerate a missing body.
- `discriminator`: for any class proposed as structurally unreachable, the settling question is whether a Kernel emitter exists at all and whether the shape it tests has a DM-JSON encoding. A source grep answering the first is cheap; the second needs the serializer's own property set, not the API's.
- `discriminator`: that analyst documentation classifies 103 classes into four buckets, 64 of them in this denominator, but only its H-model and extension-product buckets are scope statements. The other two mark a class undocumented or unclear **for business analysts**, and two classes sitting in them have live emitters — so it is a prioritisation signal and a corroborating second reading, never a denominator argument on its own.
- `prerequisite`: none for the classification itself. The instrument-limited classes need the upstream capability described in the 2026-09-07 instrument note.
- `route-state`: probe-ready — every candidate is settled by a source grep plus, where a shape exists, one authoring probe.
