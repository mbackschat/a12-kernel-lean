# Keystone construction gaps

The high-connectivity mechanisms whose shape constrains everything built on them: computation scheduling and state transition, the addressed computation families' calibration, and result projection into a document.

One family shard of the open-gap index. [`SEMANTICS-GAPS.md`](../SEMANTICS-GAPS.md) is the hub and owns selection, the query contract, and the hard-frontier order; this file owns the detailed obligations below. The record contract is unchanged: current missing behaviour, prerequisites, discriminators, consumer consequences, evidence needs, route state, and reopening triggers only.

### SG4 — computation scheduling and state transition

- `state`: open
- `missing`: compose authored tables, dependency order, poison and clearing, and repeatable-target scheduling without collapsing checked definition, transient state, or dependency outcomes.
- `baseline`: [§11](../IMPLEMENTATION-MAP.md#11--calculations-and-formal-checking) owns the bounded fixed and repeatable planning, execution, and transition families. [`ARCHITECTURE.md`](../ARCHITECTURE.md#whole-model-computation-execution-keeps-definition-activation-result-application-and-validation-separate) owns the required phase separation.
- `remaining`: nonrepeatable authored planning **beyond three targets is measured**, on a four-deep diamond — one producer, two independent dependents, one join — whose clean row refutes both a join-before-branches and a branches-before-producer order at once ([checkpoint](../sources/evaluation-and-application-routes.md#src-diamond-dependency-clear-kinds)). The same round settled the seam this gap's own discriminator names: a producer cleared by an **unmet precondition** reads EMPTY and its dependent computes, while one cleared by a **malformed source** poisons its dependent, and poison then crosses the join rather than being substituted away ([`SPEC-2026-09-03-09`](../A12-DMKITS-SPEC-SYNC-LEDGER.md#spec-2026-09-03-09)). One failing branch never aborts the plan. Still open here: a join whose branches poison from different producers, arity above two, and non-Number join families.
- `remaining`: the **repeatable crossing is measured**: the same diamond inside a repeatable group keeps all three producer states apart within **one call**, each confined to its own row, which refutes plan-level scheduling directly ([checkpoint](../sources/evaluation-and-application-routes.md#src-repeatable-diamond-per-row-states)). Left open on that axis: two repetition levels, branches sitting at different levels, a join reading across rows, and a repeatable diamond under an over-limit row.
- `remaining`: this gap's `forbidden` rule against deltas as the dependency overlay now has an **external witness** rather than only a design argument. `NumericDelta` collapses clean no-result, domain invalidity, and inherited poison into one `.cleared`, and the measured dependents refuse exactly that collapse; `dependencyObservation` is the correct overlay and every arm of it is already asserted in [`Conformance/NumericDependency.lean`](../../A12Kernel/Conformance/NumericDependency.lean).
- `remaining`: **route limit, not a semantic gap.** The probe artifact's per-outcome `cleared`/`errored` flags collapse the two clear-kinds — both read cleared-and-not-errored, and the precondition case reports nothing in `formalErrorsInOperands` — so the only channel separating them is the dependents' own outcomes. That is instrument feedback for a12-dmkits rather than a ledger entry; [`PLAN.md`](../PLAN.md) carries it as a pending instrument request. The bounded triple's exact reverse-authored Number-to-String-to-Number value behavior is Kernel-calibrated for fresh completion, reached and unreached producer invalidity, and empty zero ([checkpoint](../SOURCES.md#src-scalar-mixed-reverse-authored-triple)). The public artifact sorts computed outcomes by field, so it carries no private execution-order observation and cannot calibrate the internally authored-stable tie-break between independent steps.
- `remaining`: cross-group fixed-target admission and execution is closed for all four constant families at the [declaring-group gate checkpoint](../SOURCES.md#src-computation-declaring-group-gate), which also fixes the containment gate and measures that a repeatable declaring group adds no repetition. A repeatable *target* declared cross-group is measured too: all four constant families compute once per instantiated target row from the root exactly as from the target's own group, isolating the target-scope disjunct that a fixed target or star operand had confounded earlier ([checkpoint](../sources/computation-placement-and-constant-probes.md#src-cross-group-repeatable-constant-target)).
- `remaining`: non-constant cross-group operations and generated-validation firing stay open here; [SG16](#sg16--computation-result-projection-and-application) owns result/application correspondence. Do not extrapolate the fixed constant target-scope mechanism to list, construction, repeatable, or generated-validation routes.

- `remaining`: the bare-constant carrier families are split out into [SG15](targets-and-derivation.md#sg15--bare-constant-target-families), which owns their per-kind admission, rendering, and target-check timing. Scheduling, dependency order, poison, and clearing stay here; [SG16](#sg16--computation-result-projection-and-application) owns result projection and application.
- `remaining`: a bare constant under a precondition is **measured**: it is admitted, writes when the precondition is met, and clears when not, its clear read as empty by the same rule as any other silent clear ([checkpoint](../sources/evaluation-and-application-routes.md#src-diamond-dependency-clear-kinds)). The same batch settled that **a clear is visible to a dependent inside the same call** — a stale stored value in the cleared target is not read, which no fresh-*value* row could have shown. That half is **implemented and locked at the shift-cascade carrier**, whose amount read returns clean empty for a plan target with no completion even when the immutable source still holds a stale value; what remains is the other cascade carriers, each of which needs its own row rather than inheriting this one.
- `remaining`: the complementary refusal is **unimplemented** and has no known witness here. An unstarred per-row operand of a repeatable declaring group must refuse a fixed target outside it, and no checked elaborator derives iteration from an operand. Treat it as a constraint on the next family, not a to-do: a family admitting such an operand must derive iteration and apply containment in the same change. The checkpoint's `separator` and `local-reach` rows own the discriminator and the survey.
- `remaining`: the three carriers are not merged and should stay separate until a fourth consumer or a concrete need argues otherwise. Their result domains differ, which is the usual reason not to, and their target checks differ in *when* they run: String checks everything at runtime, Number splits its two grounds across authoring and runtime, and Boolean/Confirm has no target check to delegate at all. A shared carrier would have to abstract over that split rather than over a common check.
- `remaining`: admission across all of them is **one shared rule**: the target's declared *format string* gates the literal's temporal family, and the field's declared kind is measured irrelevant. Within a family the format then renders and may drop components silently. A carrier for any of these kinds reuses that gate rather than restating a kind-specific one.
- `remaining`: that gate's open discriminator is **resolved**. It reads the family and the year agreement and **not** component sets: `MM` names the month alone, and the yearless literals `"05.03."` and `"13.07."` are both admitted into it with no Base Year, storing `03` ([checkpoint](../sources/computation-placement-and-constant-probes.md#src-temporal-format-gate-not-component-sets), outbound as [`SPEC-2026-09-03-08`](../A12-DMKITS-SPEC-SYNC-LEDGER.md#spec-2026-09-03-08)). The time-side mirror is unreachable rather than unrun — an hour-only `HH` format is refused at field declaration — so nothing further is pending behind it. The same round found both refusal grounds sharing one `MVK_INVALID_COMPARE_TO_DATE`, so a consumer cannot read the cause off the code.
- `remaining`: extend group containment beyond the fixed checked numeric operation and already resolved filter fields.
- `remaining`: extend selected-preliminary execution beyond the [named whole-call baseline](../IMPLEMENTATION-MAP.md#cap-selected-computation-preliminary). The scalar and special-source baseline includes isolated parallel Number, indexed DateRange construction, and a generated Number table whose selected operation may consume a prepared repeatable aggregate and continue through separate-destination application plus explicit later validation.
- `remaining`: concrete reachability and Kernel scheduling correspondence for structural-failure arms that currently have only conditional internal laws. The one route found so far was a defect and is closed; the [over-limit target checkpoint](../sources/group-list-and-capacity-probes.md#src-over-limit-computation-target) owns why every repeatable-target carrier now shares one excluding row domain.
- `remaining`: the over-limit target exclusion is measured and level-independent across four carriers, the indexed-parallel one on its own mechanism rather than by assumption ([`SPEC-2026-08-31-08`](../A12-DMKITS-SPEC-SYNC-LEDGER.md#spec-2026-08-31-08)). Because that mechanism differed from what the assumption predicted, construction, shift, and enumeration keep theirs **unlifted** — that is the open item.
- `remaining`: the computation's over-repetition channel is modeled and covered ([capability](../IMPLEMENTATION-MAP.md#cap-computation-over-repetition-channel)). Three items stay open: a path list for an *arbitrary* checked computation expression, whose field operands would each contribute their declaring group — the group-count supply is settled, `CheckedGroupCountOperand.groupPath`; the operand-error text and address spelling; and this project's own measurement of the *upward* half, which rests on the [peer's reproduction](../sources/inbound-group-operand-batches.md#src-starred-field-operand-peer-reproduction) rather than on retained bytes here.
- `remaining`: retain a `NumericComputationRunFault.targetCheck` witness only if one appears. Every authorable candidate is now measured and refused: `SumOfProducts` and the infix `*`, `/`, and `^` all draw `MVK_INVALID_COMPARE_DEC_PLACES` into a narrower target unless suppressed, and suppression routes to `checkWithScaleWarningSuppressed` instead of this arm. The [assignment-scale reach checkpoint](../SOURCES.md#src-unsuppressed-assignment-scale-reach) owns the measurement and states what would still defeat it.
- `evidence-needed`: one coherent separating batch for each selected wider composition family, preserving fresh versus stale reads, unreached versus reached poison, empty substitution, exact row identity, and retained action placement.
- `discriminator`: dependency edges order eligible target methods but do not pre-skip a dependent after failure. Invalidity propagates only through a reached read, which short-circuiting can hide.
- `consumer`: Execute, Compile, Analyze, and Explain must distinguish checked definition, transient activation, cause-blind dependency invalidity, and rich family outcomes.
- `forbidden`: do not use deltas, applied state, or public result collections as the dependency overlay. Do not introduce a generic graph, state machine, cross-family trace framework, or registry.
- `entry-gate`: the bounded carriers listed in [§11](../IMPLEMENTATION-MAP.md#11--calculations-and-formal-checking) satisfy the local entry gate. Reopen only one selected remaining family with a verified route.
- `completion-gate`: an executable checked scheduler is deterministic for fixed checked inputs and sound against an independently meaningful relation where one is justified.
- `route-state`: discovery-required

### SG18 — addressed computation family calibration

- `state`: open
- `missing`: each landed addressed computation family needs its own Kernel calibration across the format, zone, source-shape, and target-policy axes its carrier actually admits. Split out of [SG4](#sg4--computation-scheduling-and-state-transition), which owns scheduling, dependency order, poison, and clearing; the exact baselines below are inventory of what is already implemented and executable, not of what is externally confirmed.
- `baseline`: [`computations.md`](../implementation/computations.md) and [`repeatable-computations.md`](../implementation/repeatable-computations.md) own the landed carriers, their coverage, and their per-axis evidence status. [SG12](conformance-evidence.md#sg12--retained-kernel-correspondence-coverage) owns the batching rule that decides when a family is worth a capture; [SG15](targets-and-derivation.md#sg15--bare-constant-target-families) owns bare-constant admission and rendering; [SG16](#sg16--computation-result-projection-and-application) owns result projection and application.
- `remaining`: serial computed-source Enumeration chains beyond the exact four-computation `CurrentRepetition` Number-to-String-to-Number-to-filtered-Enumeration chain.
- `remaining`: computed-source forms beyond the exact Enumeration-to-`FieldValueAsNumber`-to-filtered-Enumeration and `CurrentRepetition` alternating-to-filtered-Enumeration chains, and filter producers beyond the existing addressed Number-result union. A third fixed sibling producer is duplicate overlay width over the already arbitrary completed-result list and is not a semantic work item.
- `remaining`: addressed DateFragment Kernel calibration and copy-versus-render discrimination; wider-profile and cross-spelling calibration for addressed DateRange; wider format, zone, and source-shape calibration for addressed DateTime; extensible-enumeration String alternatives, nested temporal-expression extractors beyond the exact bound complete-DateTime sub-day shift, and world-backed component calibration for addressed Time construction; checked-source, cross-format, and wider-target-policy calibration for addressed FULL Date.
- `remaining`: the exact addressed same-family baseline includes multi-star Number, Boolean, ordinary String, Custom, DateFragment, FULL Date, Time, DateTime, and sibling-star DateRange `FirstFilledValue`, plus direct and multi-operand Enumeration `FirstFilledValue`.
- `remaining`: the exact addressed conversion and construction baseline includes `DateFromDateTime`, `TimeFromDateTime`, DateRange endpoint-component, `Time(...)`, and DateTime sub-day and calendar-day shifts.
- `remaining`: the exact cascade baseline includes the Number-to-DateTime producer source, three-stage Enumeration source, Enumeration-to-`FieldValueAsNumber`-to-filtered-Enumeration source, fixed `CurrentRepetition` Number-to-String-to-Number producer source, and four-stage filtered-Enumeration final fallback.
- `remaining`: render operand messages.
- `discriminator`: a family's own axis must separate copying a source value from rendering it into the target's declared form; a same-format fixture cannot tell those apart and is the shape most likely to pass under either account.
- `consumer`: Execute and Compile need each family's exact result domain and target-check timing; Translate needs the authored source shape preserved rather than normalized into a sibling family's spelling.
- `forbidden`: do not read one family's calibration across a kind, carrier, or target-policy boundary, and do not treat an implemented-and-tested baseline row as external confirmation. No per-family harness or capture generator.
- `entry-gate`: name the family, the axis, and the wrong account its separator refutes, then check whether the current upstream route emits that observation shape before requesting anything.
- `completion-gate`: every family in the baseline inventory carries either retained separating observations for its admitted axes or an explicit, located statement of which axis remains unconfirmed.
- `route-state`: discovery-required

### SG16 — computation result projection and application

- `state`: open
- `missing`: rich result projections, exact application, transport reconstruction, and later validation without collapsing public results, source-relative deltas, applied document state, or validation outcomes.
- `baseline`: [§11](../IMPLEMENTATION-MAP.md#11--calculations-and-formal-checking) owns the bounded result, application, and purpose-specific transition families. [`ARCHITECTURE.md`](../ARCHITECTURE.md#whole-model-computation-execution-keeps-definition-activation-result-application-and-validation-separate) owns the required phase separation.
- `remaining`: Repeatable target result/application carriers outside the exact implemented baseline in [§11](../IMPLEMENTATION-MAP.md#11--calculations-and-formal-checking). Select one only when it adds a behaviorally distinct target policy or runtime route rather than overlay width.
- `remaining`: **the reported result has two absence shapes and this projection has one.** The Kernel omits a computed-field entry entirely for a target row whose filtered candidate set is empty, while reporting a precondition-cleared or source-invalid producer *present* and cleared; a dependent reads both as EMPTY, so the cascade is unaffected and only the result surface is ([checkpoint](../sources/having-filter-probes.md#src-correlated-filter-string-computed-target)). The fix is a **collection-shape** decision — a row with no outcome should have no entry — and not a third `NumericTargetOutcome` state, which would ripple into every consumer of that type for a distinction none of them reads. Deliberately not opened: no current consumer is blocked on it, and this record's own rule is to select a carrier only when one is. Take it with the first Explain or Analyze task that renders per-row results.
- `remaining`: cross-group result/application correspondence beyond the exact implemented carriers.
- `remaining`: V1 String-ingress source identity for non-String computation targets outside Number. The typed checked-document route correctly uses typed equality; a future transport-facing carrier must retain whether the source V2 object is unconverted text instead of reconstructing identity from stored text or parsed value.
- `remaining`: materialized document topology beyond the exact normalized two-level repeatable Number `FirstFilledValue` target projection; later-rule execution beyond that route and the exact scalar-target generated-Number routes for direct expressions, one unfiltered repeatable sum, one correlated repeatable `FirstFilledValue`, one- and two-level ordinary direct-Number comparisons, and one-level direct-String-length comparison; transport reconstruction and pointer-dialect rendering.
- `remaining`: extend the checked multi-operation direct-field union and whole-call result projection to a behaviorally distinct family beyond the [direct-field baseline](../IMPLEMENTATION-MAP.md#cap-checked-direct-field-formal-input).
- `remaining`: Kernel result/application correspondence for repeatable bare constants, including seeded source-target classification, applied document state after target rejection, and whether a stored prior value survives. The internal same-model ordinary Number route does not discharge this carrier-specific external claim.
- `remaining`: applied document state after an indexed-parallel over-limit clear, which the compute observation does not report.
- `remaining`: retain addressed-index clearing route attribution only when an Explain consumer requires it.
- `remaining`: certify source/destination model compatibility at the result type boundary only for a consumer that cannot supply the same-model precondition.
- `evidence-needed`: one coherent separating batch for each selected result or application carrier, preserving public partitions, exact row identity, source-relative actions, clearing, and later-validation placement.
- `discriminator`: public result collection, source-relative delta, applied document state, and later validation are separate observations and cannot serve as the scheduler's dependency overlay.
- `consumer`: Execute, Transform, Analyze, and Explain must retain public results, source-relative actions, applied state, and later validation as distinct phases.
- `forbidden`: do not reconstruct source identity, private schedule order, or applied state from a public outcome collection. Do not introduce a transport schema, compatibility wrapper, or generic application framework without an adopted consumer.
- `entry-gate`: select one behaviorally distinct result or application carrier with a verified route and an adopted consumer need.
- `completion-gate`: result and application laws preserve every named public partition, and validation remains separate.
- `route-state`: discovery-required
