The previous plan here was a per-carrier measurement plus a certificate switch under a "do not widen one on another's row" rule — right as caution, wrong as economics, because it treated the carrier as a possible input without first asking whether it is one. Source says it is not, twice over: admission is `checkDateType` over the two operands' result formats, with no path to the target's declared kind, and one `VkDate` store overload reached from one emitted call site renders through the declared format ([checkpoint](../sources/computation-placement-and-constant-probes.md#src-computed-target-gate-is-carrier-invariant)).
- `closed`: the four target certificates that carried it. `CheckedTimeTarget`, `CheckedFullDateTarget`, and `CheckedDateTimeTarget` are now aliases of the measured format-keyed certificates, and `CheckedOmittedComponentDateTarget` lost its inline kind field; each family gained a cross-kind conformance grid holding every declared kind on both sides of the outcome.
- `closed`: the DateRange construction **endpoint**, which was a twelfth site of this class and an operand position rather than a target one — its refusal reports the operand code. Its own clause forbids transferring a claim between DateRange carriers, so it was measured instead of inherited: all three declared kinds admitted on `yyyy-MM-dd`, all three refused on a clock or stamp format ([checkpoint](../sources/computation-placement-and-constant-probes.md#src-daterange-endpoint-reads-the-format), outbound [`SPEC-2026-09-07-07`](../A12-DMKITS-SPEC-SYNC-LEDGER.md#spec-2026-09-07-07)).
- `closed`: the **reader** side of the target axis, which the certificate switch had left behind. Admission was widened and four sites that consume the same declaration still keyed on the kind: the Time, DateTime and complete-Date `acceptsActionKind` target acceptors refused at apply time exactly the models their own certificates admit, and `CheckedDocument.temporallyCoherent` skipped a cross-declared cell its own classifier owns. Found by applying the peer's tell for a widening — a case list carrying no read-back row ([provenance](../SOURCES.md#inbound-2026-09-07-dispositions)) — and grounded in [`SPEC-2026-09-06-09`](../A12-DMKITS-SPEC-SYNC-LEDGER.md#spec-2026-09-06-09) rather than a new measurement, since the parser follows the declared format with no fallback to the kind. The three acceptors now share one `acceptsDeclaredComponents` predicate, so the conjunct cannot be respelled by the next family.
- `remaining`: DATE_RANGE **targets** are deliberately outside this result and keep plain kind equality, because a range declaration is a `(format, separator)` pair and nothing measured here assigns across it — the peer's own exclusion, adopted rather than re-derived. The partial-precision and Base-Year target gates are also outside it: they sit before `checkDateType` and no row above moves them.
- `baseline`: [temporal comparison and aggregates](../implementation/temporal.md#cap-temporal-comparison-and-aggregates) and [number source conversions](../implementation/numeric.md#cap-number-source-conversions) own the corrected carriers; [SG6](#sg6--temporal-authoring-calendar-and-target-completion) owns the rest of temporal authoring.
- `discriminator`: every carrier in this class needs the same shape of row and nothing more — one declaration whose kind and format disagree, exercised on that carrier, beside the same carrier's ordinary same-kind control. Each kind must appear on **both** sides of both outcomes, because one direction alone reads as "that kind is permissive" and settles nothing.
- `remaining`: one cause is orthogonal to this whole class and worth keeping separate: an unreal **component** must be settled before position in time, so year zero reports the format cause and year one the date cause. Checked here by execution and already correct in the complete-date classifier, with rows now locking the ordering; the peer's own fix had it as a class defect, so the other four classifiers' orderings are worth the same check when each is next opened.
- `remaining`: the representation. Nothing in Lean changes yet, because the resolution happens at model load and this project has no loader; a `FlatFieldDecl` reaching the gates already carries a resolved format. What is missing is the default table itself and the statement that a flat model's temporal format is post-resolution. Landing it needs a consumer — the first lowering path that accepts a format-less declaration — rather than a function with no caller.
- `remaining`: the exact resolved **literal** is not measured, only its component set and its equality class at every gate probed. Those pin behaviour everywhere tested and would still not distinguish two spellings the Kernel treats as one; a loader-side read would settle it directly and is the peer's to take.
- `entry-gate`: a carrier enters only with its own rows. A measured carrier does not license its neighbour, however similar the mechanism: the reuse-across-a-carrier crossing has been declined three times in this class alone ([`LF116`](../LEAN-FINDINGS.md)), and the alternative is a conjunct that happens to hold and therefore produces no signal.
- `completion-gate`: no `A12Kernel/Elaboration/` or `A12Kernel/Semantics/` site tests a declared temporal kind except where a retained row measures that the kind is what the Kernel reads, or a stated `unmeasured` note names the missing witness.
- `route-state`: ready — the route is `dmtool rule check` for static gates and `:adapter:kernelProbe` for runtime ones, both already exercised on this class. The comparison rows measured a *static admission gate* ([checkpoint](../sources/computation-placement-and-constant-probes.md#src-temporal-value-family-is-the-formats-not-the-kinds)) and the operand rows a second one; which **text parser** runs over a cross-kind stored value is a runtime question neither reaches. The discriminator for that batch: one DATE-declared `HH:mm:ss` field, stored `12:30:00`, read at runtime against its ordinary same-kind control.

### SG27 — the Number formal cascade's conversion route and its two unmodelled readings

- `state`: open
- `owner`: [`NumberFormalCheck.lean`](../../A12Kernel/Semantics/NumberFormalCheck.lean), clause [`04-numbers-and-decimals.md` §4](../../spec/04-numbers-and-decimals.md), outbound [`SPEC-2026-09-07-13`](../A12-DMKITS-SPEC-SYNC-LEDGER.md#spec-2026-09-07-13).
- `closed`: the eleven refusals reachable from a document-loaded value, their order, and their surfaced codes, replayed against 278 measured observations with zero disagreements ([checkpoint](../sources/evaluation-and-application-routes.md#src-number-formal-cascade-code-axis-and-load-canonicalisation)).
- `missing`: the **display-to-internal conversion** entry point, whose input is raw text rather than a canonical value. Four Kernel refusals live only there — leading plus, signed zero, leading zeros, and a missing separator where fractional places are declared. This project has no route to it: `:adapter:kernelProbe` observes `validateFull` and `compute`, both of which consume an already-loaded document.
- `missing`: the money **text** split. The Kernel selects the with-cents message bundle at exactly two declared fractional places and the without-cents bundle otherwise, so a one- or three-place money field renders without-cents text under a with-cents type name. Read from the Kernel's own dispatch, never measured; no probed declaration used one or three places.
- `missing`: a declaration retaining **leading zeros** keeps them in the stored text, so its rendered length exceeds what the numeric value implies. `StoredNumber` cannot represent that, so the length checks are unmodelled for `leadingZerosAllowed: true` and the one probed field carrying it is excluded from the replay.
- `discriminator`: for the conversion route, a value whose canonical and raw forms differ in length — a leading `+` on a field whose minimum rendered length the canonical form fails and the raw form passes — separates the two entry points without needing either to be named.
- `prerequisite`: the first item needs either a Kernel route that accepts raw display text, or a peer measurement naming which of their routes bypasses canonicalisation; `SPEC-2026-09-07-13`'s acceptance asks exactly that. The second needs only two more probed declarations and can close whenever a Number batch is next authored.
- `route-state`: probe-ready for the money text split; discovery-required for the conversion route.
